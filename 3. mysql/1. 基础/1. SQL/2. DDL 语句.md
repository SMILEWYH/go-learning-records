# DDL 语句

## 第一部分：数据库操作

### 1. 查询当前MYSQL实例下的所有数据库：

```sql
SHOW DATABASES;
```

### 2. 查询当前位置处于哪个数据库（查）：

```sql
SELECT DATABASE();
```

### 3. 创建数据库（增）：

```sql
CREATE DATABASE [IF NOT EXISTS] 数据库名 [DEFAULT CHARSET 字符集][COLLATE 排序规则];
```

### 4. 删除数据库（删）：

```sql
DROP DATABASE [IF EXISTS] 数据库名;
```

### 5. 使用数据库（改）：

```sql
USE 数据库名;
```



## 第二部分：表操作

### 1. 查询当前数据库下所有表（查）：

```sql
SHOW TABLES;
```

### 2. 查询表结构（查）：

```sql
DESC 表名;
```

### 3. 查询表的创建语句（查）：

```sql
SHOW CREATE TABLE 表名;
```

### 4. 创建表（增）：

```sql
CREATE TABLE [IF NOT EXISTS] 表名(
    字段名 数据类型 [COMMENT '字段注释'],
    ...  最后一列不要加逗号
) [COMMENT '表注释'] [ENGINE=存储引擎] [DEFAULT CHARSET=字符集] [COLLATE=排序规则];
```

- `ENGINE=InnoDB`：指定该表使用 InnoDB 存储引擎。
- 字段定义中的 `COMMENT '字段注释'`：说明该字段的含义。
- 括号外的 `COMMENT '表注释'`：说明整张表的用途。

示例：

```sql
CREATE TABLE example_user (
    id INT PRIMARY KEY COMMENT '用户编号',
    name VARCHAR(50) COMMENT '用户姓名'
) ENGINE=InnoDB COMMENT='用户表';
```

### 5. 修改表名（改）：

```sql
ALTER TABLE 表名 RENAME TO 新表名;
```

### 6. 删除表（删）：

```sql
DROP TABLE [IF EXISTS] 表名;
```

### 7. 清空表数据（删）：

```sql
TRUNCATE TABLE 表名;
```

删除所有数据行，表结构和约束保留



## 第三部分：字段操作

### 1. 字段数据类型

MySQL中的数据类型有很多，主要分为三类:数值类型、字符串类型、日期时间类型。

#### 1.1 数值类型：

##### 1.1.1 整数类型：

- TINYINT：1字节，范围-128~127 （第二常用）

- SMALLINT：2字节，范围-32768~32767

- MEDIUMINT：3字节，范围-8388608~8388607

- INT：4字节，范围-2147483648~2147483647  （最常用）

- BIGINT：8字节，范围-9223372036854775808~9223372036854775807

默认情况为有正负符号的范围, 如果想要无符号的范围，可以在数据类型后加上UNSIGNED关键字。

##### 1.1.2 浮点数类型：

- FLOAT：4字节，单精度浮点数

- DOUBLE：8字节，双精度浮点数

##### 1.1.3 定点数类型：

- DECIMAL：用于存储精确的小数值，使用的时候需要指定精度和小数位数



#### 1.2 字符串类型：

##### 1.2.1 定长字符串类型：

- CHAR(n)：固定长度的字符串，长度为n，最大长度为255

##### 1.2.2 变长字符串类型：

- VARCHAR(n)：可变长度的字符串，长度为n，最大长度为65535

CHAR和VARCHAR的区别：

​	CHAR是定长的，如果存储的字符串长度小于n，则会在字符串后面补空格，存储时会占用固定的空间。

​	VARCHAR是变长的，如果存储的字符串长度小于n，则只占用实际存储的空间加上1个字节的长度信息。

所以可以根据不同的场景需要来使用：

​	CHAR适合存储长度固定的字符串，如身份证号、手机号等。

​	VARCHAR适合存储长度不固定的字符串，如用户名、地址等。

##### 1.2.3 文本类型：

- TINYBLOB：0-255 bytes，不超过255个字符的二进制数据
- TINYTEXT：0-255 bytes，短文本字符串
- BLOB：0-65535 bytes，二进制形式的长文本数据
- TEXT：0-65535 bytes，长文本数据
- MEDIUMBLOB：0-16777215 bytes，二进制形式的中等长度文本数据
- MEDIUMTEXT：0-16777215 bytes，中等长度文本数据
- LONGBLOB：0-4294967295 bytes，二进制形式的极大文本数据
- LONGTEXT：0-4294967295 bytes，极大文本数据



#### 1.3 日期类型：

- YEAR：1字节，年份值，范围1901~2155（另支持0000），格式YYYY

- DATE：3字节，日期值，范围1000-01-01~9999-12-31，格式YYYY-MM-DD

- TIME：3字节，时间值或持续时间，范围-838:59:59~838:59:59，格式HH:MM:SS

- DATETIME：5字节，日期和时间值，范围1000-01-01 00:00:00~9999-12-31 23:59:59，格式YYYY-MM-DD HH:MM:SS

- TIMESTAMP：4字节，日期和时间值（时间戳），范围1970-01-01 00:00:01~2038-01-19 03:14:07（UTC），格式YYYY-MM-DD HH:MM:SS

##### DATETIME 与 TIMESTAMP 的区别

1. **时间范围**：`DATETIME` 的范围更大，支持 1000～9999 年；`TIMESTAMP` 的范围较小，支持上面列出的 1970～2038 年区间。

2. **时区转换**：`TIMESTAMP` 写入时按当前数据库连接的时区转换成 UTC 保存，读取时再转换成当前连接的时区；`DATETIME` 读取时不会随连接时区转换。

例如：在 UTC+8 的连接中，向两个字段都写入不带时区的 `2026-10-06 12:00:00`，查询时的预期结果如下：

| 查询时的连接时区 | DATETIME | TIMESTAMP |
| --- | --- | --- |
| UTC+8（北京时间） | 2026-10-06 12:00:00 | 2026-10-06 12:00:00 |
| UTC+0 | 2026-10-06 12:00:00 | 2026-10-06 04:00:00 |

注意：`TIMESTAMP` 转换的是时间的显示方式，代表的实际时刻没有改变；北京时间 12:00 和 UTC 时间 04:00 是同一个时刻。



### 2. 添加字段（增）：

```sql
ALTER TABLE 表名 ADD COLUMN 字段名 数据类型 [COMMENT '字段注释'] [FIRST | AFTER 已有字段名];
```

字段位置说明：

- `AFTER 已有字段名`：把新增字段放在该已有字段后面。
- `FIRST`：把新增字段放在第一个位置，与 `AFTER` 二选一。
- 不指定位置：默认添加到所有字段的最后。

例如：`student` 表原有字段顺序为 `id → name → age`，在 `name` 后添加 `gender`：

```sql
ALTER TABLE student ADD COLUMN gender CHAR(1) COMMENT '性别' AFTER name;
```

预期字段顺序变为 `id → name → gender → age`。

### 3. 修改字段类型（改）：

```sql
ALTER TABLE 表名 MODIFY COLUMN 字段名 新数据类型;
```

### 4. 修改字段注释（改）：

```sql
ALTER TABLE 表名 MODIFY COLUMN 字段名 数据类型 COMMENT '新注释';
```

### 5. 修改字段名（改）：

```sql
ALTER TABLE 表名 CHANGE COLUMN 旧字段名 新字段名 数据类型;
```

### 6. 删除字段（删）：

```sql
ALTER TABLE 表名 DROP COLUMN 字段名;
```
