# 表级锁

## 介绍

表级锁，每次操作锁住整张表。锁定粒度大，发生锁冲突的概率最高，并发度最低。应用在 MyISAM、InnoDB、BDB 等存储引擎中。

## 分类

对于表级锁，主要分为以下三类：

1. 表锁
2. 元数据锁（meta data lock，MDL）
3. 意向锁



## 表锁

### 类型

对于表锁，分为两类：

1. 表共享读锁（read lock）
2. 表独占写锁（write lock）

### 语法

1. 加锁：`lock tables 表名... read/write;`

   ```sql
   -- 表共享读锁
   lock tables 表名 read;

   -- 表独占写锁
   lock tables 表名 write;
   ```

2. 释放锁：执行 `unlock tables;`，或客户端断开连接。

   ```sql
   unlock tables;
   ```

### 表现

表共享读锁：加锁客户端、其他客户端可以 DQL；加锁客户端 DDL、DML 会报错失败，其他客户端 DDL、DML 会被堵塞等待。

表独占写锁：加锁客户端可以 DQL 和 DDL、DML；其他客户端 DQL 和 DDL、DML 会被堵塞等待。





## 元数据锁（meta data lock，MDL）

MDL 加锁过程是系统自动控制，无需显式使用，在访问一张表的时候会自动加上。MDL 锁主要作用是维护表元数据的数据一致性（表元数据 = 表结构）。

在表上有活动事务的时候，不可以对元数据进行写入操作。**为了避免 DML 与 DDL 冲突，保证读写的正确性。**

比如我开起了一个事务并在里 insert 数据， 那么在另一个客户端中的修改表结构操作会被堵塞等待。只有在事务中 commit 后，另一个客户端的修改表结构操作才会被正常执行。

| 对应 SQL | 锁类型 | 说明 |
| --- | --- | --- |
| `lock tables xxx read/write` | `SHARED_READ_ONLY` / `SHARED_NO_READ_WRITE` | |
| `select`、`select ... lock in share mode` | `SHARED_READ` | 与 `SHARED_READ`、`SHARED_WRITE` 兼容，与 `EXCLUSIVE` 互斥 |
| `insert`、`update`、`delete`、`select ... for update` | `SHARED_WRITE` | 与 `SHARED_READ`、`SHARED_WRITE` 兼容，与 `EXCLUSIVE` 互斥 |
| `alter table ...` | `EXCLUSIVE` | 与其他的   都互斥 |

注意：

读写表锁和 MDL 共享读锁不是同一种锁。**读写表锁主要限制“谁能读写这张表的数据”；元数据锁（MDL）主要协调“使用这张表”和“修改这张表的结构”，防止两者发生冲突。** 后者通常允许其他会话对表行数据的增删改，但会阻止不兼容的表结构变更。



## 意向锁

为了避免 DML 在执行时，加的行锁与表锁的冲突，在 InnoDB 中引入了意向锁，使得表锁不用检查每行数据是否加锁，使用意向锁来减少表锁的检查。

### 类型

1. 意向共享锁（IS）：由语句 `select ... lock in share mode` 添加。
2. 意向排他锁（IX）：由 `insert`、`update`、`delete`、`select ... for update` 添加。

### 兼容关系

1. 意向共享锁（IS）：与表锁共享锁（read）兼容，与表锁排它锁（write）互斥。
2. 意向排他锁（IX）：与表锁共享锁（read）及排它锁（write）都互斥。意向锁之间不会互斥。
