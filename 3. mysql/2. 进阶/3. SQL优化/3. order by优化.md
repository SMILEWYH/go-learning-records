# order by优化

## 额外说明：ORDER BY 与 WHERE 的顺序区别

**前提：这里讨论的是为了利用索引避免额外排序。** `ORDER BY` 可以按需要指定字段顺序，即使与索引顺序不同，SQL 仍然可以正常排序，只是未必能利用现有索引直接得到排序结果。

在这个前提下，**ORDER BY 中的字段顺序通常需要与联合索引的字段顺序一致；WHERE 中通过 AND 连接的等值条件，其书写顺序不需要与索引字段顺序一致。**

以联合索引 `(age, phone)` 为例：

- `where age = 20 and phone = '13800000000'` 与 `where phone = '13800000000' and age = 20`，不会仅因条件书写顺序不同而影响联合索引的使用。最左前缀原则关注的是查询涉及哪些索引列，而不是 WHERE 条件写在前面还是后面。
- `order by age, phone` 表示先按 age 排序，age 相同时再按 phone 排序，与该索引的字段顺序一致。
- `order by phone, age` 表示先按 phone 排序，排序含义发生了变化，通常不能直接利用 `(age, phone)` 索引的顺序消除额外排序。

注意：如果前导索引列已被等值条件固定，例如 `where age = 20 order by phone`，也可以利用 `(age, phone)` 索引的顺序。此外，升降序方向也需要匹配索引的正向或反向扫描；最终是否采用索引排序，以实际执行计划为准。



## 排序方式

1. **Using filesort**：通过表的索引或全表扫描，读取满足条件的数据行，然后在排序缓冲区 sort buffer 中完成排序操作。所有不是通过索引直接返回排序结果的排序都叫 FileSort 排序。
2. **Using index**：通过有序索引顺序扫描直接返回有序数据，这种情况即为 using index，不需要额外排序，操作效率高。

## 索引与排序示例

```sql
-- 没有创建索引时，根据 age、phone 进行排序是 Using filesort
explain select id,age,phone from tb_user order by age, phone;

-- 创建索引
create index idx_user_age_phone_aa on tb_user(age,phone);

-- 创建索引后，根据 age、phone 进行升序排序是 Using index
explain select id,age,phone from tb_user order by age, phone;

-- 创建索引后，根据 age、phone 进行降序排序是 Using index
explain select id,age,phone from tb_user order by age desc, phone desc;
```

## 一个升序、一个降序

```sql
-- 根据 age、phone 进行排序：age 升序，phone 降序是 Using index 和 Using filesort
explain select id,age,phone from tb_user order by age asc, phone desc;

-- 创建索引
create index idx_user_age_phone_ad on tb_user(age asc,phone desc);

-- 根据 age、phone 进行排序：age 升序，phone 降序是 Using index 
explain select id,age,phone from tb_user order by age asc, phone desc;
```

## order by 优化建议

1. 根据排序字段建立合适的索引，多字段排序时，也遵循最左前缀法则（order by 是有顺序的！）。
2. 尽量使用覆盖索引。
3. 多字段排序，一个升序、一个降序，此时需要注意联合索引在创建时的规则（`ASC` / `DESC`）。
4. 如果不可避免地出现 filesort，大数据量排序时，可以适当增大排序缓冲区大小 `sort_buffer_size`（默认 256 KB）。
