# 索引语法

## 创建索引

```sql
CREATE [ UNIQUE | FULLTEXT ] INDEX index_索引名 ON table_name ( index_col_name,... );
```

额外说明：

1. 不指定 `UNIQUE` 或 `FULLTEXT` 时，创建的是常规索引（普通索引）。
2. `( index_col_name,... )` 内可以填写多个字段名，字段名之间用逗号分隔：单个字段名创建的是单列索引；多个字段名创建的是联合索引，并且联合索引中字段的排序是有讲究的。

## 查看索引

```sql
SHOW INDEX FROM table_name;
```

## 使用索引（消费索引）

创建索引后，正常编写 SELECT 即可，通常不需要在查询中指定索引名。MySQL 优化器会根据查询条件、已有索引和估算成本，决定是否使用索引以及使用哪个索引。

以下假设已创建后文练习中的 `idx_user_name` 和 `idx_user_pro_age_sta` 索引，表名为 `tb_user`。

### 1. 普通索引查询示例

```sql
-- name 字段已有普通索引 idx_user_name，可供本次等值查询使用
SELECT * FROM tb_user WHERE name = '吕布';
```

按后文示例数据，预期返回 `id = 1` 的吕布记录。

### 2. 联合索引查询示例

```sql
-- 已有联合索引 idx_user_pro_age_sta (profession, age, status)
-- 查询条件包含该索引的全部三列，可利用它们进行等值定位
SELECT * FROM tb_user
WHERE profession = '软件工程' AND age = 23 AND status = 1;
```

按后文示例数据，预期返回 `id = 5` 的花木兰记录。

### 3. 确认实际使用了哪个索引

```sql
EXPLAIN SELECT * FROM tb_user
WHERE profession = '软件工程' AND age = 23 AND status = 1;
```

查看结果中的 `key`：若为 `idx_user_pro_age_sta`，表示执行计划选择了该联合索引；若为 `NULL`，表示未选择索引。

**普通 SELECT 本身就会进行索引选择，EXPLAIN 只是用于查看执行计划。** 有索引不代表一定使用，数据量很小或预计匹配记录很多时，优化器可能选择全表扫描。创建索引前后，查询结果应保持一致，主要比较的是访问方式和实际耗时。

## 删除索引

```sql
DROP INDEX index_name ON table_name;
```

### 练习要求

以下 SQL 假设表名为 `tb_user`，使用时替换为实际表名。

1. `name` 字段为姓名字段，该字段的值可能会重复，为该字段创建索引。

   ```sql
   CREATE INDEX idx_user_name ON tb_user (name);
   ```

2. `phone` 手机号字段的值是非空且唯一的，为该字段创建唯一索引。

   ```sql
   CREATE UNIQUE INDEX idx_user_phone ON tb_user (phone);
   ```

   注：唯一索引保证值不重复；非空需要字段本身设置 `NOT NULL`。

3. 为 `profession`、`age`、`status` 创建联合索引。

   ```sql
   CREATE INDEX idx_user_pro_age_sta ON tb_user (profession, age, status);
   ```

4. 为 `email` 建立合适的索引来提升查询效率。

   ```sql
   CREATE INDEX idx_user_email ON tb_user (email);
   ```
