# 存储引擎特点

## 一、InnoDB

### 1. 介绍

InnoDB 是一种兼顾高可靠性和高性能的通用存储引擎。
从 MySQL 5.5 起，InnoDB 是默认的 MySQL 存储引擎。

### 2. 特点（外键、事务、行锁）

1. 支持外键 FOREIGN KEY 约束，保证数据的完整性和正确性。
2. DML 操作遵循 ACID 模型，支持事务
3. 支持行级锁，提高并发访问性能。

### 3. 文件名

- 表名.ibd：使用独立表空间时，每一个 .ibd 文件都对应一张表, 储存着表结构、数据和索引。

​	参数：innodb_file_per_table，用于控制新建表默认是否使用独立表空间, 默认开启。

### 4. 逻辑存储结构

层级关系：表空间（Tablespace）→ 段（Segment）→ 区（Extent）→ 页（Page）→ 行（Row）。

1. 表空间：包含多个段。
2. 段：包含多个区。
3. 区：在默认页大小为 16KB 时，一个区为 1MB，包含 64 个连续的页。
4. 页：默认大小为 16KB，一个数据页中可以存放多行记录。
5. 行：一条数据记录，图中包含以下内容：
   - Trx id：事务 ID。
   - Roll pointer：回滚指针。
   - col1、col2、col3……：各列的数据。

## 二、MyISAM

### 1. 介绍

MyISAM 是 MySQL 早期的默认存储引擎。

### 2. 特点（表锁）

1. 不支持外键，不支持事务，不支持行锁。
2. 支持表锁。
3. 访问速度快（具体性能取决于实际业务场景）。

### 3. 文件

- xxx.sdi：存储表结构信息。
- xxx.MYD：存储数据。
- xxx.MYI：存储索引。

## 三、Memory

### 1. 介绍

Memory 引擎的表数据存储在内存中，硬件故障或断电可能导致数据丢失，适合存放临时数据或作为缓存使用。

### 2. 特点

1. 数据存放在内存中。
2. 默认使用 HASH 索引。

### 3. 文件

- xxx.sdi：存储表结构信息。

## 四、存储引擎特点对比（按图整理）

| 特点 | InnoDB | MyISAM | Memory |
| --- | --- | --- | --- |
| 存储限制 | 64TB | 有 | 有 |
| 事务安全 | 支持（重点） | - | - |
| 锁机制 | 行锁（重点） | 表锁 | 表锁 |
| B+tree 索引 | 支持 | 支持 | 支持 |
| Hash 索引 | - | - | 支持 |
| 全文索引 | 支持（5.6 版本之后） | 支持 | - |
| 空间使用 | 高 | 低 | N/A |
| 内存使用 | 高 | 低 | 中等 |
| 批量插入速度 | 低 | 高 | 高 |
| 支持外键 | 支持（重点） | - | - |

说明：- 表示不支持，N/A 表示不适用；资源占用和速度为图中的概括，实际表现取决于数据、配置和业务场景。
