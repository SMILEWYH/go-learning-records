IllegalPrefixes 是一组小写前缀，用于标识某条注释不是文档注释。这有助于避免将紧挨 package 语句之前的版权声明误认为文档注释；这是一种常见错误。

var IllegalPrefixes = []string{
    "copyright",
    "all rights",
    "author",
}

func ToHTML 

func ToHTML(w io.Writer, text string, words map[string]string)

ToHTML 将注释文本转换为格式化的 HTML。

已弃用：ToHTML 无法识别文档注释中的文档链接，因为识别这些链接需要知道文本来自哪个包，而此 API 不包含该信息。

已知包含 text 的 *doc.Package p 时，可以将 ToHTML(w, text, nil) 替换为：

w.Write(p.HTML(text))

这又是以下写法的简写：

w.Write(p.Printer().HTML(p.Parser().Parse(text)))

如果 words 可能非 nil，则需要使用更完整的替代写法：

parser := p.Parser()
parser.Words = words
w.Write(p.Printer().HTML(parser.Parse(d)))

func ToText 

func ToText(w io.Writer, text string, prefix, codePrefix string, width int)

ToText 将注释文本转换为格式化文本。

已弃用：ToText 无法识别文档注释中的文档链接，因为识别这些链接需要知道文本来自哪个包，而此 API 不包含该信息。

已知包含 text 的 *doc.Package p 时，可以将 ToText(w, text, "", " ", 80) 替换为：

w.Write(p.Text(text))

在一般情况下，可以将 ToText(w, text, prefix, codePrefix, width) 替换为：

d := p.Parser().Parse(text)
pr := p.Printer()
pr.TextPrefix = prefix
pr.TextCodePrefix = codePrefix
pr.TextWidth = width
w.Write(pr.Text(d))

详情请参阅 Package.Text 和 comment.Printer.Text 的文档。

type Example

Example 表示在测试源文件中找到的一个示例函数。

type Example struct {
    Name        string // 被示例演示的条目名称（含可选后缀）
    Suffix      string // 示例后缀，不包含前导 '_'（仅由 NewFromFiles 填充）；Go 1.14 中加入
    Doc         string // 示例函数的文档字符串
    Code        ast.Node
    Play        *ast.File // 示例的完整程序版本；Go 1.1 中加入
    Comments    []*ast.CommentGroup
    Output      string // 预期输出
    Unordered   bool // Go 1.7
    EmptyOutput bool // 预期输出为空；Go 1.1 中加入
    Order       int  // 原始源代码中的顺序；Go 1.1 中加入
}

func Examples 

func Examples(testFiles ...*ast.File) []*Example

Examples 返回在 testFiles 中找到的示例，并按 Name 字段排序。Order 字段记录找到示例的先后顺序。直接调用 Examples 时不会填充 Suffix 字段；只有 NewFromFiles 会为它在 _test.go 文件中找到的示例填充该字段。

可运行的示例必须位于名称以 "_test" 结尾的包中。满足以下任一条件时，Example 就是“可运行的”（Play 字段非 nil）：

  • 示例函数自包含：该函数只引用其他包中的标识符（或 "int" 等预声明标识符），并且测试文件不包含点导入。
  • 整个测试文件就是示例：文件恰好包含一个示例函数，不包含任何测试函数、模糊测试函数或基准测试函数，并且除示例函数之外，还至少包含一个顶层函数、类型、变量或常量声明。

type Func

Func 是 func 声明的文档。

type Func struct {
    Doc  string
    Name string
    Decl *ast.FuncDecl

    // 方法
    // （对于函数，这些字段为各自的零值）
    Recv  string // 实际接收者 "T" 或 "*T"，后面可能跟类型参数 [P1, ..., Pn]
    Orig  string // 原始接收者 "T" 或 "*T"
    Level int    // 嵌入层级；0 表示未嵌入

    // Examples 是与此函数或方法关联的
    // 已排序示例列表。示例的来源是
    // 提供给 NewFromFiles 的 _test.go 文件。
    Examples []*Example // Go 1.14
}

type Mode

Mode 值控制 New 和 NewFromFiles 的行为。

type Mode int
const (
    // AllDecls 表示提取所有包级声明的文档，
    // 而不局限于导出的声明。
    AllDecls Mode = 1 << iota

    // AllMethods 表示显示所有嵌入方法，而不局限于
    // 不可见（未导出）的匿名字段的方法。
    AllMethods

    // PreserveAST 表示不修改 AST。最初，为了在 godoc 中
    // 节省内存，会将 AST 的某些部分（例如函数体）置为 nil，
    // 但并非所有程序都需要这种行为。
    PreserveAST
)

type Note 1.1

Note 表示以 "MARKER(uid): note body" 开头的标记注释。只要标记由至少两个大写字母 [A-Z] 组成，且 uid 至少有一个字符，该注记就会被识别。uid 后面的 ":" 可省略。注记收集在 Package.Notes 映射中，以注记标记为索引。

type Note struct {
    Pos, End token.Pos // 包含该标记的注释的位置范围
    UID      string    // 与标记一起找到的 uid
    Body     string    // 注记的正文文本
}

type Package

Package 是整个包的文档。

type Package struct {
    Doc        string
    Name       string
    ImportPath string
    Imports    []string
    Filenames  []string
    Notes      map[string][]*Note // Go 1.1

    // 已弃用：为了向后兼容，仍会填充 Bugs，
    // 但所有新代码都应改用 Notes。
    Bugs []string

    // 声明
    Consts []*Value
    Types  []*Type
    Vars   []*Value
    Funcs  []*Func

    // Examples 是已排序的示例列表，关联对象为
    // 当前包。示例的来源是
    // 提供给 NewFromFiles 的 _test.go 文件。
    Examples []*Example // Go 1.14
    // 包含已过滤或未导出的字段
}

func New 

func New(pkg *ast.Package, importPath string, mode Mode) *Package

New 为给定的包 AST 生成包文档。New 接管 AST pkg 的所有权，可能编辑或覆盖它。要填充 Examples 字段，请使用 NewFromFiles，并包含该包的 _test.go 文件。

func NewFromFiles 1.14 

func NewFromFiles(fset *token.FileSet, files []*ast.File, importPath string, opts ...any) (*Package, error)

NewFromFiles 为包生成文档。

包通过一个 *ast.File 列表及其对应的文件集指定；文件集不能为 nil。

NewFromFiles 在生成文档时会使用所有提供的文件，因此调用方有责任仅提供与目标构建上下文匹配的文件。可以使用 "go/build".Context.MatchFile，判断文件是否匹配具有指定 GOOS、GOARCH 值及其他构建约束的构建上下文。包的导入路径由 importPath 指定。

在 _test.go 文件中找到的示例，会根据其名称与相应的类型、函数、方法或包关联。如果示例名称带有后缀，则将其设置到 Example.Suffix 字段。名称格式不正确的 Examples 会被跳过。

可以选择额外提供一个 Mode 类型的参数，以控制文档提取行为的底层细节。

NewFromFiles 接管 AST 文件的所有权，并可能编辑它们，除非启用了 PreserveAST Mode 位。

func (*Package) Synopsis 1.19 

func (p *Package) Synopsis(text string) string

Synopsis 返回 text 中第一句话经过清理后的版本。该句子在首个满足以下条件的句点之后结束：句点后跟空格，且其前面不是恰好一个大写字母；也会在首次段落分隔处结束。结果字符串不包含 \n、\r 或 \t 字符，单词之间只使用单个空格。如果 text 以 IllegalPrefixes 中的任何前缀开头，结果为空字符串。

func (*Package) Text 1.19 

func (p *Package) Text(text string) []byte

Text 返回文档注释文本的格式化文本，按 80 个 Unicode 码点换行，并用制表符缩进代码块。

要自定义格式化细节，请使用 Package.Printer 获取 comment.Printer，并在调用其 Text 方法之前进行配置。

type Type

Type 是类型声明的文档。

type Type struct {
    Doc  string
    Name string
    Decl *ast.GenDecl

    // 关联的声明
    Consts  []*Value // 主要属于此类型的常量的已排序列表
    Vars    []*Value // 主要属于此类型的变量的已排序列表
    Funcs   []*Func  // 返回此类型的函数的已排序列表
    Methods []*Func  // 此类型的方法的已排序列表（包括嵌入方法）

    // Examples 是已排序的示例列表，关联对象为
    // 此类型。示例的来源是
    // 提供给 NewFromFiles 的 _test.go 文件。
    Examples []*Example // Go 1.14
}
