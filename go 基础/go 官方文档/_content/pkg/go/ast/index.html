语法树可以直接构造，但通常由语法分析器从 Go 源代码生成；参见 go/parser.ParseFile 函数。

func FileExports 

func FileExports(src *File) bool

FileExports 就地裁剪 Go 源文件的 AST，使其只保留导出节点：删除所有未导出的顶层标识符及其关联信息（例如类型、初始值或函数体）。导出类型中未导出的字段和方法也会被移除。File.Comments 列表不会改变。

FileExports 报告是否存在导出声明。

func FilterDecl 

func FilterDecl(decl Decl, f Filter) bool

FilterDecl 就地裁剪 Go 声明的 AST，删除所有未通过过滤函数 f 的名称，包括结构体字段名和接口方法名，但不包括参数列表中的名称。

FilterDecl 报告过滤后是否还剩下任何声明的名称。

func FilterFile 

func FilterFile(src *File, f Filter) bool

FilterFile 就地裁剪 Go 文件的 AST，从顶层声明中删除所有未通过过滤函数 f 的名称，包括结构体字段名和接口方法名，但不包括参数列表中的名称。如果某个声明在删除后为空，就将该声明从 AST 中移除。导入声明始终被移除。File.Comments 列表不会改变。

FilterFile 报告过滤后是否还剩下任何顶层声明。

func FilterPackage 

func FilterPackage(pkg *Package, f Filter) bool

FilterPackage 就地裁剪 Go 包的 AST，从顶层声明中删除所有未通过过滤函数 f 的名称，包括结构体字段名和接口方法名，但不包括参数列表中的名称。如果某个声明在删除后为空，就将该声明从 AST 中移除。pkg.Files 列表不会改变，以免丢失文件名和顶层包注释。

FilterPackage 报告过滤后是否还剩下任何顶层声明。

已弃用：请使用类型检查器 go/types 代替 Package；参见 Object。也可以使用 FilterFile。

func Fprint 

func Fprint(w io.Writer, fset *token.FileSet, x any, f FieldFilter) error

Fprint 将从 AST 节点 x 开始的树或子树输出到 w。如果 fset != nil，则相对于该文件集解释位置信息；否则将位置输出为整数值（文件集特定的偏移量）。

可以提供非 nil 的 FieldFilter f 来控制输出：只有 f(fieldname, fieldvalue) 为 true 的结构体字段才会被输出，其他字段均被过滤掉。未导出的结构体字段永远不会输出。

func Inspect 

func Inspect(node Node, f func(Node) bool)

Inspect 按深度优先顺序遍历 AST：首先调用 f(node)，node 不能为 nil。如果 f 返回 true，Inspect 会对 node 的每个非 nil 子节点递归调用 f，最后再调用 f(nil)。

在许多情况下，使用 Preorder 会更方便，它返回遍历节点序列的迭代器；也可以使用 PreorderStack，它与 Inspect 一样允许控制是否进入子树，但还会报告包含当前节点的祖先节点栈。

func IsGenerated 1.21 

func IsGenerated(file *File) bool

IsGenerated 通过检测 https://go.dev/s/generatedcode 描述的特殊注释，报告该文件是否由程序生成，而非手工编写。

必须使用 go/parser.ParseComments 标志解析语法树。例如：

func Preorder 1.23 

func Preorder(root Node) iter.Seq[Node]

Preorder 返回一个迭代器，按深度优先的前序顺序遍历指定根节点之下（包括根节点）的语法树全部节点。

要更精细地控制各个子树的遍历，请使用 Inspect 或 PreorderStack。

func PreorderStack 1.25 

func PreorderStack(root Node, stack []Node, f func(n Node, stack []Node) bool)

PreorderStack 遍历以 root 为根的树，在访问每个节点之前调用 f。

每次调用 f 都提供当前节点和遍历栈；遍历栈由 stack 的原始值加上从 root 到 n 的所有节点组成，但不包括 n 本身。（这种设计允许嵌套调用 PreorderStack 而不会重复计算节点。）

如果 f 返回 false，遍历将跳过该子树。与 Inspect 不同，访问节点 n 后不会再次调用 f。（实践中，第二次调用几乎总是仅用于出栈，而正确完成这件事意外地棘手。）

func Print 

func Print(fset *token.FileSet, x any) error

Print 将 x 输出到标准输出，跳过 nil 字段。Print(fset, x) 与 Fprint(os.Stdout, fset, x, NotNilFilter) 相同。

SortImports 对 f 的导入块中连续的导入行进行排序。只要不会丢失数据，它还会删除重复导入。

func Walk 

func Walk(v Visitor, node Node)

Walk 按深度优先顺序遍历 AST：首先调用 v.Visit(node)，node 不能为 nil。如果 v.Visit(node) 返回的访问器 w 非 nil，则对 node 的每个非 nil 子节点以访问器 w 递归调用 Walk，最后调用 w.Visit(nil)。

type BasicLit

BasicLit 节点表示基本类型字面量。

注意，对于 CHAR 和 STRING 种类，字面量连同引号一起存储。例如，对于双引号 STRING，Value 字段中的第一个和最后一个 rune 都是 "。可以分别使用 strconv.Unquote 和 strconv.UnquoteChar 函数去除 STRING 和 CHAR 值的引号。

对于原始字符串字面量（Kind == token.STRING && Value[0] == '`'），Value 字段包含字符串文本，但不包含源代码中可能存在的回车符（\r）。

type BasicLit struct {
    ValuePos token.Pos   // 字面量的位置
    ValueEnd token.Pos   // 紧接字面量之后的位置；Go 1.26 中加入
    Kind     token.Token // token.INT、token.FLOAT、token.IMAG、token.CHAR 或 token.STRING
    Value    string      // 字面量字符串，例如 42、0x7f、3.14、1e-9、2.4i、'a'、'\x7f'、"foo" 或 `\m\n\o`
}

func NewCommentMap 1.1 

func NewCommentMap(fset *token.FileSet, node Node, comments []*CommentGroup) CommentMap

NewCommentMap 创建新的注释映射，将 comments 列表中的注释组与 node 指定的 AST 中的节点关联。

满足以下任一条件时，注释组 g 与节点 n 关联：

  • g 的起始行与 n 的结束行相同
  • g 从紧接 n 的下一行开始，且 g 之后、下一个节点之前至少有一个空行
  • g 从 n 之前开始，并且按前面的规则，它没有与 n 前面的节点关联

NewCommentMap 尽量将注释组关联到“最大”的节点。例如，如果注释是赋值语句尾部的行注释，就将它关联到整个赋值，而不是赋值中最后一个操作数。

type Directive 1.26

Directive 是以下形式的注释：

//tool:name args

例如，对于以下指令：

//go:generate stringer -type Op -trimprefix Op

其 Tool 为 "go"，Name 为 "generate"，Args 为 "stringer -type Op -trimprefix Op"。

虽然 Args 没有严格的语法，但按照惯例，它是以空格分隔的序列，序列元素可以是不带引号的单词、以 '"' 括起的 Go 字符串，或以 '`' 括起的原始字符串。

规范见 https://go.dev/doc/comment#directives。

type Directive struct {
    Tool string
    Name string
    Args string // 无前导或尾随空白

    // Slash 是指令开头 "//" 的位置。
    Slash token.Pos

    // ArgsPos 是 Args 的起始位置，根据传给
    // ParseDirective 的位置计算。
    ArgsPos token.Pos
}

func ParseDirective 1.26 

func ParseDirective(pos token.Pos, c string) (Directive, bool)

ParseDirective 从单行注释中解析指令注释。

如果该行不是指令注释，则返回 false。

提供的文本必须只有一行，并应包含开头的 "//"。如果文本不以 "//" 开头，则返回 false。

调用方可以提供 c 起始处的文件位置，用于跟踪各个参数的位置。该位置可以是 Comment.Slash，也可以由调用方构造，或者直接为 0。如果调用方传入 0，那么这些位置实际上就是字符串 c 内的字节偏移量。

type File

File 节点表示 Go 源文件。

Comments 列表按出现顺序包含源文件中的全部注释，包括其他节点通过 Doc 和 Comment 字段指向的注释。

type Object

Object 描述命名的语言实体，例如包、常量、类型、变量、函数（包括方法）或标签。

Data 字段包含对象特定的数据：

Kind    Data 类型         Data 值
Pkg     *Scope            包作用域
Con     int               相应声明的 iota 值

已弃用：没有类型信息，就无法正确计算 Ident 与 Object 之间的关系。例如，表达式 T{K: 0} 可能表示结构体、映射、切片或数组字面量，这取决于 T 的类型。如果 T 是结构体，则 K 引用 T 的字段；对于其他类型，K 引用环境中的某个值。

新程序应设置 go/parser.SkipObjectResolution 语法分析器标志，禁用基于语法的对象解析（这也会节省 CPU 和内存）；如果需要解析对象，则改用类型检查器 go/types。详情参见 go/types.Info 结构体的 Defs、Uses 和 Implicits 字段。

type Object struct {
    Kind ObjKind
    Name string // 声明的名称
    Decl any    // 对应的 Field、XxxSpec、FuncDecl、LabeledStmt、AssignStmt、Scope；或 nil
    Data any    // 对象特定的数据；或 nil
    Type any    // 类型信息的占位符；可以为 nil
}
