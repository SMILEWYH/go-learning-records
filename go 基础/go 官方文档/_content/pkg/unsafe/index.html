unsafe 包包含绕过 Go 程序类型安全的操作。

导入 unsafe 的包可能不具备可移植性，也不受 Go 1 兼容性准则保护。

func Alignof 

func Alignof(x ArbitraryType) uintptr

Alignof 接受任意类型的表达式 x，并返回假想变量 v 所需的对齐值，就好像 v 是通过 var v = x 声明的一样。它是满足 v 的地址对 m 取模始终为零的最大 m。此值与 reflect.TypeOf(x).Align() 的返回值相同。有一种特殊情况：如果变量 s 是结构体类型，f 是该结构体中的字段，则 Alignof(s.f) 返回结构体中该类型字段所需的对齐值。此时它与 reflect.TypeOf(s.f).FieldAlign() 的返回值相同。如果实参类型不具有可变大小，Alignof 的返回值是 Go 常量。（可变大小类型的定义见 Sizeof 的说明。）

func Offsetof 

func Offsetof(x ArbitraryType) uintptr

Offsetof 返回 x 所表示的字段在结构体中的偏移量；x 必须采用 structValue.field 的形式。换言之，它返回结构体起始位置与字段起始位置之间的字节数。如果实参 x 的类型不具有可变大小，Offsetof 的返回值是 Go 常量。（可变大小类型的定义见 Sizeof 的说明。）

func Sizeof 

func Sizeof(x ArbitraryType) uintptr

Sizeof 接受任意类型的表达式 x，并返回假想变量 v 的字节大小，就好像 v 是通过 var v = x 声明的一样。该大小不包括 x 可能引用的任何内存。例如，如果 x 是切片，Sizeof 返回切片描述符的大小，而不是切片所引用内存的大小；如果 x 是接口，Sizeof 返回接口值本身的大小，而不是接口中存储的值的大小。对于结构体，此大小包括字段对齐引入的所有填充。如果实参 x 的类型不具有可变大小，Sizeof 的返回值是 Go 常量。（如果类型是类型参数，或者是包含大小可变元素的数组或结构体类型，则该类型具有可变大小。）

func String 

func String(ptr *byte, len IntegerType) string

String 返回一个字符串值，其底层字节从 ptr 开始，长度为 len。

len 实参必须具有整数类型或为无类型常量。常量 len 实参必须非负，且可以由 int 类型的值表示；如果它是无类型常量，则赋予其 int 类型。在运行时，如果 len 为负，或者 ptr 为 nil 而 len 不为零，将发生运行时 panic。

由于 Go 字符串不可变，只要返回的字符串值仍然存在，就不得修改传给 String 的字节。

func StringData 

func StringData(str string) *byte

StringData 返回指向 str 底层字节的指针。对于空字符串，返回值未指定，可能为 nil。

由于 Go 字符串不可变，不得修改 StringData 返回的字节。

func Slice 

func Slice(ptr *ArbitraryType, len IntegerType) []ArbitraryType

Slice 函数返回一个切片，其底层数组从 ptr 开始，长度和容量均为 len。Slice(ptr, len) 等价于

(*[len]ArbitraryType)(unsafe.Pointer(ptr))[:]

但有一种特殊情况例外：如果 ptr 为 nil 且 len 为零，则 Slice 返回 nil。

len 实参必须具有整数类型或为无类型常量。常量 len 实参必须非负，且可以由 int 类型的值表示；如果它是无类型常量，则赋予其 int 类型。在运行时，如果 len 为负，或者 ptr 为 nil 而 len 不为零，将发生运行时 panic。

func SliceData 

func SliceData(slice []ArbitraryType) *ArbitraryType

SliceData 返回指向实参 slice 的底层数组的指针。

  • 如果 cap(slice) > 0，SliceData 返回 &slice[:1][0]。
  • 如果 slice == nil，SliceData 返回 nil。
  • 否则，SliceData 返回指向未指定内存地址的非 nil 指针。

type Pointer

Pointer 表示指向任意类型的指针。Pointer 类型允许以下四种其他类型不具备的特殊操作：

  • 任意类型的指针值都可以转换为 Pointer。
  • Pointer 可以转换为任意类型的指针值。
  • uintptr 可以转换为 Pointer。
  • Pointer 可以转换为 uintptr。

因此，Pointer 允许程序绕过类型系统并读写任意内存，使用时必须极其谨慎。

以下涉及 Pointer 的用法是有效的。不遵循这些用法的代码，现在很可能无效，或将来可能失效。即使以下有效用法也有重要的注意事项。

运行“go vet”可以帮助发现不符合这些用法的 Pointer 使用，但“go vet”没有报告问题并不保证代码有效。

（1）将 *T1 转换为 Pointer，再转换为 *T2。

只要 T2 不大于 T1，且两者具有等价的内存布局，此转换就允许将一种类型的数据重新解释为另一种类型的数据。例如 math.Float64bits 的实现：

func Float64bits(f float64) uint64 {
	return *(*uint64)(unsafe.Pointer(&f))
}

（2）将 Pointer 转换为 uintptr（但不再转回 Pointer）。

将 Pointer 转换为 uintptr，会得到以整数表示的所指向值的内存地址。此类 uintptr 的常见用途是打印地址。

通常，将 uintptr 转换回 Pointer 是无效的。

uintptr 是整数，不是引用。将 Pointer 转换为 uintptr 会创建一个不具有指针语义的整数值。即使 uintptr 保存着某个对象的地址，当对象移动时，垃圾回收器也不会更新该 uintptr 的值；该 uintptr 也不能阻止对象被回收。

剩余用法列出了从 uintptr 转换为 Pointer 的全部有效情形。

（3）将 Pointer 转换为 uintptr，进行算术运算，再转回 Pointer。

如果 p 指向一个已分配对象内部，可以将其转换为 uintptr、加上偏移量，再转换回 Pointer，从而在对象内部移动指针。

p = unsafe.Pointer(uintptr(p) + offset)

此用法最常用于访问结构体字段或数组元素：

// 等价于 f := unsafe.Pointer(&s.f)
f := unsafe.Pointer(uintptr(unsafe.Pointer(&s)) + unsafe.Offsetof(s.f))

// 等价于 e := unsafe.Pointer(&x[i])
e := unsafe.Pointer(uintptr(unsafe.Pointer(&x[0])) + i*unsafe.Sizeof(x[0]))

以这种方式对指针加上或减去偏移量都是有效的。使用 &^ 对指针取整也是有效的，通常用于对齐。无论哪种情况，结果都必须仍然指向原来已分配对象的内部。

与 C 不同，将指针前移到刚好越过原始分配区域末尾的位置是无效的：

// 无效：end 指向已分配空间之外。
var s thing
end = unsafe.Pointer(uintptr(unsafe.Pointer(&s)) + unsafe.Sizeof(s))

// 无效：end 指向已分配空间之外。
b := make([]byte, n)
end = unsafe.Pointer(uintptr(unsafe.Pointer(&b[0])) + uintptr(n))

注意，两次转换必须出现在同一个表达式中，中间只能有相关算术运算：

// 无效：uintptr 不能先存入变量，
// 再转换回 Pointer。
u := uintptr(p)
p = unsafe.Pointer(u + offset)

注意，指针必须指向一个已分配对象内部，因此不得为 nil。

// 无效：转换 nil 指针
u := unsafe.Pointer(nil)
p := unsafe.Pointer(uintptr(u) + offset)

（4）在调用 syscall.Syscall 之类函数时，将 Pointer 转换为 uintptr。

syscall 包的 Syscall 函数会将其 uintptr 实参直接传给操作系统，操作系统可能根据调用的具体情况将其中一些重新解释为指针。也就是说，系统调用实现会隐式地将某些实参从 uintptr 转换回指针。

如果指针实参必须转换为 uintptr 才能用作实参，则转换必须直接出现在调用表达式中：

syscall.Syscall(SYS_READ, uintptr(fd), uintptr(unsafe.Pointer(p)), uintptr(n))

在调用由汇编实现的函数时，对于实参列表中转换为 uintptr 的 Pointer，编译器会确保其引用的已分配对象（如果存在）一直保留且不移动，直到调用完成；尽管仅从类型来看，该对象似乎在调用期间已不再需要。

为了让编译器识别此用法，转换必须出现在实参列表中：

// 无效：uintptr 不能先存入变量，
// 再在系统调用期间隐式转换回 Pointer。
u := uintptr(unsafe.Pointer(p))
syscall.Syscall(SYS_READ, uintptr(fd), u, uintptr(n))

（5）将 reflect.Value.Pointer 或 reflect.Value.UnsafeAddr 的返回结果从 uintptr 转换为 Pointer。

reflect 包中 Value 的 Pointer 和 UnsafeAddr 方法返回 uintptr，而不是 unsafe.Pointer，以防调用方在尚未导入 "unsafe" 时就将结果改为任意类型。不过，这意味着结果很脆弱，必须在调用后立即于同一个表达式中转换为 Pointer：

p := (*int)(unsafe.Pointer(reflect.ValueOf(new(int)).Pointer()))

与上述情况一样，在转换之前存储结果是无效的：

// 无效：uintptr 不能先存入变量，
// 再转换回 Pointer。
u := reflect.ValueOf(new(int)).Pointer()
p := (*int)(unsafe.Pointer(u))

（6）将 reflect.SliceHeader 或 reflect.StringHeader 的 Data 字段转换为 Pointer，或反向转换。

与上一种情况一样，reflect 的 SliceHeader 和 StringHeader 数据结构将 Data 字段声明为 uintptr，以防调用方在尚未导入 "unsafe" 时就将结果改为任意类型。不过，这意味着 SliceHeader 和 StringHeader 仅在解释实际切片值或字符串值的内容时才有效。

var s string
hdr := (*reflect.StringHeader)(unsafe.Pointer(&s)) // 情形 1
hdr.Data = uintptr(unsafe.Pointer(p))              // 情形 6（当前情形）
hdr.Len = n

在此用法中，hdr.Data 实际上是引用字符串头部底层指针的另一种方式，而不是独立的 uintptr 变量。

一般而言，reflect.SliceHeader 和 reflect.StringHeader 只应以指向实际切片或字符串的 *reflect.SliceHeader 和 *reflect.StringHeader 形式使用，绝不能作为普通结构体使用。程序不应声明或分配这些结构体类型的变量。

// 无效：直接声明的头部不会将 Data 作为引用持有。
var hdr reflect.StringHeader
hdr.Data = uintptr(unsafe.Pointer(p))
hdr.Len = n
s := *(*string)(unsafe.Pointer(&hdr)) // p 可能已经丢失

func Add 

func Add(ptr Pointer, len IntegerType) Pointer

Add 函数将 len 加到 ptr 上，并返回更新后的指针 Pointer(uintptr(ptr) + uintptr(len))。len 实参必须具有整数类型或为无类型常量。常量 len 实参必须可以由 int 类型的值表示；如果它是无类型常量，则赋予其 int 类型。关于 Pointer 有效用法的规则仍然适用。
