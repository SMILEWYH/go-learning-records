func Marshal 

func Marshal(v any) ([]byte, error)

Marshal 返回 v 的 XML 编码。

Marshal 处理数组或切片时，会序列化每个元素。处理指针时，会序列化指针指向的值；如果指针为 nil，则不写入任何内容。处理接口值时，会序列化接口中包含的值；如果接口值为 nil，则不写入任何内容。处理其他数据时，会写入一个或多个包含该数据的 XML 元素。

XML 元素的名称按以下优先顺序选取：

  • 如果数据是结构体，使用 XMLName 字段上的标签
  • 类型为 Name 的 XMLName 字段的值
  • 用于获取该数据的结构体字段上的标签
  • 用于获取该数据的结构体字段名
  • 被序列化类型的名称

结构体对应的 XML 元素包含该结构体每个导出字段序列化后的元素，但以下情况除外：

  • 省略上述 XMLName 字段。
  • 省略标签为“-”的字段。
  • 标签为“name,attr”的字段成为 XML 元素中具有指定名称的属性。
  • 标签为“,attr”的字段成为 XML 元素中以字段名命名的属性。
  • 标签为“,chardata”的字段作为字符数据写入，而非 XML 元素。
  • 标签为“,cdata”的字段作为字符数据写入，由一个或多个 <![CDATA[ ... ]]> 标签包裹，而非作为 XML 元素。
  • 标签为“,innerxml”的字段原样写入，不经过通常的序列化过程。
  • 标签为“,comment”的字段作为 XML 注释写入，不经过通常的序列化过程。其内容不得包含“--”字符串。
  • 如果字段标签含有“omitempty”选项，且字段值为空，则省略该字段。空值包括 false、0、任何 nil 指针或接口值，以及长度为零的数组、切片、映射或字符串。
  • 匿名结构体字段的处理方式与将其值的各字段视为外层结构体的一部分相同。
  • 接口类型的匿名结构体字段会以该类型名作为字段名处理，而不视为匿名字段。
  • 实现了 Marshaler 的字段通过调用其 MarshalXML 方法写入。
  • 实现了 encoding.TextMarshaler 的字段通过将其 MarshalText 方法的结果编码为文本来写入。

如果字段使用标签“a>b>c”，则元素 c 会嵌套在父元素 a 和 b 内。彼此相邻且指定相同父元素的字段会被包含在同一个 XML 元素中。

如果结构体字段的 XML 名称同时由字段标签和该结构体的 XMLName 字段定义，则这两个名称必须一致。

示例见 MarshalIndent。

如果要求序列化通道、函数或映射，Marshal 会返回错误。

func Unmarshal 

func Unmarshal(data []byte, v any) error

Unmarshal 解析 XML 编码的数据，并将结果存入 v 指向的值中；该值必须是任意结构体、切片或字符串。格式正确但无法放入 v 的数据会被丢弃。

由于 Unmarshal 使用 reflect 包，它只能给导出的字段（以大写字母开头）赋值。Unmarshal 采用区分大小写的比较，将 XML 元素名与标签值和结构体字段名匹配。

Unmarshal 按以下规则将 XML 元素映射到结构体。规则中的字段标签指结构体字段标签内与键“xml”关联的值（见上面的示例）。

  • 如果结构体有一个 []byte 或 string 类型的字段，且标签为“,innerxml”，Unmarshal 会将元素内部嵌套的原始 XML 累积到该字段中。其余规则仍然适用。

  • 如果结构体有一个名为 XMLName、类型为 Name 的字段，Unmarshal 会将元素名称记录到该字段中。

  • 如果 XMLName 字段带有“name”或“namespace-URL name”形式的标签，XML 元素必须具有给定名称（以及可选的命名空间），否则 Unmarshal 会返回错误。

  • 如果 XML 元素有一个属性，其名称与标签包含“,attr”的结构体字段名匹配，或与“name,attr”形式的结构体字段标签中显式指定的名称匹配，Unmarshal 会将该属性值记录到相应字段中。

  • 如果 XML 元素有一个属性未被上一条规则处理，且结构体中存在标签包含“,any,attr”的字段，Unmarshal 会将该属性值记录到第一个这样的字段中。

  • 如果 XML 元素包含字符数据，该数据会累积到第一个标签为“,chardata”的结构体字段中。该字段可以是 []byte 或 string 类型。如果不存在这样的字段，则丢弃字符数据。

  • 如果 XML 元素包含注释，它们会累积到第一个标签为“,comment”的结构体字段中。该字段可以是 []byte 或 string 类型。如果不存在这样的字段，则丢弃注释。

  • 如果 XML 元素包含子元素，且其名称与“a”或“a>b>c”形式标签的前缀匹配，Unmarshal 会深入 XML 结构，查找具有给定名称的元素，并将最内层的元素映射到该结构体字段。以“>”开头的标签等价于以字段名加“>”开头的标签。

  • 如果 XML 元素包含子元素，其名称与某个结构体字段的 XMLName 标签匹配，且该字段没有按上一条规则显式指定名称标签，Unmarshal 会将该子元素映射到此字段。

  • 如果 XML 元素包含子元素，其名称与一个没有任何模式标志（“,attr”、“,chardata”等）的字段匹配，Unmarshal 会将该子元素映射到此字段。

  • 如果 XML 元素包含子元素，但该子元素不匹配上述任何规则，且结构体存在标签为“,any”的字段，Unmarshal 会将该子元素映射到此字段。

  • 匿名结构体字段的处理方式与将其值的各字段视为外层结构体的一部分相同。

  • 标签为“-”的结构体字段永远不会被写入反序列化结果。

如果 Unmarshal 遇到实现了 Unmarshaler 接口的字段类型，它会调用该字段的 UnmarshalXML 方法，从 XML 元素生成值。否则，如果该值实现了 encoding.TextUnmarshaler，Unmarshal 会调用该值的 UnmarshalText 方法。

Unmarshal 将 XML 元素映射到 string 或 []byte 时，会将该元素的字符数据拼接后保存在字符串或 []byte 中。保存的 []byte 永远不会是 nil。

Unmarshal 将属性值映射到 string 或 []byte 时，会将该值保存在字符串或切片中。

Unmarshal 将属性值映射到 Attr 时，会将包含名称在内的整个属性保存在 Attr 中。

Unmarshal 将 XML 元素或属性值映射到切片时，会扩展切片长度，并将该元素或属性映射到新创建的值。

Unmarshal 将 XML 元素或属性值映射到 bool 时，会将其设为字符串表示的布尔值。首尾空白会被去除并忽略。

Unmarshal 将 XML 元素或属性值映射到整数或浮点字段时，会按十进制解释字符串值，并将结果赋给该字段。不检查溢出。首尾空白会被去除并忽略。

Unmarshal 将 XML 元素映射到 Name 时，会记录元素名称。

Unmarshal 将 XML 元素映射到指针时，会将指针指向新分配的值，再将元素映射到该值。

缺失的元素或空属性值会被反序列化为零值。如果字段是切片，则向该字段追加一个零值；否则，将字段设为其零值。

type Decoder

Decoder 表示从特定输入流读取的 XML 解析器。解析器假定输入使用 UTF-8 编码。 

type Decoder struct {
    // Strict 默认为 true，强制遵守
    // XML 规范的要求。
    // 如果设为 false，解析器允许输入包含以下
    // 常见错误：
    //	* 如果元素缺少结束标签，解析器会按需补充
    //	  结束标签，使 Token 返回的值
    //	  正确配对。
    //	* 在属性值和字符数据中，未知或格式错误的
    //	  字符实体（以 & 开头的序列）会保持原样。
    //
    // 设置：
    //
    //	d.Strict = false
    //	d.AutoClose = xml.HTMLAutoClose
    //	d.Entity = xml.HTMLEntity
    //
    // 可以创建一个能够处理常见 HTML 的解析器。
    //
    // 严格模式不会强制遵守 XML 命名空间技术建议书的要求。
    // 尤其是，它不会拒绝使用未定义前缀的命名空间标签。
    // 这些标签会将未知前缀作为命名空间 URL 记录。
    Strict bool

    // 当 Strict == false 时，AutoClose 指定一组元素，
    // 这些元素在打开后立即被视为已关闭，
    // 无论是否存在结束元素。
    AutoClose []string

    // Entity 可用于将非标准实体名映射到替换字符串。
    // 无论映射的实际内容如何，解析器的行为都相当于
    // 映射中包含以下标准项：
    //
    //	"lt": "<",
    //	"gt": ">",
    //	"amp": "&",
    //	"apos": "'",
    //	"quot": `"`,
    Entity map[string]string

    // CharsetReader 非 nil 时，指定一个生成字符集转换
    // 读取器的函数，将给定的非 UTF-8 字符集
    // 转换为 UTF-8。如果 CharsetReader 为 nil 或
    // 返回错误，解析会停止并报错。CharsetReader
    // 返回的结果值中至少有一个必须非 nil。
    CharsetReader func(charset string, input io.Reader) (io.Reader, error)

    // DefaultSpace 设置无修饰标签所用的默认命名空间，
    // 相当于整个 XML 流被包裹在一个带有
    // xmlns="DefaultSpace" 属性的元素中。
    DefaultSpace string // Go 1.1
    // 包含已过滤或未导出的字段
}

func (*Decoder) Token 

func (d *Decoder) Token() (Token, error)

Token 返回输入流中的下一个 XML token。到达输入流末尾时，Token 返回 nil、io.EOF。

返回的 token 数据中的字节切片引用解析器的内部缓冲区，仅在下次调用 Token 之前有效。若要获取这些字节的副本，请调用 CopyToken 或该 token 的 Copy 方法。

Token 会将 <br> 等自闭合元素展开为独立的起始元素和结束元素，并通过连续调用分别返回。

Token 保证返回的 StartElement 和 EndElement token 正确嵌套且相互匹配：如果遇到意外的结束元素，或在所有预期的结束元素出现之前遇到 EOF，Token 会返回错误。

如果调用了 Decoder.CharsetReader 且它返回错误，该错误会被包装后返回。

Token 按照 https://www.w3.org/TR/REC-xml-names/ 实现 XML 命名空间。Token 中包含的每个 Name 结构，如果其命名空间已知，Space 都会设为标识该命名空间的 URL。如果遇到无法识别的命名空间前缀，Token 会将该前缀用作 Space，而不会报告错误。

func (*Encoder) EncodeToken 1.2 

func (enc *Encoder) EncodeToken(t Token) error

EncodeToken 将给定的 XML token 写入流。如果 StartElement 和 EndElement token 没有正确匹配，则返回错误。

EncodeToken 不调用 Encoder.Flush，因为它通常是 Encoder.Encode 或 Encoder.EncodeElement 等更大操作的一部分（也可能由这些操作调用的自定义 Marshaler 的 MarshalXML 使用），而这些操作会在完成时调用 Flush。创建 Encoder 后，如果直接调用 EncodeToken，而不使用 Encode 或 EncodeElement，调用者就需要在完成后调用 Flush，以确保 XML 写入底层写入器。

type Marshaler 1.2

Marshaler 接口由能够将自身序列化为有效 XML 元素的对象实现。

MarshalXML 将接收者编码为零个或多个 XML 元素。按惯例，数组或切片通常编码为一系列元素，每个条目对应一个元素。不要求使用 start 作为元素标签，但这样做可使 Unmarshal 将 XML 元素匹配到正确的结构体字段。常见的实现方式是构造一个独立值，使其布局对应所需的 XML，再用 e.EncodeElement 编码。另一种常见方式是反复调用 e.EncodeToken，逐个 token 生成 XML 输出。编码后的 token 序列必须构成零个或多个有效的 XML 元素。 

type Marshaler interface {
    MarshalXML(e *Encoder, start StartElement) error
}

type MarshalerAttr 1.2

MarshalerAttr 接口由能够将自身序列化为有效 XML 属性的对象实现。

MarshalXMLAttr 返回包含接收者编码值的 XML 属性。不要求使用 name 作为属性名，但这样做可使 Unmarshal 将属性匹配到正确的结构体字段。如果 MarshalXMLAttr 返回零值属性 Attr{}，输出中不会生成属性。MarshalXMLAttr 仅用于字段标签中带有“attr”选项的结构体字段。 

type MarshalerAttr interface {
    MarshalXMLAttr(name Name) (Attr, error)
}

type TokenReader 1.10

TokenReader 是任何能够解码 XML token 流的对象，包括 Decoder。

Token 在成功读取一个 token 后遇到错误或文件结束时，会返回该 token。它可以在同一次调用中返回非 nil 错误，也可以在后续调用中返回该错误（并返回 nil token）。这种一般情况的一个实例是：TokenReader 在 token 流末尾返回非 nil token 时，可以同时返回 io.EOF，也可以返回 nil 错误。下一次 Read 应返回 nil、io.EOF。

不建议 Token 的实现同时返回 nil token 和 nil 错误。调用者应将 nil、nil 视为没有发生任何操作；尤其不能将其解释为 EOF。 

type TokenReader interface {
    Token() (Token, error)
}

type Unmarshaler 1.2

Unmarshaler 接口由能够从描述自身的 XML 元素进行反序列化的对象实现。

UnmarshalXML 解码一个以给定起始元素开头的 XML 元素。如果它返回错误，外层 Unmarshal 调用会停止并返回该错误。UnmarshalXML 必须恰好消耗一个 XML 元素。常见的实现方式是使用 d.DecodeElement 反序列化到一个独立值中，使其布局与预期 XML 匹配，再将该值的数据复制到接收者。另一种常见方式是使用 d.Token，逐个 token 处理 XML 对象。UnmarshalXML 不得使用 d.RawToken。 

type Unmarshaler interface {
    UnmarshalXML(d *Decoder, start StartElement) error
}

type UnmarshalerAttr 1.2

UnmarshalerAttr 接口由能够从描述自身的 XML 属性进行反序列化的对象实现。

UnmarshalXMLAttr 解码单个 XML 属性。如果它返回错误，外层 Unmarshal 调用会停止并返回该错误。UnmarshalXMLAttr 仅用于字段标签中带有“attr”选项的结构体字段。 

type UnmarshalerAttr interface {
    UnmarshalXMLAttr(attr Attr) error
}

    XML 元素与数据结构之间的映射存在固有缺陷：XML 元素是依赖顺序的匿名值集合，而数据结构是不依赖顺序的具名值集合。更适合数据结构的文本表示见 encoding/json。
