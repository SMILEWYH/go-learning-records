json 包实现 RFC 7159 定义的 JSON 编码与解码。JSON 与 Go 值之间的映射关系，参见 Marshal 和 Unmarshal 函数的文档。

本包的入门介绍参见 JSON 与 Go。

安全注意事项

参见 encoding/json/v2 中的“安全注意事项”一节。

由于历史原因，v1 encoding/json 的默认设置在安全性方面存在不足。建议新的 Go JSON 代码改用 encoding/json/v2。

迁移到 v2

本包（即 encoding/json）现正式称为 v1 包，因为现在已有位于 encoding/json/v2 的 v2 包。v1 包的所有行为都基于 v2 包实现，通过指定适当的选项集合保留 v1 的历史行为。

jsonv2.Marshal 函数是 v1 Marshal 的新版对应函数。jsonv2.Unmarshal 函数是 v1 Unmarshal 的新版对应函数。v2 函数与对应 v1 函数的调用签名相同，但额外接受可变数量的 Options 实参，用于调整序列化或反序列化行为。v1 和 v2 整体行为相似，但存在一些显著差异。

以下列出 v1 与 v2 之间的差异：

  • 在 v1 中，将 JSON 对象成员反序列化到 Go 结构体时，会与字段的 JSON 名称进行不区分大小写的匹配；v2 则使用区分大小写的精确匹配。jsonv2.MatchCaseInsensitiveNames 和 MatchCaseSensitiveDelimiter 选项控制这一行为差异。要显式指定某个 Go 结构体字段采用特定的名称匹配方式，可以设置 `case:ignore` 或 `case:strict` 字段选项。字段上指定的选项优先于调用方指定的选项。

  • 在 v1 中，序列化 Go 结构体时，标记为 `omitempty` 的字段若具有“空”的 Go 值，就会被省略。空值定义为 false、0、nil 指针、nil 接口值，以及空数组、切片、映射或字符串。v2 重新定义了 `omitempty`：如果字段编码为“空”的 JSON 值，就省略该字段；JSON 空值定义为 JSON null，或空的 JSON 字符串、对象或数组。OmitEmptyWithLegacySemantics 选项控制这一行为差异。注意，对于 Go 数组、切片、映射或字符串，`omitempty` 在 v1 和 v2 中的行为相同（假定没有用户定义的 MarshalJSON 方法覆盖默认表示形式）。现有代码中对 Go 布尔值、数值、指针或接口值使用的 `omitempty`，应迁移为 `omitzero`，后者在 v1 和 v2 中均以相同方式支持。

  • 在 v1 中，Go 结构体字段上的 `string` 选项可以将 Go 字符串、布尔值、数值或指向这些类型的指针，进一步编码为 JSON 字符串。v2 将 `string` 选项限制为仅将通常表示为 JSON 数字的值编码为字符串，同时扩大其支持范围，使其适用于通常表示为 JSON 数字的任意 Go 类型。StringifyWithLegacySemantics 选项控制这一行为差异。

  • 在 v1 中，nil Go 切片或映射序列化为 JSON null；在 v2 中，它们分别序列化为空 JSON 数组或空 JSON 对象。jsonv2.FormatNilSliceAsNull 和 jsonv2.FormatNilMapAsNull 选项控制这一行为差异。

  • 在 v1 中，任意长度的 JSON 数组都可以反序列化为 Go 数组；在 v2 中，JSON 数组必须与 Go 数组长度相同，否则返回错误。UnmarshalArrayFromAnyLength 选项控制这一行为差异。

  • 在 v1 中，Go 字节数组表示为由 JSON 数字组成的 JSON 数组；在 v2 中，它表示为经过 Base64 编码的 JSON 字符串。FormatByteArrayAsArray 选项控制这一行为差异。

  • 在 v1 中，只有 Go 值可寻址时，才会调用定义在指针接收者上的 MarshalJSON 方法；在 v2 中，无论值是否可寻址，MarshalJSON 方法都可以被调用。CallMethodsWithLegacySemantics 选项控制这一行为差异。

  • 在 v1 中，从不对 Go 映射的键调用 MarshalJSON 和 UnmarshalJSON 方法；在 v2 中，可以对映射的键调用这两个方法。CallMethodsWithLegacySemantics 选项控制这一行为差异。

  • 在 v1 中，Go 映射按确定的顺序序列化；在 v2 中，Go 映射按不确定的顺序序列化。jsonv2.Deterministic 选项控制这一行为差异。

  • 在 v1 中，编码 JSON 字符串时会转义 HTML 或 JavaScript 特有的字符；在 v2 中，JSON 字符串采用最少转义的编码方式，仅在 JSON 文法要求时才转义。jsontext.EscapeForHTML 和 jsontext.EscapeForJS 选项控制这一行为差异。

  • 在 v1 中，字符串内无效的 UTF-8 字节会被静默替换为 Unicode 替换字符；在 v2 中，出现无效 UTF-8 会返回错误。jsontext.AllowInvalidUTF8 选项控制这一行为差异。

  • 在 v1 中，允许 JSON 对象包含重复名称；在 v2 中，重复名称会导致错误。jsontext.AllowDuplicateNames 选项控制这一行为差异。

  • 在 v1 中，将 JSON null 反序列化到非空 Go 值时，行为不一致：可能将该值置零，也可能不作任何操作。在 v2 中，将 JSON null 反序列化时始终一致地将底层 Go 值置零。MergeWithLegacySemantics 选项控制这一行为差异。

  • 在 v1 中，将 JSON 值反序列化到非零 Go 值时，对于数组元素、切片元素、结构体字段（但不包括映射值）、指针值，以及接口值（仅当其中包含非 nil 指针时），会合并到原有 Go 值中。在 v2 中，反序列化会对结构体字段、映射值、指针值和接口值进行合并。总体而言，v2 在反序列化 JSON 对象时采用合并语义，其他情况下则替换原值。MergeWithLegacySemantics 选项控制这一行为差异。

  • 在 v1 中，time.Duration 表示为包含十进制纳秒数的 JSON 数字；在 v2 中，time.Duration 没有默认表示形式，会导致运行时错误。FormatDurationAsNano 选项控制这一行为差异。

  • 在 v1 中，对于存在某种结构性错误的 Go 结构体类型（例如格式错误的标签选项），运行时从不报告错误；v2 则会对不适合 JSON 序列化的无效 Go 类型报告运行时错误。例如，仅包含未导出字段的 Go 结构体无法序列化。ReportErrorsWithLegacySemantics 选项控制这一行为差异。

如前所述，v1 完全基于 v2 实现，并隐式指定选项以启用旧版行为。例如，Marshal 直接调用 jsonv2.Marshal，并传入 DefaultOptionsV1。类似地，Unmarshal 直接调用 jsonv2.Unmarshal，并传入 DefaultOptionsV1。DefaultOptionsV1 表示指定 v1 默认行为的全部选项集合。

对于许多行为差异，Go 类型的作者可以通过结构体字段选项控制行为，使该类型在 v1 或 v2 语义下具有相同的 JSON 表示形式。

DefaultOptionsV1 和 jsonv2.DefaultOptionsV2，配合后面的选项优先于前面的选项这一规则，支持从 v1 渐进迁移到 v2。例如：

  • jsonv1.Marshal(v) 使用 v1 默认语义。

  • jsonv2.Marshal(v, jsonv1.DefaultOptionsV1()) 在语义上等价于 jsonv1.Marshal，因此使用 v1 默认语义。

  • jsonv2.Marshal(v, jsonv1.DefaultOptionsV1(), jsontext.AllowDuplicateNames(false)) 大体使用 v1 语义，但启用一项特定的 v2 行为。

  • jsonv2.Marshal(v, jsonv1.CallMethodsWithLegacySemantics(true)) 大体使用 v2 语义，但启用一项特定的 v1 行为。

  • jsonv2.Marshal(v, ..., jsonv2.DefaultOptionsV2()) 在语义上等价于 jsonv2.Marshal，因为 jsonv2.DefaultOptionsV2 覆盖此前指定的所有选项，因此使用 v2 默认语义。

  • jsonv2.Marshal(v) 使用 v2 默认语义。

Go 中所有新的 JSON 代码都应使用 v2 包，但 v1 包会始终保持支持。

关于迁移方式的更多细节，参见 encoding/json/v2 迁移指南。

func Compact 

func Compact(dst *bytes.Buffer, src []byte) error

Compact 移除 JSON 编码的 src 中无关紧要的空白字符，并将结果追加到 dst。

func HTMLEscape 

func HTMLEscape(dst *bytes.Buffer, src []byte)

HTMLEscape 将 JSON 编码的 src 追加到 dst，并将字符串字面量内的 <、>、&、U+2028 和 U+2029 分别替换为 \u003c、\u003e、\u0026、\u2028 和 \u2029，使 JSON 可以安全地嵌入 HTML <script> 标签中。由于历史原因，Web 浏览器在 <script> 标签内不遵循标准 HTML 转义规则，因此必须使用这种替代的 JSON 编码方式。

func Indent 

func Indent(dst *bytes.Buffer, src []byte, prefix, indent string) error

Indent 将 JSON 编码的 src 以缩进格式追加到 dst。JSON 对象或数组的每个元素都从一个新的缩进行开始，行首为 prefix，后跟一个或多个 indent，具体数量取决于嵌套层级。追加到 dst 的数据开头不带 prefix 或任何缩进，以便嵌入其他已格式化的 JSON 数据。src 开头的空白字符（空格、制表符、回车和换行）会被丢弃，但末尾的空白字符会保留并复制到 dst。例如，src 没有尾随空白时，dst 也不会有；src 以换行结尾时，dst 也如此。

func Marshal 

func Marshal(v any) ([]byte, error)

Marshal 返回 v 的 JSON 编码。

Marshal 递归遍历值 v。

输入值按以下规则编码为 JSON：

  • 如果值的类型实现了 jsonv2.MarshalerTo，则调用 MarshalJSONTo 方法编码该值。如果该方法返回 errors.ErrUnsupported，则按后续规则编码输入。

  • 如果值的类型实现了 Marshaler，则调用 MarshalJSON 方法编码该值。

  • 如果值的类型实现了 encoding.TextAppender，则调用 AppendText 方法编码该值，再将结果编码为 JSON 字符串。

  • 如果值的类型实现了 encoding.TextMarshaler，则调用 MarshalText 方法编码该值，再将结果编码为 JSON 字符串。

否则，Marshal 根据类型使用以下默认编码方式：

布尔值编码为 JSON 布尔值。

浮点数、整数和 Number 值编码为 JSON 数字。NaN 和 +/-Inf 值会返回 UnsupportedValueError。

字符串值编码为 JSON 字符串，并转换为有效 UTF-8，其中无效字节替换为 Unicode 替换字符。为使 JSON 可以安全地嵌入 HTML <script> 标签中，字符串使用 HTMLEscape 编码，将“<”、“>”、“&”、U+2028 和 U+2029 分别转义为“\u003c”、“\u003e”、“\u0026”、“\u2028”和“\u2029”。使用 Encoder 时，可以通过调用 Encoder.SetEscapeHTML(false) 禁用这种替换。

数组和切片值编码为 JSON 数组，但 []byte 编码为经过 base64 编码的字符串，nil 切片编码为 JSON null。

结构体值编码为 JSON 对象。每个导出字段成为对象的一个成员，以字段名作为对象键，除非该字段因下述某种原因被省略。

每个结构体字段的编码方式都可以通过其标签中“json”键对应的格式字符串自定义。格式字符串给出字段名称，后面可以跟以逗号分隔的选项列表。名称可以为空，以便在不覆盖默认字段名的情况下指定选项。

“omitempty”选项指定：如果字段具有空值，则在编码中省略该字段。空值包括 false、0、nil 指针、nil 接口值，以及长度为零的数组、切片、映射或字符串。

有一种特殊情况：如果字段标签为“-”，则始终省略该字段。包含逗号或引号的 JSON 名称，以及恰好为“”或“-”的名称，可以通过单引号字符串字面量指定。其语法与 Go 的双引号字符串字面量语法相同，但使用单引号作为分隔符。

结构体字段标签及其含义示例： 

// Field 在 JSON 中以键 "myName" 出现。
Field int `json:"myName"`

// Field 在 JSON 中以键 "myName" 出现；
// 如果其值按上文定义属于空值，
// 则从对象中省略此字段。
Field int `json:"myName,omitempty"`

// Field 在 JSON 中以键 "Field"（默认值）出现，
// 但值为空时跳过此字段。
// 注意开头的逗号。
Field int `json:",omitempty"`

// 本包忽略 Field。
Field int `json:"-"`

// Field 在 JSON 中以键 "-" 出现。
Field int `json:"'-'"`

“omitzero”选项指定：如果字段根据以下规则具有零值，则在编码中省略该字段：

1）如果字段类型具有“IsZero() bool”方法，则用它判断值是否为零。

2）否则，如果该值等于其类型的零值，则判定为零值。

如果同时指定“omitempty”和“omitzero”，则值为空或为零（或同时满足两者）时都会省略该字段。

“string”选项表示，字段先编码为 JSON，再存储在一个 JSON 编码的字符串中。它仅适用于字符串、浮点数、整数或布尔类型的字段。与 JavaScript 程序通信时，有时会使用这一额外的编码层： 

Int64String int64 `json:",string"`

如果键名是非空字符串，且仅由 Unicode 字母、数字以及除引号、反斜杠、逗号之外的 ASCII 标点符号组成，就会使用该键名。

嵌入的结构体字段通常会按其内部导出字段属于外层结构体字段的方式序列化，遵循普通 Go 可见性规则，但有下一段所述的调整。如果匿名结构体字段的 JSON 标签指定了名称，则将它视为具有该名称，而不再是匿名字段。接口类型的匿名结构体字段，则视为以该类型名为名称，而不再是匿名字段。

在决定序列化或反序列化哪个字段时，JSON 对 Go 的结构体字段可见性规则作了调整。如果最浅嵌套层级中存在多个字段（按普通 Go 规则，也会选择这一层级），则额外应用以下规则：

1）这些字段中，只要有字段带 JSON 标签，就只考虑带标签的字段，即使其他多个不带标签的字段原本会发生冲突。

2）如果恰好只有一个字段（是否带标签由第一条规则决定），就选择它。

3）否则，若存在多个字段，则全部忽略，不产生错误。

Go 1.1 新增了对匿名结构体字段的处理。在 Go 1.1 之前，匿名结构体字段会被忽略。要在当前及更早版本中都强制忽略某个匿名结构体字段，请为其设置“-”JSON 标签。

映射值编码为 JSON 对象。映射的键类型必须是字符串、整数类型，或实现 encoding.TextMarshaler。映射键经过排序后用作 JSON 对象键，遵循以下规则，并应用前文字符串值部分所述的 UTF-8 转换：

  • 任意字符串类型的键直接使用。
  • 实现 encoding.TextMarshaler 的键通过其方法序列化。
  • 整数键转换为字符串。

指针值编码为其指向的值。nil 指针编码为 JSON null。

接口值编码为接口中包含的值。nil 接口值编码为 JSON null。

通道、复数和函数值无法编码为 JSON。尝试编码此类值时，Marshal 返回 UnsupportedTypeError。

JSON 无法表示循环数据结构，Marshal 也不处理此类结构。将循环结构传给 Marshal 会返回错误。

func Unmarshal 

func Unmarshal(data []byte, v any) error

Unmarshal 解析 JSON 编码的 data，并将结果存入 v 指向的值。如果 v 为 nil 或不是指针，Unmarshal 返回 InvalidUnmarshalError。

Unmarshal 采用与 Marshal 的编码规则相反的过程，根据需要分配映射、切片和指针，并遵循以下附加规则：

将 JSON 反序列化到指针时，Unmarshal 首先处理 JSON 为字面量 null 的情况：此时将指针设为 nil。否则，将 JSON 反序列化到指针指向的值。如果指针为 nil，Unmarshal 会分配一个新值，使指针指向它。

JSON 输入按以下规则解码：

  • 如果值的类型实现了 jsonv2.UnmarshalerFrom，则调用 UnmarshalJSONFrom 方法解码 JSON 值。如果该方法返回 errors.ErrUnsupported，则按后续规则解码输入。

  • 如果值的类型实现了 Unmarshaler，则调用 UnmarshalJSON 方法解码 JSON 值，包括输入为 JSON null 的情况。

  • 如果值实现了 encoding.TextUnmarshaler，且输入为 JSON 字符串，则以去掉引号后的字符串内容调用 UnmarshalText 方法。

否则，Unmarshal 根据类型使用以下默认解码方式：

将 JSON 反序列化到结构体时，Unmarshal 将输入对象的键与 Marshal 使用的键（结构体字段名或标签）进行匹配，优先精确匹配，但也接受不区分大小写的匹配。默认情况下，没有对应结构体字段的对象键会被忽略；如需其他行为，参见 Decoder.DisallowUnknownFields。

将 JSON 反序列化到接口值时，Unmarshal 会在接口值中存入以下某种值：

  • JSON 布尔值对应 bool。
  • JSON 数字对应 float64。
  • JSON 字符串对应 string。
  • JSON 数组对应 []any。
  • JSON 对象对应 map[string]any。
  • JSON null 对应 nil。

将 JSON 数组反序列化到切片时，Unmarshal 将每个 JSON 数组元素解码到对应的切片元素，原地复用已有元素。切片会扩展以容纳更多元素；如果 JSON 数组较短，则截短切片。有一种特殊情况：将空 JSON 数组反序列化到切片时，Unmarshal 用一个新的空切片替换原切片。

将 JSON 数组反序列化到 Go 数组时，Unmarshal 将 JSON 数组元素解码到对应的 Go 数组元素。如果 Go 数组较短，多余的 JSON 数组元素会被丢弃；如果 JSON 数组较短，多余的 Go 数组元素会被设为零值。

将 JSON 对象反序列化到映射时，Unmarshal 首先确定要使用的映射。如果映射为 nil，则分配新映射；否则复用现有映射，并保留已有条目。然后，Unmarshal 将 JSON 对象中的键值对存入映射。映射的键类型必须是任意字符串类型、整数类型，或实现 encoding.TextUnmarshaler。

如果 JSON 编码的数据包含语法错误，Unmarshal 返回 SyntaxError。

如果 JSON 值不适合给定的目标类型，或 JSON 数字超出目标类型范围，Unmarshal 会跳过该字段，并尽可能完成其余反序列化。如果没有遇到更严重的错误，Unmarshal 返回 UnmarshalTypeError，描述最先遇到的此类错误。无论如何，都不保证出错字段之后的所有剩余字段能被反序列化到目标对象。

将 JSON null 反序列化到接口、映射、指针或切片时，会将对应 Go 值设为 nil。由于 JSON 中经常用 null 表示“不存在”，将 JSON null 反序列化到其他任何 Go 类型时，都不会改变该值，也不会产生错误。

反序列化带引号的字符串时，无效 UTF-8 或无效 UTF-16 代理项对不视为错误，而是替换为 Unicode 替换字符 U+FFFD。

func CallMethodsWithLegacySemantics 1.27 

func CallMethodsWithLegacySemantics(v bool) Options

CallMethodsWithLegacySemantics 指定：调用类型提供的序列化和反序列化方法时，遵循旧版语义：

  • 序列化时，只有 Go 值可寻址，才会调用定义在指针接收者上的序列化方法。从接口或映射元素取得的值不可寻址；通过指针或从切片元素取得的值可寻址；从数组元素或结构体字段取得的值，继承其所属值的可寻址性。v2 则始终调用序列化方法，不受可寻址性影响。

  • 序列化或反序列化映射键时，会忽略 Marshaler 或 Unmarshaler 方法，但仍可调用 encoding.TextMarshaler 或 encoding.TextUnmarshaler。v2 在方法调用方面将映射键与其他值同等处理，因此可能调用 Marshaler 或 Unmarshaler 方法；方法实现负责将 Go 值表示为 JSON 字符串，以满足 JSON 对象名称的要求。

  • 序列化时，如果映射键实现了序列化方法且为 nil 指针，则将其序列化为空 JSON 字符串。v2 则会报告错误。

  • 序列化时，如果接口类型实现了序列化方法，且接口值包含指向具体类型的 nil 指针，则始终调用该序列化方法。v2 则从不直接调用接口值上的方法，而是根据底层具体值决定如何处理。与非接口值相同，不会对 nil 指针调用序列化方法，而是将其序列化为 JSON null。

这会影响序列化或反序列化。v1 默认值为 true。

func MergeWithLegacySemantics 1.27 

func MergeWithLegacySemantics(v bool) Options

MergeWithLegacySemantics 指定：反序列化到非零 Go 值时，遵循旧版语义：

  • 反序列化 JSON null 时，如果 Go 值的种类为 bool、int、uint、float、string、array 或 struct，则保留原值；否则将其置零。v2 默认行为则是在反序列化 JSON null 时始终一致地将 Go 值置零。

func ReportErrorsWithLegacySemantics 1.27 

func ReportErrorsWithLegacySemantics(v bool) Options

ReportErrorsWithLegacySemantics 指定 Marshal 和 Unmarshal 按旧版语义报告错误：

  • 序列化或反序列化时，返回的错误值通常是 SyntaxError、MarshalerError、UnsupportedTypeError、UnsupportedValueError、InvalidUnmarshalError 或 UnmarshalTypeError 等类型。v2 则始终返回 jsonv2.SemanticError 或 jsontext.SyntacticError 类型的错误。

  • 序列化时，如果用户定义的序列化方法报告错误，始终将其包装在 MarshalerError 中，即使该错误本身已是 MarshalerError，这可能产生多层冗余包装。v2 则始终将错误包装在 jsonv2.SemanticError 中，除非它已经是语义错误。

  • 反序列化时，如果用户定义的反序列化方法报告错误，不会包装，而是原样返回。v2 则始终将错误包装在 jsonv2.SemanticError 中，除非它已经是语义错误。

  • 序列化或反序列化时，如果 Go 结构体包含类型错误（例如名称冲突或字段标签格式错误），会忽略这些错误，并尽可能为结构体生成表示。v2 则会报告运行时错误。

  • 使用 jsonv2.MatchCaseInsensitiveNames 反序列化时，如果某个 JSON 对象名称与多个 Go 结构体字段形成非精确匹配，不会报告错误，而是使用最先声明的字段。v2 则会报告运行时错误。

  • 反序列化时，在将 JSON 数据按语义反序列化到 Go 值之前，会先完整验证 JSON 输入的语法结构。因此，存在语法错误的 JSON 输入不会修改目标 Go 值。v2 则采用流式解码，逐步将 JSON 输入反序列化到目标 Go 值；这意味着遇到语法错误时，Go 值可能已被部分修改。

  • 反序列化时，语义错误不会立即终止处理，解析会继续进行。反序列化返回时，仅报告第一个语义错误。v2 则在遇到错误时立即终止反序列化。

这会影响序列化或反序列化。v1 默认值为 true。

func StringifyWithLegacySemantics(v bool) Options

StringifyWithLegacySemantics 指定 `string` 标签选项可以将布尔值和字符串值进一步编码为字符串。它只对顶层类型为布尔、字符串、数值种类，或指向这些类型的指针的字段生效。v2 默认仅允许对原本会序列化为 JSON 数字的 Go 类型使用 `string` 标签选项，并将该 JSON 数字放入 JSON 字符串中；特别地，v2 默认不会将 Go 布尔值和字符串这样处理。如果 ReportErrorsWithLegacySemantics 为 false，错误使用 `string` 会导致运行时错误。

序列化时，这类 Go 值先转换为通常的 JSON 表示，再放入带引号的 JSON 字符串中。反序列化时，必须从 JSON 字符串还原这类 Go 值，字符串内容应为该值通常的 JSON 表示，或对应数值种类的 Go 数字表示。注意，Go 数字文法是 JSON 数字文法的超集。对 `string` 生效的 Go 值进行反序列化时，放在 JSON 字符串中的 JSON null 可以替代 JSON null 本身。v2 默认则拒绝文法超出 JSON 数字范围的字符串化数字，也拒绝放在 JSON 字符串中的 JSON null。

这会影响序列化或反序列化。v1 默认值为 true。

func UnmarshalArrayFromAnyLength 1.27 

func UnmarshalArrayFromAnyLength(v bool) Options

UnmarshalArrayFromAnyLength 指定允许将任意长度的输入 JSON 数组反序列化到 Go 数组。如果 JSON 数组过短，则将 Go 数组的剩余元素置零；如果 JSON 数组过长，则跳过多余的 JSON 数组元素。v2 默认要求输入 JSON 数组与 Go 数组长度完全相同。

这只影响反序列化，序列化时忽略。v1 默认值为 true。
