json 包实现了 RFC 8259 规定的 JSON 语义处理。JSON 是一种简单的数据交换格式，可以表示布尔值、字符串和数值等基本数据类型，以及对象和数组等结构化数据类型。

本包的入门介绍见使用 JSON 教程。

Marshal 和 Unmarshal 在 Go 值与 []byte 中的 JSON 文本之间进行编码和解码。MarshalWrite 和 UnmarshalRead 通过向 io.Writer 写入或从 io.Reader 读取来处理 JSON 文本。MarshalEncode 和 UnmarshalDecode 通过向 jsontext.Encoder 编码或从 jsontext.Decoder 解码来处理 JSON 文本。可以向各个序列化或反序列化函数传入 Options，配置序列化和反序列化的语义行为（即改变如何将 JSON 数据理解为 Go 数据，以及反向的解释方式）。还可以传入 jsontext.Options，配置编码或解码的语法行为。

JSON 与 Go 的数据类型之间，按照两个类型系统中逻辑上最接近的对应关系进行映射。例如，JSON 布尔值对应 Go bool，JSON 字符串对应 Go string，JSON 数值对应 Go int、uint 或 float，JSON 数组对应 Go 切片或数组，JSON 对象对应 Go 结构体或映射。JSON 和 Go 类型系统之间完整的对应关系列表，见 Marshal 和 Unmarshal 文档。

任意 Go 类型都可以通过实现 Marshaler、MarshalerTo、Unmarshaler 或 UnmarshalerFrom 来定制自身的 JSON 表示。这使 Go 类型的作者能够控制其类型如何序列化为 JSON。另一种方式是实现与 MarshalFunc、MarshalToFunc、UnmarshalFunc 或 UnmarshalFromFunc 匹配的函数，为任意类型指定 JSON 表示。这使 JSON 功能的调用者能够控制任意类型如何序列化为 JSON。

Go 结构体的 JSON 表示

Go 结构体自然地表示为 JSON 对象，每个 Go 结构体字段对应一个 JSON 对象成员。序列化时，除被忽略或省略的字段外，所有 Go 结构体字段都按深度优先顺序递归编码为 JSON 对象成员。反序列化时，JSON 对象成员递归解码到对应的 Go 结构体字段。不匹配任何结构体字段的对象成员又称“未知成员”，默认会被忽略；如果指定 RejectUnknownMembers，则会被拒绝。

每个结构体字段的表示都可以通过“json”结构体字段标签定制，标签是一组以逗号分隔的选项。特殊情况下，如果整个标签为 `json:"-"`，则在 JSON 表示中忽略该字段。某些选项也有由调用者指定的 Options 控制的等价行为。字段指定的选项优先于调用者指定的选项。

第一个选项覆盖 Go 结构体字段对应的 JSON 对象成员名称。如果未指定名称，则使用 Go 结构体字段名。默认情况下，反序列化采用区分大小写的匹配方式，确定与 JSON 对象成员名称关联的 Go 结构体字段。

名称之后支持以下标签选项：

  • omitzero：序列化时，“omitzero”指定在字段值为零值时省略该结构体字段。如果存在“IsZero() bool”方法，则由该方法判断；否则根据字段是否为 Go 零值判断。此选项不影响反序列化。

  • omitempty：序列化时，“omitempty”指定在字段值将被编码为 JSON null、空字符串、空对象或空数组时，省略该结构体字段。此选项不影响反序列化。

  • string：“string”选项指定在序列化或反序列化结构体字段值时设置 StringifyNumbers。这使通常编码为 JSON 数值的类型改为编码成 JSON 字符串中带引号的 JSON 数值，并从包含 JSON 数值、且数值前后不带空白的 JSON 字符串解码。“string”选项仅作用于 Go 结构体字段值的顶层。对任何不编码为 JSON 数值的类型应用此选项都会出错。注意，数组、切片、结构体和映射等复合类型不编码为 JSON 数值，因此应用此选项会导致错误，而不会作用于这些类型内部的 JSON 数值。由于许多 JSON 解析器无法精确表示 64 位整数，这一额外编码层级通常是必要的。

  • case：反序列化时，“case”选项指定 JSON 对象成员名称如何匹配 Go 结构体字段的 JSON 名称。该选项是“case:value”形式的键值对，值必须为 'ignore' 或 'strict'。'ignore' 指定不区分大小写，并忽略连字符和下划线。如果有多个字段匹配，则选择名称完全匹配的字段；否则因无法确定应反序列化到哪个字段而报告错误。'strict' 指定区分大小写。此选项优先于 MatchCaseInsensitiveNames。

  • embed：“embed”选项指定将此字段类型中可由 JSON 表示的内容提升，视为直接声明于父结构体中。这相当于 Go 结构体嵌入在 JSON 中的对应机制。除非显式指定 JSON 名称，Go 嵌入字段会隐式进行 JSON 嵌入。嵌入字段必须是 Go 结构体（不能实现任何 JSON 方法）、jsontext.Value、map[~string]T，或指向这些类型的未命名指针。序列化时，如果指针类型的嵌入字段为 nil，则将其省略。类型为 jsontext.Value 和 map[~string]T 的嵌入字段称为“嵌入兜底字段”，因为它们可以表示父结构体未直接处理的所有可能的 JSON 对象成员。一个结构体只能指定一个嵌入兜底字段，但可以指定多个非兜底字段。此选项不能与任何其他选项（包括 JSON 名称）同时指定。

“omitzero”和“omitempty”选项的行为相似。前者根据 Go 类型系统定义，后者根据 JSON 类型系统定义，因此在某些情况下行为不同。例如，“omitzero”仅省略 nil 切片或映射；“omitempty”则会省略空切片或映射，无论它们是否为 nil。“omitzero”适用于零值定义明确的类型（例如 net/netip.Addr），或具有 IsZero 方法的类型（例如 time.Time.IsZero）。

每个 Go 结构体都对应一个可由 JSON 表示的字段列表。该列表通过对所有结构体字段进行广度优先搜索构建（排除未导出或被忽略的字段），并递归进入嵌入结构体。结构体的非嵌入字段必须具有唯一的 JSON 名称。如果多个字段具有相同的 JSON 名称，则深度最浅的字段优先，更深层的其他字段从可由 JSON 表示的字段列表中排除。如果最浅层有多个同名字段，但只有一个字段通过标签显式指定了 JSON 名称，则该字段优先，其他字段全部排除。这类似于 Go 在含嵌入结构体类型时选择字段的可见性规则。

对非空但没有任何可由 JSON 表示字段的结构体进行序列化或反序列化，会产生 SemanticError；但如果该 Go 结构体有字段带有显式 `json` 标签，则例外，因为这表示该类型具有有效的 JSON 表示（即使为空）。未导出字段除 `json:"-"` 外，不得带有任何 `json` 标签。

安全性注意事项

JSON 经常用作数据交换格式，用于不同系统之间通信，这些系统可能使用不同语言实现。出于互操作性和安全考虑，各实现必须对数据的语义含义达成一致。

例如，假设有两个微服务。第一个服务负责对 JSON 请求进行身份认证，第二个服务在假定请求已通过认证的前提下负责执行它。如果攻击者能恶意构造 JSON 请求，使两个服务认为同一个请求分别来自不同用户，就可能使用某用户的有效凭据通过认证，却以另一个用户的身份恶意执行操作。

遗憾的是，按照 RFC 8259，许多 JSON 文本在语法上有效，但在语义上存在歧义。例如，标准没有定义如何解释对象中的重复名称。

v1 encoding/json 和 encoding/json/v2 包对某些输入采用不同解释，具体包括：

  • 标准规定 JSON 必须使用 UTF-8 编码。默认情况下，v1 将 JSON 字符串中的无效 UTF-8 字节替换为 Unicode 替换字符，而 v2 拒绝含有无效 UTF-8 的输入。若要更改默认行为，请指定 jsontext.AllowInvalidUTF8 选项。替换无效 UTF-8 是一种数据损坏，会改变字符串的精确含义。

  • 标准没有规定遇到 JSON 对象中的重复名称时应采取何种行为，因此不同实现可能表现不同。默认情况下，v1 允许重复名称，v2 则拒绝重复名称。若要更改默认行为，请指定 jsontext.AllowDuplicateNames 选项。如果允许重复名称，对象成员按出现顺序处理，这意味着后面的值会替换先前值，或合并到先前值中，具体取决于 Go 值的类型。

  • 标准将 JSON 对象定义为无序的名称/值对集合。虽然可以通过底层 jsontext API 观察顺序，但 v1 和 v2 通常都避免暴露该顺序。任何应用都不应在语义上依赖对象成员的顺序。允许重复名称会提供一种途径，使成员顺序被意外观察并形成依赖。

  • 标准建议通常根据 Unicode 码点序列是否相等来比较 JSON 对象成员名称，这意味着名称比较通常区分大小写。将 JSON 对象反序列化到 Go 结构体时，默认情况下，v1 使用（宽松的）不区分大小写匹配，而 v2 使用（严格的）区分大小写匹配。若要更改默认行为，请指定 MatchCaseInsensitiveNames 选项。不区分大小写的匹配提供了另一种出现重复名称的途径。允许不区分大小写匹配，意味着 v1 或 v2 对 JSON 对象的解释可能不同于大多数其他 JSON 实现（它们通常采用区分大小写匹配）。

  • 标准没有规定遇到 JSON 对象中的未知名称时应采取何种行为。将 JSON 对象反序列化到 Go 结构体时，v1 和 v2 默认都忽略未知名称及其对应值。若要更改默认行为，请指定 RejectUnknownMembers 选项。

  • 标准建议实现可以使用 float64 表示 JSON 数值。因此，将较大的 JSON 整数存为浮点类型时可能丢失精度。序列化和反序列化具体整数类型时，v1 和 v2 都能正确保留精度。但即使它们保留了具体类型的精度，其他 JSON 实现也可能无法保留 v1 或 v2 输出中的精度。可以使用 `string` 标签选项，将整数类型放入 JSON 字符串并加上引号，以避免精度损失。此外，反序列化到 any 接口值时，v1 和 v2 仍可能丢失精度，因为此时默认使用 float64 表示 JSON 数值。若要更改默认行为，请通过 WithUnmarshalers 选项提供自定义反序列化器，用能够保留精度的具体 Go 类型预先填充接口值。

RFC 8785 为 JSON 文本规定了一种规范形式，明确了 RFC 8259 留作未定义的具体行为。理论上，如果文本可以成功执行 jsontext.Value.Canonicalize，且不改变数据语义，就能更有把握地认为该数据具有更好的安全性和互操作性。

v2 API 通常选择比 v1 更安全的默认值，但仍需谨慎处理大整数和未知成员。

func Marshal(in any, opts ...Options) (out []byte, err error)

			
Marshal 按给定的序列化和编码选项，将 Go 值序列化为 []byte（忽略反序列化或解码选项）。它不会在输出末尾添加换行符。

针对特定类型的序列化函数和方法优先于值的默认表示。操作 *T 的函数或方法，仅在编码 T 类型的值（通过取地址）或非 nil 的 *T 值时调用。Marshal 确保值始终可寻址（必要时复制该值），以便一致地调用这些函数和方法。出于性能考虑，建议向 Marshal 传入指向该值的非 nil 指针。

输入值按以下规则编码为 JSON：

    

  • 如果 WithMarshalers 选项中的类型专用函数与该值类型匹配，则调用这些函数编码该值。如果所有适用函数都返回 errors.ErrUnsupported，则按后续规则编码该值。

  • 如果值的类型实现了 MarshalerTo，则调用 MarshalJSONTo 方法编码该值。如果该方法返回 errors.ErrUnsupported，则按后续规则编码输入。

  • 如果值的类型实现了 Marshaler，则调用 MarshalJSON 方法编码该值。

  • 如果值的类型实现了 encoding.TextAppender，则调用 AppendText 方法编码该值，再将其结果编码为 JSON 字符串。

  • 如果值的类型实现了 encoding.TextMarshaler，则调用 MarshalText 方法编码该值，再将其结果编码为 JSON 字符串。

  • 否则，根据该值的类型编码，详细规则如下。



多数 Go 类型具有如下默认 JSON 表示：

    

  • Go 布尔值编码为 JSON 布尔值（例如 true 或 false）。

  • Go 字符串编码为 JSON 字符串。

  • Go []byte 或 [N]byte 编码为 JSON 字符串，其中的二进制值采用 RFC 4648 第 4 节规定的 Base64 编码。

  • Go 整数编码为不带小数部分或指数的 JSON 数值。如果指定了 StringifyNumbers，或正在编码 JSON 对象成员名称，则将 JSON 数值编码在 JSON 字符串中。

  • Go 浮点数编码为 JSON 数值。如果指定了 StringifyNumbers，或正在编码 JSON 对象成员名称，则将 JSON 数值编码在 JSON 字符串中。编码 NaN 或 ±Inf 会产生 SemanticError。

  • Go 映射编码为 JSON 对象，每个 Go 映射的键和值递归编码为 JSON 对象中的名称/值对。Go 映射键必须编码为 JSON 字符串，否则会产生 SemanticError。Go 映射按不确定的顺序遍历。若需要确定性编码，请考虑 Deterministic 选项。默认情况下，nil 映射编码为空 JSON 对象，除非指定 FormatNilMapAsNull 选项。

  • Go 结构体编码为 JSON 对象。详情见包级文档中的“Go 结构体的 JSON 表示”一节。

  • Go 切片编码为 JSON 数组，其中每个 Go 切片元素递归编码为 JSON 数组元素。默认情况下，nil 切片编码为空 JSON 数组，除非指定 FormatNilSliceAsNull 选项。

  • Go 数组编码为 JSON 数组，其中每个 Go 数组元素递归编码为 JSON 数组元素。JSON 数组长度始终与 Go 数组长度相同。

  • Go 指针为 nil 时编码为 JSON null，否则递归编码其指向值的 JSON 表示。

  • Go 接口为 nil 时编码为 JSON null，否则递归编码其底层值的 JSON 表示。

  • Go time.Time 编码为 JSON 字符串，其中包含按 RFC 3339 格式表示、精确到纳秒的时间戳。

  • Go time.Duration 目前没有默认表示，会产生 SemanticError；但如果指定了 encoding/json.FormatDurationAsNano 选项，则编码为不带小数部分或指数的 JSON 数值，以纳秒表示时长。

  • 其他所有 Go 类型（例如复数、通道和函数）都没有默认表示，会产生 SemanticError。



JSON 无法表示循环数据结构，Marshal 也不处理此类结构。

func Unmarshal
				
				1.27
			

			
func Unmarshal(in []byte, out any, opts ...Options) (err error)

			
Unmarshal 按给定的反序列化和解码选项，将 []byte 输入解码到 Go 值中（忽略序列化或编码选项）。输入必须是单个 JSON 值，其间可包含空白。输出必须为非 nil 指针。

针对特定类型的反序列化函数和方法优先于值的默认表示。操作 *T 的函数或方法，仅在解码 T 类型的值（通过取地址）或非 nil 的 *T 值时调用。Unmarshal 确保值始终可寻址（必要时复制该值），以便一致地调用这些函数和方法。如果必须浅复制某个值，才能调用指针接收者的 Unmarshaler、UnmarshalerFrom 或 encoding.TextUnmarshaler 方法，则该方法所做的所有修改会通过浅复制写回目标值。

输入按以下规则解码到输出中：

    

  • 如果 WithUnmarshalers 选项中的类型专用函数与该值类型匹配，则调用这些函数解码 JSON 值。如果所有适用函数都返回 errors.ErrUnsupported，则按后续规则解码输入。

  • 如果值的类型实现了 UnmarshalerFrom，则调用 UnmarshalJSONFrom 方法解码 JSON 值。如果该方法返回 errors.ErrUnsupported，则按后续规则解码输入。

  • 如果值的类型实现了 Unmarshaler，则调用 UnmarshalJSON 方法解码 JSON 值。

  • 如果值的类型实现了 encoding.TextUnmarshaler，则将输入解码为 JSON 字符串，并以解码后的字符串值调用 UnmarshalText 方法。如果输入不是 JSON 字符串，则以 SemanticError 失败。

  • 否则，根据值的类型解码 JSON 值，详细规则如下。



多数 Go 类型具有默认的 JSON 表示。JSON null 可以解码到每一种受支持的 Go 值中，等价于存储该 Go 值的零值。如果当前 Go 值类型无法处理输入 JSON 的种类，则以 SemanticError 失败。除非另有说明，解码后的值会替换已有值。

各类型的表示如下：

    

  • Go 布尔值从 JSON 布尔值（例如 true 或 false）解码。

  • Go 字符串从 JSON 字符串解码。

  • Go []byte 或 [N]byte 从 JSON 字符串解码，其中的二进制值采用 RFC 4648 第 4 节规定的 Base64 编码。解码到非 nil 的 []byte 时，先将切片长度重置为零，再追加解码后的输入。解码到 [N]byte 时，输入必须恰好解码出 N 个字节，否则以 SemanticError 失败。

  • Go 整数从 JSON 数值解码。如果指定了 StringifyNumbers，或正在解码 JSON 对象成员名称，则必须从包含 JSON 数值的 JSON 字符串解码。如果 JSON 数值包含小数部分或指数，则以 SemanticError 失败。如果数值超出 Go 整数类型的表示范围，也会失败。

  • Go 浮点数从 JSON 数值解码。如果指定了 StringifyNumbers，或正在解码 JSON 对象成员名称，则必须从包含 JSON 数值的 JSON 字符串解码。如果数值超出 Go 浮点类型的表示范围，则失败。由于 JSON 没有 NaN 或 ±Inf 的原生表示，解码结果不可能是这些值。

  • Go 映射从 JSON 对象解码，每个 JSON 对象名称/值对递归解码为 Go 映射的键和值。映射不会被清空。如果 Go 映射为 nil，则分配新映射用于解码。如果解码后的键匹配现有 Go 映射条目，则复用该条目的值，将 JSON 对象值解码到其中。

  • Go 结构体从 JSON 对象解码。详情见包级文档中的“Go 结构体的 JSON 表示”一节。

  • Go 切片从 JSON 数组解码，每个 JSON 元素递归解码后追加到 Go 切片。追加之前，如果 Go 切片为 nil，则分配新切片；否则将切片长度重置为零。

  • Go 数组从 JSON 数组解码，每个 JSON 数组元素递归解码到对应的 Go 数组元素。解码到每个 Go 数组元素之前，都会将其清零。如果 JSON 数组的元素数量与 Go 数组不完全相同，则以 SemanticError 失败。

  • Go 指针根据 JSON 种类和底层 Go 类型解码。如果输入为 JSON null，则存储 nil 指针。否则，如果指针为 nil，则分配新的底层值，再将 JSON 递归解码到该底层值中。

  • Go 接口根据 JSON 种类和底层 Go 类型解码。如果输入为 JSON null，则存储 nil 接口值。否则，对于空接口类型的 nil 接口值，会根据输入是 JSON 布尔值、字符串、数值、对象还是数组，分别使用 Go bool、string、float64、map[string]any 或 []any 的零值初始化。如果接口值此时仍为 nil，则以 SemanticError 失败，因为无法确定适当的 Go 目标类型。例如，反序列化到 nil io.Reader 会失败，因为没有可以填充接口值的具体类型。否则，底层值已存在，JSON 输入会递归解码到该值中。

  • Go time.Time 从 JSON 字符串解码，其中包含按 RFC 3339 格式表示、精确到纳秒的时间。

  • Go time.Duration 目前没有默认表示，会产生 SemanticError；但如果指定了 encoding/json.FormatDurationAsNano 选项，则从不带小数部分或指数的 JSON 数值解码，以纳秒表示时长。

  • 其他所有 Go 类型（例如复数、通道和函数）都没有默认表示，会产生 SemanticError。



一般来说，反序列化遵循合并语义（类似 RFC 7396）：对于对象之外的任何 JSON 种类，解码后的 Go 值都会替换目标值。对于 JSON 对象，输入对象会合并到目标值中，匹配的对象成员递归应用合并语义。

type MarshalerTo
				
				1.27
			

			
MarshalerTo 由能够序列化自身的类型实现。建议实现 MarshalerTo 而非 Marshaler，因为它性能更好，也更灵活。如果某类型同时实现 Marshaler 和 MarshalerTo，则优先使用 MarshalerTo。此时，两种实现在默认序列化选项下应尽量保持等价行为。

实现必须恰好向 Encoder 写入一个 JSON 值。另一种选择是在不修改 Encoder 的情况下返回 errors.ErrUnsupported。调用此方法的“json”包将采用接收者类型的下一种可用 JSON 表示，具体见 Marshal。实现不得保留指向 jsontext.Encoder 的指针。

如果返回的错误是 SemanticError，json 可能会用额外上下文填充其中尚未设置的字段。其他类型的错误会被包装在 SemanticError 中，但 I/O 错误除外。

不应直接调用 MarshalJSONTo 方法，因为它可能返回需要特殊处理的哨兵错误。使用者应改为调用 MarshalEncode，它会处理这些情况。

实现应通过 jsontext.Encoder.Options 检查序列化选项，并按需调整行为以遵守这些选项。

以下选项可能与 MarshalerTo 实现有关：

- Deterministic：如果实现可能产生不确定的输出
- StringifyNumbers：如果该类型表示为 JSON 数值

某些选项（例如 FormatNilSliceAsNull）仅适用于原生 Go 类型，因此通常与 MarshalerTo 的实现没有直接关系。但表示复合类型的类型应使用 MarshalEncode 序列化其中包含的类型，以确保这些选项作用于它们。同样，WithMarshalers 也可能影响复合类型内部任意类型的序列化。

其他所有选项都由 MarshalerTo 实现之外的代码自动处理，因此与具体实现无关。

			
type MarshalerTo interface {
    MarshalJSONTo(*jsontext.Encoder) error
}

type Options
				
				1.27
			

			
Options 为 Marshal、MarshalWrite、MarshalEncode、Unmarshal、UnmarshalRead 和 UnmarshalDecode 配置特定功能。每个函数都接受可变长度的选项列表，后面的选项所设置的属性会覆盖之前设置的属性值。

Options 类型与 encoding/json.Options 和 encoding/json/jsontext.Options 完全相同。其他包的选项可以与本包功能互换使用。

一个 Options 值表示单个选项或一组选项。可以将它理解为保存选项属性的 Go 映射（尽管底层实现出于性能考虑避免使用 Go 映射）。

构造函数（例如 Deterministic）返回单个选项的值：

opt := Deterministic(true)



这类似于创建只有一个条目的映射：

opt := Options{"Deterministic": true}



JoinOptions 将多个选项值组合起来：

out := JoinOptions(opts...)



这类似于创建一个新映射，并将选项复制进去：

out := make(Options)
for _, m := range opts {
	for k, v := range m {
		out[k] = v
	}
}



GetOption 查询某个选项参数的值：

v, ok := GetOption(opts, Deterministic)



这类似于 Go 映射查询：

v, ok := Options["Deterministic"]



序列化和反序列化共用同一个 Options 类型。有些选项影响两种操作，有些只影响其中一种：

    

  • StringifyNumbers 影响序列化和反序列化

  • Deterministic 仅影响序列化

  • FormatNilSliceAsNull 仅影响序列化

  • FormatNilMapAsNull 仅影响序列化

  • OmitZeroStructFields 仅影响序列化

  • MatchCaseInsensitiveNames 影响序列化和反序列化

  • RejectUnknownMembers 仅影响反序列化

  • WithMarshalers 仅影响序列化

  • WithUnmarshalers 仅影响反序列化



不影响某项操作的选项会被忽略。

StringifyNumbers 指定将通常编码为 JSON 数值的类型，改为编码为包含等价 JSON 数值的 JSON 字符串。反序列化时，从包含 JSON 数值且数值前后不带空白的 JSON 字符串解析该值。

为 Go 结构体字段指定 `string` 标签选项，会将此选项应用于该字段的顶层 JSON 值。通过 `string` 标签选项应用时，StringifyNumbers 不会递归作用于 JSON 对象或数组内部嵌套的 JSON 数值。

与所有选项一样，在调用 Marshal、Unmarshal 等函数时显式指定此选项，会递归应用它。

具有自定义序列化/反序列化行为、且表示 JSON 数值的 Go 类型应遵守 StringifyNumbers 选项：如果指定了该选项，应将 JSON 数值序列化在 JSON 字符串中。自定义序列化/反序列化应使用 MarshalEncode/UnmarshalDecode 处理嵌套的 JSON 对象，它们会自动应用 `string` 标签选项的非递归行为。

根据 RFC 8259 第 6 节，JSON 实现可以选择将 JSON 数值的表示限制为 IEEE 754 binary64 值。这可能导致解码器对 int64 和 uint64 类型丢失精度。将 JSON 数值加引号作为 JSON 字符串保存，可以保留精确值。

此选项影响序列化和反序列化。

type SemanticError
				
				1.27
			

			
SemanticError 描述在确定 JSON 数据对应的 Go 数据含义，或反向确定其含义时发生的错误。

如果 Marshaler、MarshalerTo、Unmarshaler 或 UnmarshalerFrom 方法被 json 包调用时返回 SemanticError，则 ByteOffset、JSONPointer 和 GoType 字段如果为零值，会由调用上下文自动填充。

本包生成的此类错误的内容可能随时间变化。

			
type SemanticError struct {

    // ByteOffset 表示错误发生在此字节偏移量处或其后。
    ByteOffset int64
    // JSONPointer 用 JSON Pointer 表示法（见 RFC 6901）
    // 指出错误发生在哪个 JSON 值内部。
    JSONPointer jsontext.Pointer

    // JSONKind 是无法处理的 JSON 种类。
    JSONKind jsontext.Kind // 未知时可以为零
    // JSONValue 是无法反序列化的 JSON 数值或字符串。
    // 序列化时不会填充此字段。
    JSONValue jsontext.Value // 不相关或未知时可以为 nil
    // GoType 是无法处理的 Go 类型。
    GoType reflect.Type // 未知时可以为 nil

    // Err 是底层错误。
    Err error // 可以为 nil
    // 包含已过滤或未导出的字段
}

type UnmarshalerFrom
				
				1.27
			

			
UnmarshalerFrom 由能够反序列化自身的类型实现。建议实现 UnmarshalerFrom 而非 Unmarshaler，因为它性能更好，也更灵活。如果某类型同时实现 Unmarshaler 和 UnmarshalerFrom，则优先使用 UnmarshalerFrom。此时，两种实现在默认反序列化选项下应尽量保持等价行为。

实现必须恰好从 Decoder 读取一个 JSON 值。建议 UnmarshalJSONFrom 在反序列化到预先填充值时实现 Unmarshal 所述的合并语义。另一种选择是在不修改 Decoder 的情况下返回 errors.ErrUnsupported。调用此方法的“json”包将采用接收者类型的下一种可用 JSON 表示。实现不得保留指向 jsontext.Decoder 的指针。

如果返回的错误是 SemanticError，json 可能会用额外上下文填充其中尚未设置的字段。其他类型的错误会被包装在 SemanticError 中，但 [jsontext.SyntacticError] 和 I/O 错误除外。

不应直接调用 UnmarshalJSONFrom 方法，因为它可能返回需要特殊处理的哨兵错误。使用者应改为调用 UnmarshalDecode，它会处理这些情况。

实现应通过 jsontext.Decoder.Options 检查反序列化选项，并按需调整行为以遵守这些选项。

以下选项可能与 UnmarshalerFrom 实现有关：

- StringifyNumbers：如果该类型表示为 JSON 数值

某些选项（例如 FormatNilSliceAsNull）仅适用于原生 Go 类型，因此通常与 UnmarshalerFrom 的实现没有直接关系。但表示复合类型的类型应使用 UnmarshalDecode 反序列化其中包含的类型，以确保这些选项作用于它们。同样，WithUnmarshalers 也可能影响复合类型内部任意类型的反序列化。

其他所有选项都由 UnmarshalerFrom 实现之外的代码自动处理，因此与具体实现无关。

			
type UnmarshalerFrom interface {
    UnmarshalJSONFrom(*jsontext.Decoder) error
}

func JoinUnmarshalers
					
					1.27
				

				
func JoinUnmarshalers(us ...*Unmarshalers) *Unmarshalers

				
JoinUnmarshalers 将反序列化函数合并为一个扁平列表。如果列表中多个函数都适用于给定类型的值，则靠前的函数优先。如果某函数返回 errors.ErrUnsupported，则调用下一个适用函数；没有可用函数时，使用默认反序列化行为。

例如：

u1 := JoinUnmarshalers(f1, f2)
u2 := JoinUnmarshalers(f0, u1, f3)     // 等价于 u3
u3 := JoinUnmarshalers(f0, f1, f2, f3) // 等价于 u2
