jsontext 包按 RFC 4627、RFC 7159、RFC 7493、RFC 8259 和 RFC 8785 的规定实现 JSON 的语法处理。JSON 是一种简单的数据交换格式，既能表示布尔值、字符串和数字等基本数据类型，也能表示对象和数组等结构化数据类型。

Encoder 和 Decoder 类型用于对 JSON 词法单元或值的流进行编码或解码。

词法单元与值

JSON 词法单元（token）指 JSON 的基本结构元素：

  • JSON 字面量（即 null、true 或 false）
  • JSON 字符串（例如 "hello, world!"）
  • JSON 数字（例如 123.456）
  • JSON 对象的起始或结束分隔符（即 '{' 或 '}'）
  • JSON 数组的起始或结束分隔符（即 '[' 或 ']'）

JSON 词法单元在 Go 中由 Token 类型表示。严格来说，还有两个结构字符（即 ':' 和 ','），但它们没有对应的 Token 表示，因为可从 JSON 文法的结构推断它们的存在。例如，JSON 对象成员的名称和值之间始终隐含一个冒号。

JSON 值指一个完整的 JSON 数据单元：

  • JSON 字面量、字符串或数字
  • JSON 对象（例如 `{"name":"value"}`）
  • JSON 数组（例如 `[1,2,3]`）

JSON 值在 Go 中由 Value 类型表示，它是一个包含该值原始文本表示的 []byte。词法单元和值有一部分重叠，两者都包括字面量、字符串和数字；但只有值才能表示整个 JSON 对象或数组。

Encoder 和 Decoder 提供读取或写入序列中下一个 Token 或 Value 的方法。它们维护一个状态机，验证 JSON 词法单元和/或值组成的序列是否构成有效 JSON。可以向 NewEncoder 或 NewDecoder 构造函数传入 Options，配置编码和解码行为。

术语

“编码”（encode）和“解码”（decode）用于描述依据 JSON 文法进行处理的语法层功能；“序列化”（marshal）和“反序列化”（unmarshal）用于描述决定 JSON 值与 Go 值之间对应含义的语义层功能。本包处理 JSON 语法，encoding/json/v2 则处理 JSON 语义。这样做是为了明确区分纯粹的编码功能与序列化功能。例如，可以直接编码 JSON 词法单元流，而无须先将表示它们的具体 Go 值序列化；同样，也可以解码 JSON 词法单元流，而无须将它们反序列化为具体 Go 值。

本包讨论 JSON 时采用 JSON 术语，这些术语可能与 Go 或其他计算机文献中的相关概念不同。

  • JSON“对象”指名称/值成员的无序集合。
  • JSON“数组”指元素的有序序列。
  • JSON“值”指字面量（即 null、false 或 true）、字符串、数字、对象或数组。

更多信息参见 RFC 8259。

规范

相关规范包括 RFC 4627、RFC 7159、RFC 7493、RFC 8259 和 RFC 8785。每个 RFC 通常是另一个 RFC 的更严格子集。按严格程度递增排列如下：

  • RFC 4627 和 RFC 7159 不强制要求（但建议）使用 UTF-8，也不强制要求（但建议）对象成员名称唯一。
  • RFC 8259 要求使用 UTF-8，但不强制要求（只建议）对象成员名称唯一。
  • RFC 7493 要求使用 UTF-8，且对象成员名称必须唯一。
  • RFC 8785 定义规范化表示，要求使用 UTF-8，对象成员名称必须唯一且按特定顺序排列，并精确规定字符串和数字的格式。

RFC 4627 与 RFC 7159 的主要区别是：前者将顶层值限制为 JSON 对象和数组，而 RFC 7159 及后续 RFC 还允许顶层值为 JSON null、布尔值、字符串或数字。

默认情况下，本包按 RFC 7493 运行，也可配置为遵循其他 RFC。RFC 7493 是 RFC 8259 的更严格子集，与后者完全兼容。具体而言，它对 RFC 8259 中未定义的行为做出明确选择，以提高互操作性。

ErrDuplicateName 表示某个 JSON 词法单元因导致 JSON 对象成员名称重复而无法编码或解码。产生此错误时，它会直接包装在 SyntacticError 中。

可以按以下方式提取重复的 JSON 对象成员名称：

err := ...
serr, ok := errors.AsType[*jsontext.SyntacticError](err)
if ok && serr.Err == jsontext.ErrDuplicateName {
	ptr := serr.JSONPointer // 指向重复名称的 JSON 指针
	name := ptr.LastToken() // 重复名称本身
	...
}

仅当 AllowDuplicateNames 为 false 时，才会返回此错误。

var ErrDuplicateName = errors.New("duplicate object member name")

func AppendFloat 1.27 

func AppendFloat(dst []byte, src float64, bits int) []byte

AppendFloat 按 RFC 8259 第 6 节将 src 作为 JSON 数字追加到 dst。

除了将 -0 格式化为 -0 而不是 0 这一点外，输出与 ECMA-262 第 10 版第 7.1.12.1 节相同；使用 64 位精度时，也与 RFC 8785 第 3.2.2.3 节相同。NaN、+Inf 和 -Inf 分别表示为值为 "NaN"、"Infinity" 和 "-Infinity" 的 JSON 字符串。

注意，大多数 JSON 库和标准都假设 JSON 数字是 64 位浮点数。因此，应优先使用 64 位精度，除非接收方能够从其他上下文得知编码的数字使用了 32 位精度。

func AppendFormat 

func AppendFormat[Bytes ~[]byte | ~string](dst []byte, src Bytes, opts ...Options) ([]byte, error)

AppendFormat 按指定选项格式化 src 中的 JSON 值，并将其追加到 dst。格式化行为详见 Value.Format。

func AppendQuote 

func AppendQuote[Bytes ~[]byte | ~string](dst []byte, src Bytes) ([]byte, error)

AppendQuote 将表示 src 的双引号 JSON 字符串字面量追加到 dst，并返回扩展后的缓冲区。它采用 RFC 8785 第 3.2.2.2 节规定的最简字符串表示。无效的 UTF-8 字节会替换为 Unicode 替换字符，并在最后返回错误以说明存在无效 UTF-8。dst 不得与 src 重叠。

func AppendUnquote 

func AppendUnquote[Bytes ~[]byte | ~string](dst []byte, src Bytes) ([]byte, error)

AppendUnquote 将 src 作为双引号 JSON 字符串字面量解码，把解码结果追加到 dst，并返回扩展后的缓冲区。输入 src 必须是前后不带空白的 JSON 字符串。无效的 UTF-8 字节会替换为 Unicode 替换字符，并在最后返回错误以说明存在无效 UTF-8。JSON 字符串字面量之后的任何尾随字节都会导致错误。dst 不得与 src 重叠。

type Decoder 1.27

Decoder 是用于原始 JSON 词法单元和值的流式解码器。它用于读取顶层 JSON 值的流，各值之间可用空白字符分隔。

可以交错调用 Decoder.ReadToken 和 Decoder.ReadValue。例如，以下 JSON 值：

{"name":"value","array":[null,false,true,3.14159],"object":{"k":"v"}}

可以通过以下调用解析（为简洁起见，忽略错误）：

d.ReadToken() // {
d.ReadToken() // "name"
d.ReadToken() // "value"
d.ReadValue() // "array"
d.ReadToken() // [
d.ReadToken() // null
d.ReadToken() // false
d.ReadValue() // true
d.ReadToken() // 3.14159
d.ReadToken() // ]
d.ReadValue() // "object"
d.ReadValue() // {"k":"v"}
d.ReadToken() // }

以上只是多种可能调用顺序中的一种，对某个具体词法单元或值而言，未必采用了最合理的方法。例如，对于对象成员名称，更常见的做法可能是调用 Decoder.ReadToken 获取字符串词法单元。

type Decoder struct {
    // 包含已过滤或未导出的字段
}

func (*Decoder) PeekKind 1.27 

func (d *Decoder) PeekKind() Kind

PeekKind 获取下一个词法单元的类别，但不推进读取偏移量。

发生错误时返回 KindInvalid。错误会缓存到下一次读取调用；调用方有责任在调用 PeekKind 后最终执行一次读取。

func (*Decoder) ReadToken 1.27 

func (d *Decoder) ReadToken() (Token, error)

ReadToken 读取下一个 Token 并推进读取偏移量。返回的词法单元仅在下一次 Peek、Read 或 Skip 调用前有效。如果没有更多词法单元，则返回 io.EOF。

func (*Decoder) ReadValue 1.27 

func (d *Decoder) ReadValue() (Value, error)

ReadValue 返回下一个原始 JSON 值并推进读取偏移量。值的首尾空白会被移除，其余字节与输入完全一致；如果指定了 AllowInvalidUTF8，其中可能含有无效 UTF-8。

返回值仅在下一次 Peek、Read 或 Skip 调用前有效，且只要 Decoder 仍在使用，就不得修改该值。如果解码器当前位于对象或数组的结束词法单元处，则报告 SyntacticError，内部状态保持不变。如果没有更多值，则返回 io.EOF。

func (*Decoder) Reset 1.27 

func (d *Decoder) Reset(r io.Reader, opts ...Options)

Reset 重置解码器，使其从 r 重新开始读取，并采用提供的选项。对于传给 encoding/json/v2.UnmarshalerFrom.UnmarshalJSONFrom 方法或 encoding/json/v2.UnmarshalFromFunc 函数的 Decoder，不得调用 Reset。

func (*Decoder) SkipValue 1.27 

func (d *Decoder) SkipValue() error

SkipValue 在语义上等价于调用 Decoder.ReadValue 后丢弃结果，但不会为了保存整个结果而浪费内存。

func (*Decoder) StackDepth 1.27 

func (d *Decoder) StackDepth() int

StackDepth 返回状态机中已读取 JSON 数据的栈深度。每一层表示一个嵌套的 JSON 对象或数组。遇到 BeginObject 或 BeginArray 词法单元时深度加一，遇到 EndObject 或 EndArray 时减一。

不在任何对象或数组内部时，StackDepth 返回 0。具体包括尚未读取任何词法单元、已读完任意顶层值，以及解码顶层值流（例如 NDJSON）时处于两个值之间。位于顶层对象或数组内部时返回 1，位于其嵌套的对象或数组内部时返回 2，依此类推。

例如，考虑解码以下 JSON：

{"a": [1, 2], "b": {"c": 3}}

解码过程中，StackDepth 的返回值如下：

  • 开始时返回 0。
  • 解码外层 '{' 后返回 1。
  • 解码内层 '[' 后返回 2。
  • 解码内层 ']' 后返回 1。
  • 解码外层 '}' 后返回 0。

func (*Decoder) StackIndex 1.27 

func (d *Decoder) StackIndex(i int) (Kind, int64)

StackIndex 返回指定栈层的信息。level 必须介于 0 和 Decoder.StackDepth 之间（包含端点）。每层返回的类别为：

  • 第 0 层为 KindInvalid；
  • 表示 JSON 对象的层为 KindBeginObject；
  • 表示 JSON 数组的层为 KindBeginArray。

它还返回该 JSON 对象或数组目前已解码的长度。JSON 对象中的每个名称和值分别计数，因此实际成员数为长度的一半。完整 JSON 对象的长度必须为偶数。

func (*Decoder) StackPointer 1.27 

func (d *Decoder) StackPointer() Pointer

StackPointer 返回指向最近读取的值的 JSON Pointer（RFC 6901）。

func (*Decoder) UnreadBuffer 1.27 

func (d *Decoder) UnreadBuffer() []byte

UnreadBuffer 返回未读缓冲区中剩余的数据，可能包含零个或多个字节。这些数据已从输入 io.Reader 消耗，但尚未被 Decoder.ReadToken 或 Decoder.ReadValue 读取。由于还没有按 JSON 文法验证，它可能包含不构成有效 JSON 的字节。缓冲数据的确切数量属于 Decoder 的实现细节，可能随实现变化。

调用方有责任将此缓冲区与输入 Reader 中的剩余内容拼接，以获取最后读取的 JSON 词法单元或值之后的完整字节序列。

只要 Decoder 还在继续使用，就不得修改返回的缓冲区。缓冲区内容在下一次 Peek、Read 或 Skip 调用前有效。

type Encoder 1.27

Encoder 是将数据编码为原始 JSON 词法单元和值的流式编码器。它用于写入顶层 JSON 值的流，每个值都以换行符结尾。

可以交错调用 Encoder.WriteToken 和 Encoder.WriteValue。例如，以下 JSON 值：

{"name":"value","array":[null,false,true,3.14159],"object":{"k":"v"}}

可以通过以下调用构造（为简洁起见，忽略错误）：

e.WriteToken(BeginObject)        // {
e.WriteToken(String("name"))     // "name"
e.WriteToken(String("value"))    // "value"
e.WriteValue(Value(`"array"`))   // "array"
e.WriteToken(BeginArray)         // [
e.WriteToken(Null)               // null
e.WriteToken(False)              // false
e.WriteValue(Value("true"))      // true
e.WriteToken(Float(3.14159))     // 3.14159
e.WriteToken(EndArray)           // ]
e.WriteValue(Value(`"object"`))  // "object"
e.WriteValue(Value(`{"k":"v"}`)) // {"k":"v"}
e.WriteToken(EndObject)          // }

以上只是多种可能调用顺序中的一种，对某个具体词法单元或值而言，未必采用了最合理的方法。例如，对于对象成员名称，更常见的做法可能是使用字符串词法单元调用 Encoder.WriteToken。

}

func NewEncoder 1.27 

func NewEncoder(w io.Writer, opts ...Options) *Encoder

NewEncoder 构造一个向 w 写入数据、采用指定选项的新流式编码器。当内部缓冲区足够满，或已经写完一个顶层值时，会将缓冲内容写出。

如果 w 是 bytes.Buffer，编码器会直接向缓冲区追加内容，无须从中间缓冲区复制。

func (*Encoder) AvailableBuffer 1.27 

func (e *Encoder) AvailableBuffer() []byte

AvailableBuffer 返回长度为零、容量可能非零的缓冲区。此缓冲区用于填充一个 Value，随后立即将它传给 Encoder.WriteValue。

用法示例：

b := e.AvailableBuffer()
b = append(b, '"')
b = appendString(b, v) // 追加 v 的字符串形式
b = append(b, '"')
... := e.WriteValue(b)

注意，WriteValue 要求有效的 JSON 值。直接在原始 []byte 中构造值，需要比使用 String 等构造函数更加谨慎；这些函数总会返回有效的 [Token] 或 [Value]。

不在任何对象或数组内部时，StackDepth 返回 0。具体包括尚未写入任何词法单元、已写完任意顶层值，以及编码顶层值流（例如 NDJSON）时处于两个值之间。位于顶层对象或数组内部时返回 1，位于其嵌套的对象或数组内部时返回 2，依此类推。

例如，考虑编码以下 JSON：

{"a": [1, 2], "b": {"c": 3}}

编码过程中，StackDepth 的返回值如下：

  • 开始时返回 0。
  • 编码外层 '{' 后返回 1。
  • 编码内层 '[' 后返回 2。
  • 编码内层 ']' 后返回 1。
  • 编码外层 '}' 后返回 0。

func (*Encoder) StackIndex 1.27 

func (e *Encoder) StackIndex(i int) (Kind, int64)

StackIndex 返回指定栈层的信息。level 必须介于 0 和 Encoder.StackDepth 之间（包含端点）。每层返回的类别为：

  • 第 0 层为 KindInvalid；
  • 表示 JSON 对象的层为 KindBeginObject；
  • 表示 JSON 数组的层为 KindBeginArray。

它还返回该 JSON 对象或数组目前已编码的长度。JSON 对象中的每个名称和值分别计数，因此实际成员数为长度的一半。完整 JSON 对象的长度必须为偶数。

func (e *Encoder) StackPointer() Pointer

StackPointer 返回指向最近写入的值的 JSON Pointer（RFC 6901）。

func (*Encoder) WriteToken 1.27 

func (e *Encoder) WriteToken(t Token) error

WriteToken 写入下一个词法单元，并推进内部写入偏移量。

提供的词法单元类别必须符合 JSON 文法。例如，编码器期待对象成员名称（必须为字符串）时提供数字，或在结束数组时提供对象结束分隔符，都会出错。如果提供的词法单元无效，WriteToken 会报告 SyntacticError，内部状态保持不变。SyntacticError 中的偏移量等于 Encoder.OutputOffset 加上在该词法单元前本应出现的分隔符或空白字符数。

func (*Encoder) WriteValue 1.27 

func (e *Encoder) WriteValue(v Value) error

WriteValue 写入下一个原始值，并推进内部写入偏移量。Encoder 并非直接原样复制该值，而是解析它以确保语法有效，并按照空白和字符串的格式配置重新格式化。如果指定了 AllowInvalidUTF8，所有无效 UTF-8 都会替换为 Unicode 替换字符 U+FFFD。

提供的值类别必须符合 JSON 文法（参见 Encoder.WriteToken 中的示例）。如果值无效，WriteValue 会报告 SyntacticError，内部状态保持不变。SyntacticError 中的偏移量等于 Encoder.OutputOffset 加上所遇语法错误在 v 中的偏移量。

func AllowDuplicateNames 1.27 

func AllowDuplicateNames(v bool) Options

AllowDuplicateNames 指定 JSON 对象可以包含重复的成员名称。禁用重名检查可能提升性能，但不再符合 RFC 7493 第 2.3 节。输入或输出仍符合 RFC 8259，因为该规范未规定重复名称的处理方式。

此选项同时影响编码和解码。

func AllowInvalidUTF8 1.27 

func AllowInvalidUTF8(v bool) Options

AllowInvalidUTF8 指定 JSON 字符串可以包含无效的 UTF-8，这些内容会被替换为 Unicode 替换字符 U+FFFD。这使编码器或解码器不再符合 RFC 7493 第 2.1 节和 RFC 8259 第 8.1 节。

此选项同时影响编码和解码。

func CanonicalizeRawFloats 1.27 

func CanonicalizeRawFloats(v bool) Options

CanonicalizeRawFloats 指定：编码 Token 或 Value 中的原始 JSON 浮点数（即含小数部分或指数的数字）时，按照 RFC 8785 第 3.2.2.3 节将其规范化。特殊情况是将 -0 规范化为 0。

JSON 数字被视为 IEEE 754 双精度数。对已序列化的单精度数进行规范化，再将其解析回单精度数，是安全的，可以得到相同的值。如果数字超出最大有限值 ±1.7976931348623157e+308，就将其限制在对应的边界值，并按该值格式化。

此选项仅影响编码，解码时会被忽略。

func CanonicalizeRawInts 1.27 

func CanonicalizeRawInts(v bool) Options

CanonicalizeRawInts 指定：编码 Token 或 Value 中的原始 JSON 整数（即不含小数部分和指数的数字）时，按照 RFC 8785 第 3.2.2.3 节将其规范化。特殊情况是将 -0 规范化为 0。

JSON 数字被视为 IEEE 754 双精度数。超出该形式可表示精度的数字在规范化时会损失精度。例如，超出 ±2⁵³ 范围的整数会损失精度；1234567890123456789 会格式化为 1234567890123456800。

此选项仅影响编码，解码时会被忽略。

type Pointer 1.27

Pointer 是 JSON Pointer（RFC 6901），用于相对于顶层 JSON 值的根定位某个具体 JSON 值。

Pointer 是以斜杠分隔的引用片段列表，每个片段要么是 JSON 对象成员名称，要么是以十进制整数编码的 JSON 数组元素索引。如果不知道指针所引用的顶层 JSON 值的结构，就无法区分数组索引与恰好为十进制整数字符串的对象成员名称。

指向某个特定值的指针只有一种表示，因此比较 Pointer 值是否相等，就等价于检查它们是否指向同一个值。

type Token 1.27

Token 表示一个 JSON 词法单元，可以是以下之一：

  • JSON 字面量（即 null、true 或 false）
  • JSON 字符串（例如 "hello, world!"）
  • JSON 数字（例如 123.456）
  • JSON 对象的起始或结束分隔符（即 { 或 }）
  • JSON 数组的起始或结束分隔符（即 [ 或 ]）

Token 无法表示整个数组或对象值，而 Value 可以。没有用于表示逗号和冒号的 Token，因为这些结构性词法单元可以从周围上下文推断。

Token 以以下两种形式之一存储数据：

  • 原始 JSON 文本：依托 Decoder 的内部缓冲区，仅由 Decoder.ReadToken 产生。此类词法单元仅在下一次调用该 Decoder 的任意方法前有效，例如 Decoder.PeekKind、Decoder.ReadToken、Decoder.ReadValue 或 Decoder.SkipValue。调用 Token.Clone 可将原始文本复制到独立分配的内存中，使其在后续 Decoder 调用后仍保持有效。

  • 带类型的 Go 值：由构造函数（例如 String、Int、Uint、Float）产生的独立表示。此类词法单元一直有效，无须克隆。

type Token struct {
    // 包含已过滤或未导出的字段
}

var (
    Null  Token = rawToken("null")
    False Token = rawToken("false")
    True  Token = rawToken("true")

    BeginObject Token = rawToken("{")
    EndObject   Token = rawToken("}")
    BeginArray  Token = rawToken("[")
    EndArray    Token = rawToken("]")
)

type Value 1.27

Value 表示单个原始 JSON 值，可以是以下之一：

  • JSON 字面量（即 null、true 或 false）
  • JSON 字符串（例如 "hello, world!"）
  • JSON 数字（例如 123.456）
  • 整个 JSON 对象（例如 {"fizz":"buzz"}）
  • 整个 JSON 数组（例如 [1,2,3]）

Value 可以表示整个数组或对象值，而 Token 不可以。Value 可以带有前导和/或尾随空白。

type Value []byte

func (*Value) Canonicalize 1.27 

func (v *Value) Canonicalize(opts ...Options) error

Canonicalize 按 RFC 8785 定义的 JSON 规范化方案（JCS）对原始 JSON 值进行规范化。所得 JSON 值与原值含义相同，并具有稳定性：对已经规范化的值再次调用 Canonicalize，不会产生变化。

JSON 字符串格式化为最简表示，JSON 数字按稳定的序列化算法格式化为双精度数，JSON 对象成员按名称升序排列，并移除全部空白。

Canonicalize 等价于使用以下选项调用 Value.Format：

  • CanonicalizeRawInts(true)
  • CanonicalizeRawFloats(true)
  • ReorderRawObjects(true)

调用方指定的选项在这组初始选项之后应用，因此可以有意覆盖前面的选项。

注意，JCS 将所有 JSON 数字视为 IEEE 754 双精度数。超出这种形式可表示精度的数字会在规范化时损失精度，例如超出 ±2⁵³ 范围的整数。要保留 JSON 整数的原始表示，可以另外将 CanonicalizeRawInts 设为 false：

v.Canonicalize(jsontext.CanonicalizeRawInts(false))

func (*Value) Compact 1.27 

func (v *Value) Compact(opts ...Options) error

Compact 移除原始 JSON 值中的所有空白。

它不会将 JSON 字符串或数字重新格式化为其他表示。为了尽可能支持更多 JSON 值，它允许重复名称和无效 UTF-8。

Compact 等价于使用以下选项调用 Value.Format：

  • AllowDuplicateNames(true)
  • AllowInvalidUTF8(true)
  • PreserveRawStrings(true)

调用方指定的选项在这组初始选项之后应用，因此可以有意覆盖前面的选项。

func (*Value) Format 1.27 

func (v *Value) Format(opts ...Options) error

Format 就地格式化原始 JSON 值。

默认情况下（未指定任何选项时），它按 RFC 7493 验证，并产生最简 JSON 表示：省略所有空白，JSON 字符串使用最短编码。

相关选项包括：

  • AllowDuplicateNames
  • AllowInvalidUTF8
  • EscapeForHTML
  • EscapeForJS
  • PreserveRawStrings
  • CanonicalizeRawInts
  • CanonicalizeRawFloats
  • ReorderRawObjects
  • SpaceAfterColon
  • SpaceAfterComma
  • Multiline
  • WithIndent
  • WithIndentPrefix

所有其他选项都会被忽略。

如果该值按照同组选项是有效的，就保证操作成功。如果值已经是所需格式，则不会修改缓冲区。

func (*Value) Indent 1.27 

func (v *Value) Indent(opts ...Options) error

Indent 重新格式化原始 JSON 值中的空白，使 JSON 对象成员或数组元素各自另起一行，并按嵌套层级缩进。

它不会将 JSON 字符串或数字重新格式化为其他表示。为了尽可能支持更多 JSON 值，它允许重复名称和无效 UTF-8。

Indent 等价于使用以下选项调用 Value.Format：

  • AllowDuplicateNames(true)
  • AllowInvalidUTF8(true)
  • PreserveRawStrings(true)
  • Multiline(true)

调用方指定的选项在这组初始选项之后应用，因此可以有意覆盖前面的选项。

func (Value) IsValid 1.27 

func (v Value) IsValid(opts ...Options) bool

IsValid 报告原始 JSON 值是否按照指定选项在语法上有效。

默认情况下（未指定任何选项时），它按 RFC 7493 验证，检查输入是否为正确的 UTF-8 编码、字符串中的转义序列是否解码为有效 Unicode 码点，以及每个对象中的名称是否唯一。它不验证数字是否处于任何常用数值类型（例如 float64、int64 或 uint64）的可表示范围内。

相关选项包括：

  • AllowDuplicateNames
  • AllowInvalidUTF8

所有其他选项都会被忽略。
