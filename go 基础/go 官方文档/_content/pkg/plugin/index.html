plugin 包实现 Go 插件的加载和符号解析。

插件是一个包含导出函数和变量的 Go main 包，使用以下方式构建：

go build -buildmode=plugin

首次打开插件时，会调用所有尚未包含在程序中的包的 init 函数。不会运行 main 函数。插件只初始化一次，且无法关闭。

注意事项

在执行期间动态加载应用的一部分（例如根据用户定义的配置），在某些设计中可能是有用的基础能力。尤其是，应用与动态加载的函数可以直接共享数据结构，因此插件可能使不同部分之间的集成具有很高性能。

不过，插件机制有许多显著缺点，设计时应仔细考虑。例如：

  • 目前只有 Linux、FreeBSD 和 macOS 支持插件，因此它们不适合要求可移植性的应用。

  • Go 竞态检测器对插件的支持较差。即使简单的竞态条件也可能无法自动检测。更多信息见 https://go.dev/issue/24245。

  • 使用插件的应用可能需要仔细配置，以确保程序各部分位于文件系统（或容器镜像）中的正确位置。相比之下，由单个静态可执行文件组成的应用部署起来很直接。

  • 如果某些包可能在应用开始运行很久之后才初始化，就更难分析程序的初始化过程。

  • 加载插件的应用中的缺陷可能被攻击者利用，加载危险或不可信的库。

  • 除非程序的所有部分（应用及全部插件）都使用完全相同的工具链版本、相同的构建标签，以及某些标志和环境变量的相同值进行编译，否则很可能在运行时崩溃。

  • 除非应用与插件的所有共同依赖都由完全相同的源代码构建，否则也很可能发生类似的崩溃问题。

  • 这些限制合在一起意味着，实际上应用及其插件必须由同一个人或系统组件统一构建。在这种情况下，让该人员或组件生成以空白标识符导入所需插件集合的 Go 源文件，再按通常方式编译静态可执行文件，可能更简单。

因此，许多用户认为传统的进程间通信（IPC）机制，例如套接字、管道、远程过程调用（RPC）、共享内存映射或文件系统操作，尽管有性能开销，却可能更加合适。

type Plugin 1.8

Plugin 是已加载的 Go 插件。

type Plugin struct {
    // 包含已过滤或未导出的字段
}

func Open 1.8 

func Open(path string) (*Plugin, error)

Open 打开一个 Go 插件。如果某个路径已经打开过，则返回已有的 *Plugin。此函数可由多个 goroutine 安全地并发使用。

func (*Plugin) Lookup 1.8 

func (p *Plugin) Lookup(symName string) (Symbol, error)

Lookup 在插件 p 中查找名为 symName 的符号。符号可以是任何导出的变量或函数。如果找不到符号，则返回错误。此方法可由多个 goroutine 安全地并发使用。

type Symbol 1.8

Symbol 是指向变量或函数的指针。

例如，以下定义的插件：

package main

import "fmt"

var V int

func F() { fmt.Printf("Hello, number %d\n", V) }

可以使用 Open 函数加载，然后访问导出的包符号 V 和 F：

p, err := plugin.Open("plugin_name.so")
if err != nil {
	panic(err)
}
v, err := p.Lookup("V")
if err != nil {
	panic(err)
}
f, err := p.Lookup("F")
if err != nil {
	panic(err)
}
*v.(*int) = 7
f.(func())() // 打印 "Hello, number 7"
