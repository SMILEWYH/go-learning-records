hpke 包实现 RFC 9180 定义的混合公钥加密（HPKE）。

▸ 示例

▾ 示例

代码：

// 此示例使用 MLKEM768-X25519 作为 KEM、HKDF-SHA256 作为
// KDF、AES-256-GCM 作为 AEAD，通过一次性 API 加密
// 发送方发给接收方的一条消息。

kem, kdf, aead := MLKEM768X25519(), HKDFSHA256(), AES256GCM()

// 接收方
var (
    recipientPrivateKey PrivateKey
    publicKeyBytes      []byte
)
{
    k, err := kem.GenerateKey()
    if err != nil {
        panic(err)
    }
    recipientPrivateKey = k
    publicKeyBytes = k.PublicKey().Bytes()
}

// 发送方
var ciphertext []byte
{
    publicKey, err := kem.NewPublicKey(publicKeyBytes)
    if err != nil {
        panic(err)
    }

    message := []byte("|-()-|")
    ct, err := Seal(publicKey, kdf, aead, []byte("example"), message)
    if err != nil {
        panic(err)
    }

    ciphertext = ct
}

// 接收方
{
    plaintext, err := Open(recipientPrivateKey, kdf, aead, []byte("example"), ciphertext)
    if err != nil {
        panic(err)
    }
    fmt.Printf("Decrypted message: %s\n", plaintext)
}

输出：

Decrypted message: |-()-|

func Open 1.26 

func Open(k PrivateKey, kdf KDF, aead AEAD, info, ciphertext []byte) ([]byte, error)

Open 像 NewRecipient 一样实例化一个仅使用一次的 HPKE 接收上下文，再像 Recipient.Open 一样解密给定密文（不使用 aad）。ciphertext 必须由封装密钥与实际密文拼接而成。

func Seal 1.26 

func Seal(pk PublicKey, kdf KDF, aead AEAD, info, plaintext []byte) ([]byte, error)

Seal 像 NewSender 一样实例化一个仅使用一次的 HPKE 发送上下文，再像 Sender.Seal 一样加密给定明文（不使用 aad）。Seal 返回封装密钥与密文的拼接结果。

type KEM 1.26

KEM 是密钥封装机制，为 HPKE 密码套件的三个组成部分之一。 

type KEM interface {
    // ID 返回 HPKE KEM 标识符。
    ID() uint16

    // GenerateKey 生成新的密钥对。
    GenerateKey() (PrivateKey, error)

    // NewPublicKey 从字节反序列化公钥。
    //
    // 它实现 RFC 9180 定义的 DeserializePublicKey。
    NewPublicKey([]byte) (PublicKey, error)

    // NewPrivateKey 从字节反序列化私钥。
    //
    // 它实现 RFC 9180 定义的 DeserializePrivateKey。
    NewPrivateKey([]byte) (PrivateKey, error)

    // DeriveKeyPair 根据给定的输入密钥材料派生密钥对。
    //
    // 它实现 RFC 9180 定义的 DeriveKeyPair。
    DeriveKeyPair(ikm []byte) (PrivateKey, error)
    // 包含已过滤或未导出的方法
}

type PrivateKey 1.26

PrivateKey 是使用解封装密钥（即秘密密钥）实例化的 KEM，而 KEM 是 HPKE 密码套件的三个组成部分之一。

PrivateKey 通常通过相应 KEM 的方法获得，例如 KEM.GenerateKey 或 KEM.NewPrivateKey。 

type PrivateKey interface {
    // KEM 返回已实例化的 KEM。
    KEM() KEM

    // Bytes 以 RFC 9180 定义的 SerializePrivateKey 的
    // 输出形式返回私钥。
    //
    // 注意，对于 X25519，它可能与 NewPrivateKey 的输入不同。
    // 这是 RFC 9180 第 7.1.2 节的要求。
    Bytes() ([]byte, error)

    // PublicKey 返回对应的 PublicKey。
    PublicKey() PublicKey
    // 包含已过滤或未导出的方法
}

func NewDHKEMPrivateKey 1.26 

func NewDHKEMPrivateKey(priv ecdh.KeyExchanger) (PrivateKey, error)

NewDHKEMPrivateKey 返回实现下列算法之一的 PrivateKey：

  • DHKEM(P-256, HKDF-SHA256)
  • DHKEM(P-384, HKDF-SHA384)
  • DHKEM(P-521, HKDF-SHA512)
  • DHKEM(X25519, HKDF-SHA256)

具体取决于 priv 的底层曲线（ecdh.X25519、ecdh.P256、ecdh.P384 或 ecdh.P521）。

此函数适用于已经拥有实例化的 crypto/ecdh 私钥或其他 ecdh.KeyExchanger 实现（例如硬件密钥）的应用程序。否则，应用程序应使用 KEM.NewPrivateKey 方法，该方法由 DHKEM 提供。

func NewHybridPrivateKey 1.26 

func NewHybridPrivateKey(pq crypto.Decapsulator, t ecdh.KeyExchanger) (PrivateKey, error)

NewHybridPrivateKey 返回实现下列算法之一的 PrivateKey：

  • MLKEM768-X25519（也称为 X-Wing）
  • MLKEM768-P256
  • MLKEM1024-P384

这些算法来自 draft-ietf-hpke-pq，具体取决于 t 的底层曲线（ecdh.X25519、ecdh.P256 或 ecdh.P384），以及 pq.Encapsulator() 的类型（*mlkem.EncapsulationKey768 或 *mlkem.EncapsulationKey1024）。

此函数适用于已经拥有实例化的 crypto/ecdh 和 crypto/mlkem 私钥，或其他 ecdh.KeyExchanger 和 crypto.Decapsulator 实现（例如硬件密钥）的应用程序。否则，应使用 KEM.NewPrivateKey 方法，例如 MLKEM768X25519 提供的该方法。

func NewRecipient 1.26 

func NewRecipient(enc []byte, k PrivateKey, kdf KDF, aead AEAD, info []byte) (*Recipient, error)

NewRecipient 为给定的 KEM 解封装密钥（即秘密密钥）返回 HPKE 接收上下文，使用由 KEM、KDF 和 AEAD 的组合确定的密码套件。

enc 参数必须由匹配的 HPKE 发送上下文使用对应的 KEM 封装密钥生成。info 参数是附加的公开信息，发送方与接收方必须一致。

func (r *Recipient) Export(exporterContext string, length int) ([]byte, error)

Export 根据发送方与接收方之间的共享密钥派生秘密值。length 最大为 65,535。

func (*Recipient) Open 1.26 

func (r *Recipient) Open(aad, ciphertext []byte) ([]byte, error)

Open 解密给定密文，可选地绑定附加公开数据 aad；如果解密失败，则返回错误。

Open 在每次成功调用时使用递增的计数器，调用顺序必须与发送方的 Seal 相同。
