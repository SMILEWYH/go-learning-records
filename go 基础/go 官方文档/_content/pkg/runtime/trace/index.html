trace 包提供用于为 Go 执行跟踪器生成跟踪数据的功能。

跟踪运行时活动

执行跟踪会捕获各种执行事件，例如 goroutine 的创建、阻塞与解除阻塞，系统调用的进入、退出与阻塞，GC 相关事件，堆大小变化，处理器的启动与停止等。启用 CPU 性能剖析时，执行跟踪器也会尽力包含这些样本。大多数事件都会捕获精确到纳秒的时间戳及栈轨迹。生成的跟踪数据可以使用 `go tool trace` 解析。

`go test` 内置了对使用标准 testing 包编写的测试和基准测试进行跟踪的支持。例如，以下命令运行当前目录中的测试，并写出跟踪文件 trace.out。

go test -trace=trace.out

runtime/trace 包提供了 API，可为独立程序添加同等的跟踪支持。请参阅演示如何使用此 API 启用跟踪的示例。

跟踪数据也有标准 HTTP 接口。添加以下导入会在 /debug/pprof/trace URL 下注册处理器，用于下载实时跟踪数据：

import _ "net/http/pprof"

有关此导入所注册的所有调试端点的详情，请参阅 net/http/pprof 包。

用户注解

trace 包提供用户注解 API，可用于在执行期间记录值得关注的事件。

用户注解有三种类型：日志消息、区域和任务。

Log 向执行跟踪中写入带时间戳的消息，以及消息类别、调用 Log 的 goroutine 等附加信息。执行跟踪器提供界面，可使用 Log 中提供的日志类别和消息来筛选和分组 goroutine。

区域用于记录 goroutine 执行过程中的一段时间区间。按照定义，区域必须在同一个 goroutine 中开始和结束。区域可以嵌套，以表示子区间。例如，以下代码在执行跟踪中记录四个区域，用于跟踪制作卡布奇诺操作中各个顺序步骤的耗时。

trace.WithRegion(ctx, "makeCappuccino", func() {

   // orderID 可用于从众多卡布奇诺订单的
   // 区域记录中识别某个特定订单。
   trace.Log(ctx, "orderID", orderID)

   trace.WithRegion(ctx, "steamMilk", steamMilk)
   trace.WithRegion(ctx, "extractCoffee", extractCoffee)
   trace.WithRegion(ctx, "mixMilkCoffee", mixMilkCoffee)
})

任务是更高层次的组成部分，用于帮助跟踪逻辑操作，例如 RPC 请求、HTTP 请求，或可能需要多个 goroutine 协作完成的某个值得关注的本地操作。由于任务可能涉及多个 goroutine，因此通过 context.Context 对象跟踪它们。NewTask 创建新任务，并将其嵌入返回的 context.Context 对象中。如果传给 Log 和 WithRegion 的 Context 中携带任务，日志消息和区域就会附属于该任务。

例如，假设我们决定在不同的 goroutine 中分别打奶泡、萃取咖啡以及混合牛奶和咖啡。借助任务，跟踪工具就能识别出参与某个特定卡布奇诺订单的 goroutine。

ctx, task := trace.NewTask(ctx, "makeCappuccino")
trace.Log(ctx, "orderID", orderID)

milk := make(chan bool)
espresso := make(chan bool)

go func() {
        trace.WithRegion(ctx, "steamMilk", steamMilk)
        milk <- true
}()
go func() {
        trace.WithRegion(ctx, "extractCoffee", extractCoffee)
        espresso <- true
}()
go func() {
        defer task.End() // 组装完成后，订单即完成。
        <-espresso
        <-milk
        trace.WithRegion(ctx, "mixMilkCoffee", mixMilkCoffee)
}()

跟踪工具通过测量从任务创建到任务结束的时间来计算任务延迟，并为跟踪数据中每种任务类型提供延迟分布。

func (*FlightRecorder) WriteTo
					
					1.25

WriteTo 为飞行记录器维护的滑动窗口生成快照。快照预期包含截至调用 WriteTo 时的最新数据，但这不是严格保证。同一时刻只能有一个 goroutine 执行 WriteTo。如果向 w 写入失败、已有另一个 WriteTo 调用正在进行，或者飞行记录器未处于活动状态，则返回错误。
type FlightRecorderConfig
				
				1.25
			

			
			
type FlightRecorderConfig struct {
    // MinAge 是飞行记录器窗口中事件年龄的下界。
    //
    // 飞行记录器会尽力及时丢弃年龄超过该最小值的事件，
    // 但窗口快照中仍可能出现更早的事件。年龄设置始终
    // 服从 MaxBytes 的限制。
    //
    // 如果此值为 0，则最小年龄由实现定义，但可以认为其数量级
    // 是秒。
    MinAge time.Duration

    // MaxBytes 是窗口大小的上界，单位为字节。
    //
    // 此设置优先于 MinAge。
    // 不过，它既不保证 WriteTo 写出的数据大小，
    // 也不保证内存开销始终低于 MaxBytes。应将其视为
    // 提示值。
    //
    // 如果此值为 0，则最大大小由实现定义。
    MaxBytes uint64
}

					1.11
				

				
func StartRegion(ctx context.Context, regionType string) *Region

				
StartRegion 启动并返回一个区域。返回的 Region 的 Region.End 方法必须在启动该区域的同一个 goroutine 中调用。在每个 goroutine 内，区域必须遵循嵌套关系。也就是说，在此区域之后启动的区域必须先结束，才能结束此区域。建议用法如下：
defer trace.StartRegion(ctx, "myTracedRegion").End()

func NewTask
					
					1.11
				

				
func NewTask(pctx context.Context, taskType string) (ctx context.Context, task *Task)

				
NewTask 创建类型为 taskType 的任务实例，并返回该任务以及携带它的 Context。如果输入上下文包含任务，新任务就是它的子任务。
taskType 用于对任务实例分类。Go 执行跟踪器等分析工具可能假定系统中不同任务类型的数量是有限的。
返回的 Task 的 Task.End 方法用于标记任务结束。跟踪工具将从任务创建到调用 End 方法之间的时间作为任务延迟，并提供每种任务类型的延迟分布。如果多次调用 End 方法，延迟测量只使用第一次调用。
ctx, task := trace.NewTask(ctx, "awesomeTask")
trace.WithRegion(ctx, "preparation", prepWork)
// 任务的准备工作
go func() {  // 在单独的 goroutine 中继续处理任务。
    defer task.End()
    trace.WithRegion(ctx, "remainingWork", remainingWork)
}()
