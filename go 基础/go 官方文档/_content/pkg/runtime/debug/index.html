func FreeOSMemory()

FreeOSMemory 强制执行一次垃圾回收，然后尝试将尽可能多的内存归还给操作系统。（即使不调用此函数，运行时也会通过后台任务逐步向操作系统归还内存。）

func ReadGCStats 1.1 

func ReadGCStats(stats *GCStats)

ReadGCStats 将垃圾回收统计信息读入 stats。暂停历史中的条目数量取决于系统；如果 stats.Pause 切片足够大，就会复用它，否则重新分配。ReadGCStats 可能使用 stats.Pause 切片的全部容量。如果 stats.PauseQuantiles 非空，ReadGCStats 会用概括暂停时间分布的分位数填充它。例如，如果 len(stats.PauseQuantiles) 为 5，就会依次填入最短、25%、50%、75% 和最长暂停时间。

func SetCrashOutput 1.23 

func SetCrashOutput(f *os.File, opts CrashOptions) error

SetCrashOutput 配置一个额外的文件，使未处理的 panic 和其他致命错误除了输出到标准错误，还会输出到该文件。额外文件只能有一个：再次调用 SetCrashOutput 会覆盖之前的调用。SetCrashOutput 会复制 f 的文件描述符，因此调用方可以在 SetCrashOutput 返回后立即安全地关闭 f。要禁用此额外的崩溃输出，请调用 SetCrashOutput(nil)。如果此调用与崩溃并发发生，即使覆盖配置的 SetCrashOutput 调用已经返回，某些正在进行的输出仍可能写入旧文件。

func SetGCPercent(percent int) int

			
SetGCPercent 设置垃圾回收的目标百分比：新分配数据与上一次回收后剩余存活数据的比值达到此百分比时，触发回收。SetGCPercent 返回先前的设置。初始设置取启动时 GOGC 环境变量的值；若未设置该变量，则为 100。为了满足内存限制，实际使用的百分比可能会降低。负数百分比实际上会禁用垃圾回收，除非达到内存限制。详情参见 SetMemoryLimit。
func SetMaxStack
				
				1.2
			

			
func SetMaxStack(bytes int) int

			
SetMaxStack 设置单个 goroutine 栈可以使用的最大内存量。如果任何 goroutine 在扩展其栈时超过此限制，程序就会崩溃。SetMaxStack 返回先前的设置。初始设置在 64 位系统上为 1 GB，在 32 位系统上为 250 MB。无论传给 SetMaxStack 的值是多少，系统仍可能施加最大栈限制。
SetMaxStack 主要用于限制陷入无限递归的 goroutine 所造成的损害。它只限制后续的栈增长。
func SetMaxThreads
				
				1.2
			

			
func SetMaxThreads(threads int) int

			
SetMaxThreads 设置 Go 程序可以使用的操作系统线程数上限。如果程序尝试使用超过该数量的线程，就会崩溃。SetMaxThreads 返回先前的设置。初始设置为 10,000 个线程。
此限制控制的是操作系统线程数，而不是 goroutine 数量。只有在某个 goroutine 已准备好运行，但所有现有线程都阻塞在系统调用或 cgo 调用中，或者因使用 runtime.LockOSThread 而绑定到其他 goroutine 时，Go 程序才会创建新线程。
SetMaxThreads 主要用于限制创建无界数量线程的程序所造成的损害。其目的是在程序拖垮操作系统之前，先让程序自身终止。
func SetMemoryLimit
				
				1.19
			

			
func SetMemoryLimit(limit int64) int64

			
SetMemoryLimit 为运行时设置一个软内存限制。
运行时会采取多种措施来尽量遵守此内存限制，包括调整垃圾回收频率，以及更积极地将内存归还给底层系统。即使设置了 GOGC=off（或执行了 SetGCPercent(-1)），此限制仍然生效。
输入的限制以字节为单位，涵盖 Go 运行时映射、管理且尚未释放的全部内存。特别是，它不包括 Go 二进制文件占用的空间，也不包括 Go 之外的内存，例如底层系统为该进程管理的内存，或同一进程中由非 Go 代码管理的内存。未计入的内存来源包括：操作系统内核为进程持有的内存、C 代码分配的内存，以及 syscall.Mmap 映射的内存（因为它不由 Go 运行时管理）。
更具体地说，以下表达式准确反映了运行时试图维持在限制以内的值：
runtime.MemStats.Sys - runtime.MemStats.HeapReleased



或者用 runtime/metrics 包表示为：
/memory/classes/total:bytes - /memory/classes/heap/released:bytes



将限制设为零，或设为低于 Go 运行时已使用内存的值，可能导致垃圾回收器几乎持续运行。不过，应用程序仍可能继续推进执行。
Go 运行时始终会遵循内存限制，因此要实际禁用此行为，应将限制设得很高。math.MaxInt64 是用于禁用限制的标准取值，但远大于底层系统可用内存的值也同样有效。
有关软内存限制的详细解释，以及各种常见用例和场景，请参阅指南 https://go.dev/doc/gc-guide。
初始设置为 math.MaxInt64，除非设置了 GOMEMLIMIT 环境变量，此时由该变量提供初始值。GOMEMLIMIT 是以字节为单位的数值，可以带可选的单位后缀。支持的后缀包括 B、KiB、MiB、GiB 和 TiB。这些后缀表示 IEC 80000-13 标准定义的字节数量，即以 2 的幂为基数：KiB 表示 2^10 字节，MiB 表示 2^20 字节，依此类推。
SetMemoryLimit 返回先前设置的内存限制。输入负数不会调整限制，可用于获取当前设置的内存限制。
func SetPanicOnFault
				
				1.3
			

			
func SetPanicOnFault(enabled bool) bool

			
SetPanicOnFault 控制程序在意外的非 nil 地址发生内存访问故障时，运行时如何处理。此类故障通常由运行时内存损坏等缺陷造成，因此默认处理方式是使程序崩溃。处理内存映射文件或进行不安全内存操作的程序，在较轻微的情况下也可能于非 nil 地址发生故障；SetPanicOnFault 允许这些程序请求运行时仅触发 panic，而不直接使程序崩溃。运行时 panic 携带的 runtime.Error 可能还具有一个额外的方法：
Addr() uintptr



如果该方法存在，它会返回触发故障的内存地址。Addr 尽力给出结果，其准确性可能取决于平台。SetPanicOnFault 仅对当前 goroutine 生效。它返回先前的设置。
func SetTraceback
				
				1.6
			

			
func SetTraceback(level string)

			
SetTraceback 设置运行时因未恢复的 panic 或内部运行时错误而退出前输出栈回溯时的详细程度。level 参数与 GOTRACEBACK 环境变量使用相同的取值。例如，SetTraceback("all") 确保程序在崩溃时输出所有 goroutine。详情请参阅 runtime 包文档。如果调用 SetTraceback 时指定的级别低于环境变量设置的级别，则忽略该调用。

func WriteHeapDump
				
				1.3
			

			
func WriteHeapDump(fd uintptr)

			
WriteHeapDump 将堆及其中对象的描述写入给定的文件描述符。
WriteHeapDump 会暂停所有 goroutine 的执行，直到堆转储全部写入完成。因此，文件描述符不能连接到另一端位于同一 Go 进程内的管道或套接字；应使用临时文件或网络套接字。
堆转储格式定义于 https://golang.org/s/go15heapdump。

BuildInfo 表示从 Go 二进制文件读取的构建信息。
type BuildInfo struct {
    // GoVersion 是构建该二进制文件的 Go 工具链版本
    // （例如 "go1.19.2"）。
    GoVersion string `json:",omitempty"` // Go 1.18

    // Path 是该二进制文件主包的包路径
    // （例如 "golang.org/x/tools/cmd/stringer"）。
    Path string `json:",omitempty"`

    // Main 描述包含该二进制文件主包的模块。
    Main Module `json:""`

    // Deps 描述为该二进制文件的构建提供包的
    // 所有依赖模块，包括直接和间接依赖。
    Deps []*Module `json:",omitempty"`

    // Settings 描述构建该二进制文件时使用的构建设置。
    Settings []BuildSetting `json:",omitempty"` // Go 1.18
}

type BuildSetting
				
				1.18
			

			
BuildSetting 是一个键值对，描述影响构建的某项设置。
已定义的键包括：
    

  • -buildmode：所用的 buildmode 标志（通常为 "exe"）
  • -compiler：所用的编译器工具链标志（通常为 "gc"）
  • CGO_ENABLED：实际生效的 CGO_ENABLED 环境变量
  • CGO_CFLAGS：实际生效的 CGO_CFLAGS 环境变量
  • CGO_CPPFLAGS：实际生效的 CGO_CPPFLAGS 环境变量
  • CGO_CXXFLAGS：实际生效的 CGO_CXXFLAGS 环境变量
  • CGO_LDFLAGS：实际生效的 CGO_LDFLAGS 环境变量
  • DefaultGODEBUG：实际生效的 GODEBUG 设置
  • GOARCH：目标架构
  • GOAMD64/GOARM/GO386/等：GOARCH 对应的架构特性级别
  • GOOS：目标操作系统
  • GOFIPS140：固定的 FIPS 140-3 模块版本（如果有）
  • vcs：执行构建时源代码树使用的版本控制系统
  • vcs.revision：当前提交或检出版本的修订标识符
  • vcs.time：与 vcs.revision 关联的修改时间，采用 RFC3339 格式
  • vcs.modified：true 或 false，表示源代码树是否存在本地修改


			
type BuildSetting struct {
    // Key 和 Value 描述构建设置。
    // Key 不能包含等号、空格、制表符或换行符。
    Key string `json:",omitempty"`
    // Value 不能包含换行符（'\n'）。
    Value string `json:",omitempty"`
}

GCStats 收集最近几次垃圾回收的信息。
type GCStats struct {
    LastGC         time.Time       // 最近一次回收的时间
    NumGC          int64           // 垃圾回收次数
    PauseTotal     time.Duration   // 所有回收的总暂停时间
    Pause          []time.Duration // 暂停历史，最近的在前
    PauseEnd       []time.Time     // 暂停结束时间的历史，最近的在前；Go 1.4 中加入
    PauseQuantiles []time.Duration
}
