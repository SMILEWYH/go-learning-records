os 包提供与平台无关的操作系统功能接口。其设计风格类似 Unix，但错误处理采用 Go 的方式：调用失败时返回 error 类型的值，而不是错误编号。错误值中通常包含更多信息。例如，Open 或 Stat 等接收文件名的调用失败时，返回的错误类型为 *PathError；打印该错误会包含出错的文件名，也可以检查其内容以获取更多信息。

os 接口旨在为所有操作系统提供一致的行为。不具备普遍可用性的功能放在与系统相关的 syscall 包中。

下面是一个简单示例，打开文件并读取其中的一部分内容。 

file, err := os.Open("file.go") // 用于读取访问。
if err != nil {
	log.Fatal(err)
}

如果打开失败，错误字符串会说明原因，例如： 

open file.go: no such file or directory

随后可以将文件数据读入字节切片。Read 和 Write 根据实参切片的长度确定要读写的字节数。 

data := make([]byte, 100)
count, err := file.Read(data)
if err != nil {
	log.Fatal(err)
}
fmt.Printf("read %d bytes: %q\n", count, data[:count])

并发

File 的方法对应文件系统操作，均可安全地并发使用。对一个 File 同时执行的操作数量可能受到操作系统或系统本身的限制。这个上限通常较高，但超过它可能降低性能或引发其他问题。

func Chdir 

func Chdir(dir string) error

Chdir 将当前工作目录更改为指定目录。如果发生错误，其类型为 *PathError。

func Chmod 

func Chmod(name string, mode FileMode) error

Chmod 将指定文件的模式更改为 mode。如果文件是符号链接，则更改链接目标的模式。如果发生错误，其类型为 *PathError。

实际使用哪些模式位取决于操作系统。

在 Unix 上，使用 mode 中的权限位以及 ModeSetuid、ModeSetgid 和 ModeSticky。

在 Windows 上，只使用 mode 的 0o200 位（所有者可写），用于设置或清除文件的只读属性。其他位目前不使用。为了兼容 Go 1.12 及更早版本，请使用非零的 mode。只读文件使用 0o400，可读写文件使用 0o600。

在 Plan 9 上，使用 mode 中的权限位以及 ModeAppend、ModeExclusive 和 ModeTemporary。

func CopyFS
				
				1.23
			

			
func CopyFS(dir string, fsys fs.FS) error

			

CopyFS 将文件系统 fsys 复制到目录 dir，必要时创建 dir。


文件以 0o666 加上源文件的所有执行权限创建；目录以 0o777 创建，以上模式均为应用 umask 之前的值。


CopyFS 不会覆盖已有文件。如果 fsys 中的某个文件名已存在于目标目录，CopyFS 会返回一个满足 errors.Is(err, fs.ErrExist) 为 true 的错误。


dir 中的符号链接会被跟随。


不保证会复制 CopyFS 运行期间新加入 fsys 的文件，dir 是 fsys 子目录的情况也包括在内。


复制操作在遇到第一个错误时停止，并返回该错误。

func DirFS
				
				1.16
			

			
func DirFS(dir string) fs.FS

			

DirFS 返回以目录 dir 为根的文件树所对应的文件系统（fs.FS）。


注意，DirFS("/prefix") 只保证它向操作系统发出的 Open 调用的路径以 "/prefix" 开头：DirFS("/prefix").Open("file") 等同于 os.Open("/prefix/file")。因此，如果 /prefix/file 是指向 /prefix 文件树之外的符号链接，DirFS 和 os.Open 一样都不会阻止访问。此外，使用相对路径 DirFS("prefix") 返回的 fs.FS，其根目录会受后续 Chdir 调用影响。因此，当目录树包含任意内容时，DirFS 不能作为 chroot 式安全机制的通用替代方案。


可以使用 Root.FS 获取能阻止通过符号链接越出目录树的 fs.FS。


目录 dir 不能为 ""。


返回值实现了 io/fs.StatFS、io/fs.ReadFileFS、io/fs.ReadDirFS 和 io/fs.ReadLinkFS。

func (*File) SetDeadline
					
					1.10
				

				
func (f *File) SetDeadline(t time.Time) error

				

SetDeadline 设置 File 的读写截止时间，等价于同时调用 SetReadDeadline 和 SetWriteDeadline。


只有部分类型的文件支持设置截止时间。对不支持的文件调用 SetDeadline 会返回 ErrNoDeadline。在多数系统上，普通文件不支持截止时间，但管道支持。


截止时间是一个绝对时间点：超过该时间后，I/O 操作会返回错误，而不再阻塞。截止时间适用于将来及正在等待的所有 I/O，不仅是紧接着的一次 Read 或 Write。超过截止时间后，可以将截止时间重新设到未来，使连接恢复可用。


超过截止时间后，Read、Write 或其他 I/O 方法会返回包装了 ErrDeadlineExceeded 的错误。可以通过 errors.Is(err, os.ErrDeadlineExceeded) 检查。该错误实现了 Timeout 方法，调用会返回 true；但其他某些错误即使未超过截止时间，Timeout 也可能返回 true。


每次 Read 或 Write 成功后不断延长截止时间，就可以实现空闲超时。


t 为零值表示 I/O 操作不会超时。

type Root
				
				1.24
			

			

Root 可用于将文件访问限定在一个目录树内。


Root 的方法只能访问根目录下的文件和目录。如果传给 Root 方法的文件名中，任何路径分量指向根目录之外的位置，该方法会返回错误。文件名可以引用目录本身（.）。


Root 的方法会跟随符号链接，但符号链接不能指向根目录之外的位置，也不能是绝对路径。


Root 的方法不会禁止跨越文件系统边界、Linux bind 挂载、/proc 特殊文件，也不会禁止访问 Unix 设备文件。


Root 的方法可以由多个 goroutine 同时安全调用。


在多数平台上，创建 Root 会打开引用该目录的文件描述符或句柄。如果目录被移动，Root 的方法仍然引用处于新位置的原目录。


Root 在部分平台上的行为有所不同：

    

  • 
当 GOOS=windows 时，文件名不能引用 NUL、COM1 等 Windows 保留设备名。

  • 
在 Unix 上，Root.Chmod、Root.Chown 和 Root.Chtimes 存在竞态条件。如果操作进行期间，目标从普通文件变成符号链接，操作可能作用于链接本身，而不是链接目标。

  • 
当 GOOS=js 时，Root 的符号链接验证容易受到 TOCTOU（检查时间与使用时间之间的竞态）攻击，无法保证操作不会越出根目录。

  • 
当 GOOS=plan9 或 GOOS=js 时，Root 无法在目录重命名后继续跟踪它。在这些平台上，Root 引用的是目录名，而不是文件描述符。

  • 
WASI preview 1（GOOS=wasip1）不支持 Root.Chmod。
