tabwriter 包实现写入过滤器（tabwriter.Writer），将输入中以制表符划分的列转换为正确对齐的文本。

本包使用弹性制表位（Elastic Tabstops）算法，说明见 http://nickgravgaard.com/elastictabstops/index.html。

text/tabwriter 包已冻结，不再接受新功能。

要转义一段文本，请在其两端加上 Escape 字符。例如，字符串 "Ignore this tab: \xff\t\xff" 中的制表符不会终止单元格，在格式化时被视为宽度为 1 的单个字符。

选择 0xff 是因为它不会出现在有效的 UTF-8 序列中。

const Escape = '\xff'

type Writer

Writer 是一个过滤器，它在输入中由制表符分隔的列周围插入填充，以使这些列在输出中对齐。

Writer 将传入字节视为 UTF-8 编码文本，由以水平制表符（'\t'）、垂直制表符（'\v'）、换行符（'\n'）或换页符（'\f'）结束的单元格组成；换行符和换页符都起换行作用。

连续各行中以制表符结束的单元格构成一列。Writer 按需插入填充，使一列中所有单元格宽度相同，从而对齐各列。它假定所有字符宽度相同，但制表符除外，其宽度必须由 tabwidth 指定。列中的单元格必须由制表符终止，而不只是由制表符分隔：行末不以制表符结束的尾随文本会构成一个单元格，但该单元格不属于对齐的列。例如，以下示例中（| 表示水平制表符）：

aaaa|bbb|d
aa  |b  |dd
a   |
aa  |cccc|eee

b 和 c 属于不同的列（b 所在列并非一直连续）。d 和 e 完全不属于任何列（它们既没有终止制表符，所在列也不连续）。

Writer 假定所有 Unicode 码点具有相同宽度；对于某些字体，或字符串包含组合字符时，这一假设可能不成立。

如果设置了 DiscardEmptyColumns，则全部由垂直（“软”）制表符终止的空列会被丢弃。由水平（“硬”）制表符终止的列不受此标志影响。

如果将 Writer 配置为过滤 HTML，则 HTML 标签和实体会原样通过。格式化时，标签的宽度视为零，实体的宽度视为一。

可以在文本片段两端加上 Escape 字符来转义。tabwriter 会让转义后的文本片段原样通过，尤其不会解释其中的任何制表符或换行符。如果设置了 StripEscape 标志，则从输出中移除 Escape 字符；否则，这些字符也会原样通过。格式化时，转义文本的宽度始终不包括 Escape 字符。

换页符的作用类似换行符，但还会终止当前行中的所有列（实际上相当于调用 Writer.Flush）。下一行中以制表符结束的单元格将开始新的列。除非位于 HTML 标签或转义文本片段内，否则换页符在输出中显示为换行符。

Writer 必须在内部缓冲输入，因为某行正确的间距可能依赖后续行中的单元格。调用方完成 Writer.Write 调用后必须调用 Flush。

func NewWriter 

func NewWriter(output io.Writer, minwidth, tabwidth, padding int, padchar byte, flags uint) *Writer

NewWriter 分配并初始化一个新的 Writer。参数与 Init 函数相同。

func (*Writer) Flush 

func (b *Writer) Flush() error

应在最后一次 Writer.Write 调用之后调用 Flush，以确保 Writer 中缓冲的数据全部写入输出。格式化时，末尾任何不完整的转义序列均被视为完整。

func (*Writer) Init 

func (b *Writer) Init(output io.Writer, minwidth, tabwidth, padding int, padchar byte, flags uint) *Writer

Writer 必须通过调用 Init 初始化。第一个参数 output 指定过滤器输出。其余参数控制格式：

minwidth	单元格最小宽度，包含所有填充
tabwidth	制表符宽度（等价的空格数）
padding		计算单元格宽度前添加的填充量
padchar		用于填充的 ASCII 字符
		如果 padchar == '\t'，Writer 将假定格式化输出中
		'\t' 的宽度为 tabwidth，且单元格一律左对齐，
		与 align_left 无关
		（为使结果显示正确，tabwidth 必须与查看器显示结果时
		所采用的制表符宽度一致）
flags		格式控制
