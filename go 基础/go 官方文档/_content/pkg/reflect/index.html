reflect 包实现运行时反射，使程序能够操作任意类型的对象。典型用法是取得一个静态类型为 interface{} 的值，然后调用 TypeOf 提取其动态类型信息；TypeOf 返回一个 Type。

调用 ValueOf 会返回表示运行时数据的 Value。Zero 接收一个 Type，并返回表示该类型零值的 Value。

Go 反射的入门介绍见《反射法则》：https://golang.org/doc/articles/laws_of_reflection.html。

func Copy 

func Copy(dst, src Value) int

Copy 将 src 的内容复制到 dst，直到 dst 被填满或 src 的元素被复制完，并返回复制的元素数。dst 和 src 的类别都必须是 Slice 或 Array，且元素类型必须相同。如果 dst 是 Array，且 Value.CanSet 返回 false，则触发 panic。

有一个特例：如果 dst 的元素类型的类别为 Uint8，则 src 的类别可以是 String。

func DeepEqual 

func DeepEqual(x, y any) bool

DeepEqual 报告 x 和 y 是否“深度相等”，定义如下。两个类型相同的值满足下列某一种情况时，便深度相等。不同类型的值永远不会深度相等。

两个数组值在其对应元素深度相等时深度相等。

两个结构体值在其所有对应字段（包括导出和未导出的字段）深度相等时深度相等。

两个函数值仅在都为 nil 时深度相等，否则不深度相等。

两个接口值在其持有的具体值深度相等时深度相等。

两个映射值在满足以下所有条件时深度相等：它们都为 nil 或都不为 nil；长度相同；并且它们是同一个映射对象，或者其对应的键（使用 Go 的相等比较进行匹配）所映射的值深度相等。

两个指针值在使用 Go 的 == 运算符比较相等，或其指向的值深度相等时深度相等。

两个切片值在满足以下所有条件时深度相等：它们都为 nil 或都不为 nil；长度相同；并且它们指向同一个底层数组中的同一个起始元素（即 &x[0] == &y[0]），或者其长度范围内的对应元素深度相等。注意，非 nil 的空切片与 nil 切片（例如 []byte{} 和 []byte(nil)）不深度相等。

其他值——数值、布尔值、字符串和通道——在使用 Go 的 == 运算符比较相等时深度相等。

总体而言，DeepEqual 是对 Go 的 == 运算符进行递归放宽后的比较。但这种思路无法完全一致地实现。具体来说，一个值可能与自身不相等：它可能是函数类型（通常不可比较），也可能是浮点 NaN 值（在浮点比较中与自身不相等），还可能是包含此类值的数组、结构体或接口。另一方面，指针值始终与自身相等，即使它们指向或包含此类特殊值也是如此，因为使用 Go 的 == 运算符比较时它们相等；无论其内容是什么，这都是深度相等的充分条件。DeepEqual 的定义使同样的快捷判定也适用于切片和映射：如果 x 和 y 是同一个切片或同一个映射，无论其内容是什么，都深度相等。

DeepEqual 遍历数据值时可能遇到环。当 DeepEqual 第二次及以后比较之前已经比较过的两个指针值时，会将它们视为相等，而不再检查所指向的值。这保证了 DeepEqual 能够终止。

func TypeAssert 

func TypeAssert[T any](v Value) (T, bool)

TypeAssert 在语义上等价于：

v2, ok := v.Interface().(T)

注意，与上面的类型断言一样，此函数可能返回以下结果：

  • 当 v.Type() == reflect.TypeFor[T]() 时，ok == false。例如，T 和 v 都是接口类型且 v.IsNil() == true 时，v.Interface() 返回 nil 接口值，断言 .(T) 失败，ok 为 false。

  • 当 v.Type() != reflect.TypeFor[T]() 时，ok == true。例如，T 是接口类型，而 v 持有的值的具体类型实现了 T。

type SelectCase 1.1

SelectCase 描述 select 操作中的一个分支。分支的类别取决于通信方向 Dir。

如果 Dir 为 SelectDefault，该分支表示 default 分支。Chan 和 Send 都必须是零 Value。

如果 Dir 为 SelectSend，该分支表示发送操作。通常，Chan 的底层值必须是通道，而 Send 的底层值必须可赋值给该通道的元素类型。有一个特例：如果 Chan 是零 Value，则忽略此分支，同时忽略 Send 字段，此时 Send 可以是零 Value，也可以不是。

如果 Dir 为 SelectRecv，该分支表示接收操作。通常，Chan 的底层值必须是通道，Send 必须是零 Value。如果 Chan 是零 Value，则忽略此分支，但 Send 仍必须是零 Value。选中接收操作时，Select 会返回接收到的 Value。

type SelectCase struct {
    Dir  SelectDir // 分支方向
    Chan Value     // 使用的通道（用于发送或接收）
    Send Value     // 要发送的值（用于发送）
}

type Type

Type 表示一个 Go 类型。

并非所有方法都适用于所有类别的类型。每个方法的文档会注明其限制（如果有）。调用特定类别的方法之前，应先用 Kind 方法确定类型的类别。调用不适用于该类型类别的方法会在运行时触发 panic。

Type 值是可比较的，例如可使用 == 运算符比较，因此可以用作映射的键。两个 Type 值相等，当且仅当它们表示相同的类型。

type Type interface {

    // Align 返回此类型的值在内存中分配时的
    // 对齐要求，单位为字节。
    Align() int

    // FieldAlign 返回此类型的值作为结构体字段时的
    // 对齐要求，单位为字节。
    FieldAlign() int

    // Method 返回该类型的方法集中的第 i 个方法。
    // 如果 i 不在 [0, NumMethod()) 范围内，则触发 panic。
    //
    // 对于非接口类型 T 或 *T，返回的 Method 的 Type 和 Func
    // 字段描述一个以接收者为第一个实参的函数，
    // 且只能访问导出方法。
    //
    // 对于接口类型，返回的 Method 的 Type 字段给出
    // 不含接收者的方法签名，而 Func 字段为 nil。
    //
    // 方法按字典序排列。
    //
    // 调用此方法会强制链接器保留所有包中的所有导出方法。
    // 这可能增大可执行文件的体积，但不会影响执行时间。
    Method(int) Method

    // Methods 返回遍历该类型的方法集中每个方法的迭代器。此序列
    // 等价于对 [0, NumMethod()) 范围内的每个索引 i 依次调用 Method。
    Methods() iter.Seq[Method]

    // MethodByName 返回该类型的方法集中具有给定名称的方法，
    // 以及表示是否找到该方法的布尔值。
    //
    // 对于非接口类型 T 或 *T，返回的 Method 的 Type 和 Func
    // 字段描述一个以接收者为第一个实参的函数。
    //
    // 对于接口类型，返回的 Method 的 Type 字段给出
    // 不含接收者的方法签名，而 Func 字段为 nil。
    //
    // 调用此方法会使链接器保留所有包中具有该名称的方法。
    // 如果链接器无法确定名称，则会保留所有导出方法。
    // 这可能增大可执行文件的体积，但不会影响执行时间。
    MethodByName(string) (Method, bool)

    // NumMethod 返回可通过 Method 访问的方法数量。
    //
    // 对于非接口类型，它返回导出方法的数量。
    //
    // 对于接口类型，它返回导出和未导出方法的总数。
    NumMethod() int

    // 对于定义类型，Name 返回该类型在其包内的名称。
    // 对于其他（非定义）类型，它返回空字符串。
    Name() string

    // PkgPath 返回定义类型的包路径，即唯一标识其所属包的导入路径，
    // 例如 "encoding/base64"。
    // 如果类型是预声明类型（string、error），或者不是定义类型（*T、struct{}、
    // []int，或 A，其中 A 是非定义类型的别名），则包路径
    // 为空字符串。
    PkgPath() string

    // Size 返回存储给定类型的一个值所需的字节数，
    // 类似于 unsafe.Sizeof。
    Size() uintptr

    // String 返回该类型的字符串表示。
    // 字符串表示可能使用缩短的包名
    // （例如使用 base64 而非 "encoding/base64"），且不保证
    // 不同类型的表示唯一。要判断类型是否相同，
    // 应直接比较 Type 值。
    String() string

    // Kind 返回该类型的具体类别。
    Kind() Kind

    // Implements 报告该类型是否实现了接口类型 u。
    Implements(u Type) bool

    // AssignableTo 报告该类型的值是否可赋值给类型 u。
    AssignableTo(u Type) bool

    // ConvertibleTo 报告该类型的值是否可转换为类型 u。
    // 即使 ConvertibleTo 返回 true，转换仍可能触发 panic。
    // 例如，类型为 []T 的切片可转换为 *[N]T，
    // 但如果切片长度小于 N，转换就会触发 panic。

    FieldByName 及相关函数只要发现结构体字段的名称相同，就会认为它们的名称相等，即使这些名称来自不同包且未导出也是如此。这意味着，如果结构体类型 t 包含多个名为 x 的字段（从不同包嵌入），则 t.FieldByName("x") 的结果没有明确定义。FieldByName 可能返回其中一个名为 x 的字段，也可能报告没有找到字段。更多详情参见 https://golang.org/issue/4876。
