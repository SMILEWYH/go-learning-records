slog 包提供结构化日志功能。日志记录包含消息、严重级别，以及用键值对表示的各种其他属性。

本包定义了 Logger 类型，它提供多种方法（例如 Logger.Info 和 Logger.Error）来报告关注的事件。

每个 Logger 都关联一个 Handler。Logger 的输出方法根据方法参数创建 Record，然后将其传给 Handler，由 Handler 决定如何处理。可以通过包级函数（例如 Info 和 Error）访问默认 Logger，这些函数会调用相应的 Logger 方法。

一条日志记录由时间、级别、消息和一组键值对组成，其中键是字符串，值可以是任意类型。例如， 

slog.Info("hello", "count", 3)

会创建一条记录，其中包含调用时间、Info 级别、消息 "hello"，以及一个键为 "count"、值为 3 的键值对。

包级函数 Info 调用默认 Logger 的 Logger.Info 方法。除 Logger.Info 外，还有对应 Debug、Warn 和 Error 级别的方法。除了这些常用级别的便捷方法，还提供将级别作为参数的 Logger.Log 方法。上述每个方法都有对应的包级函数，使用默认日志记录器。

默认处理器将日志记录的消息、时间、级别和属性格式化为字符串，然后传给 log 包。 

2022/11/08 15:28:26 INFO hello count=3

若要更细致地控制输出格式，可以使用其他处理器创建日志记录器。以下语句通过 New 创建一个使用 TextHandler 的新日志记录器，将结构化记录以文本形式写入标准错误： 

logger := slog.New(slog.NewTextHandler(os.Stderr, nil))

TextHandler 的输出是一系列 key=value 键值对，便于机器无歧义地解析。以下语句： 

logger.Info("hello", "count", 3)

产生如下输出： 

time=2022-11-08T15:28:26.000-05:00 level=INFO msg=hello count=3

本包还提供 JSONHandler，其输出是按行分隔的 JSON： 

logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
logger.Info("hello", "count", 3)

产生如下输出： 

{"time":"2022-11-08T15:28:26.000000000-05:00","level":"INFO","msg":"hello","count":3}

TextHandler 和 JSONHandler 都可以通过 HandlerOptions 配置。配置选项包括设置最低级别（见下文“级别”）、显示日志调用所在的源文件和行号，以及在记录属性之前修改属性。

通过以下调用将日志记录器设为默认值： 

slog.SetDefault(logger)

这样，Info 等包级函数就会使用它。SetDefault 还会更新 log 包使用的默认日志记录器，因此使用 log.Printf 及相关函数的现有应用程序无需改写，就会将日志记录发送给该日志记录器的处理器。

许多日志调用共享某些属性。例如，你可能希望为服务器某个请求产生的所有日志事件都附带该请求的 URL 或跟踪标识符。可以通过 Logger.With 构建包含这些属性的新 Logger，无需在每次日志调用中重复提供属性： 

logger2 := logger.With("url", r.URL)

With 的参数与 Logger.Info 使用的键值对相同。结果是一个新 Logger，它使用与原来相同的处理器，但附加了额外属性，这些属性会出现在每次调用的输出中。

级别

Level 是表示日志事件重要程度或严重程度的整数。级别越高，事件越严重。本包为最常用的级别定义了常量，但任意 int 都可以用作级别。

应用程序可能只希望记录某个级别及以上的消息。一种常见配置是记录 Info 及以上级别的消息，在需要时才启用调试日志。可以通过设置 HandlerOptions.Level，配置内置处理器输出的最低级别。这通常在程序的 `main` 函数中完成。默认值为 LevelInfo。

将 HandlerOptions.Level 字段设为 Level 值，会在处理器整个生命周期中固定其最低级别。将其设为 LevelVar，则可以动态调整级别。LevelVar 保存一个 Level，支持多个 goroutine（轻量级协程）安全地读写。若要动态调整整个程序的日志级别，首先初始化一个全局 LevelVar： 

var programLevel = new(slog.LevelVar) // 默认为 Info

然后使用该 LevelVar 构建处理器，并将其设为默认值： 

h := slog.NewJSONHandler(os.Stderr, &slog.HandlerOptions{Level: programLevel})
slog.SetDefault(slog.New(h))

现在，程序只需一条语句就能更改日志级别： 

programLevel.Set(slog.LevelDebug)

分组

属性可以组织成组。每个组都有名称，用来限定其属性的名称。限定名称的显示方式取决于处理器。TextHandler 用点号分隔组名和属性名。JSONHandler 将每个组表示为独立的 JSON 对象，以组名作为键。

使用 Group 根据名称和一组键值对创建分组属性： 

slog.Group("request",
    "method", r.Method,
    "url", r.URL)

TextHandler 将此组显示为 

request.method=GET request.url=http://example.com

JSONHandler 将其显示为 

"request":{"method":"GET","url":"http://example.com"}

使用 Logger.WithGroup 为 Logger 的所有输出加上组名限定。对 Logger 调用 WithGroup 会生成一个新 Logger，使用与原来相同的 Handler，但其所有属性都会以该组名限定。

在大型系统中，各子系统可能使用相同的键，分组有助于避免属性键重复。为每个子系统传入带有独立组名的不同 Logger，使潜在的重复名称获得限定： 

logger := slog.Default().With("id", systemID)
parserLogger := logger.WithGroup("parser")
parseInput(input, parserLogger)

当 parseInput 通过 parserLogger 记录日志时，它的键会带有 "parser" 限定。因此，即使它使用常见键 "id"，日志行中的键也各不相同。

上下文

某些处理器可能希望附带调用处可用的 context.Context 中的信息。例如，启用跟踪时的当前 span 标识符。

Logger.Log 和 Logger.LogAttrs 方法都以 context 作为第一个参数，对应的包级函数也是如此。

虽然 Logger 的便捷方法（Info 等）及其对应的包级函数不接受 context，但以 "Context" 结尾的对应方法和函数接受。例如： 

slog.InfoContext(ctx, "message")

如果有可用的 context，建议将其传给输出方法。

属性与值

Attr 是一个键值对。Logger 的输出方法既接受 Attr，也接受交替出现的键和值。以下语句 

slog.Info("hello", slog.Int("count", 3))

与以下语句的行为相同： 

slog.Info("hello", "count", 3)

本包为 Attr 提供了便捷构造函数，例如用于常见类型的 Int、String 和 Bool，以及用于构造任意类型 Attr 的 Any 函数。

Attr 的值部分属于 Value 类型。与 [any] 一样，Value 可以保存任意 Go 值，但它能够在不分配内存的情况下表示常见值，包括所有数字和字符串。

要获得最高效的日志输出，请使用 Logger.LogAttrs。它与 Logger.Log 类似，但只接受 Attr，不接受交替的键和值；这样它也能避免分配内存。

以下调用 

logger.LogAttrs(ctx, slog.LevelInfo, "hello", slog.Int("count", 3))

是产生与以下调用相同输出的最高效方式： 

slog.InfoContext(ctx, "hello", "count", 3)

自定义类型的日志行为

如果某个类型实现了 LogValuer 接口，记录日志时就会使用其 LogValue 方法返回的 Value。可以借此控制该类型的值在日志中的呈现方式。例如，可以隐藏密码等机密信息，或将结构体字段组织到一个分组中。详情请参阅 LogValuer 下的示例。

LogValue 方法返回的 Value 本身可能又实现了 LogValuer。Value.Resolve 方法会谨慎处理这类情况，避免无限循环和无界递归。处理器作者及其他使用方可以优先使用 Value.Resolve，而不直接调用 LogValue。

封装输出方法

日志函数通过检查调用栈来确定应用程序中日志调用所在的文件名和行号。对于封装 slog 的函数，这可能产生错误的源码位置信息。例如，如果在 mylog.go 文件中定义以下函数： 

func Infof(logger *slog.Logger, format string, args ...any) {
    logger.Info(fmt.Sprintf(format, args...))
}

并在 main.go 中这样调用： 

Infof(slog.Default(), "hello, %s", "world")

那么 slog 会将源文件报告为 mylog.go，而不是 main.go。

正确的 Infof 实现应获取源码位置（pc），并将其传给 NewRecord。名为“wrapping”的包级示例中的 Infof 函数演示了具体做法。

处理记录

有时 Handler 需要先修改 Record，再将其传给其他 Handler 或后端。Record 同时包含简单的公开字段（例如 Time、Level、Message）和间接引用状态（例如属性）的隐藏字段。这意味着修改 Record 的简单副本（例如调用 Record.Add 或 Record.AddAttrs 添加属性）可能会对原记录产生意料之外的影响。在修改 Record 之前，应使用 Record.Clone 创建一个不与原记录共享状态的副本，或者使用 NewRecord 创建新记录，再通过 Record.Attrs 遍历旧属性来构建新记录的属性。

性能注意事项

如果对应用程序进行性能分析后发现日志记录耗费了大量时间，下面的建议可能有所帮助。

如果许多日志行具有共同属性，可以使用 Logger.With 创建带有该属性的 Logger。内置处理器只会在调用 Logger.With 时将该属性格式化一次。Handler 接口的设计允许这种优化，良好的 Handler 实现也应利用这一点。

日志调用的参数始终会求值，即使日志事件最终被丢弃也是如此。如果可能，应延后计算，直到该值确实需要记录时才执行。例如，考虑以下调用： 

slog.Info("starting request", "url", r.URL.String())  // 可能在不必要时计算 String

即使日志记录器丢弃 Info 级别事件，URL.String 方法也会被调用。可以改为直接传入 URL： 

slog.Info("starting request", "url", &r.URL) // 仅在需要时调用 URL.String

内置的 TextHandler 会调用其 String 方法，但只有启用了该日志事件才会调用。避免调用 String 还能保留底层值的结构。例如，JSONHandler 会将解析后 URL 的各部分输出为 JSON 对象。如果既想避免预先承担 String 调用的开销，又不希望处理器可能查看值的结构，可以将该值包装为隐藏其 Marshal 方法的 fmt.Stringer 实现。

还可以使用 LogValuer 接口，避免在未启用的日志调用中执行不必要的工作。假设需要记录一个计算成本较高的值： 

slog.Debug("frobbing", "value", computeExpensiveValue(arg))

即使未启用这条日志，computeExpensiveValue 仍会被调用。为避免这种情况，可以定义实现 LogValuer 的类型： 

type expensive struct { arg int }

func (e expensive) LogValue() slog.Value {
    return slog.AnyValue(computeExpensiveValue(e.arg))
}

然后在日志调用中使用该类型的值： 

slog.Debug("frobbing", "value", expensive{arg})

现在，只有启用这条日志时，才会调用 computeExpensiveValue。

内置处理器在调用 io.Writer.Write 之前会获取锁，确保每次完整写入且只写入一条 Record。虽然每条日志记录都有时间戳，但内置处理器不会按时间对写出的记录排序。自定义处理器需要自行负责加锁和排序。

type Handler 1.21

Handler 处理 Logger 产生的日志记录。

典型的处理器可能将日志记录打印到标准错误，写入文件或数据库，或者为其添加额外属性后传给另一个处理器。

Handler 的任意方法都可能与自身或其他方法并发调用。Handler 负责管理这种并发访问。

slog 包的使用者不应直接调用 Handler 方法，而应使用 Logger 的方法。

实现自定义处理器之前，请参阅 https://go.dev/s/slog-handler-guide。 

type Handler interface {
    // Enabled 报告处理器是否处理给定级别的记录。
    // 处理器忽略低于其级别阈值的记录。
    // 它在处理任何参数之前就会被调用，
    // 以便在应丢弃日志事件时节省工作。
    // 如果由 Logger 方法调用，第一个参数就是传给
    // 该方法的上下文；如果传入 nil，
    // 或该方法不接受上下文，则使用 context.Background()。
    // 传入上下文是为了让 Enabled 可以利用其中的值
    // 作出决定。
    Enabled(context.Context, Level) bool

    // Handle 处理 Record。
    // 只有 Enabled 返回 true 时才会调用它。
    // Context 参数的含义与 Enabled 相同。
    // 它的唯一用途是让 Handler 可以访问上下文中的值。
    // 取消上下文不应影响记录的处理。
    // （例如，调试与取消有关的问题时，
    // 可能仍然需要日志消息。）
    //
    // 产生输出的 Handle 方法应遵守以下规则：
    //   - 如果 r.Time 是零值时间，则忽略时间。
    //   - 如果 r.PC 为零，则忽略它。
    //   - 应解析 Attr 的值。
    //   - 如果 Attr 的键和值都是零值，则忽略该 Attr。
    //     可以通过 attr.Equal(Attr{}) 检查。
    //   - 如果组的键为空，则内联该组的 Attr。
    //   - 如果组没有 Attr（即使其键非空），
    //     也忽略该组。
    //
    // [Logger] 会丢弃 Handle 返回的所有错误。若要
    // 处理 Handler 的错误，请封装 Handle 方法。
    Handle(context.Context, Record) error

    // WithAttrs 返回新的 Handler，其属性包含
    // 接收者的属性和传入的属性。
    // Handler 拥有该切片，可以保留、修改或丢弃它。
    WithAttrs(attrs []Attr) Handler

    // WithGroup 返回新的 Handler，将给定分组追加到
    // 接收者已有的分组之后。
    // 后续所有属性的键，无论通过 With 添加还是来自
    // Record，都应以这些组名组成的序列进行限定。
    //
    // 具体限定方式由 Handler 决定，只要
    // 本 Handler 的属性键与组名序列不同的其他 Handler
    // 的属性键有所区别即可。
    //
    // Handler 应将 WithGroup 视为开启一个 Attr 分组，
    // 并在日志事件结束时关闭该分组。也就是说，
    //
    //     logger.WithGroup("s").LogAttrs(ctx, level, msg, slog.Int("a", 1), slog.Int("b", 2))
    //
    // 应表现得如同
    //
    //     logger.LogAttrs(ctx, level, msg, slog.Group("s", slog.Int("a", 1), slog.Int("b", 2)))
    //
    // 如果名称为空，WithGroup 返回接收者自身。
    WithGroup(name string) Handler
}

type HandlerOptions struct {

    // 如果 ReplaceAttr 返回零值 Attr，则丢弃该属性。

    //
    //     Int("a", 1), Group("g", Int("b", 2)), Int("c", 3)
    //

    //
    //     nil, Int("a", 1)
    //     []string{"g"}, Int("b", 2)
    //     nil, Int("c", 3)

    // 转换类型（例如，将 `time.Time` 替换为
    // 自 Unix 纪元以来的整数秒数）、清理个人信息，
    // 或从输出中移除属性。
    ReplaceAttr func(groups []string, a Attr) Attr

type Level 1.21

Level 表示日志事件的重要程度或严重程度。级别越高，事件越重要或越严重。 

type Level int

常用级别的名称。

级别对应的数字本来可以任意选择，但我们选择它们时满足了三个约束。任何系统都可以按需将其映射到其他编号方案。

首先，我们希望默认级别是 Info。由于 Level 是整数，所以 Info 对应 int 的默认值零。

其次，我们希望便于使用级别来指定日志记录器的详细程度。较大的级别表示更严重的事件，因此允许更小（或更负）级别事件的日志记录器会输出更详细的日志。日志详细程度因此可以看作事件严重程度的相反数，默认详细程度为 0，接受所有至少与 INFO 一样严重的事件。

第三，我们希望在各级别之间留出空间，以兼容在这些级别之间另设命名级别的方案。例如，Google Cloud Logging 在 Info 与 Warn 之间定义了 Notice 级别。由于这类中间级别并不多，数字之间无需留出很大的间隔。我们采用的间隔 4 与 OpenTelemetry 的映射相匹配。将 OpenTelemetry 中 DEBUG、INFO、WARN 和 ERROR 范围内的级别减去 9，就能转换到相应的 slog Level 范围。OpenTelemetry 还定义了 slog 中没有的 TRACE 和 FATAL 名称，但这些 OpenTelemetry 级别仍可使用适当的整数表示为 slog Level。 

const (
    LevelDebug Level = -4
    LevelInfo  Level = 0
    LevelWarn  Level = 4
    LevelError Level = 8
)

func SetLogLoggerLevel 1.22 

func SetLogLoggerLevel(level Level) (oldLevel Level)

SetLogLoggerLevel 控制与 log 包桥接时使用的级别。

在调用 SetDefault 之前，slog 的包级日志函数会调用默认 log.Logger。在此模式下，SetLogLoggerLevel 设置这些调用的最低级别。默认最低级别为 Info，因此 Debug 调用（以及更低级别的包级日志调用）不会传给 log.Logger。调用以下语句后： 

slog.SetLogLoggerLevel(slog.LevelDebug)

Debug 调用就会传给 log.Logger。

在调用 SetDefault 之后，对默认 log.Logger 的调用会传给 slog 默认处理器。在此模式下，SetLogLoggerLevel 设置这些调用记录日志时的级别。也就是说，调用以下语句后： 

slog.SetLogLoggerLevel(slog.LevelDebug)

调用 log.Printf 将产生 LevelDebug 级别的输出。

SetLogLoggerLevel 返回先前的值。

func (*TextHandler) Handle
					
					1.21
				

				
func (h *TextHandler) Handle(_ context.Context, r Record) error

				
Handle 将参数 Record 格式化为单行、由空格分隔的 key=value 项。

如果 Record 的时间为零值，则省略时间。否则，键为 "time"，值以毫秒精度的 RFC3339 格式输出。

级别的键为 "level"，值为调用 Level.String 的结果。

如果设置了 AddSource 选项，且源码信息可用，则键为 "source"，值按 FILE:LINE 格式输出。

消息的键为 "msg"。

若要修改这些属性或其他属性，或将其从输出中移除，请使用 HandlerOptions.ReplaceAttr。

如果值实现了 encoding.TextMarshaler，就写入 MarshalText 的结果。否则，写入 fmt.Sprint 的结果。

如果键或值包含 Unicode 空白字符、不可打印字符、'"' 或 '='，就使用 strconv.Quote 为其加上引号并转义。

分组内的键由点号分隔的各部分（键或组名）组成，不会执行进一步转义。因此，仅凭键 "a.b.c" 无法确定它表示两个组 "a" 和 "b" 加键 "c"，还是一个组 "a.b" 加键 "c"，或者一个组 "a" 加键 "b.c"。如果即使各部分中含有点号，也必须能够重建键的分组结构，请使用 HandlerOptions.ReplaceAttr 将相关信息编码进键中。

每次 Handle 调用都会产生一次对 io.Writer.Write 的调用，且这些调用串行执行。
