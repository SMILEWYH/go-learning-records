atomic 包提供底层的原子内存操作原语，可用于实现同步算法。

正确使用这些函数需要格外谨慎。除特殊的底层应用外，同步更适合通过通道或 sync 包提供的机制实现。应通过通信共享内存，而不是通过共享内存通信。

SwapT 系列函数实现的交换操作，原子地完成以下等价操作： 

old = *addr
*addr = new
return old

CompareAndSwapT 系列函数实现的比较并交换操作，原子地完成以下等价操作： 

if *addr == old {
	*addr = new
	return true
}
return false

AddT 系列函数实现的加法操作，原子地完成以下等价操作： 

*addr += delta
return *addr

LoadT 和 StoreT 系列函数分别实现加载和存储操作，原子地完成与“return *addr”和“*addr = val”等价的操作。

按照 Go 内存模型的术语，如果原子操作 B 观察到了原子操作 A 的效果，则 A“同步先于”B。此外，程序中执行的所有原子操作，其行为都如同按某个顺序一致的次序执行。这一定义提供的语义，与 C++ 的顺序一致原子操作及 Java 的 volatile 变量相同。

这里只支持少数几种整数大小：在许多体系结构上，对非机器字大小的整数执行原子操作效率低下，甚至不可行。例如，Bool 占用的空间可能大于内置 bool。

  • ☞ 
    在 386 上，64 位函数使用的指令在 Pentium MMX 之前的处理器上不可用。

    在非 Linux 的 ARM 平台上，64 位函数使用的指令在 ARMv6k 内核之前不可用。

    在 ARM、386 和 32 位 MIPS 上，使用底层原子函数对 64 位字进行原子访问时，调用方负责确保其按 64 位对齐（类型 Int64 和 Uint64 会自动对齐）。已分配的结构体、数组或切片中的第一个字，全局变量中的第一个字，以及局部变量中的第一个字，都可以保证按 64 位对齐；局部变量的保证来自于：在 32 位体系结构上，64 位原子操作的目标会逃逸到堆上。
