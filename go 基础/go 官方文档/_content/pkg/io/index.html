io 包为 I/O 原语提供基本接口。它主要将现有的 I/O 原语实现（例如 os 包中的实现）封装为通用的公共接口，以抽象其功能，同时提供一些相关原语。

这些接口和原语封装了具有不同实现的底层操作，因此除非另有说明，调用方不应假定它们能够安全地并行执行。

func Copy 

func Copy(dst Writer, src Reader) (written int64, err error)

Copy 将数据从 src 复制到 dst，直到 src 到达 EOF 或发生错误。它返回复制的字节数，以及复制过程中遇到的第一个错误（如果有）。

Copy 成功时返回 err == nil，而不是 err == EOF。因为 Copy 本来就会持续读取 src 直到 EOF，所以不会将 Read 返回的 EOF 作为错误上报。

如果 src 实现了 WriterTo，则调用 src.WriteTo(dst) 完成复制。否则，如果 dst 实现了 ReaderFrom，则调用 dst.ReadFrom(src) 完成复制。

func Pipe 

func Pipe() (*PipeReader, *PipeWriter)

Pipe 创建一个同步的内存管道。它可以连接接收 io.Reader 的代码和接收 io.Writer 的代码。

管道上的 Read 和 Write 一一匹配，但一次 Write 可能需要多次 Read 才能读完。也就是说，对 PipeWriter 的每次 Write 调用都会阻塞，直到 PipeReader 上的一次或多次 Read 将写入的数据全部读完。数据直接从 Write 复制到相应的 Read，不经过内部缓冲区。

Read 和 Write 可以相互并行调用，也可以与 Close 并行调用，都是安全的。多个 Read 或多个 Write 并行调用也安全：各次同类调用会依次串行执行。

func ReadAtLeast 

func ReadAtLeast(r Reader, buf []byte, min int) (n int, err error)

ReadAtLeast 从 r 向 buf 读取数据，直到至少读到 min 个字节。它返回复制的字节数；如果读取不足 min 个字节，还会返回错误。只有未读到任何字节时，错误才会是 EOF。如果读取了一些字节，但不足 min 个字节就遇到 EOF，ReadAtLeast 返回 ErrUnexpectedEOF。如果 min 大于 buf 的长度，ReadAtLeast 返回 ErrShortBuffer。返回时，当且仅当 err == nil，才有 n >= min。如果 r 在已读到至少 min 个字节时返回错误，该错误会被忽略。

type Reader

Reader 是封装基本 Read 方法的接口。

Read 向 p 中读取最多 len(p) 个字节，返回实际读取的字节数（0 <= n <= len(p)）以及遇到的错误。即使返回的 n < len(p)，Read 在调用过程中也可能将整个 p 用作临时存储空间。如果有部分数据可读，但不足 len(p) 个字节，Read 通常会返回已有数据，而不是等待更多数据。

如果 Read 在成功读取 n > 0 个字节后遇到错误或文件结束，它会返回已读取的字节数。错误可以与这些字节在同一次调用中返回，也可以在后续调用中返回，此时 n == 0。例如，当 Reader 在输入流末尾返回非零字节数时，err 可以是 EOF，也可以是 nil。下一次 Read 应返回 0, EOF。

调用方应始终先处理返回的 n > 0 个字节，再判断错误 err。这样既能正确处理读取部分字节后发生的 I/O 错误，也能正确处理上述两种允许的 EOF 返回方式。

如果 len(p) == 0，Read 应始终返回 n == 0。如果已知存在错误条件，例如 EOF，也可以返回非 nil 错误。

除 len(p) == 0 外，不建议 Read 的实现返回字节数零和 nil 错误。调用方应将 0, nil 理解为没有发生任何事情；特别是，它不表示 EOF。

实现不得保留 p。 

type Reader interface {
    Read(p []byte) (n int, err error)
}

type ReaderAt

ReaderAt 是封装基本 ReadAt 方法的接口。

ReadAt 从底层输入源的偏移量 off 处开始，向 p 读取 len(p) 个字节。它返回实际读取的字节数（0 <= n <= len(p)）以及遇到的错误。

当 ReadAt 返回 n < len(p) 时，会同时返回非 nil 错误，说明未能读取更多字节的原因。在这一点上，ReadAt 比 Read 更严格。

即使 ReadAt 返回 n < len(p)，也可能在调用过程中将整个 p 用作临时存储空间。如果有部分数据可读，但不足 len(p) 个字节，ReadAt 会阻塞，直到全部所需数据可读或发生错误。在这一点上，ReadAt 与 Read 不同。

如果 ReadAt 返回的 n = len(p) 个字节恰好位于输入源末尾，那么 err 可以是 EOF，也可以是 nil。

如果 ReadAt 从具有定位偏移量的输入源读取数据，它既不应影响底层定位偏移量，也不应受其影响。

调用方可以对同一输入源并行调用 ReadAt。

实现不得保留 p。 

type ReaderAt interface {
    ReadAt(p []byte, off int64) (n int, err error)
}

type Seeker

Seeker 是封装基本 Seek 方法的接口。

Seek 将下一次 Read 或 Write 的偏移量设置为 offset，其含义由 whence 决定：SeekStart 表示相对于文件开头，SeekCurrent 表示相对于当前偏移量，SeekEnd 表示相对于文件末尾（例如 offset = -2 表示文件的倒数第二个字节）。Seek 返回相对于文件开头的新偏移量，以及可能发生的错误。

定位到文件开头之前会报错。实现可以允许定位到任意正偏移量，但如果新偏移量超过底层对象的大小，后续 I/O 操作的行为取决于具体实现。 

type Seeker interface {
    Seek(offset int64, whence int) (int64, error)
}

type Writer

Writer 是封装基本 Write 方法的接口。

Write 将 p 中的 len(p) 个字节写入底层数据流。它返回从 p 写入的字节数（0 <= n <= len(p)），以及导致写入提前停止的错误。如果返回 n < len(p)，Write 必须同时返回非 nil 错误。Write 不得修改切片中的数据，即使只是临时修改也不允许。

实现不得保留 p。 

type Writer interface {
    Write(p []byte) (n int, err error)
}

Discard 是一个 Writer，对它的所有 Write 调用都会成功，但不会执行任何操作。 

var Discard Writer = discard{}

func MultiWriter 

func MultiWriter(writers ...Writer) Writer

MultiWriter 创建一个写入器，将每次写入的数据复制给所有给定的写入器，类似于 Unix 的 tee(1) 命令。

每次写入都会依次写给列表中的每个写入器。如果某个写入器返回错误，整个写入操作就会停止并返回该错误，不会继续写给后面的写入器。

type WriterAt

WriterAt 是封装基本 WriteAt 方法的接口。

WriteAt 将 p 中的 len(p) 个字节写入底层数据流的偏移量 off 处。它返回从 p 写入的字节数（0 <= n <= len(p)），以及导致写入提前停止的错误。如果返回 n < len(p)，WriteAt 必须同时返回非 nil 错误。

如果 WriteAt 向具有定位偏移量的目标写入数据，它既不应影响底层定位偏移量，也不应受其影响。

如果写入范围互不重叠，调用方可以对同一目标并行调用 WriteAt。

实现不得保留 p。 

type WriterAt interface {
    WriteAt(p []byte, off int64) (n int, err error)
}

type WriterTo

WriterTo 是封装 WriteTo 方法的接口。

WriteTo 向 w 写入数据，直到没有更多数据可写或发生错误。返回值 n 是写入的字节数。写入过程中遇到的任何错误也会被返回。

如果可用，Copy 函数会使用 WriterTo。 

type WriterTo interface {
    WriteTo(w Writer) (n int64, err error)
}
