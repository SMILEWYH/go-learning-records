template 包（html/template）实现了数据驱动的模板，用于生成能够防范代码注入的 HTML 输出。它提供与 text/template 相同的接口；只要输出是 HTML，就应使用本包替代 text/template。

这里的文档重点介绍本包的安全特性。有关如何编写模板本身的信息，请参阅 text/template 文档。

简介

本包封装了 text/template，因此可以使用同一套模板 API 来安全地解析和执行 HTML 模板。

tmpl, err := template.New("name").Parse(...)
// 此处省略错误检查
err = tmpl.Execute(out, data)

如果成功，tmpl 就具备了防止注入的安全性；否则，err 是 ErrorCode 文档中定义的错误。

HTML 模板将数据值视为需要编码的纯文本，从而可以安全地嵌入 HTML 文档。转义会根据上下文进行，因此模板动作可以出现在 JavaScript、CSS 和 URI 上下文中。

注释会从输出中移除，但通过 HTML、CSS 和 JS 类型传入相应上下文的注释除外。

本包的安全模型假定模板作者可信，而 Execute 的 data 参数不可信。下文会进一步说明。

例如：

import "text/template"
...
t, err := template.New("foo").Parse(`{{define "T"}}Hello, {{.}}!{{end}}`)
err = t.ExecuteTemplate(out, "T", "<script>alert('you have been pwned')</script>")

会产生：

Hello, <script>alert('you have been pwned')</script>!

但 html/template 中根据上下文进行的自动转义：

import "html/template"
...
t, err := template.New("foo").Parse(`{{define "T"}}Hello, {{.}}!{{end}}`)
err = t.ExecuteTemplate(out, "T", "<script>alert('you have been pwned')</script>")

会生成经过转义的安全 HTML 输出：

Hello, &lt;script&gt;alert(&#39;you have been pwned&#39;)&lt;/script&gt;!

上下文

本包理解 HTML、CSS、JavaScript 和 URI 的语法。它会为每个简单动作管道添加安全处理函数。例如，对于以下片段：

<a href="/search?q={{.}}">{{.}}</a>

解析时，会按需改写每个 {{.}}，加入转义函数。在此例中，它变为：

<a href="/search?q={{. | urlescaper | attrescaper}}">{{. | htmlescaper}}</a>

其中 urlescaper、attrescaper 和 htmlescaper 是内部转义函数的别名。

对于这些内部转义函数，如果动作管道求值为 nil 接口值，则按空字符串处理。

带命名空间和 data- 前缀的属性

带有命名空间的属性会按不带命名空间的属性处理。例如，给定以下片段：

<a my:href="{{.}}"></a>

解析时，该属性会被当作普通的“href”处理。因此模板会变为：

<a my:href="{{. | urlescaper | attrescaper}}"></a>

与带命名空间的属性类似，带“data-”前缀的属性会按不带该前缀的属性处理。因此，对于：

<a data-href="{{.}}"></a>

解析时会变为：

<a data-href="{{. | urlescaper | attrescaper}}"></a>

如果属性既有命名空间，又有“data-”前缀，那么确定上下文时只移除命名空间。例如：

<a my:data-href="{{.}}"></a>

处理时，“my:data-href”会被视为“data-href”，而不是同时忽略“data-”前缀后得到的“href”。因此，解析时只会变为：

<a my:data-href="{{. | attrescaper}}"></a>

有一个特殊情况：命名空间为“xmlns”的属性始终被视为包含 URL。例如，给定以下片段：

<a xmlns:title="{{.}}"></a>
<a xmlns:href="{{.}}"></a>
<a xmlns:onclick="{{.}}"></a>

解析时会变为：

<a xmlns:title="{{. | urlescaper | attrescaper}}"></a>
<a xmlns:href="{{. | urlescaper | attrescaper}}"></a>
<a xmlns:onclick="{{. | urlescaper | attrescaper}}"></a>

进一步说明

首次阅读时可以跳过本包概览的其余部分；它们介绍了理解转义上下文和错误消息所需的细节。大多数使用者无需掌握这些细节。

上下文

假设 {{.}} 的值为 `O'Reilly: How are <i>you</i>?`，下表展示 {{.}} 在左侧各种上下文中使用时得到的结果。

上下文                           {{.}} 处理后的结果
{{.}}                            O'Reilly: How are &lt;i&gt;you&lt;/i&gt;?
<a title='{{.}}'>                O&#39;Reilly: How are you?
<a href="/{{.}}">                O&#39;Reilly: How are %3ci%3eyou%3c/i%3e?
<a href="?q={{.}}">              O&#39;Reilly%3a%20How%20are%3ci%3e...%3f
<a onx='f("{{.}}")'>             O\x27Reilly: How are \x3ci\x3eyou...?
<a onx='f({{.}})'>               "O\x27Reilly: How are \x3ci\x3eyou...?"
<a onx='pattern = /{{.}}/;'>     O\x27Reilly: How are \x3ci\x3eyou...\x3f

如果用于不安全的上下文，其值可能被过滤掉：

上下文                           {{.}} 处理后的结果
<a href="{{.}}">                 #ZgotmplZ

这是因为“O'Reilly:”不是像“http:”那样受允许的协议。

如果 {{.}} 是无害的单词 `left`，它就能用于更多位置：

上下文                               {{.}} 处理后的结果
{{.}}                                left
<a title='{{.}}'>                    left
<a href='{{.}}'>                     left
<a href='/{{.}}'>                    left
<a href='?dir={{.}}'>                left
<a style="border-{{.}}: 4px">        left
<a style="align: {{.}}">             left
<a style="background: '{{.}}'>       left
<a style="background: url('{{.}}')>  left
<style>p.{{.}} {color:red}</style>   left

JavaScript 上下文中可以使用非字符串值。如果 {{.}} 为：

struct{A,B string}{ "foo", "bar" }

将其用于会自动转义的模板：

<script>var pair = {{.}};</script>

则模板输出为：

<script>var pair = {"A": "foo", "B": "bar"};</script>

非字符串内容如何序列化以嵌入 JavaScript 上下文，请参阅 json 包。

具有特定类型的字符串

本包默认假定所有管道都生成纯文本字符串。它会为管道加入必要的转义阶段，以便将该纯文本字符串正确且安全地嵌入相应上下文。

当数据值并非纯文本时，可以通过类型标记，确保它不会被过度转义。

content.go 中的 HTML、JS、URL 等类型可以承载无需转义的安全内容。

对于模板：

Hello, {{.}}!

可以这样调用：

tmpl.Execute(out, template.HTML(`<b>World</b>`))

从而生成：

Hello, <b>World</b>!

而如果 {{.}} 是普通字符串，则会生成：

Hello, &lt;b&gt;World&lt;b&gt;!

以上是将 {{.}} 作为普通字符串时产生的结果。

安全模型

https://web.archive.org/web/20160501113828/http://js-quasis-libraries-and-repl.googlecode.com/svn/trunk/safetemplate.html#problem_definition 定义了本包所使用的“安全”一词的含义。

本包假定模板作者可信，而 Execute 的 data 参数不可信，并力求在面对不可信数据时保持以下性质：

结构保持性质：“……当模板作者使用安全的模板语言编写 HTML 标签时，无论不可信数据的值是什么，浏览器都会将输出的相应部分解释为标签；对于属性边界以及 JS、CSS 字符串边界等其他结构，同样如此。”

代码效果性质：“……将模板输出插入页面后，应当只有模板作者指定的代码会运行，而且模板作者指定的所有代码都应运行。”

最小意外性质：“熟悉 HTML、CSS 和 JavaScript，并且知道会发生上下文自动转义的开发者（或代码审查者），应当能够在看到 {{.}} 时正确推断会进行哪些安全处理。”

以前，ECMAScript 6 模板字面量默认禁用，需要通过环境变量 GODEBUG=jstmpllitinterp=1 启用。现在默认支持模板字面量，设置 jstmpllitinterp 不再产生影响。

type CSS

CSS 封装已知安全、且符合以下任意一种语法产生式的内容：

  1. CSS3 样式表产生式，例如 `p { color: purple }`。
  2. CSS3 规则产生式，例如 `a[href=~"https:"].foo#bar`。
  3. CSS3 声明产生式，例如 `color: red; margin: 2px`。
  4. CSS3 值产生式，例如 `rgba(0, 0, 255, 127)`。

参见 https://www.w3.org/TR/css3-syntax/#parsing 和 https://web.archive.org/web/20090211114933/http://w3.org/TR/css3-syntax#style。

使用此类型存在安全风险：封装的内容应来自可信来源，因为它会原样写入模板输出。

type ErrorCode

ErrorCode 是某一类错误的代码。

type ErrorCode int

我们为模板转义过程中出现的每种错误都定义了错误代码，但经过转义的模板在运行时仍可能失败。

输出：“ZgotmplZ” 示例：

<img src="{{.X}}">
其中 {{.X}} 的值为 `javascript:...`

说明：

“ZgotmplZ”是一个特殊值，表示运行时有不安全内容进入了
CSS 或 URL 上下文。此示例的输出为：
  <img src="#ZgotmplZ">
如果数据来自可信来源，可以使用相应的内容类型使其免于
过滤：URL(`javascript:...`)。

const (
    // OK 表示没有错误。
    OK ErrorCode = iota

    // ErrAmbigContext：“……出现在 URL 中含义不明确的上下文中”
    // 示例：
    //   <a href="
    //      {{if .C}}
    //        /path/
    //      {{else}}
    //        /search?q=
    //      {{end}}
    //      {{.X}}
    //   ">
    // 说明：
    //   {{.X}} 所处的 URL 上下文有歧义，因为根据 {{.C}} 的值，
    //   它可能是 URL 后缀，也可能是查询参数。
    //   将 {{.X}} 移到条件分支内部即可消除歧义：
    //   <a href="{{if .C}}/path/{{.X}}{{else}}/search?q={{.X}}">
    ErrAmbigContext

    // ErrBadHTML：“预期为空格、属性名或标签结束，但实际为……”、
    //   “……出现在未加引号的属性中”、“……出现在属性名中”
    // 示例：
    //   <a href = /search?q=foo>
    //   <href=foo>
    //   <form na<e=...>
    //   <option selected<
    // 说明：
    //   这通常是 HTML 元素中的拼写错误造成的；不过，某些 rune
    //   在标签名、属性名和不带引号的属性值中本来就不允许使用，
    //   因为它们可能引发解析歧义。
    //   最稳妥的做法是给所有属性值加上引号。
    ErrBadHTML

    // ErrBranchEnd：“{{if}} 的各分支结束于不同的上下文”
    // 示例：
    //   {{if .C}}<a href="{{end}}{{.X}}
    //   <script {{with .T}}type="{{.}}"{{end}}>
    // 说明：
    //   html/template 包会静态检查经过
    //   {{if}}、{{range}} 或 {{with}} 的每条路径，以转义后续管道。
    //   第一个示例有歧义，因为 {{.X}} 可能是 HTML 文本节点，
    //   也可能是 HTML 属性中的 URL 前缀。{{.X}} 的上下文
    //   决定如何对它进行转义，但该上下文取决于
    //   静态分析时无法得知的 {{.C}} 的运行时值。
    //   第二个示例有歧义，因为 script 的 type 属性
    //   可能改变脚本内容所需的转义方式。
    //
    //   问题通常出在缺少引号或尖括号之类的地方，
    //   也可以通过重构，将两种上下文放入
    //   if、range 或 with 的不同分支来避免。如果问题
    //   出现在遍历一个本不应为空的集合的 {{range}} 中，
    //   添加一个占位的 {{else}} 分支可能有帮助。
    ErrBranchEnd

    // ErrEndContext：“……结束于非文本上下文：……”
    // 示例：
    //   <div
    //   <div title="no close quote>
    //   <script>f()
    // 说明：
    //   执行模板后应当生成 HTML 的 DocumentFragment。
    //   模板结束时如果没有闭合标签，就会触发此错误。
    //   不应在 HTML 上下文中使用的模板，或者
    //   生成不完整片段的模板，都不应直接执行。
    //
    //   {{define "main"}} <script>{{template "helper"}}</script> {{end}}
    //   {{define "helper"}} document.write(' <div title=" ') {{end}}
    //
    //   “helper”不会生成有效的文档片段，因此
    //   不应直接执行。
    ErrEndContext

    // ErrNoSuchTemplate：“不存在这样的模板……”
    // 示例：
    //   {{define "main"}}<div {{template "attrs"}}>{{end}}
    //   {{define "attrs"}}href="{{.URL}}"{{end}}
    // 说明：
    //   html/template 包会分析模板调用，以计算
    //   上下文。
    //   这里，从“main”调用“attrs”时，后者的 {{.URL}} 必须按 URL 处理；
    //   但如果解析“main”时尚未定义“attrs”，
    //   就会得到此错误。
    ErrNoSuchTemplate

    // ErrOutputContext：“无法计算模板……的输出上下文”
    // 示例：
    //   {{define "t"}}{{if .T}}{{template "t" .T}}{{end}}{{.H}}",{{end}}
    // 说明：
    //   递归模板的结束上下文与其开始上下文
    //   不同，因此无法可靠地计算输出上下文。
    //   请检查该命名模板中是否存在拼写错误。
    //   如果不应在指定的起始上下文调用该模板，
    //   请查找是否在意外的上下文中调用了它。
    //   也可以考虑将递归模板重构为非递归形式。
    ErrOutputContext

    // ErrPartialCharset：“……中的 JS 正则表达式字符集未完成”
    // 示例：
    //     <script>var pattern = /foo[{{.Chars}}]/</script>
    // 说明：
    //   html/template 包不支持在正则表达式
    //   字面量的字符集中进行插值。
    ErrPartialCharset

    // ErrPartialEscape：“……中的转义序列未完成”
    // 示例：
    //   <script>alert("\{{.X}}")</script>
    // 说明：
    //   html/template 包不支持紧跟在
    //   反斜杠后面的模板动作。
    //   这通常是错误用法，而且存在更合适的解决方案；
    //   例如：
    //     <script>alert("{{.X}}")</script>
    //   就可以正常工作。如果 {{.X}} 是“xA0”这样的
    //   部分转义序列，应将整个序列标记为安全内容：JSStr(`\xA0`)
    ErrPartialEscape

    // ErrRangeLoopReentry：“重新进入 range 循环时：……”
    // 示例：
    //   <script>var x = [{{range .}}'{{.}},{{end}}]</script>
    // 说明：
    //   如果 range 的某次迭代结束时所处的上下文
    //   与先前迭代不同，就无法确定单一的上下文。
    //   此示例中缺少一个引号，因此无法确定
    //   {{.}} 应当位于 JS 字符串内，还是处于 JS 值
    //   上下文中。第二次迭代会产生类似这样的结果：
    //
    //     <script>var x = ['firstValue,'secondValue]</script>
    ErrRangeLoopReentry

    // ErrSlashAmbig：“/”可能是除法运算符，也可能是正则表达式的开头。
    // 示例：
    //   <script>
    //     {{if .C}}var x = 1{{end}}
    //     /-{{.N}}/i.test(x) ? doThis : doThat();
    //   </script>
    // 说明：
    //   上面的示例可能生成 `var x = 1/-2/i.test(s)...`，
    //   其中第一个“/”是数学除法运算符；也可能
    //   生成 `/-2/i.test(s)`，其中第一个“/”是
    //   正则表达式字面量的开头。
    //   请检查分支内部是否缺少分号，也可以添加
    //   括号来明确希望采用的解释方式。
    ErrSlashAmbig

    // ErrPredefinedEscaper：“模板中不允许使用预定义转义器……”
    // 示例：
    //   <div class={{. | html}}>Hello<div>
    // 说明：
    //   html/template 包已经会根据上下文转义所有管道，
    //   生成能够防范代码注入的 HTML 输出。使用预定义的
    //   “html”或“urlquery”转义器手动转义管道输出
    //   是多余的，而且在 Go 1.8 及更早版本中，可能影响
    //   转义后管道输出的正确性或安全性。
    //
    //   大多数情况下（包括给出的示例），只需
    //   从管道中移除预定义转义器，让上下文自动转义器
    //   处理管道的转义，即可解决此错误。在其他
    //   情况下，预定义转义器位于管道中间，
    //   而后续命令要求输入已经转义，例如：
    //     {{.X | html | makeALink}}
    //   其中 makeALink 执行：
    //     return `<a href="`+input+`">link</a>`
    //   此时应考虑重构外围模板，让它使用
    //   上下文自动转义器，即：
    //     <a href="{{.X}}">link</a>
    //
    //   为便于迁移到 Go 1.9 及更高版本，仍允许
    //   “html”和“urlquery”作为管道中的最后一个命令。但是，
    //   如果管道位于不带引号的属性值上下文中，就不允许
    //   使用“html”。新模板应完全避免使用“html”和“urlquery”。
    ErrPredefinedEscaper

    // ErrJSTemplate：“……出现在 JS 模板字面量中”
    // 示例：
    //     <script>var tmpl = `{{.Interp}}`</script>
    // 说明：
    //   html/template 包不支持在 JS 模板
    //   字面量内部使用动作。
    //
    // 已弃用：现在 JS 模板字面量中出现动作时，
    // 不再返回 ErrJSTemplate。JS 模板字面量中的动作
    // 现在会按预期进行转义。
    ErrJSTemplate
)

type HTML

type JS

JS 封装已知安全的 EcmaScript5 表达式，例如 `(x + y * z())`。模板作者有责任确保带类型标记的表达式不会破坏预期的运算优先级，也不会产生语句／表达式歧义。例如，传入“{ foo: bar() }\n['foo']()”这样的表达式时，它既是合法的表达式，也是合法但含义截然不同的程序。

使用此类型存在安全风险：封装的内容应来自可信来源，因为它会原样写入模板输出。

使用 JS 嵌入合法但不可信的 JSON 是不安全的。安全的替代方案是先用 json.Unmarshal 解析 JSON，再将得到的对象传入模板；在 JavaScript 上下文中输出时，它会转换为经过安全处理的 JSON。

type JS string

type JSStr

JSStr 封装一段字符序列，用于嵌入 JavaScript 表达式的引号之间。该字符串必须匹配一系列 StringCharacters：

StringCharacter :: SourceCharacter but not `\` or LineTerminator
                 | EscapeSequence

注意，不允许使用 LineContinuations（续行）。JSStr("foo\\nbar") 可以使用，但 JSStr("foo\\\nbar") 不可以。

使用此类型存在安全风险：封装的内容应来自可信来源，因为它会原样写入模板输出。

type JSStr string

func ParseFiles 

func ParseFiles(filenames ...string) (*Template, error)

ParseFiles 创建一个新的 Template，并从指定文件中解析模板定义。返回的模板使用第一个文件的基本名称（不含目录）及解析后的内容。必须提供至少一个文件。如果发生错误，解析停止，返回的 *Template 为 nil。

解析不同目录下的多个同名文件时，以最后指定的文件为准。例如，ParseFiles("a/foo", "b/foo") 会将“b/foo”存为名为“foo”的模板，而“a/foo”则不可用。

func ParseGlob 

func ParseGlob(pattern string) (*Template, error)

ParseGlob 创建一个新的 Template，并从模式匹配到的文件中解析模板定义。文件按 filepath.Match 的语义匹配，且模式必须匹配至少一个文件。返回的模板使用模式匹配到的第一个文件的基本名称（不含目录）及解析后的内容。ParseGlob 等价于用模式匹配到的文件列表调用 ParseFiles。

解析不同目录下的多个同名文件时，以最后指定的文件为准。

func (*Template) Clone 

func (t *Template) Clone() (*Template, error)

Clone 返回模板及其所有关联模板的副本。底层实际表示并不会复制，但会复制关联模板的命名空间，因此在副本上进一步调用 Template.Parse 时，新模板只会添加到副本，不会添加到原模板。可以使用 Template.Clone 预先准备公共模板，再在创建副本后加入其他模板的不同定义，从而组合出不同变体。

func (*Template) Execute 

func (t *Template) Execute(wr io.Writer, data any) error

Execute 将已解析的模板应用于指定数据对象，并将输出写入 wr。如果执行模板或写入输出时发生错误，则停止执行，但可能已经向输出写入器写入部分结果。同一个模板可以安全地并行执行，不过如果并行执行共享一个 Writer，输出可能交错。

func (*Template) ExecuteTemplate 

func (t *Template) ExecuteTemplate(wr io.Writer, name string, data any) error

ExecuteTemplate 将与 t 关联、具有给定名称的模板应用于指定数据对象，并将输出写入 wr。如果执行模板或写入输出时发生错误，则停止执行，但可能已经向输出写入器写入部分结果。同一个模板可以安全地并行执行，不过如果并行执行共享一个 Writer，输出可能交错。

func (*Template) Funcs 

func (t *Template) Funcs(funcMap FuncMap) *Template

Funcs 将参数映射中的元素添加到模板的函数映射。模板中使用的任何函数，都必须在解析模板之前添加。Funcs 可以多次调用，包括在解析之后（例如 Template.Clone 之后）调用，以替换同名函数；模板执行时会使用替换后的函数。如果映射中的某个值不是具有合适返回类型的函数，则触发 panic。返回值为模板本身，因此支持链式调用。

func (*Template) New 

func (t *Template) New(name string) *Template

New 分配一个新的 HTML 模板，将它与当前模板关联，并使用相同的分隔符。这种关联具有传递性，使一个模板可以通过 {{template}} 动作调用另一个模板。

func (*Template) Option 1.5 

func (t *Template) Option(opt ...string) *Template

Option 设置模板选项。选项使用字符串描述，可以是简单字符串，也可以是“key=value”。选项字符串中最多只能出现一个等号。如果选项无法识别或因其他原因无效，Option 会触发 panic。

已知选项：

missingkey：控制模板执行期间使用不存在的键索引映射时的行为。

"missingkey=default" 或 "missingkey=invalid"
	默认行为：不做处理，继续执行。
	如果打印该索引操作的结果，会得到字符串
	"<no value>"。
"missingkey=zero"
	该操作返回映射元素类型的零值。
"missingkey=error"
	立即停止执行，并返回错误。

func (*Template) Parse 

func (t *Template) Parse(text string) (*Template, error)

Parse 将 text 解析为 t 的模板体。text 中的命名模板定义（{{define ...}} 或 {{block ...}} 语句）会定义与 t 关联的其他模板，并从 t 自身的定义中移除。

首次对 t 或其任意关联模板调用 Template.Execute 之前，可以通过连续调用 Parse 来重新定义模板。仅包含空白和注释的模板体视为空，不会替换已有模板的主体。因此，可以使用 Parse 添加新的命名模板定义，而不覆盖主模板体。
