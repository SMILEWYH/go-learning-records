textproto 包为 HTTP、NNTP 和 SMTP 这一类基于文本的请求/响应协议提供通用支持。

本包对头部键和值强制采用 RFC 9112 定义的 HTTP/1.1 字符集。

本包提供：

Error，表示服务器返回的数字错误响应。

Pipeline，管理客户端中流水线式的请求和响应。

Reader，读取数字响应码行、key: value 形式的头部、后续行以空白开头的折行文本，以及由单独一行的点结束的完整文本块。

Writer，写入点编码的文本块。

Conn，将 Reader、Writer 和 Pipeline 便捷地封装在一起，用于单个网络连接。

func CanonicalMIMEHeaderKey 

func CanonicalMIMEHeaderKey(s string) string

CanonicalMIMEHeaderKey 返回 MIME 头部键 s 的规范形式。规范化会将首字母以及连字符后的字母转为大写，其余字母转为小写。例如，“accept-encoding”的规范形式为“Accept-Encoding”。MIME 头部键被假定为仅包含 ASCII 字符。如果 s 包含空格或 RFC 9112 定义的无效头部字段字节，则原样返回。

func (*Conn) Cmd 

func (c *Conn) Cmd(format string, args ...any) (id uint, err error)

Cmd 是一个便捷方法，在流水线中等待轮到自己后发送命令。命令文本由 format 和 args 格式化后追加 \r\n 得到。Cmd 返回该命令的 ID，供 StartResponse 和 EndResponse 使用。

例如，客户端可以通过以下代码执行返回点编码正文的 HELP 命令： 

id, err := c.Cmd("HELP")
if err != nil {
	return nil, err
}

c.StartResponse(id)
defer c.EndResponse(id)

if _, _, err = c.ReadCodeLine(110); err != nil {
	return nil, err
}
text, err := c.ReadDotBytes()
if err != nil {
	return nil, err
}
return c.ReadCodeLine(250)

type Pipeline

Pipeline 管理按顺序进行的流水线式请求/响应序列。

使用 Pipeline p 管理一个连接上的多个客户端时，每个客户端应执行： 

id := p.Next()	// 领取一个编号

p.StartRequest(id)	// 等待轮到发送请求
«send request»
p.EndRequest(id)	// 通知 Pipeline 请求已发送

p.StartResponse(id)	// 等待轮到读取响应
«read response»
p.EndResponse(id)	// 通知 Pipeline 响应已读取

流水线式服务器可以使用相同的调用，确保并行计算得到的响应按正确顺序写入。

func NewReader 

func NewReader(r *bufio.Reader) *Reader

NewReader 返回一个从 r 读取数据的新 Reader。

为避免拒绝服务攻击，提供的 bufio.Reader 应从 io.LimitReader 或类似的 Reader 读取，以限制响应大小。

func (*Reader) DotReader 

func (r *Reader) DotReader() io.Reader

DotReader 返回一个新的 Reader，其 Read 操作返回从 r 读取的点编码块解码后的文本。返回的 Reader 仅在下一次调用 r 的某个方法之前有效。

点编码是 SMTP 等文本协议中常见的数据块分帧方式。数据由一系列行组成，每行以“\r\n”结束。整个序列以仅包含一个点的行结束：“.\r\n”。以点开头的行会额外添加一个点进行转义，避免被误认为序列结束。

Reader 的 Read 方法返回的解码结果会将行尾“\r\n”改为更简单的“\n”，移除开头用于转义的点（如果存在），并在消耗并丢弃序列结束行后，以错误 io.EOF 结束读取。

func (*Reader) ReadCodeLine 

func (r *Reader) ReadCodeLine(expectCode int) (code int, message string, err error)

ReadCodeLine 读取如下形式的响应码行： 

code message

其中 code 是三位状态码，message 为该行剩余内容。例如： 

220 plan9.bell-labs.com ESMTP

如果状态码前缀与 expectCode 中的数字不匹配，ReadCodeLine 返回时会将 err 设为 &Error{code, message}。例如，expectCode 为 31 时，如果状态码不在 [310,319] 范围内，则返回错误。

如果响应为多行，ReadCodeLine 返回错误。

expectCode <= 0 时，禁用状态码检查。

func (*Reader) ReadContinuedLine 

func (r *Reader) ReadContinuedLine() (string, error)

ReadContinuedLine 从 r 读取可能含有续行的逻辑行，并去除最后的尾随 ASCII 空白。首行之后的行如果以空格或制表符开头，则视为续行。返回的数据中，续行与上一行之间仅以一个空格分隔：换行符和开头的空白会被移除。

例如，考虑以下输入： 

Line 1
  continued...
Line 2

第一次调用 ReadContinuedLine 返回“Line 1 continued...”，第二次返回“Line 2”。

空行永远不会续接。

func (*Reader) ReadMIMEHeader 

func (r *Reader) ReadMIMEHeader() (MIMEHeader, error)

ReadMIMEHeader 从 r 读取 MIME 风格的头部。头部由一系列可能带续行的 Key: Value 行组成，并以空行结束。返回的映射 m 将 CanonicalMIMEHeaderKey(key) 映射到一系列值，其顺序与在输入中出现的顺序相同。

例如，考虑以下输入： 

My-Key: Value 1
Long-Key: Even
       Longer Value
My-Key: Value 2

对于上述输入，ReadMIMEHeader 返回的映射为： 

map[string][]string{
	"My-Key": {"Value 1", "Value 2"},
	"Long-Key": {"Even Longer Value"},
}

func (*Reader) ReadResponse 

func (r *Reader) ReadResponse(expectCode int) (code int, message string, err error)

ReadResponse 读取如下形式的多行响应： 

code-message line 1
code-message line 2
...
code message line n

其中 code 是三位状态码。首行以该状态码和一个连字符开头。响应以同一状态码后接空格的行结束。message 中各行以换行符（\n）分隔。

关于另一种可接受的响应形式，详见 RFC 959 第 36 页（https://www.ietf.org/rfc/rfc959.txt）： 

code-message line 1
message line 2
...
code message line n

如果状态码前缀与 expectCode 中的数字不匹配，ReadResponse 返回时会将 err 设为 &Error{code, message}。例如，expectCode 为 31 时，如果状态码不在 [310,319] 范围内，则返回错误。

expectCode <= 0 时，禁用状态码检查。
