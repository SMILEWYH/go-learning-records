rpc 包允许通过网络或其他 I/O 连接访问对象的导出方法。

net/rpc 包已冻结，不再接受新功能。

服务器注册一个对象后，该对象就以其类型名作为服务名称对外可见。注册后，对象的导出方法可以被远程访问。服务器可以注册多个不同类型的对象（服务），但注册同一类型的多个对象会产生错误。

只有满足以下条件的方法才可供远程访问；其他方法会被忽略：

  • 方法所属的类型是导出的。
  • 方法是导出的。
  • 方法有两个参数，且两个参数的类型都是导出的类型（或内置类型）。
  • 方法的第二个参数是指针。
  • 方法的返回类型为 error。

实际上，方法的形式必须类似于： 

func (t *T) MethodName(argType T1, replyType *T2) error

其中 T1 和 T2 必须能够由 encoding/gob 序列化。即使使用其他编解码器，这些要求仍然适用。（将来可能会为自定义编解码器放宽这些要求。）

方法的第一个参数表示调用者提供的参数；第二个参数表示要返回给调用者的结果。方法的返回值如果非 nil，会以字符串形式传回，客户端看到的错误如同由 errors.New 创建。如果返回错误，则不会将 reply 参数发送回客户端。

服务器可以通过调用 ServeConn 处理单个连接上的请求。更常见的方式是创建网络监听器并调用 Accept；对于 HTTP 监听器，则调用 HandleHTTP 和 http.Serve。

要使用该服务，客户端先建立连接，再对连接调用 NewClient。便捷函数 Dial（DialHTTP）为原始网络连接（HTTP 连接）完成这两个步骤。得到的 Client 对象具有 Call 和 Go 两个方法，用于指定要调用的服务和方法、包含参数的指针，以及接收结果的指针。

Call 方法等待远程调用完成；Go 方法则异步发起调用，并通过 Call 结构的 Done 通道通知调用完成。

除非显式配置其他编解码器，否则使用 encoding/gob 包传输数据。

以下是一个简单示例。服务器希望导出一个 Arith 类型的对象： 

package server

import "errors"

type Args struct {
	A, B int
}

type Quotient struct {
	Quo, Rem int
}

type Arith int

func (t *Arith) Multiply(args *Args, reply *int) error {
	*reply = args.A * args.B
	return nil
}

func (t *Arith) Divide(args *Args, quo *Quotient) error {
	if args.B == 0 {
		return errors.New("divide by zero")
	}
	quo.Quo = args.A / args.B
	quo.Rem = args.A % args.B
	return nil
}

服务器调用以下代码（用于 HTTP 服务）： 

arith := new(Arith)
rpc.Register(arith)
rpc.HandleHTTP()
l, err := net.Listen("tcp", ":1234")
if err != nil {
	log.Fatal("listen error:", err)
}
go http.Serve(l, nil)

此时，客户端可以看到名为“Arith”的服务，以及“Arith.Multiply”和“Arith.Divide”方法。要调用其中一个方法，客户端首先连接服务器： 

client, err := rpc.DialHTTP("tcp", serverAddress + ":1234")
if err != nil {
	log.Fatal("dialing:", err)
}

然后就可以进行远程调用： 

// 同步调用
args := &server.Args{7,8}
var reply int
err = client.Call("Arith.Multiply", args, &reply)
if err != nil {
	log.Fatal("arith error:", err)
}
fmt.Printf("Arith: %d*%d=%d", args.A, args.B, reply)

或者： 

// 异步调用
quotient := new(Quotient)
divCall := client.Go("Arith.Divide", args, quotient, nil)
replyCall := <-divCall.Done	// 将等于 divCall
// 检查错误、打印等。

服务器实现通常会为客户端提供一个简单且类型安全的包装。

type Call

Call 表示一个进行中的 RPC 调用。 

type Call struct {
    ServiceMethod string     // 要调用的服务和方法的名称。
    Args          any        // 函数参数（*struct）。
    Reply         any        // 函数的回复（*struct）。
    Error         error      // 完成后的错误状态。
    Done          chan *Call // Go 完成时接收 *Call。
}

type Client

Client 表示一个 RPC 客户端。单个 Client 可以关联多个尚未完成的 Call，也可以由多个 goroutine 同时使用。 

type Client struct {
    // 包含已过滤或未导出的字段
}

func NewClient 

func NewClient(conn io.ReadWriteCloser) *Client

NewClient 返回一个新的 Client，用于处理针对连接另一端服务集合的请求。它为连接的写入端添加缓冲，使头部和负载作为一个整体发送。

连接的读取端和写入端分别独立串行化，因此读写之间不需要互锁。不过，每一端都可能被并发访问，因此 conn 的实现应防护并发读取或并发写入。

func (*Client) Close

Close 调用底层编解码器的 Close 方法。如果连接已在关闭过程中，则返回 ErrShutdown。

func (*Client) Go 

func (client *Client) Go(serviceMethod string, args any, reply any, done chan *Call) *Call

Go 异步调用函数，并返回表示此次调用的 Call 结构。调用完成时，done 通道会发送同一个 Call 对象作为通知。如果 done 为 nil，Go 会分配一个新通道。如果 done 非 nil，则它必须带缓冲，否则 Go 会故意触发崩溃。

type ClientCodec

ClientCodec 为 RPC 会话的客户端实现 RPC 请求写入和 RPC 响应读取。客户端调用 ClientCodec.WriteRequest 将请求写入连接，并成对调用 ClientCodec.ReadResponseHeader 和 ClientCodec.ReadResponseBody 读取响应。连接使用完毕后，客户端调用 ClientCodec.Close。ReadResponseBody 可以接收 nil 参数，以强制读取响应体并将其丢弃。关于并发访问的信息，参见 NewClient 的注释。 

type ClientCodec interface {
    WriteRequest(*Request, any) error
    ReadResponseHeader(*Response) error
    ReadResponseBody(any) error

    Close() error
}

type Request

Request 是在每次 RPC 调用之前写入的头部。它供内部使用，但在此提供文档以辅助调试，例如分析网络流量。 

type Request struct {

type Response

type Response struct {

type ServerCodec

ServerCodec 为 RPC 会话的服务端实现 RPC 请求读取和 RPC 响应写入。服务器成对调用 ServerCodec.ReadRequestHeader 和 ServerCodec.ReadRequestBody 从连接读取请求，并调用 ServerCodec.WriteResponse 写回响应。连接使用完毕后，服务器调用 ServerCodec.Close。ReadRequestBody 可以接收 nil 参数，以强制读取请求体并将其丢弃。关于并发访问的信息，参见 NewClient 的注释。 

type ServerCodec interface {
    ReadRequestHeader(*Request) error
    ReadRequestBody(any) error
    WriteResponse(*Response, any) error

    // Close 可以调用多次，且必须具有幂等性。
    Close() error
}
