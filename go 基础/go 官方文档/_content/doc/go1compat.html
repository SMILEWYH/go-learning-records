简介

Go 版本 1（简称 Go 1）的发布，是这门语言发展过程中的重要里程碑。Go 1 为使用 Go 编写的程序和项目提供了稳定的发展平台。

Go 1 定义了两方面内容：一是语言规范，二是一组核心 API 的规范，也就是 Go 库中的“标准包”。Go 1 发行版通过两套编译器工具（gc 和 gccgo）以及核心库本身提供这些规范的实现。

我们的目标是：按照 Go 1 规范编写的程序，在该规范的整个生命周期内，都能不加修改地继续正确编译和运行。未来某个尚未确定的时间点，可能会出现 Go 2 规范；但在此之前，即使后续 Go 1 版本（Go 1.1、Go 1.2 等）不断发布，今天能够正常工作的 Go 程序也应继续正常工作。

兼容性承诺适用于源代码层面，不保证已编译包在不同版本之间的二进制兼容性。升级到新的 Go 版本后，需要重新编译 Go 源代码，才能与新版进行链接。

API 可以通过新增包和功能不断扩充，但不能破坏现有的 Go 1 代码。

兼容性预期

虽然我们预计绝大多数程序都能长期保持兼容，但无法保证未来的任何修改都不会破坏任何程序。本文旨在明确 Go 1 软件未来兼容性的预期。有若干种情况，可能导致今天能够编译和运行的程序在未来版本发布后无法继续工作。这些情况都不常见，但值得说明。

  • 安全问题。规范或实现中可能发现安全问题，而解决问题需要破坏兼容性。我们保留修复此类安全问题的权利。
  • 未明确规定的行为。Go 规范力求明确描述语言的大部分特性，但仍有一些方面没有定义。依赖这些未明确规定行为的程序，可能在未来版本中失效。
  • 规范错误。如果必须修正规范中的不一致或不完整之处，修正过程可能影响现有程序的含义或合法性。我们保留解决这些问题的权利，包括更新实现。除安全问题外，不会对规范作出不兼容的修改。
  • 实现缺陷。如果编译器或库存在违反规范的缺陷，依赖该错误行为的程序可能在缺陷修复后失效。我们保留修复此类缺陷的权利。
  • 结构体字面量。为在后续版本中添加功能，可能需要向 API 导出的结构体中增加字段。使用不带字段名的结构体字面量（如 pkg.T{3, "x"}）创建这些类型的值时，代码会在此类修改后无法编译。使用带字段名的字面量（如 pkg.T{A: 3, B: "x"}）则仍能编译。我们更新这些数据结构时，会确保带字段名的结构体字面量保持兼容，即使不带字段名的写法可能无法编译。（涉及嵌套数据结构或接口时还有更复杂的情况，但处理原则相同。）因此，建议在使用其他包定义的类型构造复合字面量时，采用带字段名的写法。
  • 方法。与结构体字段类似，有时需要向非接口类型添加方法。在某些情况下，例如该类型与另一个类型一起嵌入同一结构体时，新增方法可能与另一个嵌入类型的现有方法冲突，导致结构体无法正常使用。这种罕见情况无法完全避免，出现时不保证兼容性。
  • 点导入。如果程序通过 import . "path" 导入标准库包，该包在未来版本中新增的名称可能与程序中的其他名称冲突。不建议在测试之外使用 import .，否则程序可能在未来版本中无法编译。
  • 使用 unsafe 包。导入 unsafe 的包可能依赖 Go 实现的内部特性。我们保留修改实现的权利，即使这可能使此类程序失效。

当然，遇到上述任何情况时，只要可行，我们都会尽力在不影响现有代码的前提下更新规范、编译器或库。

这些原则同样适用于后续的各个版本。例如，在 Go 1.2 下运行的代码应兼容 Go 1.2.1、Go 1.3、Go 1.4 等，但不一定兼容 Go 1.1，因为它可能使用了 Go 1.2 才加入的特性。

在两次正式发布之间加入源码仓库、但尚未包含在有版本号的二进制发行版中的特性，仍处于积极开发阶段。在这些特性正式发布之前，不对使用它们的软件作出兼容性承诺。

最后，虽然这不是正确性问题，但程序所依赖的编译器或库的实现发生变化时，其性能也可能受到影响。我们无法保证某个程序在不同版本之间具有相同的性能。

这些预期适用于 Go 1 本身，我们也希望基于 Go 1 开发的第三方软件采取类似的兼容性考虑。

子仓库

Go 主源码树之外的子仓库，例如 golang.org/x/net，可能采用较宽松的兼容性要求。不过，子仓库会在适当的时候打上标签，标识与 Go 1 各版本兼容的版本。

操作系统

操作系统接口由外部项目维护并修改，因此无法保证长期兼容性。syscall 包不在本文兼容性承诺的范围内。自 Go 1.4 起，syscall 包已冻结；系统调用接口的后续演进需要由其他位置提供支持，例如 go.sys 子仓库。详情和背景请参阅这份文档。

工具

最后，Go 工具链（编译器、链接器、构建工具等）仍在积极开发，其行为可能变化。例如，依赖工具位置或其他属性的脚本，可能在某个版本发布后无法继续工作。

除上述注意事项外，我们相信 Go 1 将为 Go 及其生态的发展奠定坚实基础。
