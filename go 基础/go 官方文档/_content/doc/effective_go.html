引言

Go 是一种开源编程语言，注重简洁、可靠和高效，旨在降低大规模软件开发的难度。它借鉴了现有语言的思想，也拥有一些独特的特性，使得优秀的 Go 程序与那些近亲语言中的程序呈现出不同的风格。将 C++ 或 Java 程序直接翻译成 Go，通常很难得到令人满意的结果：Java 程序毕竟遵循的是 Java 的写法，而不是 Go 的写法。相反，从 Go 的角度思考问题，可能会得到同样成功、但面貌截然不同的程序。换句话说，要写好 Go，必须理解它的特性和惯用法。还应了解 Go 编程中已经形成的约定，例如命名、格式和程序组织方式，让其他 Go 程序员能够轻松读懂你的代码。

本文提供了一些建议，帮助你编写清晰、符合 Go 惯用法的代码。它是对语言规范、Go 语言之旅和如何编写 Go 代码的补充，建议先阅读这些资料。

代码格式

代码格式最容易引发争论，却往往不是最重要的问题。人们能够适应不同的格式风格，但最好不必反复适应；如果大家遵循统一风格，也就不必花太多时间争论。问题在于：如何不依赖冗长而严格的风格指南，就能达到这种理想状态？

Go 采用了一种不同寻常的办法：让机器处理大部分格式问题。gofmt 程序（也可以使用面向包而非单个源文件的 go fmt 命令）读取 Go 程序，按照统一的缩进和纵向对齐风格输出源代码，并保留注释，必要时也会调整注释格式。遇到新的排版情况，直接运行 gofmt 即可；如果结果看起来不合适，应调整程序组织方式（或报告 gofmt 的缺陷），不要设法绕过它。

例如，不必花时间手动对齐结构体字段后的注释，Gofmt 会代劳。对于下面的声明： 

type T struct {
    name string // name of the object
    value int // its value
}

gofmt 会将各列对齐： 

type T struct {
    name    string // name of the object
    value   int    // its value
}

标准库中的所有 Go 代码都经过 gofmt 格式化。

还有一些格式细节，简要说明如下：

缩进
使用制表符缩进，gofmt 默认也会输出制表符。只有确有必要时才使用空格。
行宽
Go 不限制每行的长度，不必担心超过穿孔卡片的宽度。如果一行太长，可以换行，并额外缩进一个制表符。
圆括号
Go 比 C 和 Java 更少使用圆括号：控制结构（if、for、switch）的语法不要求圆括号。此外，运算符的优先级层次更少、更清晰，因此： 
x<<8 + y<<16
其含义与空格分组所暗示的相同，这与某些其他语言不同。

注释

Go 提供 C 风格的 /* */ 块注释和 C++ 风格的 // 行注释。通常使用行注释；块注释主要用于包注释，也适合放在表达式内部，或用于暂时禁用大段代码。

紧邻顶层声明之前、与声明之间没有空行的注释，会被视为该声明的文档。这些“文档注释”是 Go 包或命令的主要文档来源。更多信息请参阅《Go 文档注释》。

命名

命名在 Go 中和其他语言中同样重要，而且还具有语义作用：一个名称在包外是否可见，取决于首字母是否大写。因此，有必要花一点时间介绍 Go 程序中的命名约定。

包名

导入一个包后，包名就成为访问其中内容的入口。例如： 

import "bytes"

之后，导入方就可以引用 bytes.Buffer。如果所有使用者都用同一个名字来访问包中的内容，会很方便，因此包名应当简短、精练、表意清晰。按照惯例，包名使用全小写的单个单词，不应需要下划线或大小写混排。应优先选择简短名称，因为所有使用者都要反复输入它。也不必提前担心重名。包名只是导入时的默认名称，无须在所有源代码中全局唯一；少数发生冲突的情况，导入方可以在本地为它指定别名。实际上很少产生混淆，因为导入路径明确指出了使用的是哪个包。

另一个惯例是：包名与源代码目录的最后一级名称一致。例如，src/encoding/base64 中的包使用 "encoding/base64" 导入，但包名是 base64，而不是 encoding_base64 或 encodingBase64。

使用者会通过包名引用包中的内容，因此给导出的标识符命名时，可以利用这一点避免重复。（不要使用 import .。它虽然能简化必须放在被测包之外的测试，但其他情况下应避免使用。）例如，bufio 包中的缓冲读取器类型名为 Reader，而不是 BufReader，因为使用者看到的是 bufio.Reader，已经足够清晰简洁。导入的实体总是通过包名限定，所以 bufio.Reader 也不会与 io.Reader 冲突。同样，创建 ring.Ring 实例的函数，也就是 Go 中所说的构造函数，通常可能叫 NewRing；但由于 Ring 是该包唯一导出的类型，而且包名已经是 ring，函数就只需叫 New，使用者看到的是 ring.New。善用包的结构，能够帮助你选择更好的名称。

另一个简短的例子是 once.Do：once.Do(setup) 已经很易读，写成 once.DoOrWaitUntilDone(setup) 并不会更好。名称越长不代表可读性越高。一条有帮助的文档注释，往往比一个特别长的名称更有价值。

获取器

Go 不会自动生成 getter 和 setter。手动提供这些方法没有问题，很多情况下也很合适，但在 getter 名称中加入 Get 既不符合惯用法，也没有必要。如果有一个名为 owner 的字段（小写、未导出），getter 方法应叫 Owner（大写、已导出），而不是 GetOwner。导出名称首字母大写的规则，已经足以区分字段和方法。如果需要 setter，可以叫 SetOwner。实际使用时，这两个名称都很自然： 

owner := obj.Owner()
if owner != user {
    obj.SetOwner(user)
}

接口名

按照惯例，只包含一个方法的接口，通常以方法名加上 -er 后缀或类似形式命名，构成表示行为执行者的名词，例如 Reader、Writer、Formatter、CloseNotifier 等。

这类名称已经形成了一些约定，遵循它们及其对应的方法名称很有帮助。Read、Write、Close、Flush、String 等都有公认的签名和含义。为避免混淆，只有方法签名和语义与约定一致时，才应使用这些名称。反过来，如果某个类型的方法与广为人知的类型上的方法含义相同，就应使用相同的名称和签名；例如，转换为字符串的方法应叫 String，而不是 ToString。

驼峰命名

最后，Go 惯例使用 MixedCaps 或 mixedCaps 来组合多个单词，而不是用下划线分隔。

分号

与 C 一样，Go 的正式语法也用分号结束语句；但与 C 不同，源代码中通常不需要写这些分号。词法分析器在扫描时会依据一条简单规则自动插入分号，因此输入的源代码基本不用显式写分号。

规则如下：如果换行前的最后一个词法单元是标识符（包括 int、float64 这样的名称）、数值或字符串常量等基本字面量，或者以下词法单元之一： 

break continue fallthrough return ++ -- ) }

词法分析器就会在其后插入分号。可以概括为：“如果换行前的词法单元能够结束一条语句，就插入分号。”

右花括号之前的分号也可以省略，因此下面这样的语句： 

    go func() { for { dst <- <-src } }()

不需要任何分号。在惯用的 Go 程序中，通常只有 for 循环的子句等位置需要分号，用于分隔初始化、条件和后置语句。如果要把多条语句写在同一行，也需要用分号分隔。

自动插入分号的规则带来一个结果：控制结构（if、for、switch 或 select）的左花括号不能另起一行，否则会在花括号之前插入分号，产生不符合预期的结果。应这样写： 

if i < f() {
    g()
}

而不要这样写： 

if i < f()  // wrong!
{           // wrong!
    g()
}

控制结构

Go 的控制结构与 C 有相似之处，但也有重要区别。Go 没有 do 或 while 循环，只有用途更广的 for；switch 更灵活；if 和 switch 都可以像 for 一样包含可选的初始化语句；break 和 continue 可以带标签，指定要跳出或继续的目标；此外还有类型分支和用于多路通信选择的 select。语法也略有不同：条件外不需要圆括号，语句体则必须用花括号包围。

if 语句

Go 中一个简单的 if 语句如下： 

if x > 0 {
    return y
}

强制要求花括号，有助于将简单的 if 语句也写成多行。这本来就是良好的代码风格，尤其当语句体包含 return 或 break 等控制语句时。

由于 if 和 switch 支持初始化语句，常见的做法是用它声明局部变量。 

if err := file.Chmod(0664); err != nil {
    log.Print(err)
    return err
}

在 Go 库中，如果 if 分支不会继续执行后续语句，也就是说分支以 break、continue、goto 或 return 结束，通常会省略不必要的 else。 

f, err := os.Open(name)
if err != nil {
    return err
}
codeUsing(f)

一种常见情况是：代码需要依次检查多种错误条件。让成功路径从上到下自然展开，遇到错误时立即处理并退出，会使代码更易读。由于错误分支通常以 return 结束，最终也就不需要 else。 

f, err := os.Open(name)
if err != nil {
    return err
}
d, err := f.Stat()
if err != nil {
    f.Close()
    return err
}
codeUsing(f, d)

重复声明与重新赋值

补充说明：上一节最后的例子展示了 := 短变量声明的一个细节。调用 os.Open 的声明是： 

f, err := os.Open(name)

这条语句声明了 f 和 err 两个变量。几行之后，调用 f.Stat 的语句是： 

d, err := f.Stat()

它看起来又声明了 d 和 err。不过，err 出现在两条语句中。这种重复是合法的：第一条语句声明 err，第二条只是对它重新赋值。也就是说，调用 f.Stat 时使用的是前面已经声明的 err 变量，仅为它赋予一个新值。

在 := 声明中，已经声明过的变量 v 仍可以出现，只要满足以下条件：

  • 本次声明与 v 的已有声明位于同一作用域（如果 v 声明在外层作用域，本次声明会创建一个新变量，见下方 §）；
  • 初始化时对应的值可以赋给 v；并且
  • 这条声明至少还创建一个其他新变量。

这一特殊设计出于实用考虑，例如在较长的 err 错误处理流程中，可以方便地复用同一个变量，避免为 if-else 链中的每一步另起名字。你会经常见到这种用法。

§ 在 Go 中，函数参数和返回值的作用域与函数体相同，尽管从代码书写位置看，它们出现在包围函数体的花括号之外。

for 循环

Go 的 for 循环与 C 相似，但并不完全相同。它统一了 for 和 while，且没有 do-while。共有三种形式，其中只有一种需要分号。 

// Like a C for
for init; condition; post { }

// Like a C while
for condition { }

// Like a C for(;;)
for { }

短变量声明让你可以方便地直接在循环中声明索引变量。 

sum := 0
for i := 0; i < 10; i++ {
    sum += i
}

遍历数组、切片、字符串或映射（map），或者从通道读取数据时，可以使用 range 子句控制循环。 

for key, value := range oldMap {
    newMap[key] = value
}

如果只需要 range 返回的第一项（键或索引），可以省略第二项： 

for key := range m {
    if key.expired() {
        delete(m, key)
    }
}

如果只需要第二项（值），可以用下划线表示的空白标识符丢弃第一项： 

sum := 0
for _, value := range array {
    sum += value
}

空白标识符还有许多用途，详见后面的章节。

对于字符串，range 会完成更多工作：解析 UTF-8 编码，逐个提取 Unicode 码点。遇到错误编码时，会消耗一个字节并产生替换字符 U+FFFD。rune 是 Go 对单个 Unicode 码点的称呼，也是相应内置类型的名称。详见语言规范。下面的循环： 

for pos, char := range "日本\x80語" { // \x80 is an illegal UTF-8 encoding
    fmt.Printf("character %#U starts at byte position %d\n", char, pos)
}

会输出： 

character U+65E5 '日' starts at byte position 0
character U+672C '本' starts at byte position 3
character U+FFFD '�' starts at byte position 6
character U+8A9E '語' starts at byte position 7

最后，Go 没有逗号运算符，++ 和 -- 是语句而不是表达式。因此，如果希望在一个 for 中同时更新多个变量，应使用多重赋值，而不能组合使用 ++ 和 --。 

// Reverse a
for i, j := 0, len(a)-1; i < j; i, j = i+1, j-1 {
    a[i], a[j] = a[j], a[i]
}

switch 语句

Go 的 switch 比 C 更通用。表达式不必是常量，甚至不必是整数；各个分支自上而下求值，直到找到匹配项。如果 switch 没有表达式，就相当于对 true 进行匹配。因此，将 if-else-if-else 判断链写成 switch，既可行，也符合 Go 惯用法。 

func unhex(c byte) byte {
    switch {
    case '0' <= c && c <= '9':
        return c - '0'
    case 'a' <= c && c <= 'f':
        return c - 'a' + 10
    case 'A' <= c && c <= 'F':
        return c - 'A' + 10
    }
    return 0
}

分支不会自动贯穿执行后续分支，但可以用逗号分隔，在一个 case 中列出多个匹配值。 

func shouldEscape(c byte) bool {
    switch c {
    case ' ', '?', '&', '=', '#', '+', '%':
        return true
    }
    return false
}

虽然 Go 中不像其他一些类 C 语言那样频繁使用 break，但仍可以用它提前结束 switch。有时需要跳出的并非 switch，而是外层循环；这时可以给循环加上标签，再通过带标签的 break 跳出。下面的例子展示了两种用法。 

Loop:
    for n := 0; n < len(src); n += size {
        switch {
        case src[n] < sizeOne:
            if validateOnly {
                break
            }
            size = 1
            update(src[n])

        case src[n] < sizeTwo:
            if n+1 >= len(src) {
                err = errShortInput
                break Loop
            }
            if validateOnly {
                break
            }
            size = 2
            update(src[n] + src[n+1]<<shift)
        }
    }

当然，continue 也可以带可选标签，不过它只适用于循环。

本节最后给出一个比较字节切片的函数，其中使用了两个 switch： 

// Compare returns an integer comparing the two byte slices,
// lexicographically.
// The result will be 0 if a == b, -1 if a < b, and +1 if a > b
func Compare(a, b []byte) int {
    for i := 0; i < len(a) && i < len(b); i++ {
        switch {
        case a[i] > b[i]:
            return 1
        case a[i] < b[i]:
            return -1
        }
    }
    switch {
    case len(a) > len(b):
        return 1
    case len(a) < len(b):
        return -1
    }
    return 0
}

类型分支

switch 还可以判断接口变量的动态类型。这种类型分支使用类似类型断言的语法，但圆括号中写的是关键字 type。如果 switch 表达式声明了一个变量，该变量在各个分支中就具有相应的类型。这时复用原变量名也是惯用写法：相当于在每个分支中声明一个同名但类型不同的新变量。 

var t interface{}
t = functionOfSomeType()
switch t := t.(type) {
default:
    fmt.Printf("unexpected type %T\n", t)     // %T prints whatever type t has
case bool:
    fmt.Printf("boolean %t\n", t)             // t has type bool
case int:
    fmt.Printf("integer %d\n", t)             // t has type int
case *bool:
    fmt.Printf("pointer to boolean %t\n", *t) // t has type *bool
case *int:
    fmt.Printf("pointer to integer %d\n", *t) // t has type *int
}

多返回值

Go 的一个独特特性是函数和方法可以返回多个值。它可以改善 C 程序中一些笨拙的惯用做法，例如用 -1 表示 EOF 这样的特殊返回值来报告错误，或通过传入地址来修改参数。

在 C 中，写入错误通常通过负数计数值表示，而具体错误码藏在一个可能被后续操作覆盖的位置。Go 的 Write 则可以返回计数值和错误，表达“已经写入了一些字节，但由于设备已满，没有全部写完”。文件的 Write 方法位于 os 包中，其签名是： 

func (file *File) Write(b []byte) (n int, err error)

如文档所述，它返回实际写入的字节数和一个 error；当 n != len(b) 时，错误值非 nil。这是常见的写法；错误处理一节还有更多示例。

类似的方式也避免了为了模拟引用参数，而把结果变量的指针传入函数。下面这个简单函数从字节切片的指定位置读取一个整数，同时返回该整数和下一个位置。 

func nextInt(b []byte, i int) (int, int) {
    for ; i < len(b) && !isDigit(b[i]); i++ {
    }
    x := 0
    for ; i < len(b) && isDigit(b[i]); i++ {
        x = x*10 + int(b[i]) - '0'
    }
    return x, i
}

可以这样用它读取输入切片 b 中的整数： 

    for i := 0; i < len(b); {
        x, i = nextInt(b, i)
        fmt.Println(x)
    }

具名返回值

Go 函数的返回“参数”也可以像输入参数一样命名，并作为普通变量使用。具名返回值会在函数开始时初始化为对应类型的零值；执行不带参数的 return 语句时，会将这些结果变量的当前值作为返回值。

返回值的名称不是必需的，但能使代码更简洁清晰，同时起到文档作用。给 nextInt 的返回值命名后，各个 int 返回值的含义就一目了然。 

func nextInt(b []byte, pos int) (value, nextPos int) {

具名返回值已经初始化，并能配合不带参数的 return，因此可以同时简化代码并提高可读性。下面这个 io.ReadFull 的实现就很好地利用了它： 

func ReadFull(r Reader, buf []byte) (n int, err error) {
    for len(buf) > 0 && err == nil {
        var nr int
        nr, err = r.Read(buf)
        n += nr
        buf = buf[nr:]
    }
    return
}

defer 延迟调用

Go 的 defer 语句安排一个函数调用，使这个延迟调用在执行 defer 的函数返回前运行。这种方式不常见，却能有效处理“无论函数从哪条路径返回，都必须释放资源”之类的情况。典型例子是解锁互斥锁或关闭文件。 

// Contents returns the file's contents as a string.
func Contents(filename string) (string, error) {
    f, err := os.Open(filename)
    if err != nil {
        return "", err
    }
    defer f.Close()  // f.Close will run when we're finished.

    var result []byte
    buf := make([]byte, 100)
    for {
        n, err := f.Read(buf[0:])
        result = append(result, buf[0:n]...) // append is discussed later.
        if err != nil {
            if err == io.EOF {
                break
            }
            return "", err  // f will be closed if we return here.
        }
    }
    return string(result), nil // f will be closed if we return here.
}

延迟调用 Close 等函数有两个好处。首先，可以避免忘记关闭文件；后续修改函数、增加返回路径时，这种遗漏尤其容易出现。其次，关闭操作可以紧邻打开操作书写，比放在函数末尾更清晰。

延迟调用的参数（如果调用的是方法，也包括接收者）在执行 defer 语句时求值，而不是在真正执行调用时求值。这既避免了函数执行期间变量值变化带来的问题，也意味着同一个 defer 语句可以安排多次延迟调用。下面是一个简单示例。 

for i := 0; i < 5; i++ {
    defer fmt.Printf("%d ", i)
}

延迟调用按后进先出顺序执行，因此这段代码会在函数返回时输出 4 3 2 1 0。更实用的例子是跟踪程序中的函数执行。可以编写两个简单的跟踪函数： 

func trace(s string)   { fmt.Println("entering:", s) }
func untrace(s string) { fmt.Println("leaving:", s) }

// Use them like this:
func a() {
    trace("a")
    defer untrace("a")
    // do something....
}

利用延迟调用的参数在 defer 执行时就求值这一特性，还可以进一步改进：让进入跟踪函数为退出跟踪函数准备参数。下面的示例： 

func trace(s string) string {
    fmt.Println("entering:", s)
    return s
}

func un(s string) {
    fmt.Println("leaving:", s)
}

func a() {
    defer un(trace("a"))
    fmt.Println("in a")
}

func b() {
    defer un(trace("b"))
    fmt.Println("in b")
    a()
}

func main() {
    b()
}

会输出： 

entering: b
in b
entering: a
in a
leaving: a
leaving: b

对于习惯其他语言中块级资源管理的程序员，defer 可能显得特殊。但它一些最有趣、最强大的用途，恰恰来自它以函数而非代码块为单位的执行方式。在 panic 和 recover 一节中，还会看到另一个例子。

数据

使用 new 分配内存

Go 有两个内存分配原语，即内置函数 new 和 make。它们的作用和适用类型不同，初看容易混淆，但规则很简单。先来看 new：它是分配内存的内置函数，但与其他一些语言中的同名操作不同，它不会执行额外的初始化，而只会将内存置零。也就是说，new(T) 为一个新的 T 类型变量分配零值存储空间，并返回其地址，类型为 *T。用 Go 的术语说，它返回一个指针，指向新分配的 T 类型零值。

从 Go 1.26 开始，new 也接受值表达式作为参数，用于指定变量的初始值。例如，new(int64(300)) 会分配一个新的 int64 变量，将其初始化为 300，并返回其地址。

由于 new 返回的内存已经置零，设计数据结构时，最好让各类型的零值无需进一步初始化就能使用。这样，使用者通过 new 创建后就可以直接操作。例如，bytes.Buffer 的文档说明：Buffer 的零值就是一个可以直接使用的空缓冲区。同样，sync.Mutex 没有显式构造函数或 Init 方法；sync.Mutex 的零值被定义为一个未加锁的互斥锁。

“零值即可用”这一特性可以组合传递。考虑下面的类型声明： 

type SyncedBuffer struct {
    lock    sync.Mutex
    buffer  bytes.Buffer
}

SyncedBuffer 类型的值在分配内存或仅仅声明后，也可以立即使用。下面的 p 和 v 都无需额外处理，就能正确工作。 

p := new(SyncedBuffer)  // type *SyncedBuffer
var v SyncedBuffer      // type  SyncedBuffer

构造函数与复合字面量

有时零值不能满足要求，需要通过构造函数进行初始化。下面的例子取自 os 包： 

func NewFile(fd int, name string) *File {
    if fd < 0 {
        return nil
    }
    f := new(File)
    f.fd = fd
    f.name = name
    f.dirinfo = nil
    f.nepipe = 0
    return f
}

这里有不少重复代码。可以通过复合字面量简化：这种表达式每次求值都会创建一个新实例。 

func NewFile(fd int, name string) *File {
    if fd < 0 {
        return nil
    }
    f := File{fd, name, nil, 0}
    return &f
}

注意，与 C 不同，返回局部变量的地址完全没有问题：函数返回后，该变量对应的存储空间仍然有效。实际上，对复合字面量取地址，每次求值都会分配一个新实例，因此最后两行可以合并： 

    return &File{fd, name, nil, 0}

复合字面量中的字段按声明顺序排列，而且必须全部给出。不过，如果将元素明确写成字段:值对，初始化项就可以按任意顺序出现，未列出的字段会保留各自的零值。因此可以写成： 

    return &File{fd: fd, name: name}

作为一种极端情况，如果复合字面量完全不包含字段，就会创建该类型的零值。表达式 new(File) 和 &File{} 是等价的。

数组、切片和映射也可以使用复合字面量，字段标签相应地换成索引或映射的键。在下面的例子中，无论 Enone、Eio 和 Einval 的具体值是什么，只要彼此不同，初始化就能正常工作。 

a := [...]string   {Enone: "no error", Eio: "Eio", Einval: "invalid argument"}
s := []string      {Enone: "no error", Eio: "Eio", Einval: "invalid argument"}
m := map[int]string{Enone: "no error", Eio: "Eio", Einval: "invalid argument"}

使用 make 分配内存

再回到内存分配。内置函数 make(T, args) 的用途与 new(T) 不同。它只用于创建切片、映射和通道，返回的是已经初始化而不只是置零的 T 类型值，而不是 *T。区别在于，这三种类型的底层都包含对内部数据结构的引用，而这些结构需要初始化后才能正常使用。例如，切片是一个包含三项内容的描述符：指向数组数据的指针、长度和容量；在这些内容初始化之前，切片为 nil。对于切片、映射和通道，make 会初始化内部数据结构，使其可以使用。例如： 

make([]int, 10, 100)

会分配一个包含 100 个 int 的数组，再创建一个长度为 10、容量为 100 的切片，指向数组的前 10 个元素。（创建切片时可以省略容量，详见切片一节。）相比之下，new([]int) 返回的是指向新分配且已置零的切片描述符的指针，也就是指向 nil 切片值的指针。

下面的示例说明了 new 与 make 的区别。 

var p *[]int = new([]int)       // allocates slice structure; *p == nil; rarely useful
var v  []int = make([]int, 100) // the slice v now refers to a new array of 100 ints

// Unnecessarily complex:
var p *[]int = new([]int)
*p = make([]int, 100, 100)

// Idiomatic:
v := make([]int, 100)

请记住，make 只适用于映射、切片和通道，而且不返回指针。要获取显式指针，可以用 new 分配，或直接对变量取地址。

数组

数组适合用于精确规划内存布局，有时还能避免额外分配。不过，它更主要的作用是构成切片的基础，下一节将介绍切片。先简要了解数组，为后续内容做准备。

Go 的数组与 C 有很大不同。在 Go 中：

  • 数组是值。将一个数组赋给另一个数组，会复制所有元素。
  • 特别是，将数组传给函数时，函数接收到的是数组的副本，而不是指向它的指针。
  • 数组长度是类型的一部分。[10]int 和 [20]int 是不同的类型。

值语义很有用，但也可能带来较大开销。如果需要类似 C 的行为和效率，可以传递数组指针。 

func Sum(a *[3]float64) (sum float64) {
    for _, v := range *a {
        sum += v
    }
    return
}

array := [...]float64{7.0, 8.5, 9.1}
x := Sum(&array)  // Note the explicit address-of operator

不过，这种写法仍不是 Go 的惯用方式。应优先使用切片。

切片

切片包装了数组，为数据序列提供更通用、强大且方便的接口。除了变换矩阵等维度明确的对象，Go 中大多数数组相关操作都使用切片，而不是直接使用数组。

切片持有对底层数组的引用。把一个切片赋给另一个切片后，两者引用同一个数组。如果函数接收切片参数，它对切片元素的修改对调用方也可见，效果类似于传入底层数组的指针。因此，Read 函数可以只接收一个切片，而不必分别接收指针和计数值；切片自身的长度就规定了最多读取多少数据。下面是 Read 方法的签名，它属于 File 类型，位于 os 包中： 

func (f *File) Read(buf []byte) (n int, err error)

该方法返回实际读取的字节数，以及可能发生的错误。要将数据读入较大缓冲区 buf 的前 32 个字节，只需对缓冲区进行切片操作： 

    n, err := f.Read(buf[0:32])

这种切片操作很常见，也很高效。事实上，暂且不考虑效率，下面的代码也能将数据读入缓冲区的前 32 个字节。 

    var n int
    var err error
    for i := 0; i < 32; i++ {
        nbytes, e := f.Read(buf[i:i+1])  // Read one byte.
        n += nbytes
        if nbytes == 0 || e != nil {
            err = e
            break
        }
    }

只要不超出底层数组的边界，就可以改变切片的长度：对原切片再次切片并赋值即可。切片的容量通过内置函数 cap 获取，表示它所能达到的最大长度。下面的函数向切片追加数据；如果超出容量，就重新分配空间，并返回最终切片。它利用了这样一个事实：len 和 cap 可以合法地用于 nil 切片，结果都为 0。 

func Append(slice, data []byte) []byte {
    l := len(slice)
    if l + len(data) > cap(slice) {  // reallocate
        // Allocate double what's needed, for future growth.
        newSlice := make([]byte, (l+len(data))*2)
        // The copy function is predeclared and works for any slice type.
        copy(newSlice, slice)
        slice = newSlice
    }
    slice = slice[0:l+len(data)]
    copy(slice[l:], data)
    return slice
}

最后必须返回切片，因为虽然 Append 可以修改 slice 中的元素，但切片本身，也就是保存指针、长度和容量的运行时数据结构，是按值传递的。

向切片追加元素非常实用，因此 Go 提供了内置函数 append。不过，要理解它的设计，还需要一些其他知识，稍后再回到这个主题。

二维切片

Go 的数组和切片都是一维的。要创建等价的二维数组或二维切片，需要定义数组的数组，或切片的切片，例如： 

type Transform [3][3]float64  // A 3x3 array, really an array of arrays.
type LinesOfText [][]byte     // A slice of byte slices.

由于切片长度可以变化，各个内层切片可以具有不同的长度。这种情况很常见，例如 LinesOfText：每一行都有自己的长度。 

text := LinesOfText{
    []byte("Now is the time"),
    []byte("for all good gophers"),
    []byte("to bring some fun to the party."),
}

有时需要为二维切片分配内存，例如处理图像的逐行像素数据。有两种办法：一种是分别为每个切片分配空间；另一种是一次分配一个数组，再让各个切片引用其中的相应部分。选择哪一种取决于应用。如果各行切片可能增长或缩短，应分别分配，以免覆盖下一行；否则，一次分配整个对象可能更高效。下面给出两种方式供参考。首先是逐行分配： 

// Allocate the top-level slice.
picture := make([][]uint8, YSize) // One row per unit of y.
// Loop over the rows, allocating the slice for each row.
for i := range picture {
    picture[i] = make([]uint8, XSize)
}

接下来是一次分配，再按行切分： 

// Allocate the top-level slice, the same as before.
picture := make([][]uint8, YSize) // One row per unit of y.
// Allocate one large slice to hold all the pixels.
pixels := make([]uint8, XSize*YSize) // Has type []uint8 even though picture is [][]uint8.
// Loop over the rows, slicing each row from the front of the remaining pixels slice.
for i := range picture {
    picture[i], pixels = pixels[:XSize], pixels[XSize:]
}

映射

映射（map）是一种方便而强大的内置数据结构，将一种类型的值（键）关联到另一种类型的值（元素或值）。键可以是任何定义了相等运算的类型，例如整数、浮点数、复数、字符串、指针、接口（前提是动态类型支持相等比较）、结构体和数组。切片没有定义相等比较，因此不能作为映射的键。与切片一样，映射持有对底层数据结构的引用。将映射传给函数后，如果函数修改映射内容，调用方也会看到这些修改。

可以用常见的复合字面量语法创建映射，以冒号分隔键值对，因此在初始化时就能方便地构造映射。 

var timeZone = map[string]int{
    "UTC":  0*60*60,
    "EST": -5*60*60,
    "CST": -6*60*60,
    "MST": -7*60*60,
    "PST": -8*60*60,
}

设置和获取映射值的语法与数组、切片相似，只是索引不必是整数。 

offset := timeZone["EST"]

使用不存在的键读取映射，会得到元素类型的零值。例如，元素为整数时，查询不存在的键会返回 0。可以用值类型为 bool 的映射实现集合：把对应项设为 true，就表示将该键加入集合；之后通过简单的索引操作即可检查它是否存在。 

attended := map[string]bool{
    "Ann": true,
    "Joe": true,
    ...
}

if attended[person] { // will be false if person is not in the map
    fmt.Println(person, "was at the meeting")
}

有时需要区分“键不存在”和“值恰好为零”。例如，"UTC" 对应的记录究竟存在，还是因为映射中没有这个键才返回 0？可以通过多重赋值来判断。 

var seconds int
var ok bool
seconds, ok = timeZone[tz]

这种写法通常称为“comma ok”惯用法。在本例中，如果 tz 存在，seconds 会得到对应值，ok 为 true；否则，seconds 为零，ok 为 false。下面的函数将这一写法与清晰的错误报告结合起来： 

func offset(tz string) int {
    if seconds, ok := timeZone[tz]; ok {
        return seconds
    }
    log.Println("unknown time zone:", tz)
    return 0
}

如果只想检查键是否存在，不关心实际值，可以用空白标识符（_）替代接收值的变量。 

_, present := timeZone[tz]

删除映射项时，使用内置函数 delete，参数分别为映射和要删除的键。即使该键本来就不存在，这样调用也是安全的。 

delete(timeZone, "PDT")  // Now on Standard Time

格式化输出

Go 的格式化输出与 C 的 printf 系列风格相似，但功能更丰富、更通用。相关函数位于 fmt 包，名称首字母大写，例如 fmt.Printf、fmt.Fprintf、fmt.Sprintf。字符串函数（如 Sprintf）直接返回字符串，无须填充调用方提供的缓冲区。

也可以不提供格式字符串。Printf、Fprintf 和 Sprintf 都各有一对对应函数，例如 Print 和 Println。它们不接收格式字符串，而是为每个参数选择默认格式。Println 版本还会在参数之间插入空格，并在输出末尾添加换行；Print 版本则只在相邻两个参数都不是字符串时添加空格。下面例子中的每一行都会产生相同的输出。 

fmt.Printf("Hello %d\n", 23)
fmt.Fprint(os.Stdout, "Hello ", 23, "\n")
fmt.Println("Hello", 23)
fmt.Println(fmt.Sprint("Hello ", 23))

fmt.Fprint 等输出函数的第一个参数可以是任何实现了 io.Writer 接口的对象；常见的例子就是 os.Stdout 和 os.Stderr。

从这里开始，Go 与 C 的区别逐渐显现。首先，%d 等数值格式不需要指定符号或位宽，输出函数会根据参数类型决定这些属性。 

var x uint64 = 1<<64 - 1
fmt.Printf("%d %x; %d %x\n", x, x, int64(x), int64(x))

会输出： 

18446744073709551615 ffffffffffffffff; -1 -1

如果只需要默认转换，例如把整数输出为十进制，可以使用通用格式 %v（v 代表 value，值），结果与 Print 和 Println 完全相同。此外，它可以输出任意值，包括数组、切片、结构体和映射。下面的语句输出上一节定义的时区映射： 

fmt.Printf("%v\n", timeZone)  // or just fmt.Println(timeZone)

输出结果为： 

map[CST:-21600 EST:-18000 MST:-25200 PST:-28800 UTC:0]

对于映射，Printf 等函数会按键的字典序排列输出。

输出结构体时，%+v 会同时显示字段名；对于任意值，%#v 则使用完整的 Go 语法表示该值。 

type T struct {
    a int
    b float64
    c string
}
t := &T{ 7, -2.35, "abc\tdef" }
fmt.Printf("%v\n", t)
fmt.Printf("%+v\n", t)
fmt.Printf("%#v\n", t)
fmt.Printf("%#v\n", timeZone)

会输出： 

&{7 -2.35 abc   def}
&{a:7 b:-2.35 c:abc     def}
&main.T{a:7, b:-2.35, c:"abc\tdef"}
map[string]int{"CST":-21600, "EST":-18000, "MST":-25200, "PST":-28800, "UTC":0}

注意输出中的取地址符号。使用 %q 输出 string 或 []byte 类型值，也能得到带引号的字符串表示；使用 %#q，则会在可行时改用反引号。（%q 也适用于整数和 rune，会输出单引号包围的 rune 常量。）此外，%x 除了用于整数，也可以用于字符串、字节数组和字节切片，生成连续的十六进制字符串；如果格式中带空格（% x），则会在各字节之间插入空格。

另一个实用格式是 %T，用于输出值的类型。 

fmt.Printf("%T\n", timeZone)

会输出： 

map[string]int

如果要控制自定义类型的默认输出格式，只需为它定义一个签名为 String() string 的方法。对于这里的简单类型 T，可以这样写： 

func (t *T) String() string {
    return fmt.Sprintf("%d/%g/%q", t.a, t.b, t.c)
}
fmt.Printf("%v\n", t)

输出格式为： 

7/-2.35/"abc\tdef"

如果既需要输出 值，即 T 类型的值，也需要输出指向 T 的指针，String 就必须使用值接收者。本例使用指针，是因为对结构体类型来说通常更高效，也更符合这里的使用习惯。更多信息请参阅后面的指针接收者与值接收者一节。

这里的 String 方法可以调用 Sprintf，因为输出函数完全可重入，允许这样包装。不过要注意一个重要细节：实现 String 时，调用 Sprintf 的方式不能再次进入自身的 String 方法，形成无限递归。如果 Sprintf 尝试直接将接收者按字符串输出，就可能再次调用该方法。这是一个很常见、也很容易犯的错误，例如： 

type MyString string

func (m MyString) String() string {
    return fmt.Sprintf("MyString=%s", m) // Error: will recur forever.
}

修复也很简单：将参数转换为没有该方法的基本字符串类型。 

type MyString string
func (m MyString) String() string {
    return fmt.Sprintf("MyString=%s", string(m)) // OK: note conversion.
}

在初始化一节中，还会介绍另一种避免递归的方法。

另一个输出技巧是将某个输出函数接收到的参数，直接传给另一个输出函数。Printf 的最后一个参数类型是 ...interface{}，表示格式字符串后面可以跟任意数量、任意类型的参数。 

func Printf(format string, v ...interface{}) (n int, err error) {

在 Printf 函数内部，v 的表现与 []interface{} 类型变量一样；将它展开后传给其他可变参数函数时，则作为普通参数列表。下面是前文使用的 log.Println 的实现：它将参数直接传给 fmt.Sprintln，完成实际格式化。 

// Println prints to the standard logger in the manner of fmt.Println.
func Println(v ...interface{}) {
    std.Output(2, fmt.Sprintln(v...))  // Output takes parameters (int, string)
}

将 ... 写在 v 后面，再传入嵌套调用的 Sprintln，就是告诉编译器将 v 当作参数列表展开；否则，v 只会作为一个切片参数传入。

格式化输出还有许多功能尚未介绍。详细信息请参阅 godoc 中 fmt 包的文档。

顺便说一下，... 参数也可以指定具体类型。例如，用 ...int 实现从一组整数中选出最小值的 min 函数： 

func Min(a ...int) int {
    min := int(^uint(0) >> 1)  // largest int
    for _, i := range a {
        if i < min {
            min = i
        }
    }
    return min
}

append 追加元素

现在，我们已经具备理解内置函数 append 设计所需的知识。append 的签名与前面自定义的 Append 不同，示意如下： 

func append(slice []T, elements ...T) []T

其中 T 代表任意给定类型。以这里展示的普通函数形式，无法让 T 的类型由调用方决定。因此，这里的 append 由语言内置，需要编译器支持。

append 将元素添加到切片末尾，并返回结果。必须返回结果，是因为和手写的 Append 一样，底层数组可能发生变化。下面这个简单例子： 

x := []int{1,2,3}
x = append(x, 4, 5, 6)
fmt.Println(x)

会输出 [1 2 3 4 5 6]。因此，append 有点像 Printf，可以接收任意数量的参数。

如果想像自定义的 Append 那样，把一个切片的所有元素追加到另一个切片中，该怎么办？很简单：在调用处使用 ...，就像前面调用 Output 时那样。下面的代码会产生与上例相同的输出。 

x := []int{1,2,3}
y := []int{4,5,6}
x = append(x, y...)
fmt.Println(x)

如果省略 ...，代码就会因类型不匹配而无法编译，因为 y 不是 int 类型。

方法

指针接收者与值接收者

正如 ByteSize 所示，可以为命名类型定义方法（指针类型和接口类型除外），接收者不一定是结构体。

前面讨论切片时，编写了一个 Append 函数。也可以将它改为切片上的方法。为此，先声明一个可以绑定方法的命名类型，再将该类型的值作为接收者。 

type ByteSlice []byte

func (slice ByteSlice) Append(data []byte) []byte {
    // Body exactly the same as the Append function defined above.
}

这种写法仍然需要返回更新后的切片。可以将方法改为使用指针接收者，也就是指向 ByteSlice 的指针，从而直接改写调用方的切片，省去显式返回这一步。 

func (p *ByteSlice) Append(data []byte) {
    slice := *p
    // Body as above, without the return.
    *p = slice
}

实际上还能进一步改进。将函数改成标准的 Write 方法形式： 

func (p *ByteSlice) Write(data []byte) (n int, err error) {
    slice := *p
    // Again as above.
    *p = slice
    return len(data), nil
}

类型 *ByteSlice 就实现了标准接口 io.Writer，非常实用。例如，可以直接将格式化输出写入其中。 

    var b ByteSlice
    fmt.Fprintf(&b, "This hour has %d days\n", 7)

这里传入 ByteSlice 的地址，因为只有 *ByteSlice 实现了 io.Writer。接收者的基本规则是：值接收者方法可以通过值和指针调用，指针接收者方法则只能通过指针调用。

这一规则源于指针接收者方法可以修改接收者。如果让它直接接收值的副本，修改就会丢失，因此语言不允许这种错误。不过有一个便利的例外：如果值可以取地址，调用指针接收者方法时，语言会自动补上取地址操作。在上例中，变量 b 可以取地址，因此调用其 Write 方法时只需写 b.Write；编译器会自动将它改写为 (&b).Write。

顺便说一下，对字节切片实现 Write 的思路，正是 bytes.Buffer 的核心实现方式。

接口与其他类型

接口

Go 的接口用于描述对象的行为：如果某个对象能够完成这样的操作，它就能用于这里。前面已经见过一些简单例子：实现 String 方法可以定制输出格式，而 Fprintf 能向任何具有合适 Write 方法的对象输出数据。Go 代码中，只包含一两个方法的接口很常见，通常根据方法来命名，例如 io.Writer 表示实现了 Write 的对象。

一个类型可以实现多个接口。例如，某个集合只要实现了 sort 包中的 sort.Interface，也就是提供 Len()、Less(i, j int) bool 和 Swap(i, j int)，就可以用该包的函数排序；它也可以同时定制输出格式。下面的示例中，Sequence 同时满足这两个要求。

类型转换

这个 String 方法属于 Sequence，它重复实现了 Sprint 已经能够为切片完成的工作，而且其复杂度是 O(N²)，效率较差。若先将 Sequence 转换为普通的 []int，再调用 Sprint，就能复用现有功能，同时提高速度。 

func (s Sequence) String() string {
    s = s.Copy()
    sort.Sort(s)
    return fmt.Sprint([]int(s))
}

这个方法再次展示了通过类型转换安全调用 Sprintf 的技巧，即使调用位于 String 方法内部也没有问题。忽略类型名称后，Sequence 和 []int 的底层类型相同，因此可以合法转换。这种转换不创建新的底层数据，只是暂时将现有值作为另一种类型使用。当然，其他合法转换，例如整数转为浮点数，会产生新的数值。

通过转换表达式的类型来使用另一组方法，是 Go 的一种惯用法。例如，借助现成的 sort.IntSlice，可以将整个例子简化为： 

type Sequence []int

// Method for printing - sorts the elements before printing
func (s Sequence) String() string {
    s = s.Copy()
    sort.IntSlice(s).Sort()
    return fmt.Sprint([]int(s))
}

这样，就不再要求 Sequence 同时实现排序和输出两个接口，而是利用同一份数据可以转换为多种类型的特性：Sequence、sort.IntSlice 和 []int 各自负责一部分工作。这种做法在实践中不那么常见，但可能很有效。

接口转换与类型断言

类型分支也可以看作一种转换：它接收一个接口值，在各个分支中将它视为相应类型。下面通过一个简化示例，展示 fmt.Printf 内部如何用类型分支将值转换为字符串。如果值本身就是字符串，就获取接口中保存的实际字符串；如果它具有 String 方法，就使用该方法的返回值。 

type Stringer interface {
    String() string
}

var value interface{} // Value provided by caller.
switch str := value.(type) {
case string:
    return str
case Stringer:
    return str.String()
}

第一个分支取出具体值，第二个分支将接口转换为另一个接口。这样混合使用不同类型完全合法。

如果只关心一种类型呢？例如，已知接口中保存着 string，只是想把它取出来。只含一个分支的类型 switch 可以做到，类型断言也可以。类型断言接收接口值，从中提取指定类型的值。语法类似于类型分支的开头，但使用明确的类型替代 type 关键字： 

value.(typeName)

结果是一个静态类型为 typeName 的新值。这个类型必须是接口中保存的具体类型，或者该值能够转换到的另一个接口类型。要提取已知保存在接口中的字符串，可以写成： 

str := value.(string)

但如果其中实际保存的不是字符串，程序就会触发运行时错误。为避免这种情况，可以用“comma ok”惯用法安全地检查它是否为字符串： 

str, ok := value.(string)
if ok {
    fmt.Printf("string value is: %q\n", str)
} else {
    fmt.Printf("value is not a string\n")
}

如果类型断言失败，str 仍然存在，类型仍是 string，但值是该类型的零值，也就是空字符串。

下面用一个 if-else 语句进一步说明，它与本节开头的类型分支等价。 

if str, ok := value.(string); ok {
    return str
} else if str, ok := value.(Stringer); ok {
    return str.String()
}

通用性

如果一个类型存在的唯一目的就是实现某个接口，并且不会导出接口以外的方法，那么没有必要导出这个类型本身。只导出接口，就能明确说明：这个值对外提供的行为只有接口所描述的那些。这也避免了为每个实现重复编写相同方法的文档。

这种情况下，构造函数应返回接口值，而不是具体实现类型。例如，哈希库中的 crc32.NewIEEE 和 adler32.New 都返回接口类型 hash.Hash32。要在 Go 程序中将 Adler-32 算法替换为 CRC-32，只需修改构造函数调用，其余代码不受算法变化影响。

类似的做法可以将各个 crypto 包中的流式加密算法，与它们所组合使用的分组密码解耦。Block 接口位于 crypto/cipher 包中，描述分组密码的行为，用于加密单个数据块。与 bufio 包的设计类似，凡是实现该接口的密码算法，都可以用于构造由 Stream 接口表示的流式加密，而无须了解分组加密的细节。

crypto/cipher 中的接口如下： 

type Block interface {
    BlockSize() int
    Encrypt(dst, src []byte)
    Decrypt(dst, src []byte)
}

type Stream interface {
    XORKeyStream(dst, src []byte)
}

下面是计数器模式（CTR）数据流的定义，它将分组密码转换为流式加密。注意，分组密码的具体细节已经被抽象出来： 

// NewCTR returns a Stream that encrypts/decrypts using the given Block in
// counter mode. The length of iv must be the same as the Block's block size.
func NewCTR(block Block, iv []byte) Stream

NewCTR 不局限于某一种加密算法和数据源，而是能够基于任意 Block 接口实现构造通用的 Stream。由于这些构造函数返回接口值，将 CTR 替换为其他加密模式只需要局部修改：更换构造函数调用即可；周围代码始终将结果当作 Stream 使用，因此感知不到区别。

接口与方法

几乎任何类型都可以定义方法，因此几乎任何类型都能实现接口。http 包中的 Handler 接口就是一个很好的例子。任何实现了 Handler 的对象都可以处理 HTTP 请求。 

type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

ResponseWriter 本身也是接口，提供向客户端返回响应所需的方法，其中包括标准的 Write 方法。因此，http.ResponseWriter 可以用于任何需要 io.Writer 的地方。Request 则是结构体，保存已经解析的客户端请求。

为简洁起见，暂不考虑 POST，假设所有 HTTP 请求都是 GET。这一简化不会影响处理器的设置方式。下面是一个简单处理器，用来统计页面访问次数。 

// Simple counter server.
type Counter struct {
    n int
}

func (ctr *Counter) ServeHTTP(w http.ResponseWriter, req *http.Request) {
    ctr.n++
    fmt.Fprintf(w, "counter = %d\n", ctr.n)
}

延续前面的主题，注意 Fprintf 如何向 http.ResponseWriter 输出内容。在真正的服务器中，需要为 ctr.n 提供并发访问保护，相关做法可参考 sync 和 atomic 包。

作为参考，下面演示如何将这样的处理器注册到 URL 路径树中的一个节点。 

import "net/http"
...
ctr := new(Counter)
http.Handle("/counter", ctr)

不过，为什么一定要把 Counter 定义成结构体呢？一个整数就够了。（接收者必须是指针，才能让调用方看到递增结果。） 

// Simpler counter server.
type Counter int

func (ctr *Counter) ServeHTTP(w http.ResponseWriter, req *http.Request) {
    *ctr++
    fmt.Fprintf(w, "counter = %d\n", *ctr)
}

如果程序中的某些内部状态需要在页面被访问时收到通知，可以将通道与网页关联起来。 

// A channel that sends a notification on each visit.
// (Probably want the channel to be buffered.)
type Chan chan *http.Request

func (ch Chan) ServeHTTP(w http.ResponseWriter, req *http.Request) {
    ch <- req
    fmt.Fprint(w, "notification sent")
}

最后，假设要在 /args 页面显示启动服务器可执行文件时传入的参数。编写一个输出这些参数的函数很容易。 

func ArgServer() {
    fmt.Println(os.Args)
}

如何让它成为 HTTP 处理器呢？可以将 ArgServer 改成某个类型的方法，再忽略该类型的值，但还有更简洁的办法。既然除指针类型和接口类型外，都可以为命名类型定义方法，那么函数类型也可以。http 包中就包含下面的代码： 

// The HandlerFunc type is an adapter to allow the use of
// ordinary functions as HTTP handlers.  If f is a function
// with the appropriate signature, HandlerFunc(f) is a
// Handler object that calls f.
type HandlerFunc func(ResponseWriter, *Request)

// ServeHTTP calls f(w, req).
func (f HandlerFunc) ServeHTTP(w ResponseWriter, req *Request) {
    f(w, req)
}

HandlerFunc 拥有 ServeHTTP 方法，因此这个类型的值能够处理 HTTP 请求。看一下方法实现：接收者是函数 f，方法体直接调用 f。这看起来有点特别，其实与“接收者是通道，方法向通道发送值”并没有本质区别。

要让 ArgServer 成为 HTTP 处理器，先将它修改为正确的签名。 

// Argument server.
func ArgServer(w http.ResponseWriter, req *http.Request) {
    fmt.Fprintln(w, os.Args)
}

此时 ArgServer 与 HandlerFunc 具有相同签名，可以转换为后者并使用其方法，就像前面将 Sequence 转换为 IntSlice，再调用 IntSlice.Sort 一样。注册代码十分简洁： 

http.Handle("/args", http.HandlerFunc(ArgServer))

访问 /args 页面时，该路径上注册的处理器值为 ArgServer，类型为 HandlerFunc。HTTP 服务器会调用这个类型的 ServeHTTP 方法，以 ArgServer 为接收者；该方法又会调用 ArgServer，具体是执行 f(w, req)，它位于 HandlerFunc.ServeHTTP 中。随后，启动参数就会显示在页面上。

本节分别用结构体、整数、通道和函数构造了 HTTP 处理器。这之所以可行，是因为接口只是一组方法，而几乎任何类型都能定义方法。

空白标识符

前面介绍 for range 循环和映射时，已经多次提到空白标识符。任何类型、任何值都可以赋给空白标识符，或在声明中交给它，结果会被直接丢弃。这有点像向 Unix 的 /dev/null 文件写入内容：它表示一个只写的占位位置，适用于语法上需要变量、但实际值无关紧要的场合。它的用途还不止前面介绍的那些。

多重赋值中的空白标识符

在 for range 循环中使用空白标识符，是更普遍的多重赋值场景的一个特例。

如果赋值语句左侧需要多个接收位置，但程序不会使用其中某个值，就可以在对应位置使用空白标识符。这样无需创建无意义的变量，也明确表达了丢弃该值的意图。例如，调用一个同时返回结果和错误的函数，但只关心错误时，就可以用空白标识符丢弃无关结果。 

if _, err := os.Stat(path); os.IsNotExist(err) {
    fmt.Printf("%s does not exist\n", path)
}

有时会看到代码通过丢弃错误值来忽略错误，这是很糟糕的做法。应始终检查返回的错误；函数提供错误值是有原因的。 

// Bad! This code will crash if path does not exist.
fi, _ := os.Stat(path)
if fi.IsDir() {
    fmt.Printf("%s is a directory\n", path)
}

这种导入形式明确说明只需要包的副作用，因为该包在当前文件中没有可用名称，也就不可能用于其他用途。（如果给了名称却不使用，编译器会拒绝编译。）

接口实现检查

如前面接口一节所述，类型无须显式声明自己实现了某个接口，只要实现接口所需的方法即可。实践中，大部分接口转换是静态的，因此会在编译期检查。例如，将 *os.File 传给需要 io.Reader 的函数，只有在 *os.File 实现了 io.Reader 接口时才能通过编译。

不过，也有一些接口检查发生在运行时。例如，encoding/json 包定义了 Marshaler 接口。当 JSON 编码器收到一个实现了该接口的值时，会调用它的序列化方法将其转换为 JSON，而不使用标准转换流程。编码器通过运行时的类型断言检查这一点，例如： 

m, ok := val.(json.Marshaler)

如果只需要判断某个类型是否实现接口，并不实际使用接口值，例如将它作为错误检查的一部分，可以用空白标识符忽略断言得到的值： 

if _, ok := val.(json.Marshaler); ok {
    fmt.Printf("value %v of type %T implements json.Marshaler\n", val, val)
}

一种应用场景是：在定义类型的包内部，保证它确实实现了某个接口。例如，json.RawMessage 需要自定义 JSON 表示，就应该实现 json.Marshaler；但代码中可能没有任何静态转换，无法让编译器自动验证。如果类型意外地不再满足该接口，JSON 编码器仍会工作，却不会使用自定义实现。为确保实现正确，可以在包中增加一个使用空白标识符的全局声明： 

var _ json.Marshaler = (*RawMessage)(nil)

这条声明包含将 *RawMessage 转换为 Marshaler 的赋值，因此要求 *RawMessage 实现 Marshaler，编译器会在编译期检查。如果 json.Marshaler 接口发生变化，这个包就无法编译，提醒我们更新实现。

这里使用空白标识符，表明声明只用于类型检查，而非创建变量。不过，不必为每个实现接口的类型都加上这样的声明。按照惯例，只有代码中没有其他静态转换时才需要这么做，而这种情况并不常见。

嵌入

Go 没有传统的、以类型继承为基础的子类机制，但可以在结构体或接口中嵌入其他类型，借用其部分实现。

接口嵌入非常简单。前面提到的 io.Reader 和 io.Writer 定义如下： 

type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}

io 包还导出了一些接口，用于描述同时提供多种操作的对象。例如，io.ReadWriter 同时包含 Read 和 Write。定义 io.ReadWriter 时，可以显式列出这两个方法，但直接嵌入两个已有接口来组成新接口，更简单，也更能表达意图： 

// ReadWriter is the interface that combines the Reader and Writer interfaces.
type ReadWriter interface {
    Reader
    Writer
}

这段声明与字面含义一致：ReadWriter 能完成 Reader 的操作，也能完成 Writer 的操作，它的方法集合是所嵌入接口的方法集合的并集。这里介绍的接口嵌入形式，只在接口内部嵌入其他接口。

相同的基本思路也适用于结构体，但影响更广。bufio 包有两个结构体类型，bufio.Reader 和 bufio.Writer，分别实现 io 包中的对应接口。此外，bufio 还提供带缓冲的读写器：通过嵌入，将读取器和写入器合并到一个结构体中。声明时只列出类型，不指定字段名。 

// ReadWriter stores pointers to a Reader and a Writer.
// It implements io.ReadWriter.
type ReadWriter struct {
    *Reader  // *bufio.Reader
    *Writer  // *bufio.Writer
}

嵌入的元素是结构体指针，使用前当然必须初始化，使其指向有效的结构体。ReadWriter 也可以写成： 

type ReadWriter struct {
    reader *Reader
    writer *Writer
}

但为了让这些字段的方法能够通过外层类型调用，并实现 io 接口，还需要手动编写转发方法，例如： 

func (rw *ReadWriter) Read(p []byte) (n int, err error) {
    return rw.reader.Read(p)
}

直接嵌入结构体，就能免去这些重复工作。嵌入类型的方法会自动提升到外层类型，因此 bufio.ReadWriter 不仅拥有 bufio.Reader 和 bufio.Writer 的方法，还同时实现了 io.Reader、io.Writer 和 io.ReadWriter 三个接口。

嵌入与继承有一个重要区别：嵌入类型的方法虽然可以通过外层类型调用，但方法真正执行时，接收者仍是内层类型，而不是外层类型。以上例来说，调用 Read 方法时，虽然调用对象是 bufio.ReadWriter，效果却与前面手写的转发方法完全相同；接收者是 reader 字段，它属于 ReadWriter，而不是整个 ReadWriter 自身。

嵌入有时只是为了使用方便。下面的示例同时包含嵌入字段和普通具名字段。 

type Job struct {
    Command string
    *log.Logger
}

现在，Job 类型拥有了 Print、Printf、Println 等来自 *log.Logger 的方法。当然，也可以给 Logger 指定字段名，但这里没有必要。初始化后，就可以通过 Job 记录日志： 

job.Println("starting now...")

Logger 仍是 Job 结构体中的普通字段，所以可以在 Job 的构造函数中按常规方式初始化，例如： 

func NewJob(command string, logger *log.Logger) *Job {
    return &Job{command, logger}
}

也可以使用复合字面量： 

job := &Job{command, log.New(os.Stderr, "Job: ", log.Ldate)}

如果需要直接引用嵌入字段，可以用去掉包限定符后的类型名作为字段名，正如前面 Read 方法访问 ReadWriter 的嵌入字段那样。这里，要访问 *log.Logger 字段，对于 Job 类型的变量 job，可以写 job.Logger。如果希望进一步定制 Logger 的方法，这种直接访问很有用。 

func (job *Job) Printf(format string, args ...interface{}) {
    job.Logger.Printf("%q: %s", job.Command, fmt.Sprintf(format, args...))
}

嵌入类型会带来命名冲突，但解决规则很简单。首先，外层字段或方法 X 会遮蔽更深嵌套层级中同名的 X。如果 log.Logger 包含名为 Command 的字段或方法，那么外层的 Command 字段，也就是 Job 自己的字段，会优先使用。

其次，同一嵌套层级出现同名项通常会导致错误。例如，嵌入 log.Logger 时，如果 Job 结构体已经有另一个名为 Logger 的字段或方法，就会出现问题。不过，如果程序在类型定义之外从未引用这个重复名称，则允许保留。这为外部嵌入类型的变化提供了一定保护：某个嵌入类型新增字段，与另一个嵌入类型中的字段重名时，只要两者都未被使用，就不会造成问题。

并发

通过通信共享内存

并发编程是个很大的主题，这里只介绍一些 Go 特有的要点。

在许多环境中，正确访问共享变量需要处理大量细节，使并发编程变得困难。Go 鼓励另一种方式：通过通道传递共享值，而不是让不同的执行线程同时操作它。在任何时刻，只有一个 goroutine（轻量级协程）能够访问该值，从设计上避免数据竞争。为了帮助理解这种思路，可以将它概括为一句话：

不要通过共享内存来通信，而要通过通信来共享内存。

这种方式也不应被过度使用。例如，实现引用计数时，为整数变量加一把互斥锁可能更合适。不过，作为一种整体设计思路，通过通道控制访问，更容易写出清晰、正确的程序。

可以这样理解这个模型：一个在单个 CPU 上运行的典型单线程程序，不需要同步原语。再运行一个同样的实例，它也不需要同步。现在让两个实例通信；如果通信本身就完成了同步，就仍然不需要其他同步机制。Unix 管道就是这个模型的典型例子。Go 的并发设计源于 Hoare 的通信顺序进程（CSP），也可以看作 Unix 管道的一种类型安全的推广。

goroutine

之所以使用 goroutine 这个名称，是因为线程、协程、进程等已有术语都不能准确传达它的含义。goroutine 的模型很简单：它是一个与其他 goroutine 在同一地址空间中并发执行的函数。它很轻量，主要开销只是分配栈空间。栈的初始大小很小，成本低，并会按需通过分配和释放堆内存来伸缩。

多个 goroutine 会复用多个操作系统线程，因此当某个 goroutine 因等待 I/O 等原因阻塞时，其他 goroutine 仍可继续运行。这种设计隐藏了线程创建和管理的许多复杂细节。

在函数或方法调用前加上 go 关键字，就会在新的 goroutine 中执行该调用。调用结束时，goroutine 会自行退出。（效果类似于 Unix shell 中通过 & 将命令放到后台运行。） 

go list.Sort()  // run list.Sort concurrently; don't wait for it.

启动 goroutine 时，使用函数字面量通常很方便。 

func Announce(message string, delay time.Duration) {
    go func() {
        time.Sleep(delay)
        fmt.Println(message)
    }()  // Note the parentheses - must call the function.
}

Go 中的函数字面量是闭包：只要闭包仍需要它引用的变量，语言实现就会保证这些变量继续存在。

这些示例还不够实用，因为函数无法通知其他部分自己已经执行完毕。为此，需要使用通道。

通道

与映射类似，通道通过 make 分配，返回值表现为对底层数据结构的引用。可选的整数参数用于设置通道缓冲区容量，默认值为零，即无缓冲通道，也称同步通道。 

ci := make(chan int)            // unbuffered channel of integers
cj := make(chan int, 0)         // unbuffered channel of integers
cs := make(chan *os.File, 100)  // buffered channel of pointers to Files

无缓冲通道将通信与同步结合起来：通信负责交换值，同步则保证参与交互的两个 goroutine 处于已知状态。

通道有许多实用的惯用法，先看一个例子。上一节在后台启动了排序操作，利用通道，就可以让启动方 goroutine 等待排序结束。 

c := make(chan int)  // Allocate a channel.
// Start the sort in a goroutine; when it completes, signal on the channel.
go func() {
    list.Sort()
    c <- 1  // Send a signal; value does not matter.
}()
doSomethingForAWhile()
<-c   // Wait for sort to finish; discard sent value.

接收操作会阻塞，直到有数据可接收。对于无缓冲通道，发送方会一直阻塞，直到接收方接收到值。对于带缓冲通道，值被复制到缓冲区后，发送操作就可以完成；如果缓冲区已满，则需要等待某个接收方取走一个值。

带缓冲通道可以用作信号量，例如限制并发处理量。在本例中，请求交给 handle 后，它先向通道发送一个值，然后处理请求，最后从通道接收一个值，为下一个使用者释放“信号量”名额。通道的缓冲区容量限制了同时调用 process 的数量。 

var sem = make(chan int, MaxOutstanding)

func handle(r *Request) {
    sem <- 1    // Wait for active queue to drain.
    process(r)  // May take a long time.
    <-sem       // Done; enable next request to run.
}

func Serve(queue chan *Request) {
    for {
        req := <-queue
        go handle(req)  // Don't wait for handle to finish.
    }
}

一旦已有 MaxOutstanding 个处理器正在执行 process，其他处理器就会在向已满通道发送值时阻塞，直到其中一个正在运行的处理器结束，并从缓冲区取出一个值。

不过，这种设计有一个问题：Serve 会为每个新请求创建 goroutine，尽管任一时刻只有 MaxOutstanding 个能够实际执行。如果请求到达过快，程序仍可能无限制地消耗资源。可以修改 Serve，在创建 goroutine 之前就限制数量： 

func Serve(queue chan *Request) {
    for req := range queue {
        sem <- 1
        go func() {
            process(req)
            <-sem
        }()
    }
}

注意，在 Go 1.22 之前的版本中，这段代码存在一个缺陷：所有 goroutine 共享同一个循环变量。详细说明请参阅 Go Wiki。

另一种能有效管理资源的方法是：启动固定数量的 handle goroutine，让它们都从请求通道中读取数据。goroutine 的数量就限制了同时调用 process 的数量。下面的 Serve 还接收一个用于通知退出的通道；启动各个 goroutine 后，它会阻塞等待该通道上的信号。 

func handle(queue chan *Request) {
    for r := range queue {
        process(r)
    }
}

func Serve(clientRequests chan *Request, quit chan bool) {
    // Start handlers
    for i := 0; i < MaxOutstanding; i++ {
        go handle(clientRequests)
    }
    <-quit  // Wait to be told to exit.
}

通道中的通道

Go 的一个重要特性是：通道是一等值，可以像其他值一样创建和传递。这一特性的常见用途是实现安全、并行的消息分发，让结果返回各自的接收方。

上一节中的 handle 是一个理想化的请求处理器，但还没有定义它处理的请求类型。如果请求类型包含用于回复的通道，每个客户端就能指定自己的响应接收路径。下面是 Request 类型的示意定义。 

type Request struct {
    args        []int
    f           func([]int) int
    resultChan  chan int
}

客户端提供函数及其参数，同时在请求对象中提供一个用于接收结果的通道。 

func sum(a []int) (s int) {
    for _, v := range a {
        s += v
    }
    return
}

request := &Request{[]int{3, 4, 5}, sum, make(chan int)}
// Send request
clientRequests <- request
// Wait for response.
fmt.Printf("answer: %d\n", <-request.resultChan)

服务器端只需要修改处理函数。 

func handle(queue chan *Request) {
    for req := range queue {
        req.resultChan <- req.f(req.args)
    }
}

要将它用于实际系统，显然还需要更多工作。不过，这段代码已经构成一个限制并发量、支持并行处理且不阻塞其他请求的 RPC 系统框架，整个过程没有使用互斥锁。

并行化

这些思路还可以用于将计算分配到多个 CPU 核心上并行执行。如果计算能够拆分为多个相互独立的部分，就可以并行化，再通过通道通知各部分已经完成。

假设需要对一组向量元素执行开销较大的操作，而每个元素的计算结果彼此独立，如下面的简化示例所示。 

type Vector []float64

// Apply the operation to v[i], v[i+1] ... up to v[n-1].
func (v Vector) DoSome(i, n int, u Vector, c chan int) {
    for ; i < n; i++ {
        v[i] += u.Op(v[i])
    }
    c <- 1    // signal that this piece is done
}

通过循环分别启动各个计算部分，每个 CPU 对应一份。它们可以按任意顺序完成，这没有关系；启动所有 goroutine 后，只需从通道接收相应数量的完成信号。 

const numCPU = 4 // number of CPU cores

func (v Vector) DoAll(u Vector) {
    c := make(chan int, numCPU)  // Buffering optional but sensible.
    for i := 0; i < numCPU; i++ {
        go v.DoSome(i*len(v)/numCPU, (i+1)*len(v)/numCPU, u, c)
    }
    // Drain the channel.
    for i := 0; i < numCPU; i++ {
        <-c    // wait for one task to complete
    }
    // All done.
}

不必将 numCPU 定义为常量，也可以询问运行时应使用什么值。函数 runtime.NumCPU 返回机器的硬件 CPU 数量，因此可以写成： 

var numCPU = runtime.NumCPU()

另一个函数 runtime.GOMAXPROCS 用于获取或设置 Go 程序可同时执行的 CPU 数量。按本文所述的默认设置，它采用 runtime.NumCPU 的值，也可以通过同名 shell 环境变量，或以正整数为参数调用该函数进行覆盖。传入零则只查询当前值。因此，如果希望遵循用户指定的资源限制，应写成： 

var numCPU = runtime.GOMAXPROCS(0)

注意不要混淆并发与并行：并发是将程序组织为独立执行的组件；并行则是在多个 CPU 上同时计算，以提高效率。Go 的并发机制虽然使某些问题容易组织为并行计算，但 Go 的语言模型侧重并发，并非所有并行问题都适合它。有关二者区别的讨论，请观看这篇博客中引用的演讲。

可丢弃的缓冲区池

并发编程工具有时也能让非并发的思路更容易表达。下面的例子提炼自一个 RPC 包：客户端 goroutine 循环从网络等数据源接收数据。为避免反复分配和释放缓冲区，它维护一个空闲列表，并用带缓冲通道表示。通道为空时，才分配新缓冲区。消息缓冲区准备好后，通过 serverChan 发送给服务器。 

var freeList = make(chan *Buffer, 100)
var serverChan = make(chan *Buffer)

func client() {
    for {
        var b *Buffer
        // Grab a buffer if available; allocate if not.
        select {
        case b = <-freeList:
            // Got one; nothing more to do.
        default:
            // None free, so allocate a new one.
            b = new(Buffer)
        }
        load(b)              // Read next message from the net.
        serverChan <- b      // Send to server.
    }
}

服务器循环接收客户端消息，处理后将缓冲区放回空闲列表。 

func server() {
    for {
        b := <-serverChan    // Wait for work.
        process(b)
        // Reuse buffer if there's room.
        select {
        case freeList <- b:
            // Buffer on free list; nothing more to do.
        default:
            // Free list full, just carry on.
        }
    }
}

客户端尝试从 freeList 获取缓冲区；如果没有可用缓冲区，就新分配一个。服务器向 freeList 发送时，会把 b 放回空闲列表；如果列表已满，就不再保留这个缓冲区，让垃圾回收器回收它。（default 分支会在 select 的其他分支都未就绪时执行，因此这些 selects 操作不会阻塞。）这段实现依靠带缓冲通道和垃圾回收器管理资源，只用几行代码就构建了一个类似“漏桶”的空闲列表。

错误

库函数经常需要向调用方报告错误。如前所述，Go 的多返回值使函数能够在返回正常结果的同时，附带详细错误描述。利用这一特性提供充分的错误信息，是良好的代码风格。例如，os.Open 失败时，不仅返回 nil 指针，还会返回一个描述问题原因的错误值。

按照惯例，错误使用 error 类型，它是一个简单的内置接口。 

type error interface {
    Error() string
}

库的作者可以用更丰富的内部结构实现该接口，不仅报告错误，还提供相关上下文。如前所述，除了通常返回的 *os.File，os.Open 还返回错误值。文件成功打开时，错误为 nil；发生问题时，则保存一个 os.PathError： 

// PathError records an error and the operation and
// file path that caused it.
type PathError struct {
    Op string    // "open", "unlink", etc.
    Path string  // The associated file.
    Err error    // Returned by the system call.
}

func (e *PathError) Error() string {
    return e.Op + " " + e.Path + ": " + e.Err.Error()
}

PathError 的 Error 方法生成类似下面的字符串： 

open /etc/passwx: no such file or directory

这样的错误包含出问题的文件名、执行的操作以及底层操作系统错误，因此即使在离原始调用很远的地方输出，仍然很有帮助。它比单纯的“no such file or directory”提供了更多信息。

如果可行，错误字符串应说明来源，例如以前缀注明产生错误的操作或包。比如在 image 包中，因未知格式导致的解码错误表示为“image: unknown format”。

需要了解具体错误细节的调用方，可以通过类型分支或类型断言识别错误类型，并提取信息。对于 PathErrors，可能需要检查内部的 Err 字段，以判断是否属于可恢复的失败。 

for try := 0; try < 2; try++ {
    file, err = os.Create(filename)
    if err == nil {
        return
    }
    if e, ok := err.(*os.PathError); ok && e.Err == syscall.ENOSPC {
        deleteTempFiles()  // Recover some space.
        continue
    }
    return
}

这里的第二个 if 使用了另一个类型断言。如果断言失败，ok 为 false，e 为 nil；如果成功，ok 为 true，表明错误的具体类型是 *os.PathError，因此 e 也具有该类型，可以进一步检查错误信息。

panic

向调用方报告错误的常规方式，是额外返回一个 error。标准的 Read 方法就是典型例子，它返回字节数和一个 error。但如果错误无法恢复，该怎么办？有时程序确实无法继续执行。

为此，Go 提供了内置函数 panic。它实际上会触发运行时错误并停止程序，下一节将介绍例外情况。该函数接收一个任意类型的参数，通常是字符串，在程序终止时输出。它也可以表示“发生了不可能发生的情况”，例如程序竟然走出了一个无限循环。 

// A toy implementation of cube root using Newton's method.
func CubeRoot(x float64) float64 {
    z := x/3   // Arbitrary initial value
    for i := 0; i < 1e6; i++ {
        prevz := z
        z -= (z*z*z-x) / (3*z*z)
        if veryClose(z, prevz) {
            return z
        }
    }
    // A million iterations has not converged; something is wrong.
    panic(fmt.Sprintf("CubeRoot(%g) did not converge", x))
}

这只是示例，实际的库函数应尽量避免使用 panic。如果问题可以被隔离或绕过，让程序继续运行通常比直接终止整个程序更好。一种可能的例外是初始化阶段：如果库确实无法完成自身初始化，触发 panic 可能是合理的选择。 

var user = os.Getenv("USER")

func init() {
    if user == "" {
        panic("no value for $USER")
    }
}

recover

调用 panic 时，包括切片索引越界、类型断言失败等运行时错误隐式触发 panic 的情况，当前函数会立即停止正常执行，并开始沿 goroutine 的调用栈向外回退，同时执行途中的延迟调用。如果回退到 goroutine 栈顶仍未被处理，整个程序就会终止。不过，可以通过内置函数 recover 重新获得控制权，让 goroutine 恢复正常执行流程。

调用 recover 会停止栈回退，并返回传给 panic 的参数。由于栈回退期间只有延迟调用会执行，recover 只有在延迟函数中直接调用才有效。

recover 的一种用途是：在服务器中结束发生错误的 goroutine，同时让其他正在执行的 goroutine 不受影响。 

func server(workChan <-chan *Work) {
    for work := range workChan {
        go safelyDo(work)
    }
}

func safelyDo(work *Work) {
    defer func() {
        if err := recover(); err != nil {
            log.Println("work failed:", err)
        }
    }()
    do(work)
}

在这个例子中，如果 do(work) 触发 panic，错误会被记录，而当前 goroutine 会正常退出，不影响其他 goroutine。延迟执行的闭包无需进行其他处理，调用 recover 就能处理这一情况。

因为 recover 除非直接在延迟函数中调用，否则总是返回 nil，所以延迟函数可以正常调用内部使用 panic 和 recover 的库函数。例如，safelyDo 中的延迟函数可以先调用日志函数，再调用 recover；日志代码不会因为外层正处于 panic 回退状态而受到影响。

有了这样的恢复模式，do 及其调用的函数就能通过 panic 从无法继续的状态中退出。可以利用这一点简化复杂软件的错误处理。下面看一个理想化的 regexp 包：它通过将包内错误类型传给 panic 来报告解析错误。代码包含 Error 类型、error 方法和 Compile 函数。 

// Error is the type of a parse error; it satisfies the error interface.
type Error string
func (e Error) Error() string {
    return string(e)
}

// error is a method of *Regexp that reports parsing errors by
// panicking with an Error.
func (regexp *Regexp) error(err string) {
    panic(Error(err))
}

// Compile returns a parsed representation of the regular expression.
func Compile(str string) (regexp *Regexp, err error) {
    regexp = new(Regexp)
    // doParse will panic if there is a parse error.
    defer func() {
        if e := recover(); e != nil {
            regexp = nil    // Clear return value.
            err = e.(Error) // Will re-panic if not a parse error.
        }
    }()
    return regexp.doParse(str), nil
}

如果 doParse 触发 panic，恢复代码会将返回值设为 nil，因为延迟函数可以修改具名返回值。接着，在给 err 赋值时，通过断言恢复出的值属于包内 Error 类型，检查这是否确实是解析错误。如果不是，类型断言会失败，触发新的运行时错误，让栈继续回退，仿佛从未被中断。这项检查保证了：即使使用 panic 和 recover 处理解析错误，索引越界等意外问题仍会让程序明确失败。

建立上述错误处理机制后，error 方法就能方便地报告解析错误，无须手动逐层退出解析调用栈。由于它是绑定在类型上的方法，与内置 error 类型同名完全合法，也很自然： 

if pos == 0 {
    re.error("'*' illegal at start of expression")
}

这种模式虽然有用，但只应在包内部使用。Parse 会将内部的 panic 转换为 error 返回值，不向调用方暴露 panics。这是一个值得遵循的原则。

顺便说一下，真正出现意外错误时，这种再次触发 panic 的惯用法会改变 panic 的值。不过，崩溃报告会同时显示原始失败和新的失败，因此仍能看到根本原因。既然程序已经崩溃，这种简单的再次 panic 通常足够。如果只想显示原始值，可以多写一些代码，识别意外问题，并用原始错误再次触发 panic。这部分留作练习。
