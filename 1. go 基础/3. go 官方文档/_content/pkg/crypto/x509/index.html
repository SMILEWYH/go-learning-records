x509 包实现 X.509 标准的一个子集。

它支持解析和生成证书、证书签名请求、证书吊销列表，以及编码形式的公钥和私钥，并提供带有证书链构建功能的证书验证器。

本包面向 IETF 定义的 X.509 技术规范（RFC 2459/3280/5280），并进一步遵循 CA/Browser Forum 基准要求中的限制。对于这些规范之外的功能，支持很有限，因为本包的主要目标是兼容公开受信任的 TLS 证书生态及其策略和约束。

在 macOS 和 Windows 上，证书验证由系统 API 处理，但本包力求在不同操作系统上应用一致的验证规则。

func CreateCertificate 

func CreateCertificate(rand io.Reader, template, parent *Certificate, pub, priv any) ([]byte, error)

CreateCertificate 根据模板创建新的 X.509 v3 证书。目前使用 template 的以下成员：

  • AuthorityKeyId
  • BasicConstraintsValid
  • CRLDistributionPoints
  • DNSNames
  • EmailAddresses
  • ExcludedDNSDomains
  • ExcludedEmailAddresses
  • ExcludedIPRanges
  • ExcludedURIDomains
  • ExtKeyUsage
  • ExtraExtensions
  • IPAddresses
  • IsCA
  • IssuingCertificateURL
  • KeyUsage
  • MaxPathLen
  • MaxPathLenZero
  • NotAfter
  • NotBefore
  • OCSPServer
  • PermittedDNSDomains
  • PermittedDNSDomainsCritical
  • PermittedEmailAddresses
  • PermittedIPRanges
  • PermittedURIDomains
  • PolicyIdentifiers（见下方说明）
  • Policies（见下方说明）
  • SerialNumber
  • SignatureAlgorithm
  • Subject
  • SubjectKeyId
  • URIs
  • UnknownExtKeyUsage

证书由 parent 签名。如果 parent 与 template 相同，则证书为自签名证书。pub 参数是待生成证书的公钥，priv 是签名方的私钥。

返回的切片是 DER 编码的证书。

当前支持的密钥类型为 *rsa.PublicKey、*ecdsa.PublicKey、ed25519.PublicKey 和 *mldsa.PublicKey。pub 必须是支持的密钥类型；priv 必须是 crypto.Signer 或 crypto.MessageSigner，且具有受支持的公钥。

除非生成的是自签名证书，否则 AuthorityKeyId 会取自 parent 的 SubjectKeyId（如果有）。其他情况下使用 template 中的值。

如果 template 的 SubjectKeyId 为空，且模板是 CA，则根据公钥的哈希值生成 SubjectKeyId。

如果 template.SerialNumber 为 nil，就会使用 rand 提供的熵，生成符合 RFC 5280 第 4.1.2.2 节要求的序列号。

PolicyIdentifier 和 Policies 字段都可用于序列化证书策略 OID。默认只序列化 Policies；如果 GODEBUG 设置 "x509usepolicies" 的值为 "0"，则改为序列化 PolicyIdentifiers，而不是 Policies。这一行为在 Go 1.24 中发生了变化。Policies 字段可用于序列化分量超过 31 位的策略 OID。

IPAddresses 中以 IPv4 映射的 IPv6 形式表示的 IP 地址，始终编码为 IPv4 形式。

func CreateRevocationList 1.15 

func CreateRevocationList(rand io.Reader, template *RevocationList, issuer *Certificate, priv crypto.Signer) ([]byte, error)

CreateRevocationList 根据 template，按照 RFC 5280 创建新的 X.509 v2 Certificate 吊销列表。

CRL 由 priv 签名；priv 应为 crypto.Signer 或 crypto.MessageSigner，并与 issuer 证书中的公钥对应。

issuer 不能为 nil，而且必须在 KeyUsage 中设置 crlSign 位，才能将其用作 CRL 颁发者。

CRL 的颁发者可辨别名称字段和颁发机构密钥标识符扩展，使用 issuer 证书填充。issuer 必须设置 SubjectKeyId。

func DecryptPEMBlock 1.1 

func DecryptPEMBlock(b *pem.Block, password []byte) ([]byte, error)

DecryptPEMBlock 接受按 RFC 1423 加密的 PEM 块及加密时使用的密码，返回解密后的 DER 编码字节切片。它检查 DEK-Info 头字段，以确定解密所用的算法。如果没有 DEK-Info 头字段，则返回错误。如果检测到密码不正确，则返回 IncorrectPasswordError。由于格式本身存在缺陷，并非总能检测出密码错误；此时不会返回错误，但解密后的 DER 字节只是随机噪声。

已弃用：RFC 1423 规定的传统 PEM 加密在设计上不安全。由于不对密文进行认证，它容易遭受填充预言机攻击，攻击者可借此恢复明文。

MarshalPKCS1PrivateKey 将 RSA 私钥转换为 PKCS #1 的 ASN.1 DER 形式。

func SetFallbackRoots
				
				1.20
			

			
func SetFallbackRoots(roots *CertPool)

			
SetFallbackRoots 设置后备根证书，供未指定自定义根证书且平台验证器或系统证书池不可用时进行证书验证（例如在没有根证书包的容器中）。如果 roots 为 nil，SetFallbackRoots 会触发 panic。

SetFallbackRoots 只能调用一次；多次调用会触发 panic。

设置 GODEBUG=x509usefallbackroots=1，可以在所有平台强制使用后备行为，即使存在系统证书池也是如此（注意，在 Windows 和 macOS 上，这会禁用平台验证 API，改用纯 Go 验证器）。未调用 SetFallbackRoots 而仅设置 x509usefallbackroots=1，不产生作用。

func SystemCertPool
					
					1.7
				

				
func SystemCertPool() (*CertPool, error)

				
SystemCertPool 返回系统证书池的副本。

可以分别使用环境变量 SSL_CERT_FILE 和 SSL_CERT_DIR 覆盖系统默认的 SSL 证书文件位置和证书文件目录位置。后者可以是冒号分隔的列表，在 Windows 上则为分号分隔的列表。在具有系统证书验证 API 的平台（macOS 和 Windows）上，设置 SSL_CERT_FILE 或 SSL_CERT_DIR 会阻止使用这些 API，除非设置 GODEBUG 选项 x509sslcertoverrideplatform=0。（这一行为在 Go 1.27 中发生了变化。）

对返回证书池的修改不会写入磁盘，也不会影响 SystemCertPool 返回的任何其他证书池。

系统证书池的新变化可能不会反映在后续调用中。

type Certificate
				
				
			

			
Certificate 表示 X.509 证书。

			
type Certificate struct {
    Raw                     []byte // 完整的 ASN.1 DER 内容（证书、签名算法和签名）。
    RawTBSCertificate       []byte // 原始 ASN.1 DER 内容中的证书部分。
    RawSubjectPublicKeyInfo []byte // DER 编码的 SubjectPublicKeyInfo。
    RawSubject              []byte // DER 编码的主体
    RawIssuer               []byte // DER 编码的颁发者
    RawSignatureAlgorithm   []byte // DER 编码的 AlgorithmIdentifier；Go 1.27 新增

    Signature          []byte
    SignatureAlgorithm SignatureAlgorithm

    PublicKeyAlgorithm PublicKeyAlgorithm
    PublicKey          any

    Version             int
    SerialNumber        *big.Int
    Issuer              pkix.Name
    Subject             pkix.Name
    NotBefore, NotAfter time.Time // 有效期范围。
    KeyUsage            KeyUsage

    // Extensions 包含原始 X.509 扩展。解析证书时，
    // 可用它提取本包不会解析的
    // 非关键扩展。序列化证书时，会忽略 Extensions
    // 字段，参见 ExtraExtensions。
    Extensions []pkix.Extension // Go 1.2

    // ExtraExtensions 包含在序列化证书时应原样复制的
    // 扩展。这些值会覆盖原本根据其他字段
    // 生成的扩展。解析证书时不会填充 ExtraExtensions
    // 字段，参见 Extensions。
    ExtraExtensions []pkix.Extension // Go 1.2

    // UnhandledCriticalExtensions 列出解析时
    // 未（完全）处理的扩展 ID。如果此切片
    // 非空，Verify 会失败，除非将验证委托给
    // 能理解所有关键扩展的操作系统库。
    //
    // 使用方可以通过 Extensions 访问这些扩展，
    // 如果认为某个扩展已得到处理，

func (*Certificate) Verify
					
					
				

				
func (c *Certificate) Verify(opts VerifyOptions) ([][]*Certificate, error)

				
Verify 尝试验证 c：从 c 构建一条或多条通向 opts.Roots 中证书的链，必要时使用 opts.Intermediates 中的证书。成功时，返回一条或多条证书链，每条链的第一个元素为 c，最后一个元素来自 opts.Roots。

如果 opts.Roots 为 nil，可能会使用平台验证器，具体的验证行为可能与下文描述不同。如果系统根证书不可用，则返回 SystemRootsError 类型的错误。

中间证书的名称约束会应用于证书链中声明的所有名称，而不仅是 opts.DNSName。因此，如果某个中间证书不允许 example.com，即使当前验证的名称不是 example.com，叶子证书声明 example.com 仍然无效。注意，不支持 DirectoryName 约束。

名称约束验证遵循 RFC 5280 的规则，并额外允许 DNS 名称约束使用为电子邮件和 URI 定义的前导点号形式。约束以前导点号开头时，表示必须在受约束名称前再添加至少一个标签，才被视为有效。

扩展密钥用途（EKU）限制会沿证书链逐层传递，因此枚举了 EKU 的中间证书或根证书，会禁止叶子证书声明该列表之外的 EKU。（虽然规范未作此要求，但为了限制 CA 可以签发的证书类型，这是常见做法。）

不支持使用 SHA1WithRSA 和 ECDSAWithSHA1 签名的证书，也不会用它们构建证书链。

返回的证书链中，除 c 外的证书都不应修改。

警告：此函数不执行任何吊销检查。

    RawTBSRevocationList []byte // Go 1.19
    // RawIssuer 包含 DER 编码的颁发者。
    RawIssuer []byte // Go 1.19
    // RawSignatureAlgorithm 包含 DER 编码的签名算法，形式为
    // PKIX AlgorithmIdentifier。
    RawSignatureAlgorithm []byte // Go 1.27

    // Issuer 包含颁发者证书的 DN。
    Issuer pkix.Name // Go 1.19
    // AuthorityKeyId 用于标识与颁发者证书关联的
    // 公钥。解析 CRL 时，它由 authorityKeyIdentifier
    // 扩展填充。创建 CRL 时忽略此字段；
    // 该扩展直接使用颁发者证书本身的信息填充。
    AuthorityKeyId []byte // Go 1.19

    Signature []byte // Go 1.19
    // SignatureAlgorithm 用于确定签署 CRL 时
    // 使用的签名算法。如果为 0，则使用签名密钥
    // 对应的默认算法。
    SignatureAlgorithm SignatureAlgorithm

    // RevokedCertificateEntries 表示 CRL 中的 revokedCertificates 序列。
    // 创建 CRL 时使用它，解析 CRL 时也会填充它。
    // 创建 CRL 时，它可以为空或 nil；此时会从 CRL 中
    // 完全省略 revokedCertificates ASN.1 序列。
    RevokedCertificateEntries []RevocationListEntry // Go 1.21

    // 当 RevokedCertificateEntries 为空时，RevokedCertificates 用于填充
    // CRL 中的 revokedCertificates 序列。它可以为空
    // 或 nil，此时会创建空 CRL。
    //
    // 已弃用：请改用 RevokedCertificateEntries。
    RevokedCertificates []pkix.RevokedCertificate

    // Number 用于填充 CRL 中的 X.509 v2 cRLNumber 扩展，
    // 对于给定的 CRL 范围和颁发者，此值应为单调递增的
    // 序列号。解析 CRL 时，也会根据 cRLNumber
    // 扩展填充此字段。
    Number *big.Int

    // ThisUpdate 用于填充 CRL 中的 thisUpdate 字段，
    // 表示 CRL 的签发时间。
    ThisUpdate time.Time
    // NextUpdate 用于填充 CRL 中的 nextUpdate 字段，
    // 表示下一份 CRL 最迟签发的时间。NextUpdate
    // 必须晚于 ThisUpdate。
    NextUpdate time.Time

    // Extensions 包含原始 X.509 扩展。创建 CRL 时，
    // 会忽略 Extensions 字段，参见 ExtraExtensions。
    Extensions []pkix.Extension // Go 1.19

    // ExtraExtensions 包含要直接添加到
    // CRL 中的额外扩展。
    ExtraExtensions []pkix.Extension
}

type RevocationListEntry
				
				1.21
			

			
RevocationListEntry 表示 CRL 的 revokedCertificates 序列中的条目。

			
type RevocationListEntry struct {
    // Raw 包含 revokedCertificates 条目的原始字节。解析 CRL 时设置；
    // 生成 CRL 时忽略。
    Raw []byte

    // SerialNumber 表示已吊销证书的序列号。
    // 创建 CRL 时使用它，解析 CRL 时也会填充它。不得
    // 为 nil。
    SerialNumber *big.Int
    // RevocationTime 表示证书被吊销的时间。
    // 创建 CRL 时使用它，解析 CRL 时也会填充它。不得
    // 为零值时间。
    RevocationTime time.Time
    // ReasonCode 表示吊销原因，使用 RFC 5280
    // 第 5.3.1 节规定的整数枚举值。创建 CRL 时，零值
    // 会使 reasonCode 扩展被省略。解析 CRL 时，
    // 零值既可能表示没有 reasonCode 扩展
    // （这意味着默认吊销原因为 0/Unspecified），
    // 也可能表示存在 reasonCode 扩展，且显式
    // 包含值 0/Unspecified（按 DER 编码规则不应发生，
    // 但实际仍可能出现）。
    ReasonCode int

    // Extensions 包含原始 X.509 扩展。解析 CRL 条目时，
    // 可用它提取本包不会解析的
    // 非关键扩展。序列化 CRL 条目时，会忽略 Extensions
    // 字段，参见 ExtraExtensions。
    Extensions []pkix.Extension
    // ExtraExtensions 包含在序列化 CRL 条目时应原样复制的
    // 扩展。这些值会覆盖原本根据其他字段
    // 生成的扩展。解析 CRL 条目时，不会填充 ExtraExtensions
    // 字段，参见 Extensions。
    ExtraExtensions []pkix.Extension
}

type VerifyOptions
				
				
			

			
VerifyOptions 包含 Certificate.Verify 的参数。

			
type VerifyOptions struct {
    // 如果设置了 DNSName，会通过 Certificate.VerifyHostname
    // 或平台验证器对叶子证书进行主机名验证。
    DNSName string

    // Intermediates 是可选的证书池，其中的证书不是信任
    // 锚点，但可用于构建从叶子证书到
    // 根证书的证书链。
    Intermediates *CertPool
    // Roots 是叶子证书必须通过证书链连接到的受信任根证书集合。
    // 如果为 nil，则使用系统根证书或平台验证器。
    Roots *CertPool

    // CurrentTime 用于检查证书链中所有证书的
    // 有效期。如果为零值，则使用当前时间。
    CurrentTime time.Time

    // KeyUsages 指定可接受的扩展密钥用途值。
    // 只要证书链允许列表中的任意值，就会被接受。空列表
    // 表示 ExtKeyUsageServerAuth。若要接受任意密钥用途，请包含 ExtKeyUsageAny。
    KeyUsages []ExtKeyUsage // Go 1.1

    // MaxConstraintComparisions 指定检查某个证书的名称约束时
    // 允许执行的最大比较次数。如果
    // 为零，则使用合理的默认值。此限制用于防止异常
    // 证书在验证过程中消耗过多的 CPU
    // 时间。它不适用于平台验证器。
    MaxConstraintComparisions int // Go 1.10

    // CertificatePolicies 指定策略验证期间可接受的
    // 证书策略 OID。CertificatePolices 字段为空
    // 表示接受任意有效策略。
    CertificatePolicies []OID // Go 1.24
    // 包含已过滤或未导出的字段
}
