rsa 包实现 PKCS #1 和 RFC 8017 规定的 RSA 加密。

RSA 本身是一种基本运算，本包用它实现公钥加密和公钥签名。

RSA 加密和签名最初的规范是 PKCS #1，术语“RSA 加密”和“RSA 签名”默认指 PKCS #1 第 1.5 版。不过，该规范存在缺陷，新的设计应尽可能使用第 2 版，通常直接称为 OAEP 和 PSS。

本包包含两组接口。不需要更抽象的接口时，可以使用函数通过 v1.5/OAEP 加密和解密，或通过 v1.5/PSS 签名和验证。如果需要对公钥原语进行抽象，PrivateKey 类型实现了 crypto 包中的 Decrypter 和 Signer 接口。

涉及私钥的操作使用常量时间算法实现，但 GenerateKey 以及涉及已弃用的多素数密钥的某些操作除外。

最小密钥长度

请求生成少于 1024 位的密钥时，GenerateKey 返回错误；所有 Sign、Verify、Encrypt 和 Decrypt 方法在使用少于 1024 位的密钥时也会返回错误。此类密钥不安全，不应使用。

GODEBUG 设置 rsa1024min=0 可以抑制此错误，但建议仅在测试确有需要时这样做。测试可以通过 testing.T.Setenv 设置此选项，也可以在 *_test.go 源文件中添加 "//go:debug rsa1024min=0"。

也可以参阅 GenerateKey (TestKey) 示例，其中提供了预先生成、仅供测试使用的 2048 位密钥。

func DecryptPKCS1v15 

func DecryptPKCS1v15(random io.Reader, priv *PrivateKey, ciphertext []byte) ([]byte, error)

DecryptPKCS1v15 使用 RSA 和 PKCS #1 v1.5 的填充方案解密得到明文。random 参数是历史遗留参数，会被忽略，可以为 nil。

func DecryptPKCS1v15SessionKey 

func DecryptPKCS1v15SessionKey(random io.Reader, priv *PrivateKey, ciphertext []byte, key []byte) error

DecryptPKCS1v15SessionKey 使用 RSA 和 PKCS #1 v1.5 的填充方案解密会话密钥。random 参数是历史遗留参数，会被忽略，可以为 nil。

如果密文长度错误，或密文的数值大于公钥模数，DecryptPKCS1v15SessionKey 返回错误。否则不返回错误。如果填充有效，就将解密得到的明文复制到 key；否则保持 key 不变。这两种情况均以常量时间执行。此函数的预期用法是调用方预先生成随机会话密钥，然后使用最终得到的值继续执行协议。

注意，如果会话密钥过短，攻击者可能通过穷举破解。若能做到这一点，就能判断是否使用了随机值（因为同一密文对应的随机值每次不同），进而判断填充是否正确，这会使此函数失去意义。使用至少 16 字节的密钥可以防御此攻击。

此方法实现 RFC 3218 第 2.3.2 节 [1] 描述的针对 Bleichenbacher 选择密文攻击 [0] 的防护。虽然这些措施大幅提高了 Bleichenbacher 攻击的难度，但只有使用 DecryptPKCS1v15SessionKey 的协议在其余部分的设计中也考虑到这些问题，防护才有效。尤其是，如果后续使用解密会话密钥的任何操作泄露了有关密钥的信息（例如它是固定密钥还是随机密钥），就会破坏这些缓解措施。必须极其谨慎地使用此方法；通常只有为兼容已在设计中考虑这些性质的现有协议（例如 TLS），且确有必要时，才应使用。

  • [0]《针对基于 RSA 加密标准 PKCS #1 的协议的选择密文攻击》（“Chosen Ciphertext Attacks Against Protocols Based on the RSA Encryption Standard PKCS #1”），Daniel Bleichenbacher，《密码学进展》（Crypto '98）。
  • [1] RFC 3218，《防止针对 CMS 的百万消息攻击》（Preventing the Million Message Attack on CMS），https://www.rfc-editor.org/rfc/rfc3218.html。

已弃用：PKCS #1 v1.5 加密存在危险，不应使用。如上所述，此函数实现的防护有限且脆弱。更多信息参见 draft-irtf-cfrg-rsa-guidance-05。请改用 EncryptOAEP 和 DecryptOAEP。

RSA 只能加密非常有限的数据量。要加密实际需要处理的数据量，通常采用混合方案：使用 RSA 加密供 AES-GCM 等对称密码原语使用的密钥。 加密之前，会将数据嵌入已知结构来进行“填充”。这样做有多种原因，最明显的是保证数值足够大，使幂运算结果大于模数。（否则就可以通过开方解密。） 在这类设计中，使用 PKCS #1 v1.5 时，必须避免泄露收到的 RSA 消息格式是否正确（即解密结果是否为填充正确的消息），因为这会泄露秘密信息。DecryptPKCS1v15SessionKey 专为这种情况设计，会以常量时间将解密得到的对称密钥（若格式正确）复制到一个原本含有随机密钥的缓冲区。因此，如果 RSA 结果格式不正确，实现就会以常量时间使用随机密钥。

代码：

// 混合方案应使用至少 16 字节的对称密钥。这里
// 读取随机密钥，以便在 RSA 解密结果格式
// 不正确时使用。
key := make([]byte, 32)
if _, err := rand.Read(key); err != nil {
    panic("RNG failure")
}

rsaCiphertext, _ := hex.DecodeString("aabbccddeeff")

if err := rsa.DecryptPKCS1v15SessionKey(nil, rsaPrivateKey, rsaCiphertext, key); err != nil {
    // 产生的所有错误都是“公开的”，即无需
    // 任何秘密信息即可判断这些错误。（例如，
    // 对于给定 RSA 公钥，key 的长度
    // 不可能成立。）
    fmt.Fprintf(os.Stderr, "Error from RSA decryption: %s\n", err)
    return
}

// 得到密钥后，就可以使用对称方案解密
// 更长的密文。
block, err := aes.NewCipher(key)
if err != nil {
    panic("aes.NewCipher failed: " + err.Error())
}

// 由于密钥是随机的，可以使用固定 nonce，
// 因为 (key, nonce) 组合仍满足唯一性要求。
var zeroNonce [12]byte
aead, err := cipher.NewGCM(block)
if err != nil {
    panic("cipher.NewGCM failed: " + err.Error())
}
ciphertext, _ := hex.DecodeString("00112233445566")
plaintext, err := aead.Open(nil, zeroNonce[:], ciphertext, nil)
if err != nil {
    // RSA 密文格式不正确；由于 AES-GCM 密钥错误，
    // 解密将在这里失败。
    fmt.Fprintf(os.Stderr, "Error decrypting: %s\n", err)
    return
}

fmt.Printf("Plaintext: %s\n", plaintext)

func EncryptOAEP 

func EncryptOAEP(hash hash.Hash, random io.Reader, pub *PublicKey, msg []byte, label []byte) ([]byte, error)

EncryptOAEP 使用 RSA-OAEP 加密给定消息。

OAEP 以一个用作随机预言机的哈希函数作为参数。对同一消息加密和解密必须使用相同的哈希函数，sha256.New() 是合理的选择。

random 参数用作熵源，确保对同一消息加密两次不会得到相同密文。多数应用程序应使用 crypto/rand.Reader 作为 random。

label 参数可以包含任意数据，这些数据不会被加密，但为消息提供重要上下文。例如，如果同一公钥用于加密两类消息，可以使用不同的 label 值，确保攻击者无法将一种用途的密文挪作另一用途。如果不需要，label 可以为空。

消息长度不得超过公钥模数的字节长度减去两倍哈希长度，再减 2。

▸ 示例

▾ 示例

代码：

secretMessage := []byte("send reinforcements, we're going to advance")
label := []byte("orders")

// crypto/rand.Reader 是用于对加密函数进行随机化的
// 良好熵源。
rng := rand.Reader

ciphertext, err := rsa.EncryptOAEP(sha256.New(), rng, &test2048Key.PublicKey, secretMessage, label)
if err != nil {
    fmt.Fprintf(os.Stderr, "Error from encryption: %s\n", err)
    return
}

// 由于加密函数是随机化的，每次生成的密文
// 都会不同。
fmt.Printf("Ciphertext: %x\n", ciphertext)

func SignPKCS1v15 

func SignPKCS1v15(random io.Reader, priv *PrivateKey, hash crypto.Hash, hashed []byte) ([]byte, error)

SignPKCS1v15 使用 RSA PKCS #1 v1.5 中的 RSASSA-PKCS1-V1_5-SIGN 计算 hashed 的签名。注意，hashed 必须是使用给定哈希函数对输入消息计算得到的哈希值。如果 hash 为零，则直接对 hashed 签名；除互操作需要外，不建议这样做。

random 参数是历史遗留参数，会被忽略，可以为 nil。

此函数是确定性的。因此，如果可能的消息集合很小，攻击者或许能够建立消息到签名的映射，从而识别被签名的消息。签名始终提供真实性，而不提供机密性。

▸ 示例

▾ 示例

代码：

message := []byte("message to be signed")

// 只有短消息才能直接签名，因此签名针对消息的
// 哈希值，而非消息本身。这要求
// 哈希函数具有抗碰撞性。在本文撰写时
// （2016 年），SHA-256 是此用途应采用的
// 最低强度哈希函数。
hashed := sha256.Sum256(message)

signature, err := rsa.SignPKCS1v15(nil, rsaPrivateKey, crypto.SHA256, hashed[:])
if err != nil {
    fmt.Fprintf(os.Stderr, "Error from signing: %s\n", err)
    return
}

fmt.Printf("Signature: %x\n", signature)

func SignPSS 1.2 

func SignPSS(random io.Reader, priv *PrivateKey, hash crypto.Hash, digest []byte, opts *PSSOptions) ([]byte, error)

SignPSS 使用 PSS 计算 digest 的签名。

digest 必须是使用给定哈希函数对输入消息计算得到的哈希值。opts 参数可以为 nil，此时使用合理的默认值。如果设置了 opts.Hash，它会覆盖 hash。

func VerifyPKCS1v15 

func VerifyPKCS1v15(pub *PublicKey, hash crypto.Hash, hashed []byte, sig []byte) error

VerifyPKCS1v15 验证 RSA PKCS #1 v1.5 签名。hashed 是使用给定哈希函数对输入消息计算得到的哈希值，sig 是签名。返回 nil 错误表示签名有效。如果 hash 为零，则直接使用 hashed；除互操作需要外，不建议这样做。

输入不被视为机密信息，可能通过计时侧信道泄露，或在攻击者能够控制部分输入时泄露。

type PrecomputedValues struct {
    Dp, Dq *big.Int // D mod (P-1) (or mod Q-1)
    Qinv   *big.Int // Q^-1 mod P

    // CRTValues 用于第三个及后续素数。由于
    // 历史原因，PKCS #1 对前两个素数的 CRT 采用
    // 不同处理方式；为了保证互操作性，
    // 本实现也遵循这一做法。
    //
    // 已弃用：出于向后兼容，Precompute 仍会填入
    // 这些值，但不会使用它们。多素数 RSA 非常少见，
    // 本包实现时不使用 CRT 优化，
    // 以限制复杂度。
    CRTValues []CRTValue
    // 包含已过滤或未导出的字段
}

调用 PrivateKey.Precompute 后，不得修改其字段，也不应直接将这些字段作为 big.Int 值用于密码学操作。

    PublicKey            // 公开部分。

func GenerateMultiPrimeKey
					
					
				

				
func GenerateMultiPrimeKey(random io.Reader, nprimes int, bits int) (*PrivateKey, error)

				
GenerateMultiPrimeKey 使用给定随机源，生成给定位数的多素数 RSA 密钥对。

《论多素数 RSA 的安全性》中的表 1 给出了不同位数下建议使用的最大素数数量。

虽然公钥与两个素数的情形兼容（实际上无法区分），但私钥并不兼容。因此，可能无法以某些格式导出多素数私钥，或随后将其导入其他实现。

func (*PrivateKey) Precompute
					
					
				

				
func (priv *PrivateKey) Precompute()

				
Precompute 执行一些计算，以加快后续私钥操作。它可以安全地用于尚未验证的私钥，并且对于有效密钥，可以加快后续对 PrivateKey.Validate 的调用。

Precompute 会写入 Precomputed 字段，因此不得与任何其他方法并发调用。

Precompute 不返回错误。应用程序应在 Precompute 之后调用 PrivateKey.Validate，检查密钥是否存在问题，包括会导致 Precompute 失败的问题。

对已经预计算的密钥调用 Precompute 不产生任何作用。

func (*PrivateKey) Sign
					
					1.4
				

				
func (priv *PrivateKey) Sign(rand io.Reader, digest []byte, opts crypto.SignerOpts) ([]byte, error)

				
Sign 使用 priv 对 digest 签名，并从 rand 读取随机数据。如果 opts 为 *PSSOptions，则使用 PSS 算法；否则使用 PKCS #1 v1.5。digest 必须是使用 opts.HashFunc() 对输入消息计算得到的哈希值。
