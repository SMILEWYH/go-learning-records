driver 包定义供 sql 包使用的数据库驱动必须实现的接口。

大多数代码应使用 database/sql 包。

驱动接口一直在演进。驱动应实现 Connector 和 DriverContext 接口。Connector.Connect 和 Driver.Open 方法绝不应返回 ErrBadConn。只有连接已处于无效状态（例如已关闭）时，才应从 Validator、SessionResetter 或查询方法返回 ErrBadConn。

所有 Conn 实现都应实现以下接口：Pinger、SessionResetter 和 Validator。

如果支持命名参数或 context，驱动的 Conn 应实现：ExecerContext、QueryerContext、ConnPrepareContext 和 ConnBeginTx。

要支持自定义数据类型，请实现 NamedValueChecker。NamedValueChecker 还允许通过参数接受针对单次查询的选项，此时从 CheckNamedValue 返回 ErrRemoveArgument。

如果支持多个结果集，Rows 应实现 RowsNextResultSet。如果驱动能够描述返回结果中的类型，应实现以下接口：RowsColumnTypeScanType、RowsColumnTypeDatabaseTypeName、RowsColumnTypeLength、RowsColumnTypeNullable 和 RowsColumnTypePrecisionScale。某个行值也可以返回 Rows 类型，用来表示数据库游标值。

如果 Conn 实现 Validator，在将连接放回连接池前会调用 IsValid 方法。如果连接池中的条目实现 SessionResetter，在复用该连接执行另一次查询前会调用 ResetSession。如果连接没有归还连接池就立即被复用，则复用前会调用 ResetSession，但不会调用 IsValid。

Bool 是将输入值转换为 bool 的 ValueConverter。

转换规则如下：

  • 布尔值原样返回
  • 对于整数类型，1 为 true，0 为 false，其他整数会报错
  • 对于字符串和 []byte，规则与 strconv.ParseBool 相同
  • 其他所有类型都会报错
var Bool boolType

DefaultParameterConverter 是 ValueConverter 的默认实现，在 Stmt 未实现 ColumnConverter 时使用。

如果 IsValue(arg) 为 true，DefaultParameterConverter 直接返回其参数。否则，如果参数实现了 Valuer，就调用其 Value 方法返回 Value。后备处理使用参数的底层类型，将其转换为 Value：底层整数类型转换为 int64，浮点类型转换为 float64，bool、string 和 []byte 保持不变。如果参数是 nil 指针，defaultConverter.ConvertValue 返回 nil Value。如果参数是非 nil 指针，则解引用后递归调用 defaultConverter.ConvertValue。其他类型会报错。

var DefaultParameterConverter defaultConverter

驱动应返回 ErrBadConn，向 database/sql 包表明某个 driver.Conn 状态异常（例如服务端此前已关闭连接），database/sql 包应在新连接上重试。

为防止重复操作，只要数据库服务端有可能已经执行该操作，就绝不能返回 ErrBadConn。即使服务端返回错误，也不应返回 ErrBadConn。

错误会使用 errors.Is 检查。错误可以包装 ErrBadConn，或实现 Is(error) bool 方法。

var ErrBadConn = errors.New("driver: bad connection")

NamedValueChecker 可以返回 ErrRemoveArgument，指示 database/sql 包不要将该参数传给驱动的查询接口。在接受查询专用选项或不属于 SQL 查询参数的结构时返回此错误。

var ErrRemoveArgument = errors.New("driver: remove argument from query")

某些可选接口的方法可以返回 ErrSkip，表示运行时无法使用快速路径，sql 包应按未实现该可选接口的方式继续执行。只有文档明确说明的地方才支持 ErrSkip。

var ErrSkip = errors.New("driver: skip fast-path; continue as if unimplemented")

type Conn

Conn 是数据库连接。它不会被多个 goroutine 并发使用。

Conn 被视为有状态的。

type Conn interface {
    // Prepare 返回绑定到此连接的预处理语句。
    Prepare(query string) (Stmt, error)

    // Close 使当前的预处理语句和事务失效，
    // 并可能终止它们，同时将此连接
    // 标记为不再使用。
    //
    // 由于 sql 包维护了空闲连接池，
    // 并且只有空闲连接过多时才调用 Close，
    // 驱动通常不需要
    // 自行缓存连接。
    //
    // 驱动必须确保 Close 发起的所有网络调用
    // 不会无限期阻塞（例如设置超时）。
    Close() error

    // Begin 启动并返回新事务。
    //
    // 已弃用：驱动应改为（或额外）实现 ConnBeginTx。
    Begin() (Tx, error)
}

type ConnBeginTx 1.8

ConnBeginTx 为 Conn 接口增加 context 和 TxOptions 支持。

type ConnBeginTx interface {
    // BeginTx 启动并返回新事务。
    // 如果用户取消 context，sql 包会在
    // 丢弃并关闭连接之前调用 Tx.Rollback。
    //
    // 必须检查 opts.Isolation，确定是否设置了
    // 隔离级别。如果设置了非默认级别，而驱动不支持
    // 非默认级别，或者所设置的具体非默认隔离级别
    // 不受支持，必须返回错误。
    //
    // 还必须检查 opts.ReadOnly，确定只读值
    // 是否为 true；如果支持，就设置事务的只读属性，
    // 否则返回错误。
    BeginTx(ctx context.Context, opts TxOptions) (Tx, error)
}

type ConnPrepareContext interface {

type Connector 1.10

Connector 表示具有固定配置的驱动，可以创建任意数量的等价 Conn，供多个 goroutine 使用。

Connector 可以传给 database/sql.OpenDB，让驱动实现自己的 database/sql.DB 构造函数；也可以由 DriverContext 的 OpenConnector 方法返回，让驱动能访问 context，并避免重复解析驱动配置。

如果 Connector 实现 io.Closer，database/sql.DB.Close 方法会调用其 Close 方法，并返回产生的错误（如果有）。

type Connector interface {
    // Connect 返回数据库连接。
    // Connect 可以返回缓存的连接（此前已
    // 关闭的连接），但没有必要；sql 包
    // 维护了空闲连接池，以高效复用连接。
    //
    // 传入的 context.Context 仅用于建立连接
    // （参见 net.DialContext），不应保存它，或将它用于
    // 其他用途。建立连接时仍应采用默认超时，
    // 因为连接池可能独立于任何查询
    // 异步调用 Connect。
    //
    // 返回的连接在同一时刻仅会被一个 goroutine
    // 使用。
    Connect(context.Context) (Conn, error)

    // Driver 返回 Connector 的底层 Driver，
    // 主要用于保持与 sql.DB 上
    // Driver 方法的兼容性。
    Driver() Driver
}

type Driver

Driver 是数据库驱动必须实现的接口。

数据库驱动可以实现 DriverContext，以访问 context，并针对整个连接池仅解析一次 name，而不是对每个连接分别解析。

type Driver interface {
    // Open 返回新的数据库连接。
    // name 是采用驱动专有格式的字符串。
    //
    // Open 可以返回缓存的连接（此前已
    // 关闭的连接），但没有必要；sql 包
    // 维护了空闲连接池，以高效复用连接。
    //
    // 返回的连接在同一时刻仅会被一个 goroutine
    // 使用。
    Open(name string) (Conn, error)
}

type DriverContext 1.10

如果 Driver 实现 DriverContext，database/sql.DB 会调用 OpenConnector 获得 Connector，然后调用该 Connector 的 Connect 方法获取每个所需连接，而不是对每个连接调用 Driver 的 Open 方法。这两个步骤使驱动只需解析一次 name，同时可以访问每个 Conn 的 context。

type DriverContext interface {
    // OpenConnector 必须使用与 Driver.Open 解析 name 参数
    // 相同的格式来解析 name。
    OpenConnector(name string) (Connector, error)
}

type NamedValueChecker 1.9

Conn 或 Stmt 可以选择实现 NamedValueChecker。它给予驱动更多控制能力，以处理默认允许的 Value 类型以外的 Go 类型和数据库类型。

database/sql 包按以下顺序查找值检查器，并在找到第一个匹配项后停止：Stmt.NamedValueChecker、Conn.NamedValueChecker、Stmt.ColumnConverter、DefaultParameterConverter。

如果 CheckNamedValue 返回 ErrRemoveArgument，该 NamedValue 不会包含在最终查询参数中。这可用于向查询本身传递特殊选项。

如果返回 ErrSkip，会对该参数使用列转换器的错误检查路径。驱动处理完自己的所有特殊情况后，可以返回 ErrSkip。

type NamedValueChecker interface {
    // CheckNamedValue 在将参数传给驱动前调用，
    // 并替代任何 ColumnConverter。CheckNamedValue 必须根据驱动要求
    // 进行类型验证和转换。
    CheckNamedValue(*NamedValue) error
}

type Rows

Rows 是用于遍历已执行查询结果的迭代器。

type Rows interface {
    // Columns 返回列名。结果的列数
    // 由返回切片的长度
    // 推导得出。如果不知道某列的名称，应在对应位置
    // 返回空字符串。
    Columns() []string

    // Close 关闭行迭代器。
    Close() error

    // 调用 Next 将下一行数据填入
    // 提供的切片。该切片的长度
    // 与 Columns() 的列数相同。
    //
    // 没有更多行时，Next 应返回 io.EOF。
    //
    // 不得在 Next 以外写入 dest。关闭 Rows 时
    // 应注意不要修改
    // dest 中持有的缓冲区。
    Next(dest []Value) error
}

type Stmt

Stmt 是预处理语句。它绑定到一个 Conn，不会被多个 goroutine 并发使用。

type Stmt interface {
    // Close 关闭语句。
    //
    // 从 Go 1.1 开始，正在被任何查询使用的 Stmt
    // 不会被关闭。
    //
    // 驱动必须确保 Close 发起的所有网络调用
    // 不会无限期阻塞（例如设置超时）。
    Close() error

    // NumInput 返回占位参数的数量。
    //
    // 如果 NumInput 返回 >= 0，sql 包会检查
    // 调用方传入的参数数量是否合理，并在调用语句的
    // Exec 或 Query 方法之前向调用方返回错误。
    //
    // 如果驱动不知道占位参数的数量，
    // NumInput 也可以返回 -1。这时 sql 包
    // 不会检查 Exec 或 Query 的参数数量。
    NumInput() int

    // Exec 执行不返回行的查询，例如
    // INSERT 或 UPDATE。
    //
    // 已弃用：驱动应改为（或额外）实现 StmtExecContext。
    Exec(args []Value) (Result, error)

    // Query 执行可能返回行的查询，例如
    // SELECT。
    //
    // 已弃用：驱动应改为（或额外）实现 StmtQueryContext。
    Query(args []Value) (Rows, error)
}

    // QueryContext 执行可能返回行的查询，例如
    // SELECT。
    //
    // QueryContext 必须遵守 context 的超时要求，并在其被取消时返回。
    QueryContext(ctx context.Context, args []NamedValue) (Rows, error)
}

type Validator 1.15

Conn 可以实现 Validator，让驱动报告连接是否有效，或者是否应被丢弃。

如果实现了此接口，即使连接应由连接池丢弃，驱动也可以从查询中返回底层错误。

type Validator interface {

    IsValid() bool
}

type Value

Value 是驱动必须能够处理的值。它可以是 nil、数据库驱动的 NamedValueChecker 接口能够处理的类型，或以下类型之一的实例：

int64
float64
bool
[]byte
string
time.Time

如果驱动支持游标，返回的 Value 也可以实现本包中的 Rows 接口。例如，当用户选择游标时会用到这一点，如 "select cursor(select * from my_table) from dual"。如果 select 返回的 Rows 被关闭，游标的 Rows 也会被关闭。

type Value any

type ValueConverter

ValueConverter 是提供 ConvertValue 方法的接口。

driver 包提供了多种 ValueConverter 实现，使不同驱动之间的转换实现保持一致。ValueConverter 有以下用途：

  • 将 sql 包提供的 Value 类型转换为数据库表的特定列类型，并确保值适合该列，例如确保某个 int64 值能存入表的 uint16 列。

  • 将数据库给出的值转换为驱动的某个 Value 类型。

  • 由 database/sql 包在扫描时，将驱动的 Value 类型转换为用户的类型。

type ValueConverter interface {
    // ConvertValue 将值转换为驱动的 Value。
    ConvertValue(v any) (Value, error)
}

type Valuer

Valuer 是提供 Value 方法的接口。

Value 方法返回的错误会由 database/sql 包包装。这样，调用方可在 database/sql.Query、database/sql.Exec 或 database/sql.QueryRow 等操作后，使用 errors.Is 进行精确的错误处理。

实现 Valuer 接口的类型能够将自身转换为驱动的 Value。

type Valuer interface {
    // Value 返回驱动的 Value。
    // Value 不得引发 panic。
    Value() (Value, error)
}
