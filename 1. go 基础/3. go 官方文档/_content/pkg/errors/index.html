errors 包提供操作错误的函数。

New 函数创建内容仅包含一条文本消息的错误。

如果错误 e 的类型具有以下任意一种方法，就表示 e 可以包装另一个错误： 

Unwrap() error
Unwrap() []error

如果 e.Unwrap() 返回非 nil 错误 w，或返回包含 w 的切片，我们就说 e 包装了 w。e.Unwrap() 返回 nil 错误表示 e 没有包装任何错误。Unwrap 方法返回的 []error 中不得包含 nil 错误值。

创建包装错误的一种简单方式是调用 fmt.Errorf，并对错误实参使用 %w 格式动词： 

wrapsErr := fmt.Errorf("... %w ...", ..., err, ...)

对错误逐层解包会得到一棵树。Is 和 As 函数检查错误树时，先检查错误本身，再依次检查各个子错误的树，即采用先序的深度优先遍历。

关于错误包装的设计理念，以及何时应该包装错误，详见 https://go.dev/blog/go1.13-errors。

Is 在第一个实参的错误树中查找与第二个实参匹配的错误，并报告是否找到匹配项。应优先使用它，而不是直接比较是否相等： 

if errors.Is(err, fs.ErrExist)

优于 

if err == fs.ErrExist

因为即使 err 包装了 io/fs.ErrExist，前一种写法也能匹配成功。

AsType 在实参的错误树中查找类型与其类型实参匹配的错误。如果找到，就返回该类型的相应值和 true；否则返回该类型的零值和 false。以下写法 

if perr, ok := errors.AsType[*fs.PathError](err); ok {
	fmt.Println(perr.Path)
}

优于 

if perr, ok := err.(*fs.PathError); ok {
	fmt.Println(perr.Path)
}

因为即使 err 包装了 *io/fs.PathError，前一种写法也能匹配成功。

ErrUnsupported 表示请求的操作不受支持，因而无法执行。例如，在不支持硬链接的文件系统上调用 os.Link。

函数和方法不应直接返回这个错误，而应返回一个包含适当上下文、且满足以下条件的错误： 

errors.Is(err, errors.ErrUnsupported)

可以通过直接包装 ErrUnsupported，或实现 Is 方法来满足这个条件。

函数和方法的文档应说明在哪些情况下会返回包装了这个错误的错误。 

var ErrUnsupported = New("unsupported operation")

func As 1.13 

func As(err error, target any) bool

As 在 err 的错误树中查找第一个与 target 匹配的错误。如果找到，就将 target 设置为该错误值并返回 true；否则返回 false。

在大多数场景中，应优先使用 AsType。As 与 AsType 的作用等价，但它通过设置 target 实参返回匹配的错误，而不是直接返回该错误，并且不要求 target 实参实现 error 接口。

错误树由 err 自身，以及反复调用其 Unwrap() error 或 Unwrap() []error 方法得到的错误组成。当 err 包装多个错误时，As 先检查 err，再按深度优先顺序遍历它的子错误。

如果错误的具体值可赋给 target 指向的值，或者该错误具有 As(any) bool 方法且 As(target) 返回 true，就认为该错误与 target 匹配。后一种情况下，As 方法负责设置 target。

错误类型可以提供 As 方法，使其能够被当作另一种错误类型处理。

target 必须是非 nil 指针，指向实现了 error 的类型或任意接口类型，否则 As 会触发 panic。

func AsType 

func AsType[E error](err error) (E, bool)

AsType 在 err 的错误树中查找第一个与类型 E 匹配的错误。如果找到，就返回该错误值和 true；否则返回 E 的零值和 false。

错误树由 err 自身，以及反复调用其 Unwrap() error 或 Unwrap() []error 方法得到的错误组成。当 err 包装多个错误时，AsType 先检查 err，再按深度优先顺序遍历它的子错误。

如果类型断言 err.(E) 成功，或者错误具有 As(any) bool 方法，且当 target 为非 nil 的 *E 时 err.As(target) 返回 true，就认为错误 err 与类型 E 匹配。后一种情况下，As 方法负责设置 target。

func Is 1.13 

func Is(err, target error) bool

Is 报告 err 的错误树中是否存在与 target 匹配的错误。target 必须可比较。

错误树由 err 自身，以及反复调用其 Unwrap() error 或 Unwrap() []error 方法得到的错误组成。当 err 包装多个错误时，Is 先检查 err，再按深度优先顺序遍历它的子错误。

如果一个错误等于 target，或者实现了 Is(error) bool 方法且 Is(target) 返回 true，就认为它与 target 匹配。

错误类型可以提供 Is 方法，使其能够被视为与某个已有错误等价。例如，如果 MyError 定义了 

func (m MyError) Is(target error) bool { return target == fs.ErrExist }

那么 Is(MyError{}, fs.ErrExist) 就会返回 true。标准库中的示例见 syscall.Errno.Is。Is 方法只应对 err 和 target 进行浅层比较，不应对任一方调用 Unwrap。

func Join 1.20 

func Join(errs ...error) error

Join 返回一个包装了给定所有错误的错误。nil 错误值会被忽略。如果 errs 中所有值都是 nil，Join 返回 nil。返回错误的文本表示由 errs 各元素的 Error 方法所返回的字符串拼接而成，各字符串之间以换行符分隔。

Join 返回的非 nil 错误实现了 Unwrap() []error 方法。可以使用 Is 和 As 检查这些错误。

func Unwrap 1.13 

func Unwrap(err error) error

如果 err 的类型具有返回 error 的 Unwrap 方法，Unwrap 返回调用该方法的结果；否则返回 nil。

Unwrap 只调用形式为“Unwrap() error”的方法。特别是，Unwrap 不会解包 Join 返回的错误。
