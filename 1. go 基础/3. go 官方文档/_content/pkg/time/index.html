time 包提供测量和显示时间的功能。

历法计算始终采用公历，不考虑闰秒。

单调时钟

操作系统同时提供“墙上时钟”和“单调时钟”：前者会因时钟同步而调整，后者不会。一般原则是，墙上时钟用于表示当前时间，单调时钟用于测量经过的时间。本包没有为此拆分 API，而是让 time.Now 返回的 Time 同时包含墙上时钟读数和单调时钟读数；之后表示时间的操作使用墙上时钟读数，而测量时间的操作，具体来说是比较和相减，则使用单调时钟读数。

例如，即使测量期间墙上时钟发生变化，下面的代码也总会计算出约 20 毫秒的正数耗时： 

start := time.Now()
... operation that takes 20 milliseconds ...
t := time.Now()
elapsed := t.Sub(start)

其他惯用写法，如 time.Since(start)、time.Until(deadline) 和 time.Now().Before(deadline)，同样不会受墙上时钟重设的影响。

本节余下内容精确说明各类操作如何使用单调时钟，但使用本包并不要求掌握这些细节。

time.Now 返回的 Time 包含单调时钟读数。如果 Time t 包含单调时钟读数，t.Add 会为墙上时钟读数和单调时钟读数加上相同的时长，得到结果。t.AddDate(y, m, d)、t.Round(d) 和 t.Truncate(d) 是基于墙上时间的计算，因此总会从结果中去掉单调时钟读数。t.In、t.Local 和 t.UTC 用于改变墙上时间的解释方式，也会去掉结果中的单调时钟读数。去除单调时钟读数的标准写法是 t = t.Round(0)。

如果 Time 值 t 和 u 都包含单调时钟读数，t.After(u)、t.Before(u)、t.Equal(u)、t.Compare(u) 和 t.Sub(u) 只使用单调时钟读数，忽略墙上时钟读数。如果 t 或 u 有一个不包含单调时钟读数，这些操作就退回到使用墙上时钟读数。

在某些系统上，计算机休眠时单调时钟会停止。在这样的系统上，t.Sub(u) 可能无法准确反映 t 和 u 之间实际经过的时间。其他涉及时间相减的函数和方法也一样，例如 Since、Until、Time.Before、Time.After、Time.Add、Time.Equal 和 Time.Compare。某些情况下，需要去掉单调时钟读数才能得到准确结果。

单调时钟读数在当前进程之外没有意义，因此 t.GobEncode、t.MarshalBinary、t.MarshalJSON 和 t.MarshalText 生成的序列化形式都省略它，t.Format 也不提供表示它的格式。同样，构造函数 time.Date、time.Parse、time.ParseInLocation 和 time.Unix，以及反序列化方法 t.GobDecode、t.UnmarshalBinary、t.UnmarshalJSON 和 t.UnmarshalText，创建的时间都不包含单调时钟读数。

单调时钟读数只存在于 Time 值中，不属于 Duration 值，也不属于 t.Unix 等方法返回的 Unix 时间。

注意，Go 的 == 运算符不仅比较时间点，还会比较 Location 和单调时钟读数。关于 Time 值的相等性判断，请参阅 Time 类型的文档。

为了便于调试，如果存在单调时钟读数，t.String 的结果会包含它。如果 t != u 是因为单调时钟读数不同，打印 t.String() 和 u.String() 就能看到该差异。

定时器分辨率

Timer 的分辨率取决于 Go 运行时、操作系统和底层硬件。在 Unix 上约为 1 毫秒；在 Windows 1803 及更新版本上约为 0.5 毫秒。较早的 Windows 版本默认约为 16 毫秒，但可以通过 golang.org/x/sys/windows.TimeBeginPeriod 请求更高的分辨率。

常量

这些是供 Time.Format 和 time.Parse 使用的预定义布局。布局中使用的参考时间是下面这个特定时间戳： 

01/02 03:04:05PM '06 -0700

即 2006 年 1 月 2 日 15:04:05，所在时区比 GMT 晚七小时。这个值保存在下面列出的 Layout 常量中。对应的 Unix 时间为 1136239445。由于 MST 是 GMT-0700，Unix 的 date 命令会将该参考时间打印为： 

Mon Jan 2 15:04:05 MST 2006

日期采用美国习惯，将数字月份放在日期之前，这是一个令人遗憾的历史设计问题。

Time.Format 的示例详细展示了布局字符串的工作方式，是很好的参考。

注意，RFC822、RFC850 和 RFC1123 格式只应应用于本地时间。用于 UTC 时间时，时区缩写会是 "UTC"，但严格来说，这些 RFC 要求此时使用 "GMT"。使用 RFC1123 或 RFC1123Z 格式解析时，要注意它们为月内日期定义了前导零，而 RFC 1123 严格来说不允许这样做；因此解析每月前 9 天的某些日期字符串时会出错。对于必须使用该格式的服务器，通常应使用 RFC1123Z 代替 RFC1123；新协议应优先使用 RFC3339。RFC3339、RFC822、RFC822Z、RFC1123 和 RFC1123Z 适合用于格式化；但用于 time.Parse 时，它们既不能接受 RFC 允许的全部时间格式，也会接受一些并未正式定义的格式。RFC3339Nano 会删除秒的小数部分末尾的零，因此格式化后的结果未必能正确排序。

多数程序可以将某个预定义常量作为布局传给 Format 或 Parse。除非要创建自定义布局字符串，否则可以忽略这段说明的其余内容。

要定义自己的格式，请按所需格式写出参考时间的样子；示例可查看 ANSIC、StampMicro 或 Kitchen 等常量。其设计思路是展示参考时间的格式，让 Format 和 Parse 能将同样的转换应用于任意时间值。

下面概括了布局字符串的组成部分。每一项都通过示例展示参考时间某一部分的格式化方式；只有这些值会被识别。布局字符串中无法识别为参考时间一部分的文本，Format 会原样输出，Parse 则要求输入中原样出现。 

Year: "2006" "06"
Month: "Jan" "January" "01" "1"
Day of the week: "Mon" "Monday"
Day of the month: "2" "_2" "02"
Day of the year: "__2" "002"
Hour: "15" "3" "03" (PM or AM)
Minute: "4" "04"
Second: "5" "05"
AM/PM mark: "PM"

数字时区偏移量的格式如下： 

"-0700"     ±hhmm
"-07:00"    ±hh:mm
"-07"       ±hh
"-070000"   ±hhmmss
"-07:00:00" ±hh:mm:ss

将格式中的正负号替换为 Z，就会采用 ISO 8601 的行为：对于 UTC 时区，输出 Z 而不是偏移量。因此： 

"Z0700"      Z or ±hhmm
"Z07:00"     Z or ±hh:mm
"Z07"        Z or ±hh
"Z070000"    Z or ±hhmmss
"Z07:00:00"  Z or ±hh:mm:ss

格式字符串中，"_2" 和 "__2" 的下划线表示空格；如果后面的数字有多位，空格可能被数字替代，以兼容固定宽度的 Unix 时间格式。前导零表示用零填充。

__2 和 002 分别表示用空格和零填充的三字符“年内第几天”；没有不填充的年内天数格式。

逗号或小数点后跟一个或多个零，表示按指定小数位数输出秒的小数部分。逗号或小数点后跟一个或多个 9，也表示按指定小数位数输出，但会去掉末尾的零。例如，"15:04:05,000" 或 "15:04:05.000" 以毫秒精度格式化或解析。

某些有效布局对 time.Parse 来说并不是有效时间值，因为其中可能包含用于空格填充的 _ 或用于时区信息的 Z 等格式。

func After 

func After(d Duration) <-chan Time

After 等待指定时长后，通过返回的通道发送当前时间。它等价于 NewTimer(d).C。

在 Go 1.23 之前，本文档曾提醒：底层 Timer 要等到触发后才能被垃圾回收，因此关注效率的代码应改用 NewTimer，并在不再需要时调用 Timer.Stop。从 Go 1.23 起，垃圾回收器可以回收不再被引用且尚未停止的定时器。如果 After 已经满足需求，就没有理由优先选择 NewTimer。

type Time
				
				
			

			

Time 表示一个精确到纳秒的时间点。


程序通常应以值而不是指针的形式保存和传递时间。也就是说，时间变量和结构体字段应使用 time.Time 类型，而不是 *time.Time。


Time 值可以由多个 goroutine 同时使用，但 Time.GobDecode、Time.UnmarshalBinary、Time.UnmarshalJSON 和 Time.UnmarshalText 方法并发不安全。


可以使用 Time.Before、Time.After 和 Time.Equal 比较时间点。Time.Sub 将两个时间点相减，得到 Duration。Time.Add 将 Time 与 Duration 相加，得到新的 Time。


Time 类型的零值是 UTC 时间公元 1 年 1 月 1 日 00:00:00.000000000。实际使用中很少遇到这一时间，因此 Time.IsZero 提供了检测时间是否尚未被显式初始化的简单方式。


每个时间都关联一个 Location。Time.Local、Time.UTC 和 Time.In 返回具有指定 Location 的 Time。用这些方法更改 Location，不会改变 Time 表示的实际时间点，只会更改解释它时使用的时区。


Time.GobEncode、Time.MarshalBinary、Time.AppendBinary、Time.MarshalJSON、Time.MarshalText 和 Time.AppendText 保存的 Time 表示会记录 Time.Location 的偏移量，但不记录位置名称，因此会丢失夏令时信息。


除了必需的墙上时钟读数，Time 还可以包含当前进程单调时钟的读数，为比较或相减提供额外的准确性。详情请参阅包文档中的“单调时钟”一节。


注意，Go 的 == 运算符不仅比较时间点，还比较 Location 和单调时钟读数。因此，将 Time 值用作映射键或数据库键之前，应先通过 UTC 或 Local 等方法确保所有值使用同一个 Location，并通过 t = t.Round(0) 去掉单调时钟读数。通常应优先使用 t.Equal(u)，而不是 t == u，因为 t.Equal 会使用可用的最准确比较方式，也能正确处理仅一个操作数包含单调时钟读数的情况。

func Parse
					
					
				

				
func Parse(layout, value string) (Time, error)

				

Parse 解析格式化字符串，返回它表示的时间值。格式的表达方式请参阅 Layout 常量的文档。第二个实参必须能按照第一个实参提供的格式字符串（layout）解析。


Time.Format 的示例详细展示了布局字符串的工作方式，是很好的参考。


仅在解析时，即使布局没有指定秒的小数部分，输入也可以在秒字段后紧跟小数秒。此时，会将逗号或小数点及其后尽可能长的连续数字解析为小数秒。小数秒会截断到纳秒精度。


布局中省略的部分默认为零；如果零无效，则默认为一。因此，解析 "3:04pm" 会得到公元 0 年 1 月 1 日 15:04:00 UTC；注意，由于年份为 0，该时间早于 Time 的零值。年份必须在 0000..9999 范围内。星期几只进行语法检查，其他方面会被忽略。


对于使用 06 表示两位数年份的布局，NN >= 69 时会解释为 19NN，NN < 69 时会解释为 20NN。


无法解析表示闰秒的时间戳（秒数为 60），因为 Time 无法表示它们。


以下说明介绍时区的处理方式。


没有时区标识时，Parse 返回 UTC 时间。


解析带有 -0700 等时区偏移量的时间时，如果该偏移量对应当前位置（Local）使用的某个时区，Parse 会在返回值中使用该位置和时区。否则，会创建一个固定使用给定偏移量的位置，并将时间记录为处于该位置。


解析带有 MST 等时区缩写的时间时，如果当前位置为该缩写定义了偏移量，就使用该偏移量。无论位置如何，缩写 "UTC" 都会被识别为 UTC。如果时区缩写未知，Parse 会创建一个具有给定缩写、偏移量为零的位置，并将时间记录为处于该位置。这样可以用相同布局无损地解析并重新格式化时间，但实际表示的时间点会与正确值相差真实的时区偏移量。为避免这类问题，应优先使用包含数字时区偏移量的布局，或使用 ParseInLocation。

type Timer
				
				
			

			

Timer 类型表示一次性事件。Timer 到期时，会向 C 发送当前时间，但由 AfterFunc 创建的 Timer 除外。Timer 必须通过 NewTimer 或 AfterFunc 创建。

type Timer struct {
    C <-chan Time
    // 包含已过滤或未导出的字段
}



			

			

			

			
				
func AfterFunc
					
					
				

				
func AfterFunc(d Duration, f func()) *Timer

				

AfterFunc 等待指定时长后，在独立的 goroutine 中调用 f。它返回一个 Timer，可通过其 Stop 方法取消调用。返回 Timer 的 C 字段不使用，值为 nil。

func NewTimer
					
					
				

				
func NewTimer(d Duration) *Timer

				

NewTimer 创建一个新的 Timer，至少经过时长 d 后，通过其通道发送当前时间。


在 Go 1.23 之前，垃圾回收器不会回收尚未到期或停止的 Timer，因此代码通常在调用 NewTimer 后立即 defer t.Stop，以便不再需要时能够回收。从 Go 1.23 起，即使 Timer 尚未到期或停止，垃圾回收器也能回收不再被引用的 Timer。无需再为了协助垃圾回收而调用 Stop；当然，代码仍然可以出于其他原因调用 Stop 来停止定时器。


在 Go 1.23 之前，Timer 关联的通道是异步的，也就是容量为 1 的缓冲通道，因此即使 Timer.Stop 或 Timer.Reset 已经返回，仍可能接收到过期的时间值。从 Go 1.23 起，该通道是同步的，也就是容量为 0 的无缓冲通道，消除了接收这些过期值的可能。

func (*Timer) Reset
					
					1.1
				

				
func (t *Timer) Reset(d Duration) bool

				

Reset 将定时器改为在时长 d 后到期。如果定时器此前处于活动状态，则返回 true；如果此前已经到期或停止，则返回 false。


对于 AfterFunc(d, f) 创建的函数型定时器，Reset 要么重新安排 f 的执行时间并返回 true，要么安排再次执行 f 并返回 false。返回 false 时，Reset 不会等待上一次 f 执行完成，也不保证后续执行 f 的 goroutine 不会与前一次并发运行。如果调用者需要知道前一次 f 是否完成，就必须显式与 f 协调。


对于 NewTimer 创建的通道型定时器，从 Go 1.23 起，Reset 返回后从 t.C 接收的值保证不会对应之前的定时器设置；如果程序尚未从 t.C 接收过值，而且定时器仍在运行，Reset 保证返回 true。在 Go 1.23 之前，安全使用 Reset 的唯一方式是先调用 Timer.Stop，并显式排空定时器通道。详情请参阅 NewTimer 的文档。

func (*Timer) Stop
					
					
				

				
func (t *Timer) Stop() bool

				

Stop 阻止 Timer 触发。如果此次调用停止了定时器，返回 true；如果定时器已经到期或停止，返回 false。


对于 AfterFunc(d, f) 创建的函数型定时器，如果 t.Stop 返回 false，说明定时器已经到期，f 已在独立 goroutine 中启动。Stop 不会等待 f 完成才返回。如果调用者需要知道 f 是否完成，就必须显式与 f 协调。


对于 NewTimer(d) 创建的通道型定时器，从 Go 1.23 起，Stop 返回后从 t.C 接收保证会阻塞，而不会收到 Stop 之前遗留的过期时间值；如果程序尚未从 t.C 接收过值，而且定时器仍在运行，Stop 保证返回 true。在 Go 1.23 之前，安全使用 Stop 的唯一方式是在它返回 false 时额外执行一次 <-t.C，排空可能遗留的过期值。详情请参阅 NewTimer 的文档。
