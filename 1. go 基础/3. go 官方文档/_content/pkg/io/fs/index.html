fs 包定义文件系统的基本接口。文件系统既可以由宿主操作系统提供，也可以由其他包提供。

路径名

无论宿主操作系统是什么，本包中的接口都使用同一套路径名语法。

路径名是以 UTF-8 编码、不带根路径、由斜杠分隔的路径分量序列，例如“x/y/z”。路径名中不能包含“.”、“..”或空字符串这样的分量，唯一的例外是可以用名称 "." 表示根目录。路径不能以斜杠开头或结尾：“/x”和“x/”都是无效路径。

测试

测试文件系统实现所需的支持，请参阅 testing/fstest 包。

func Glob 1.16 

func Glob(fsys FS, pattern string) (matches []string, err error)

Glob 返回所有匹配 pattern 的文件名；如果没有匹配的文件，则返回 nil。模式语法与 path.Match 相同。模式可以描述具有层级结构的名称，例如 usr/*/bin/ed。

Glob 会忽略文件系统错误，例如读取目录时发生的 I/O 错误。它唯一可能返回的错误是 path.ErrBadPattern，表示模式格式不正确。

如果 fsys 实现了 GlobFS，Glob 就调用 fsys.Glob。否则，Glob 使用 ReadDir 遍历目录树，查找与模式匹配的文件。

ReadFile 从文件系统 fsys 中读取指定文件，并返回文件内容。调用成功时返回的错误为 nil，而不是 io.EOF。（由于 ReadFile 会读取整个文件，最后一次 Read 预期会遇到 EOF，因此不会将它作为错误报告。）

func ValidPath 1.16 

func ValidPath(name string) bool

ValidPath 报告给定路径名是否可以有效地用于 Open 调用。

注意，所有系统（包括 Windows）上的路径都使用斜杠分隔。包含反斜杠、冒号等其他字符的路径也被视为有效路径，但 FS 实现绝不能将这些字符解释为路径分量分隔符。更多细节请参阅路径名一节。

func WalkDir 1.16 

func WalkDir(fsys FS, root string, fn WalkDirFunc) error

WalkDir 遍历以 root 为根的文件树，对树中的每个文件或目录（包括 root 本身）调用 fn。

访问文件和目录时产生的所有错误都由 fn 处理；详情请参阅 fs.WalkDirFunc 的文档。

文件按字典序遍历，这使输出顺序确定，但要求 WalkDir 在继续遍历某个目录之前，先将该目录的全部条目读入内存。

WalkDir 不会跟随目录中遇到的符号链接；但如果 root 本身是符号链接，则会遍历它指向的目标。

type DirEntry
				
				1.16
			

			
DirEntry 是从目录中读取的一个条目（通过 ReadDir 函数或 ReadDirFile 的 ReadDir 方法读取）。

			
type DirEntry interface {
    // Name 返回此条目所描述文件（或子目录）的名称。
    // 该名称仅为路径的最后一个分量（基本名称），而不是完整路径。
    // 例如，Name 返回 "hello.go"，而不是 "home/gopher/hello.go"。
    Name() string

    // IsDir 报告此条目是否描述一个目录。
    IsDir() bool

    // Type 返回此条目的类型位。
    // 类型位是通常的 FileMode 位的子集，即 FileMode.Type 方法返回的那些位。
    Type() FileMode

    // Info 返回此条目描述的文件或子目录的 FileInfo。
    // 返回的 FileInfo 可能来自最初读取目录时，
    // 也可能来自调用 Info 时。如果在读取目录之后文件已被删除或重命名，
    // Info 可能返回满足 errors.Is(err, ErrNotExist) 的错误。
    // 如果此条目表示符号链接，Info 报告链接本身的信息，
    // 而不是链接目标的信息。
    Info() (FileInfo, error)
}

type FS
				
				1.16
			

			
FS 提供对具有层级结构的文件系统的访问。

FS 接口规定文件系统必须提供的最小实现。文件系统还可以实现其他接口，例如 ReadFileFS，以提供额外功能或优化实现。

可以使用 testing/fstest.TestFS 测试 FS 实现的正确性。

			
type FS interface {
    // Open 打开指定文件。
    // 必须调用 [File.Close] 以释放所有相关资源。
    //
    // Open 返回的错误应为 *PathError 类型，
    // 其中 Op 字段设为 "open"，Path 字段设为 name，
    // Err 字段描述具体问题。
    //
    // 对于不满足 ValidPath(name) 的名称，Open 应拒绝
    // 打开，并返回 *PathError，将 Err 设为
    // ErrInvalid 或 ErrNotExist。
    Open(name string) (File, error)
}


			

			

			

			
				
func Sub
					
					1.16
				

				
func Sub(fsys FS, dir string) (FS, error)

				
Sub 返回一个 FS，对应于 fsys 中以 dir 为根的子树。

如果 dir 为 "."，Sub 原样返回 fsys。否则，如果 fsys 实现了 SubFS，Sub 返回 fsys.Sub(dir)。否则，Sub 返回一个新的 FS 实现 sub，它的 sub.Open(name) 实际上通过 fsys.Open(path.Join(dir, name)) 实现。该实现还会对 ReadDir、ReadFile、ReadLink、Lstat 和 Glob 调用进行相应转换。Sub 不检查目录当前是否存在。

注意，Sub(os.DirFS("/"), "prefix") 等价于 os.DirFS("/prefix")，两者都不能保证操作系统访问不会超出 "/prefix"，因为 os.DirFS 的实现不会检查 "/prefix" 中是否存在指向其他目录的符号链接。也就是说，os.DirFS 通常不能替代 chroot 一类的安全机制，Sub 也不会改变这一点。要将访问限制在特定目录树内，请使用 os.Root。

type FileMode
				
				1.16
			

			
FileMode 表示文件的模式位和权限位。这些位在所有系统上都有相同的定义，因此文件信息可以在不同系统之间移植。并非所有位都适用于所有系统。唯一必须支持的位是表示目录的 ModeDir。

			
type FileMode uint32


			
				
已定义的文件模式位位于 FileMode 的高位。最低的九位是标准 Unix rwxrwxrwx 权限位。这些位的值应视为公共 API 的一部分，可能用于通信协议或磁盘存储表示：可以添加新的位，但不能更改已有位的值。

				
const (
    // 单个字母是 String 方法
    // 格式化时使用的缩写。
    ModeDir        FileMode = 1 << (32 - 1 - iota) // d：目录
    ModeAppend                                     // a：仅允许追加
    ModeExclusive                                  // l：独占使用
    ModeTemporary                                  // T：临时文件，仅适用于 Plan 9
    ModeSymlink                                    // L：符号链接
    ModeDevice                                     // D：设备文件
    ModeNamedPipe                                  // p：命名管道（FIFO）
    ModeSocket                                     // S：Unix 域套接字
    ModeSetuid                                     // u：setuid 位
    ModeSetgid                                     // g：setgid 位
    ModeCharDevice                                 // c：设置了 ModeDevice 时表示 Unix 字符设备
    ModeSticky                                     // t：粘滞位
    ModeIrregular                                  // ?：非普通文件，对该文件没有其他已知信息

    // 类型位掩码。普通文件不设置其中任何一位。
    ModeType = ModeDir | ModeSymlink | ModeNamedPipe | ModeSocket | ModeDevice | ModeCharDevice | ModeIrregular

    ModePerm FileMode = 0777 // Unix 权限位
)

type ReadDirFile
				
				1.16
			

			
ReadDirFile 是可以通过 ReadDir 方法读取条目的目录文件。每个目录文件都应实现此接口。（任何文件都可以实现此接口，但对于非目录文件，ReadDir 应返回错误。）

			
type ReadDirFile interface {
    File

    // ReadDir 读取目录内容，并按目录中的顺序返回
    // 最多包含 n 个 DirEntry 值的切片。
    // 对同一文件继续调用，会得到后续的 DirEntry 值。
    //
    // 如果 n > 0，ReadDir 最多返回 n 个 DirEntry 结构。
    // 此时，如果 ReadDir 返回空切片，就会同时返回
    // 一个非 nil 错误来说明原因。
    // 到达目录末尾时，错误为 io.EOF。
    // （ReadDir 必须返回 io.EOF 本身，不能返回包装了 io.EOF 的错误。）
    //
    // 如果 n <= 0，ReadDir 会在一个切片中返回目录中所有剩余的 DirEntry 值。
    // 此时，如果 ReadDir 成功（一直读到
    // 目录末尾），则返回该切片和 nil 错误。
    // 如果在到达目录末尾之前遇到错误，
    // ReadDir 返回截至该处读到的 DirEntry 列表和非 nil 错误。
    ReadDir(n int) ([]DirEntry, error)
}

type WalkDirFunc
				
				1.16
			

			
WalkDirFunc 是 WalkDir 访问每个文件或目录时所调用函数的类型。

path 参数以传给 WalkDir 的参数为前缀。也就是说，如果调用 WalkDir 时 root 参数为 "dir"，并在该目录中发现名为 "a" 的文件，那么调用遍历函数时传入的参数就是 "dir/a"。

d 参数是指定路径对应的 DirEntry。

函数返回的错误结果决定 WalkDir 如何继续。如果函数返回特殊值 SkipDir，WalkDir 就跳过当前目录（如果 d.IsDir() 为 true，则是 path；否则是 path 的父目录）。如果函数返回特殊值 SkipAll，WalkDir 就跳过所有剩余文件和目录。除此之外，如果函数返回非 nil 错误，WalkDir 就会完全停止，并返回该错误。

err 参数报告与 path 有关的错误，表示 WalkDir 不会进入该目录。函数可以决定如何处理此错误；如上所述，返回该错误会使 WalkDir 停止遍历整棵树。

WalkDir 在两种情况下会以非 nil 的 err 参数调用该函数。

第一种情况是最初对根目录的 Stat 调用失败，此时 WalkDir 调用函数，path 设为 root，d 设为 nil，err 设为 fs.Stat 返回的错误。

第二种情况是目录的 ReadDir 方法（参见 ReadDirFile）失败，此时 WalkDir 调用函数，path 设为该目录的路径，d 设为描述该目录的 DirEntry，err 设为 ReadDir 返回的错误。在第二种情况下，会针对该目录的路径调用函数两次：第一次调用发生在尝试读取目录之前，err 为 nil，让函数有机会返回 SkipDir 或 SkipAll，从而完全避免执行 ReadDir。第二次调用发生在 ReadDir 失败后，用来报告 ReadDir 的错误。（如果 ReadDir 成功，则不会发生第二次调用。）

WalkDirFunc 与 path/filepath.WalkFunc 的区别如下：

    

  • 第二个参数的类型为 DirEntry，而不是 FileInfo。

  • 在读取目录之前就会调用函数，因此可以分别通过 SkipDir 或 SkipAll 完全跳过目录读取，或跳过所有剩余文件和目录。

  • 如果读取目录失败，会针对该目录第二次调用函数，以报告错误。



			
type WalkDirFunc func(path string, d DirEntry, err error) error
