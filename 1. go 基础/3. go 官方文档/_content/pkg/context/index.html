context 包定义 Context 类型，用于跨 API 边界和进程传递截止时间、取消信号及其他请求作用域内的值。

服务器收到请求时应创建一个 Context，向其他服务器发起调用时应接受一个 Context。两者之间的函数调用链必须传递该 Context，也可以用 WithCancel、WithDeadline、WithTimeout 或 WithValue 创建的派生 Context 替换它。

可以取消 Context，以表示与它关联的工作应停止。带截止时间的 Context 会在超过截止时间后被取消。某个 Context 被取消时，所有由它派生的 Context 也都会被取消。

WithCancel、WithDeadline 和 WithTimeout 函数接受一个父 Context，并返回一个派生的子 Context 和一个 CancelFunc。调用 CancelFunc 会直接取消该子 Context 及其所有后代，移除父 Context 对它的引用，并停止所有关联的定时器。如果未调用 CancelFunc，子 Context 及其后代会发生资源泄漏，直到父 Context 被取消。go vet 工具会检查所有控制流路径是否都使用了 CancelFunc。

WithCancelCause 函数返回一个 CancelCauseFunc，它接受一个错误，并将其记录为取消原因。WithDeadlineCause 和 WithTimeoutCause 接受一个原因，在截止时间到达时使用。在已取消的上下文或它的任何子上下文上调用 Cause，可以取得该原因。如果没有指定原因，Cause(ctx) 返回与 ctx.Err() 相同的值。

使用 Context 的程序应遵循以下规则，以保持各包接口的一致性，并使静态分析工具能够检查上下文的传递：

不要将 Context 存储在结构体类型中，而应将其显式传给每个需要它的函数。更多讨论参见 https://go.dev/blog/context-and-structs。Context 应为第一个参数，通常命名为 ctx： 

func DoSomething(ctx context.Context, arg Arg) error {
	// ……使用 ctx……
}

即使函数允许，也不要传入 nil Context。如果不确定应使用哪个 Context，请传入 context.TODO。

仅将上下文中的值用于跨进程和 API 传递的请求作用域数据，不要用它们传递函数的可选参数。

同一个 Context 可以传给在不同 goroutine（轻量级协程）中运行的函数；多个 goroutine 同时使用 Context 是安全的。

使用 Context 的服务器示例代码参见 https://go.dev/blog/context。

func AfterFunc 1.21 

func AfterFunc(ctx Context, f func()) (stop func() bool)

AfterFunc 安排在 ctx 被取消后，在独立的 goroutine 中调用 f。如果 ctx 已被取消，AfterFunc 会立即在独立的 goroutine 中调用 f。

对同一个上下文多次调用 AfterFunc，各次调用相互独立，不会相互替换。

调用返回的 stop 函数，会解除 ctx 与 f 的关联。如果这次调用成功阻止 f 运行，则返回 true。如果 stop 返回 false，则可能是上下文已被取消，f 已在独立的 goroutine 中启动；也可能是 f 之前已被停止。stop 函数返回前不会等待 f 完成。如果调用方需要知道 f 是否完成，必须显式与 f 协调。

如果 ctx 具有 "AfterFunc(func()) func() bool" 方法，AfterFunc 会使用该方法安排调用。

func Cause 1.20 

func Cause(c Context) error

Cause 返回一个非 nil 错误，说明 c 被取消的原因。c 或其某个父上下文首次被取消时，会设置该原因。如果这次取消由 CancelCauseFunc(err) 调用触发，则 Cause 返回 err；否则，Cause(c) 返回与 c.Err() 相同的值。如果 c 尚未被取消，Cause 返回 nil。

func WithCancel 1.7 

func WithCancel(parent Context) (ctx Context, cancel CancelFunc)

WithCancel 返回一个指向父上下文的派生上下文，但具有新的 Done 通道。当返回的 cancel 函数被调用，或父上下文的 Done 通道被关闭时，返回上下文的 Done 通道会关闭，以先发生者为准。

取消此上下文会释放与其关联的资源，因此，在此 Context 中运行的操作一旦完成，代码就应调用 cancel。

func WithCancelCause 1.20 

func WithCancelCause(parent Context) (ctx Context, cancel CancelCauseFunc)

WithCancelCause 的行为类似于 WithCancel，但返回 CancelCauseFunc，而非 CancelFunc。以非 nil 错误（即“原因”）调用 cancel，会将该错误记录在 ctx 中，之后可以通过 Cause(ctx) 取得。以 nil 调用 cancel，会将原因设置为 Canceled。

用法示例： 

ctx, cancel := context.WithCancelCause(parent)
cancel(myError)
ctx.Err() // 返回 context.Canceled
context.Cause(ctx) // 返回 myError

func WithDeadline 1.7 

func WithDeadline(parent Context, d time.Time) (Context, CancelFunc)

WithDeadline 返回一个指向父上下文的派生上下文，但将截止时间调整为不晚于 d。如果父上下文的截止时间已早于 d，则 WithDeadline(parent, d) 在语义上等价于 parent。当截止时间到达、返回的 cancel 函数被调用，或父上下文的 Done 通道被关闭时，返回的 Context.Done 通道会关闭，以最先发生者为准。

取消此上下文会释放与其关联的资源，因此，在此 Context 中运行的操作一旦完成，代码就应调用 cancel。

▸ 示例

▾ 示例

本示例将一个带指定截止时间的上下文传给阻塞函数，告知该函数应在到达截止时间时立即放弃工作。

代码：

d := time.Now().Add(shortDuration)
ctx, cancel := context.WithDeadline(context.Background(), d)

// 即使 ctx 最终会过期，也应始终调用其取消函数。
// 否则，可能会让此上下文及其父上下文
// 存活得比实际需要更久。
defer cancel()

select {
case <-neverReady:
    fmt.Println("ready")
case <-ctx.Done():
    fmt.Println(ctx.Err())
}

输出：

context deadline exceeded

func WithTimeout 1.7 

func WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc)

WithTimeout 返回 WithDeadline(parent, time.Now().Add(timeout))。

取消此上下文会释放与其关联的资源，因此，在此 Context 中运行的操作一旦完成，代码就应调用 cancel： 

func slowOperationWithTimeout(ctx context.Context) (Result, error) {
	ctx, cancel := context.WithTimeout(ctx, 100*time.Millisecond)
	defer cancel()  // 若 slowOperation 在超时前完成，则释放资源
	return slowOperation(ctx)
}

type CancelCauseFunc 1.20

CancelCauseFunc 的行为类似于 CancelFunc，但还会设置取消原因。在已取消的 Context 或它的任何派生 Context 上调用 Cause，可以取得该原因。

如果上下文已被取消，CancelCauseFunc 不会设置原因。例如，假设 childContext 派生自 parentContext：

  • 如果 parentContext 先以 cause1 被取消，之后 childContext 才以 cause2 被取消，则 Cause(parentContext) == Cause(childContext) == cause1。
  • 如果 childContext 先以 cause2 被取消，之后 parentContext 才以 cause1 被取消，则 Cause(parentContext) == cause1，而 Cause(childContext) == cause2。 
type CancelCauseFunc func(cause error)

type CancelFunc 1.7

CancelFunc 通知操作放弃工作，但不会等待工作停止。多个 goroutine 可以同时调用 CancelFunc。首次调用之后，后续调用不执行任何操作。

type Context 1.7

Context 用于跨 API 边界传递截止时间、取消信号及其他值。

多个 goroutine 可以同时调用 Context 的方法。 

type Context interface {
    // Deadline 返回应当取消代表此上下文执行的工作的时间。
    // 未设置截止时间时，返回 ok==false。
    // 连续调用 Deadline 会得到相同的结果。
    Deadline() (deadline time.Time, ok bool)

    // Done 返回一个通道，当代表此上下文执行的工作应被取消时，
    // 此通道会关闭。如果此上下文永远不会被取消，Done 可能返回 nil。
    // 连续调用 Done 会返回相同的值。
    // Done 通道可能在取消函数返回后才异步关闭。
    //
    // WithCancel 安排在调用 cancel 时关闭 Done；
    // WithDeadline 安排在截止时间到达时关闭 Done；
    // WithTimeout 安排在超时时关闭 Done。
    //
    // Done 用于 select 语句：
    //
    //  // Stream 用 DoSomething 生成值并发送到 out，
    //  // 直到 DoSomething 返回错误或 ctx.Done 被关闭。
    //  func Stream(ctx context.Context, out chan<- Value) error {
    //  	for {
    //  		v, err := DoSomething(ctx)
    //  		if err != nil {
    //  			return err
    //  		}
    //  		select {
    //  		case <-ctx.Done():
    //  			return ctx.Err()
    //  		case out <- v:
    //  		}
    //  	}
    //  }
    //
    // 更多使用 Done 通道实现取消的示例，
    // 参见 https://go.dev/blog/pipelines。
    Done() <-chan struct{}

    // 如果 Done 尚未关闭，Err 返回 nil。
    // 如果 Done 已关闭，Err 返回非 nil 错误说明原因：
    // 超过上下文截止时间时为 DeadlineExceeded，
    // 因其他原因取消上下文时为 Canceled。
    // Err 返回非 nil 错误后，后续调用都会返回相同的错误。
    Err() error

    // Value 返回此上下文中与 key 关联的值；若不存在，则返回 nil。
    // 使用相同的 key 连续调用 Value，会返回相同的结果。
    //
    // 上下文值仅应用于跨进程和 API 边界传递的请求作用域数据，
    // 不应用于向函数传递可选参数。
    //
    // 键标识 Context 中的一个特定值。需要在 Context 中保存值的函数，
    // 通常用全局变量定义一个键，再将其传给 context.WithValue 和 Context.Value。
    // 键可以是任何支持相等比较的类型；包应为键定义未导出的类型，以避免冲突。
    //
    // 定义 Context 键的包应为该键对应的值提供类型安全的访问函数：
    //
    // 	// user 包定义保存在 Context 中的 User 类型。
    // 	package user
    //
    // 	import "context"
    //
    // 	// User 是保存在 Context 中的值的类型。
    // 	type User struct {...}
    //
    // 	// key 是本包所定义的键使用的未导出类型。
    // 	// 这可以避免与其他包定义的键发生冲突。
    // 	type key int
    //
    // 	// userKey 是 Context 中 user.User 值所用的键。
    // 	// 它未被导出；使用者通过 user.NewContext 和 user.FromContext
    // 	// 访问值，而不直接使用此键。
    // 	var userKey key
    //
    // 	// NewContext 返回携带值 u 的新 Context。
    // 	func NewContext(ctx context.Context, u *User) context.Context {
    // 		return context.WithValue(ctx, userKey, u)
    // 	}
    //
    // 	// FromContext 返回 ctx 中存储的 User 值（如果存在）。
    // 	func FromContext(ctx context.Context) (*User, bool) {
    // 		u, ok := ctx.Value(userKey).(*User)
    // 		return u, ok
    // 	}
    Value(key any) any
}

func Background 1.7 

func Background() Context

Background 返回一个非 nil 的空 Context。它永远不会被取消，不包含任何值，也没有截止时间。通常用于 main 函数、初始化和测试，也用作传入请求的顶层 Context。

func TODO 1.7 

func TODO() Context

TODO 返回一个非 nil 的空 Context。如果不确定该使用哪个 Context，或 Context 尚不可用（因为外围函数尚未扩展为接受 Context 参数），代码应使用 context.TODO。

func WithValue 1.7 

func WithValue(parent Context, key, val any) Context

WithValue 返回一个指向父 Context 的派生上下文。在派生上下文中，与 key 关联的值为 val。

仅将上下文中的值用于跨进程和 API 传递的请求作用域数据，不要用它们传递函数的可选参数。

提供的 key 必须可比较，且不应使用 string 或其他内置类型，以避免使用 context 的不同包之间发生冲突。WithValue 的使用者应为键定义自己的类型。为避免赋值给 interface{} 时发生内存分配，上下文键的具体类型通常使用 struct{}。另一种方式是让导出的上下文键变量的静态类型为指针或接口。

func WithoutCancel 1.21 

func WithoutCancel(parent Context) Context

WithoutCancel 返回一个指向父上下文的派生上下文，父上下文被取消时它不会被取消。返回的上下文没有 Deadline 或 Err，其 Done 通道为 nil。在它上面调用 Cause 返回 nil。
