csv 包用于读写逗号分隔值（CSV）文件。CSV 文件存在多种形式；本包支持 RFC 4180 描述的格式，但 Writer 默认使用 LF 而非 CRLF 作为换行符。

CSV 文件包含零条或多条记录，每条记录包含一个或多个字段。各条记录以换行符分隔；最后一条记录后面可以带有换行符，也可以没有。

field1,field2,field3

空白字符被视为字段的一部分。

换行符之前的回车符会被自动移除。

空行会被忽略。仅包含空白字符的行（不计末尾的换行符）不被视为空行。

以双引号字符 " 开始和结束的字段称为带引号字段。开头和结尾的引号不属于字段内容。

以下原始内容：

normal string,"quoted-field"

会得到以下字段：

{`normal string`, `quoted-field`}

在带引号字段内，两个连续的双引号字符会被视为一个双引号。

"the ""word"" is true","a ""quoted-field"""

会得到：

{`the "word" is true`, `a "quoted-field"`}

带引号字段中可以包含换行符和逗号：

"Multi-line
field","comma is ,"

会得到：

{`Multi-line
field`, `comma is ,`}

type Reader

Reader 从采用 CSV 编码的文件中读取记录。

NewReader 返回的 Reader 默认要求输入符合 RFC 4180。在首次调用 Reader.Read 或 Reader.ReadAll 之前，可以修改其导出字段来自定义处理细节。

Reader 会将输入中的所有 \r\n 序列转换为单独的 \n，包括多行字段值中的换行。因此，返回的数据不依赖输入文件使用的换行约定。

type Reader struct {
    // Comma 是字段分隔符。
    // NewReader 将其设置为逗号（','）。
    // Comma 必须是有效的 rune，且不能是 \r、\n，
    // 也不能是 Unicode 替换字符（0xFFFD）。
    Comma rune

    // Comment 非 0 时，表示注释字符。以该字符开头且
    // 前面没有空白字符的行会被忽略。
    // 如果前面有空白字符，Comment 字符就会成为字段的
    // 一部分，即使 TrimLeadingSpace 为 true 也是如此。
    // Comment 必须是有效的 rune，且不能是 \r、\n，
    // 也不能是 Unicode 替换字符（0xFFFD）。
    // 它还不能与 Comma 相同。
    Comment rune

    // FieldsPerRecord 是每条记录预期包含的字段数。
    // 如果 FieldsPerRecord 为正数，Read 要求每条记录
    // 都包含指定数量的字段。如果 FieldsPerRecord 为 0，Read 会将它
    // 设置为第一条记录的字段数，使后续记录必须
    // 具有相同字段数。如果 FieldsPerRecord 为负数，则不做
    // 检查，每条记录的字段数可以不同。
    FieldsPerRecord int

    // 如果 LazyQuotes 为 true，不带引号的字段中允许出现双引号，
    // 带引号的字段中也允许出现未成对转义的双引号。
    LazyQuotes bool

    // 如果 TrimLeadingSpace 为 true，则忽略字段开头的空白字符。
    // 即使字段分隔符 Comma 本身就是空白字符，也会如此处理。
    TrimLeadingSpace bool

    // ReuseRecord 控制 Read 是否可以让返回的切片与
    // 上次调用返回的切片共享底层数组，以提高性能。
    // 默认情况下，每次 Read 都会返回新分配的、归调用方所有的内存。
    ReuseRecord bool // Go 1.9

    // 已弃用：TrailingComma 已不再使用。
    TrailingComma bool
    // 包含已过滤或未导出的字段
}

func (*Reader) FieldPos 1.17 

func (r *Reader) FieldPos(field int) (line, column int)

FieldPos 返回最近一次 Reader.Read 所返回切片中，给定索引对应字段的起始行号和列号。行号和列号从 1 开始；列按字节计数，而不是按 rune 计数。

如果传入越界索引，则触发 panic。

func (*Reader) InputOffset 1.19 

func (r *Reader) InputOffset() int64

InputOffset 返回读取器当前位置在输入流中的字节偏移量。该偏移量对应最近读入行的结尾，也是下一行的开头。

func (*Reader) Read 

func (r *Reader) Read() (record []string, err error)

Read 从 r 读取一条记录（一个字段切片）。如果记录的字段数不符合预期，Read 会同时返回该记录和 ErrFieldCount 错误。如果记录包含无法解析的字段，Read 会同时返回部分记录和解析错误；部分记录包含错误发生前已读入的所有字段。如果没有剩余数据可读，Read 返回 nil、io.EOF。如果 Reader.ReuseRecord 为 true，多次 Read 调用可能共享返回的切片。

func (*Reader) ReadAll 

func (r *Reader) ReadAll() (records [][]string, err error)

ReadAll 从 r 读取所有剩余记录，每条记录都是一个字段切片。调用成功时返回 err == nil，而不是 err == io.EOF。由于 ReadAll 的定义就是一直读取到 EOF，因此它不会将文件结束视为需要报告的错误。

type Writer

Writer 使用 CSV 编码写入记录。

NewWriter 返回的 Writer 默认以换行符结束每条记录，并使用 ',' 作为字段分隔符。在首次调用 Writer.Write 或 Writer.WriteAll 之前，可以修改其导出字段来自定义处理细节。

Writer.Comma 是字段分隔符。

如果 Writer.UseCRLF 为 true，Writer 会以 \r\n 而非 \n 结束每一行输出。

单条记录的写入会经过缓冲。写入全部数据后，调用方应调用 Writer.Flush 方法，确保所有数据都已转发到底层 io.Writer。应通过调用 Writer.Error 方法检查是否发生错误。

type Writer struct {
    Comma   rune // 字段分隔符（NewWriter 将其设置为 ','）
    UseCRLF bool // 为 true 时使用 \r\n 作为行终止符
    // 包含已过滤或未导出的字段
}

func (*Writer) Flush 

func (w *Writer) Flush()

Flush 将缓冲区内的数据写入底层 io.Writer。要检查 Flush 期间是否发生错误，请调用 Writer.Error。

func (*Writer) Write 

func (w *Writer) Write(record []string) error

Write 向 w 写入一条 CSV 记录，并按需添加引号。记录是一个字符串切片，其中每个字符串就是一个字段。写入会经过缓冲，因此最后必须调用 Writer.Flush，确保记录已写入底层 io.Writer。

func (*Writer) WriteAll 

func (w *Writer) WriteAll(records [][]string) error

WriteAll 使用 Writer.Write 向 w 写入多条 CSV 记录，随后调用 Writer.Flush，并返回 Flush 产生的错误。
