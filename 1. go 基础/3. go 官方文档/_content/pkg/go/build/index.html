build 包收集有关 Go 包的信息。

构建约束

构建约束也称为构建标签，是决定某个文件是否应包含在包中的条件。构建约束通过以下内容开头的行注释给出：

//go:build

构建约束也可以是文件名的一部分（例如，只有目标操作系统为 windows 时，才会包含 source_windows.go）。

详情参见 'go help buildconstraint'（https://pkg.go.dev/cmd/go#hdr-Build_constraints）。

Go 路径

Go 路径是一组包含 Go 源代码的目录树。在标准 Go 目录树中找不到导入的包时，会查询这些目录。默认路径是 GOPATH 环境变量的值，并按操作系统适用的方式解释为路径列表（在 Unix 上为冒号分隔的字符串；在 Windows 上为分号分隔的字符串；在 Plan 9 上为列表）。

Go 路径中列出的每个目录都必须采用规定的结构：

src/ 目录存放源代码。src 下的路径决定导入路径或可执行文件名。

pkg/ 目录存放已安装的包目标文件。与 Go 目录树相同，每一对目标操作系统和架构在 pkg 下都有自己的子目录（pkg/GOOS_GOARCH）。

如果 DIR 是 Go 路径中列出的目录，那么源代码位于 DIR/src/foo/bar 的包可以通过 "foo/bar" 导入，其编译后的形式安装到 "DIR/pkg/GOOS_GOARCH/foo/bar.a"（使用 gccgo 时为 "DIR/pkg/gccgo/foo/libbar.a"）。

bin/ 目录存放编译后的命令。每个命令以其源代码目录命名，但只使用最后一个路径元素，而非完整路径。也就是说，源代码位于 DIR/src/foo/quux 的命令会安装到 DIR/bin/quux，而不是 DIR/bin/foo/quux。去掉 foo/ 后，你只需将 DIR/bin 加入 PATH，就能访问已安装的命令。

下面是一个目录布局示例：

GOPATH=/home/user/gocode

/home/user/gocode/
    src/
        foo/
            bar/               （bar 包的 Go 代码）
                x.go
            quux/              （main 包的 Go 代码）
                y.go
    bin/
        quux                   （已安装的命令）
    pkg/
        linux_amd64/
            foo/
                bar.a          （已安装的包目标文件）

仅含二进制的包

在 Go 1.12 及更早版本中，可以以二进制形式分发包，而不包含编译该包所使用的源代码。分发的包需要附带一个未被构建约束排除、且包含 "//go:binary-only-package" 注释的源文件。与构建约束类似，该注释位于文件顶部，前面只能有空行和其他行注释，后面跟一个空行，以便与包文档分隔。与构建约束不同，只有非测试 Go 源文件中的这种注释才会被识别。

因此，仅含二进制的包所需的最小源代码为：

//go:binary-only-package

package mypkg

源代码可以包含额外的 Go 代码。这些代码从不会被编译，但会被 godoc 等工具处理，可作为面向最终用户的文档。

"go build" 等命令已不再支持仅含二进制的包。对于包含这些注释的包，Import 和 ImportDir 仍会设置 BinaryOnly 标志，以供工具和错误消息使用。

type Context

Context 指定构建所依赖的上下文。

type Context struct {
    GOARCH string // 目标架构
    GOOS   string // 目标操作系统
    GOROOT string // Go 根目录
    GOPATH string // Go 路径

    // Dir 是调用方的工作目录，若为空字符串则使用
    // 运行中进程的当前目录。在模块模式下，它用于
    // 定位主模块。
    //
    // 如果 Dir 非空，传给 Import 和 ImportDir 的目录
    // 必须是绝对路径。
    Dir string // Go 1.14

    CgoEnabled  bool   // 是否包含 cgo 文件
    UseAllFiles bool   // 使用文件时忽略 go:build 行和文件名的限制
    Compiler    string // 计算目标路径时所假定使用的编译器

    // 构建标签、工具标签和发布版本标签指定处理 go:build 行时
    // 应视为已满足的构建约束。
    // 创建新上下文的调用方可以自定义 BuildTags，它默认为空，
    // 但自定义 ToolTags 或 ReleaseTags 通常是错误的。
    // ToolTags 默认为适用于当前 Go 工具链配置的构建标签。
    // ReleaseTags 默认为当前版本所兼容的 Go 发布版本列表。
    // 默认构建上下文 Default 不设置 BuildTags。
    // 除 BuildTags、ToolTags 和 ReleaseTags 外，构建约束
    // 也将 GOARCH 和 GOOS 的值视为已满足的标签。
    // 假定 ReleaseTags 的最后一个元素为当前发布版本。
    BuildTags   []string
    ToolTags    []string // Go 1.17
    ReleaseTags []string // Go 1.1

    // 安装后缀指定安装目录名称中使用的后缀。
    // 默认情况下它为空，但需要将输出分开存放的
    // 自定义构建可以通过设置 InstallSuffix 达到此目的。例如，
    // 使用竞态检测器时，go 命令会设置 InstallSuffix = "race"，
    // 因此在 Linux/386 系统上，包会写入名为
    // "linux_386_race" 的目录，而非通常的 "linux_386"。
    InstallSuffix string // Go 1.1

    // JoinPath 将一组路径片段连接为单个路径。
    // 如果 JoinPath 为 nil，Import 使用 filepath.Join。
    JoinPath func(elem ...string) string

    // SplitPathList 将路径列表拆分为由各条路径组成的切片。
    // 如果 SplitPathList 为 nil，Import 使用 filepath.SplitList。
    SplitPathList func(list string) []string

    // IsAbsPath 报告 path 是否为绝对路径。
    // 如果 IsAbsPath 为 nil，Import 使用 filepath.IsAbs。
    IsAbsPath func(path string) bool

    // IsDir 报告该路径是否指向目录。
    // 如果 IsDir 为 nil，Import 调用 os.Stat，并使用结果的 IsDir 方法。
    IsDir func(path string) bool

    // HasSubdir 报告从路径文本上看，dir 是否为
    // root 的子目录，可以相隔多层。它不会尝试检查
    // dir 是否存在。
    // 如果是，HasSubdir 将 rel 设置为用斜杠分隔的路径，
    // 该路径与 root 连接后得到的路径与 dir 等价。
    // 如果 HasSubdir 为 nil，Import 使用基于
    // filepath.EvalSymlinks 的实现。
    HasSubdir func(root, dir string) (rel string, ok bool)

    // ReadDir 返回按 Name 排序的 fs.FileInfo 切片，
    // 描述指定目录的内容。
    // 如果 ReadDir 为 nil，Import 使用 os.ReadDir。
    ReadDir func(dir string) ([]fs.FileInfo, error)

    // OpenFile 以读取方式打开文件（不能是目录）。
    // 如果 OpenFile 为 nil，Import 使用 os.Open。
    OpenFile func(path string) (io.ReadCloser, error)
}

Default 是构建的默认 Context。如果设置了 GOARCH、GOOS、GOROOT 和 GOPATH 环境变量，它会使用这些值；否则使用已编译代码的 GOARCH、GOOS 和 GOROOT。

var Default Context = defaultContext()

func (*Context) Import 

func (ctxt *Context) Import(path string, srcDir string, mode ImportMode) (*Package, error)

Import 返回由导入路径指定的 Go 包的详细信息，并将本地导入路径解释为相对于 srcDir 目录的路径。如果 path 是本地导入路径，而该包也能通过标准导入路径导入，则返回的包会将 p.ImportPath 设置为该标准路径。

在包含该包的目录中，.go、.c、.h 和 .s 文件都被视为包的一部分，以下情况除外：

  • 属于 documentation 包的 .go 文件
  • 以 _ 或 . 开头的文件（可能是编辑器临时文件）
  • 构建约束不被当前上下文满足的文件

如果发生错误，Import 返回非 nil 错误，以及包含部分信息的非 nil *Package。

type ImportMode

ImportMode 控制 Import 方法的行为。

type ImportMode uint
const (
    // 如果设置了 FindOnly，Import 在定位到应包含
    // 包源代码的目录后就会停止。它不会
    // 读取该目录中的任何文件。
    FindOnly ImportMode = 1 << iota

    // 如果设置了 AllowBinary，Import 可以接受
    // 没有对应源代码的已编译包目标文件。
    //
    // 已弃用：
    // 创建仅含编译结果的包所支持的方式是
    // 编写源代码，并在文件顶部包含
    // //go:binary-only-package 注释。无论此标志
    // 如何设置，这类包都会被识别（因为它有源代码），
    // 且返回的 Package 中 BinaryOnly 会设为 true。
    AllowBinary

    // 如果设置了 ImportComment，则解析 package 语句上的导入注释。
    // 如果 Import 发现无法理解的注释，
    // 或多个源文件中有相互冲突的注释，则返回错误。
    // 更多信息参见 golang.org/s/go14customimport。
    ImportComment

    // 默认情况下，Import 会先搜索
    // 适用于给定源目录的 vendor 目录，再搜索
    // GOROOT 和 GOPATH 根目录。
    // 如果 Import 通过 vendor 目录找到并返回某个包，
    // 结果中的 ImportPath 就是该包的完整路径，
    // 包含通往 "vendor" 的各级路径元素，
    // 也包含 "vendor" 本身。
    // 例如，如果 Import("y", "x/subdir", 0) 找到了
    // "x/vendor/y"，返回包的 ImportPath 就是 "x/vendor/y"，
    // 而不只是 "y"。
    // 更多信息参见 golang.org/s/go15vendor。
    //
    // 设置 IgnoreVendor 会忽略 vendor 目录。
    //
    // 与包的 ImportPath 不同，
    // 返回包的 Imports、TestImports 和 XTestImports
    // 始终精确保留源文件中的导入路径：
    // Import 不会尝试解析或检查这些路径。
    IgnoreVendor
)

type Package

Package 描述在某个目录中找到的 Go 包。

type Package struct {
    Dir           string   // 包含包源代码的目录
    Name          string   // 包名
    ImportComment string   // package 语句上导入注释中的路径；Go 1.4 中加入
    Doc           string   // 文档摘要
    ImportPath    string   // 包的导入路径（未知时为 ""）
    Root          string   // 此包所在的 Go 目录树的根目录
    SrcRoot       string   // 包源代码根目录（未知时为 ""）
    PkgRoot       string   // 包安装根目录（未知时为 ""）
    PkgTargetRoot string   // 与架构相关的安装根目录（未知时为 ""）；Go 1.5 中加入
    BinDir        string   // 命令安装目录（未知时为 ""）
    Goroot        bool     // 是否在 Go 根目录中找到此包
    PkgObj        string   // 已安装的 .a 文件
    AllTags       []string // 可能影响此目录中文件选择的标签；Go 1.2 中加入
    ConflictDir   string   // 此目录在 $GOPATH 中遮蔽 Dir；Go 1.2 中加入
    BinaryOnly    bool     // 无法从源代码重新构建（含 //go:binary-only-package 注释）；Go 1.7 中加入

    // 源文件
    GoFiles           []string // .go 源文件（不包括 CgoFiles、TestGoFiles、XTestGoFiles）
    CgoFiles          []string // 导入 "C" 的 .go 源文件
    IgnoredGoFiles    []string // 本次构建忽略的 .go 源文件（包括被忽略的 _test.go 文件）；Go 1.1 中加入
    InvalidGoFiles    []string // 检测到问题的 .go 源文件（语法分析错误、包名错误等）；Go 1.6 中加入
    IgnoredOtherFiles []string // 本次构建忽略的非 .go 源文件；Go 1.16 中加入
    CFiles            []string // .c 源文件
    CXXFiles          []string // .cc、.cpp 和 .cxx 源文件；Go 1.2 中加入
    MFiles            []string // .m（Objective-C）源文件；Go 1.3 中加入
    HFiles            []string // .h、.hh、.hpp 和 .hxx 源文件
    FFiles            []string // .f、.F、.for 和 .f90 Fortran 源文件；Go 1.7 中加入
    SFiles            []string // .s 源文件
    SwigFiles         []string // .swig 文件；Go 1.1 中加入
    SwigCXXFiles      []string // .swigcxx 文件；Go 1.1 中加入
    SysoFiles         []string // 需加入归档的 .syso 系统目标文件

    // Cgo 指令
    CgoCFLAGS    []string // Cgo CFLAGS 指令
    CgoCPPFLAGS  []string // Cgo CPPFLAGS 指令；Go 1.2 中加入
    CgoCXXFLAGS  []string // Cgo CXXFLAGS 指令；Go 1.2 中加入
    CgoFFLAGS    []string // Cgo FFLAGS 指令；Go 1.7 中加入
    CgoLDFLAGS   []string // Cgo LDFLAGS 指令
    CgoPkgConfig []string // Cgo pkg-config 指令

    // 测试信息
    TestGoFiles  []string // 包内的 _test.go 文件
    XTestGoFiles []string // 包外的 _test.go 文件

    // 源文件中找到的 Go 指令注释（//go:zzz...）。
    Directives      []Directive // Go 1.21
    TestDirectives  []Directive // Go 1.21
    XTestDirectives []Directive // Go 1.21

    // 依赖信息
    Imports        []string                    // GoFiles、CgoFiles 中的导入路径
    ImportPos      map[string][]token.Position // Imports 的行信息
    TestImports    []string                    // TestGoFiles 中的导入路径
    TestImportPos  map[string][]token.Position // TestImports 的行信息
    XTestImports   []string                    // XTestGoFiles 中的导入路径
    XTestImportPos map[string][]token.Position // XTestImports 的行信息

    // 在 Go 源文件中找到的 //go:embed 模式
    // 例如，如果某个源文件写了
    //	//go:embed a* b.c
    // 那么列表会将这两个字符串包含为独立条目。
    // （有关 //go:embed 的详情，请参阅 embed 包。）
    EmbedPatterns        []string                    // GoFiles、CgoFiles 中的模式；Go 1.16 中加入
    EmbedPatternPos      map[string][]token.Position // EmbedPatterns 的行信息；Go 1.16 中加入
    TestEmbedPatterns    []string                    // TestGoFiles 中的模式；Go 1.16 中加入
    TestEmbedPatternPos  map[string][]token.Position // TestEmbedPatterns 的行信息；Go 1.16 中加入
    XTestEmbedPatterns   []string                    // XTestGoFiles 中的模式；Go 1.16 中加入
    XTestEmbedPatternPos map[string][]token.Position // XTestEmbedPatternPos 的行信息；Go 1.16 中加入
}
