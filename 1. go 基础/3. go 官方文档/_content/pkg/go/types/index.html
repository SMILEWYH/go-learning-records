types 包声明用于 Go 包类型检查的数据类型，并实现相应算法。使用 Config.Check 可以对一个包调用类型检查器。也可以用 NewChecker 创建新的类型检查器，再调用 Checker.Files 增量检查。

类型检查由多个相互依赖的阶段组成：

名称解析将程序中的每个标识符（ast.Ident）映射到它表示的符号（Object）。使用 Info 的 Defs 和 Uses 字段或 Info.ObjectOf 方法，可以查找标识符对应的符号；使用 Info 的 Implicits 字段，可以查找某些其他语法节点对应的符号。

常量折叠计算每个编译期常量表达式（ast.Expr）的精确常量值（constant.Value）。使用 Info 的 Types 字段，可以取得表达式的常量折叠结果。

类型推导计算每个表达式（ast.Expr）的类型（Type），并检查其是否符合语言规范。使用 Info 的 Types 字段，可以取得类型推导结果。

对于需要对一个或多个完整 Go 源码包进行类型检查的应用，使用 golang.org/x/tools/go/packages 包的 Load 函数，可能比直接调用类型检查器更方便。

教程参见 https://go.dev/s/types-tutorial。

func AssertableTo 1.5 

func AssertableTo(V *Interface, T Type) bool

AssertableTo 报告是否可以将 V 类型的值断言为 T 类型。

以下三种情况下，AssertableTo 的行为未指定：

  • T 为 Typ[Invalid]
  • V 是广义接口，即只能在 Go 代码中用作类型约束的接口
  • T 是尚未实例化的泛型类型

func CheckExpr 1.13 

func CheckExpr(fset *token.FileSet, pkg *Package, pos token.Pos, expr ast.Expr, info *Info) (err error)

CheckExpr 对表达式 expr 进行类型检查，视同它出现在包 pkg 的 pos 位置。表达式的类型信息记录在 info 中。表达式可以是表示尚未实例化的泛型函数或类型的标识符。

如果 pkg == nil，使用 Universe 作用域，并忽略提供的位置 pos。如果 pkg != nil 且 pos 无效，则使用包作用域。否则，pos 必须属于该包。

如果 pos 不在包内，或无法对节点进行类型检查，则返回错误。

注意：不应使用 Eval 和 CheckExpr 代替 Check 来计算类型和值，而应将它们作为 Check 的补充，因为这些函数忽略表达式使用的上下文（例如赋值）。因此，顶层无类型常量会返回无类型的类型，而不是对应上下文中的具体类型。

func Identical 1.5 

func Identical(x, y Type) bool

Identical 报告 x 和 y 是否是相同类型。忽略 Signature 类型的接收者。

Identical、Implements、Satisfies 等判定函数假定两个操作数都属于一致的符号集合（Object 值）。例如，只有两个 Named 类型的 Named.Obj 方法返回同一个 TypeName 符号时，它们才可能相同。如果对于路径为 P 的每个逻辑包，在创建这些符号时至多调用一次 NewPackage(P, ...)，该符号集合就是一致的。为确保一致性，应对所有加载的包及其依赖使用同一个 Importer。更多信息参见 https://github.com/golang/go/issues/57497。

type Info 1.5

Info 保存已进行类型检查的包所得的类型信息。仅收集为其提供了映射的信息。如果包存在类型错误，所收集的信息可能不完整。

type Info struct {
    // Types 将表达式映射到其类型；对于常量
    // 表达式，还包含其值。无效表达式
    // 会被省略。
    //
    // 对于表示内置函数的标识符（可能带括号），
    // 记录的签名取决于调用位置：
    // 如果调用结果不是常量，记录的类型就是
    // 针对具体实参的签名。否则，记录的类型
    // 为无效类型。
    //
    // Types 映射不会记录每个标识符的类型，
    // 只记录出现在允许任意表达式的位置上的
    // 标识符。例如：
    // - 选择器表达式 x.f 中的标识符 f
    //   仅存在于 Selections 映射；
    // - 变量声明 'var z int' 中的标识符 z
    //   仅存在于 Defs 映射；
    // - 限定标识符 p.X 中表示包的标识符 p
    //   仅存在于 Uses 映射。
    //
    // 同样，FuncDecl.Type 字段中的合成 FuncType
    // 节点也不会记录类型，因为这种情况下源码中没有
    // 对应的函数类型表达式语法。
    // 应改为在对应函数声明的
    // Defs 映射项中查找函数类型。
    Types map[ast.Expr]TypeAndValue

    // Instances 将表示泛型类型或函数的标识符映射到
    // 其类型实参和实例化后的类型。
    //
    // 例如，Instances 会将类型实例化
    // T[int, string] 中的标识符 'T' 映射到类型实参 [int, string]，
    // 以及由此产生的实例化 *Named 类型。对于泛型函数
    // func F[A any](A)，Instances 会将调用表达式
    // F(int(1)) 中的标识符 'F' 映射到推断的类型实参 [int]，
    // 以及由此产生的实例化 *Signature。
    //
    // 不变式：用 Instances[id].TypeArgs 实例化 Uses[id].Type()，
    // 结果等价于 Instances[id].Type。
    Instances map[*ast.Ident]Instance // Go 1.18

    // Defs 将标识符映射到它们定义的对象（包括
    // 包名、点导入的点 "."，以及空白标识符 "_"）。
    // 对于不表示对象的标识符（例如 package 子句中的包名，
    // 或类型 switch 头部 t := x.(type) 中的符号变量 t），
    // 对应对象为 nil。
    //
    // 对于嵌入字段，Defs 返回其定义的字段 *Var。
    //
    // 在类型有误的代码中，例如同名重复声明，
    // Defs 可能缺少某个声明标识符对应的条目。
    //
    // 不变式：Defs[id] == nil || Defs[id].Pos() == id.Pos()
    Defs map[*ast.Ident]Object

    // Uses 将标识符映射到它们表示的对象。
    //
    // 对于嵌入字段，Uses 返回其表示的 *TypeName。
    //
    // 不变式：Uses[id].Pos() != id.Pos()
    Uses map[*ast.Ident]Object

    // Implicits 将节点映射到它们隐式声明的对象（如果有）。
    // 可能出现以下节点和对象类型：
    //
    //     节点               声明的对象
    //
    //     *ast.ImportSpec    未重命名的导入对应的 *PkgName
    //     *ast.CaseClause    每个类型 switch case 子句（包括 default）中特定类型的 *Var
    //     *ast.Field         匿名参数 *Var（包括未命名结果）
    //
    Implicits map[ast.Node]Object

    // Selections 将选择器表达式（不包括限定标识符）
    // 映射到相应的选择。
    Selections map[*ast.SelectorExpr]*Selection

    // Scopes 将 ast.Node 映射到它们定义的作用域。包作用域不与
    // 特定节点关联，而是与属于该包的全部文件关联。
    // 因此，可以在完成类型检查的 Package 对象中找到包作用域。
    // 作用域相互嵌套：Universe 是最外层作用域，包含
    // 包作用域；包作用域包含一个或多个文件作用域，后者包含
    // 函数作用域，而函数作用域又包含语句和函数字面量作用域。
    // 注意，虽然包级函数在包作用域中声明，
    // 但函数作用域嵌套在包含其声明的
    // 文件的文件作用域中。
    //
    // 函数的 Scope 包含所有类型形参、
    // 参数和具名结果的声明，以及
    // 函数体块中的所有局部声明。
    // 其范围与该函数语法（[*ast.FuncDecl] 或 [*ast.FuncLit]）的
    // 完整范围相同。
    // Scopes 映射不包含函数体（[*ast.BlockStmt]）
    // 对应的条目；函数作用域与
    // [*ast.FuncType] 关联。
    //
    // Scopes 中可能出现以下节点类型：
    //
    //     *ast.File
    //     *ast.FuncType
    //     *ast.TypeSpec
    //     *ast.BlockStmt
    //     *ast.IfStmt
    //     *ast.SwitchStmt
    //     *ast.TypeSwitchStmt
    //     *ast.CaseClause
    //     *ast.CommClause
    //     *ast.ForStmt
    //     *ast.RangeStmt
    //
    Scopes map[ast.Node]*Scope

    // InitOrder 按必须执行的顺序列出包级初始化器。
    // 如果初始化器引用的变量之间存在初始化依赖，
    // 则按拓扑顺序排列；其他初始化器
    // 按源码顺序排列。没有初始化表达式的变量
    // 不会出现在此列表中。
    InitOrder []*Initializer

    // FileVersions 将文件映射到其 Go 版本字符串。
    // 如果文件未指定版本，返回的
    // 字符串就是 Config.GoVersion。
    // 版本字符串以 “go” 开头，例如 “go1.21”，
    // 适合与 [go/version] 包配合使用。
    FileVersions map[*ast.File]string // Go 1.22

type SelectionKind 1.5

SelectionKind 描述选择器表达式 x.f 的种类（不包括限定标识符）。

如果 x 是结构体或结构体指针，选择器表达式 x.f 可以表示选择操作序列 x.a.b.c.f。SelectionKind 描述最后一次显式操作的种类；之前的隐式操作始终都是字段选择。Indices 的每个元素都通过隐式字段（a、b、c）在字段选择操作数的结构体类型中的索引来指定该字段。

对于 FieldVal 操作，最后一次选择引用 Selection.Obj 指定的字段。

对于 MethodVal 操作，最后一次选择引用方法。如果方法声明的接收者是否为指针，与隐式字段选择后实际接收者是否为指针不一致，就会对接收者变量或值隐式应用 & 或 * 操作。因此，当 f 要求指针接收者、而 x.a.b.c 是非指针变量时，x.f 表示 (&x.a.b.c).f；当 f 要求非指针接收者、而 x.a.b.c 是指针值时，x.f 表示 (*x.a.b.c).f。

所有指针间接访问，无论来自隐式或显式字段选择，还是为匹配指针属性而插入的 * 操作，只要作用于 nil 指针都会引发 panic。因此，方法调用 x.f() 甚至可能在函数调用之前就引发 panic。

相比之下，MethodExpr 操作 T.f 本质上等价于以下形式的函数字面量：

func(x T, args) (results) { return x.f(args) }

因此，任何隐式字段选择，以及为匹配指针属性而插入的 * 操作，直到函数被调用时才会求值，所以 T.f 或 (*T).f 表达式本身绝不会引发 panic。

type SelectionKind int
const (
    FieldVal   SelectionKind = iota // x.f 是结构体字段选择器
    MethodVal                       // x.f 是方法选择器
    MethodExpr                      // x.f 是方法表达式
)

type StdSizes 1.5

StdSizes 是创建常用 Sizes 的便捷类型。它采用以下简化假设：

  • 显式指定大小的基本类型（int16 等）的大小就是指定大小。
  • 字符串和接口的大小为 2*WordSize。
  • 切片的大小为 3*WordSize。

  • 数组和结构体按规范定义对齐；其他所有类型采用自然对齐，最大对齐值为 MaxAlign。

func Instantiate 1.18 

func Instantiate(ctxt *Context, orig Type, targs []Type, validate bool) (Type, error)

Instantiate 使用给定的类型实参 targs 实例化类型 orig。orig 必须是泛型 *Alias、*Named 或 *Signature 类型。如果没有错误，得到的 Type 是同种类的实例化类型（分别为 *Alias、*Named 或 *Signature）。

如果 ctxt 非 nil，可用它将当前实例与先前具有相同身份的实例去重。作为特殊情况，泛型 *Signature 原始类型仅在指针相等时才被视为相同，因此对不同的（即使可能类型相同的）签名进行实例化，会产生不同实例。使用共享上下文并不保证在所有情况下都会对相同实例去重。

如果设置 validate，Instantiate 会验证 orig 确实为泛型类型、类型实参与形参数量相符，以及类型实参满足各自的类型约束。如果验证失败，产生的错误可能包装 *ArgumentError，指出哪个类型实参未满足其类型形参约束，以及失败原因。

如果未设置 validate，Instantiate 不检查 orig 是否为泛型，不验证类型实参数量，也不检查类型实参是否满足约束。Instantiate 保证不返回错误，但可能引发 panic。具体而言，对于 *Signature 类型，如果类型实参数量不正确，会立即引发 panic；对于 *Named 类型，可能稍后在 *Named API 内引发 panic。
