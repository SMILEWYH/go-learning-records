tar 包实现对 tar 归档的访问。

磁带归档（tar）是一种用于存储一系列文件的文件格式，可以按流式方式读取和写入。本包旨在覆盖该格式的大多数变体，包括 GNU 和 BSD tar 工具生成的格式。

type Format 1.10

Format 表示 tar 归档格式。

最初的 tar 格式在 Unix V7 中引入。此后，出现了多种相互竞争的格式，试图将 V7 格式标准化或对其扩展，以克服其局限。最常见的是 USTAR、PAX 和 GNU 格式，它们各有优势和限制。

下表汇总了各格式的能力：

                  |  USTAR |       PAX |       GNU
------------------+--------+-----------+----------
Name              |   256B |      不限 |      不限
Linkname          |   100B |      不限 |      不限
Size              | uint33 |      不限 |    uint89
Mode              | uint21 |    uint21 |    uint57
Uid/Gid           | uint21 |      不限 |    uint57
Uname/Gname       |    32B |      不限 |       32B
ModTime           | uint33 |      不限 |     int89
AccessTime        | 不适用 |      不限 |     int89
ChangeTime        | 不适用 |      不限 |     int89
Devmajor/Devminor | uint21 |    uint21 |    uint57
------------------+--------+-----------+----------
字符串编码        |  ASCII |     UTF-8 |    二进制
亚秒级时间        |     否 |        是 |        否
稀疏文件          |     否 |        是 |        是

表格上半部分展示 Header 字段，其中每种格式列出了各字符串字段允许的最大字节数，以及存储各数值字段所用的整数类型（时间戳存储为自 Unix 纪元以来的秒数）。

表格下半部分展示每种格式的专有特性，例如支持的字符串编码、是否支持亚秒级时间戳，以及是否支持稀疏文件。

Writer 目前不支持稀疏文件。

type Format int

用于标识各种 tar 格式的常量。

const (

    // FormatUnknown 表示格式未知。
    FormatUnknown Format

    // FormatUSTAR 表示 POSIX.1-1988 定义的 USTAR 头部格式。
    //
    // 虽然此格式与大多数 tar 读取器兼容，
    // 但它具有若干限制，因此不适用于某些用途。
    // 尤其是，它不支持稀疏文件、大于 8GiB 的文件、
    // 超过 256 个字符的文件名以及非 ASCII 文件名。
    //
    // 参考：
    //	http://pubs.opengroup.org/onlinepubs/9699919799/utilities/pax.html#tag_20_92_13_06
    FormatUSTAR

    // FormatPAX 表示 POSIX.1-2001 定义的 PAX 头部格式。
    //
    // PAX 通过在原始头部之前写入一个 Typeflag 为 TypeXHeader 的
    // 特殊文件来扩展 USTAR。此文件包含一组键值记录，
    // 用于克服 USTAR 的不足，此外还提供了
    // 亚秒级分辨率时间戳的能力。
    //
    // 一些较新的格式会定义自己的键，并为相应值赋予特定语义，
    // 从而向 PAX 添加自己的扩展。
    // 例如，PAX 对稀疏文件的支持使用了
    // GNU 手册定义的键（如 "GNU.sparse.map"）。
    //
    // 参考：
    //	http://pubs.opengroup.org/onlinepubs/009695399/utilities/pax.html
    FormatPAX

    // FormatGNU 表示 GNU 头部格式。
    //
    // GNU 头部格式早于 USTAR 和 PAX 标准，
    // 且与二者不兼容。GNU 格式支持
    // 任意大小的文件、任意编码及长度的文件名、
    // 稀疏文件及其他特性。
    //
    // 除非目标应用只能解析 GNU 格式的归档，
    // 否则建议选择 PAX 而不是 GNU。
    //
    // 参考：
    //	https://www.gnu.org/software/tar/manual/html_node/Standard.html
    FormatGNU
)

type Header

Header 表示 tar 归档中的单个头部。某些字段可能未填充。

为了向前兼容，如果使用者从 Reader.Next 获取 Header、对其进行某些修改后再传给 Writer.WriteHeader，应创建新的 Header，并仅复制希望保留的字段。

type Header struct {
    // Typeflag 是头部条目的类型。
    // 零值会根据 Name 是否以斜杠结尾，
    // 自动提升为 TypeReg 或 TypeDir。
    Typeflag byte

    Name     string // 文件条目的名称
    Linkname string // 链接的目标名称（对 TypeLink 或 TypeSymlink 有效）

    Size  int64  // 逻辑文件大小，以字节为单位
    Mode  int64  // 权限位和模式位
    Uid   int    // 所有者的用户 ID
    Gid   int    // 所有者的组 ID
    Uname string // 所有者的用户名
    Gname string // 所有者的组名

    // 如果未指定 Format，则 Writer.WriteHeader 会将 ModTime
    // 舍入到最近的整秒，并忽略 AccessTime 和 ChangeTime 字段。
    //
    // 要使用 AccessTime 或 ChangeTime，请将 Format 指定为 PAX 或 GNU。
    // 要使用亚秒级分辨率，请将 Format 指定为 PAX。
    ModTime    time.Time // 修改时间
    AccessTime time.Time // 访问时间（需要 PAX 或 GNU 支持）
    ChangeTime time.Time // 状态变更时间（需要 PAX 或 GNU 支持）

    Devmajor int64 // 主设备号（对 TypeChar 或 TypeBlock 有效）
    Devminor int64 // 次设备号（对 TypeChar 或 TypeBlock 有效）

    // Xattrs 将扩展属性作为 PAX 记录存储在
    // "SCHILY.xattr." 命名空间下。
    //
    // 以下两者在语义上等价：
    //  h.Xattrs[key] = value
    //  h.PAXRecords["SCHILY.xattr."+key] = value
    //
    // 调用 Writer.WriteHeader 时，Xattrs 的内容
    // 优先于 PAXRecords 中的内容。
    //
    // 已弃用：请改用 PAXRecords。
    Xattrs map[string]string // Go 1.3

    // PAXRecords 是 PAX 扩展头部记录的映射。
    //
    // 用户定义的记录应使用以下形式的键：
    //	VENDOR.keyword
    // 其中 VENDOR 是全大写的命名空间，keyword
    // 不得包含 '=' 字符（例如 "GOLANG.pkg.version"）。
    // 键和值都应为非空的 UTF-8 字符串。
    //
    // 调用 Writer.WriteHeader 时，从 Header 中
    // 其他字段推导出的 PAX 记录优先于 PAXRecords。
    PAXRecords map[string]string // Go 1.10

    // Format 指定 tar 头部的格式。
    //
    // Reader.Next 会尽力推测格式并设置此字段。
    // 由于 Reader 对某些不符合规范的文件采取宽松读取，
    // 此字段可能为 FormatUnknown。
    //
    // 如果调用 Writer.WriteHeader 时未指定格式，
    // 则按 USTAR、PAX、GNU 的顺序使用第一个
    // 能够编码此 Header 的格式（参见 Format）。
    Format Format // Go 1.10
}

func FileInfoHeader 1.1 

func FileInfoHeader(fi fs.FileInfo, link string) (*Header, error)

FileInfoHeader 根据 fi 创建一个仅填充部分字段的 Header。如果 fi 描述符号链接，FileInfoHeader 将 link 记录为链接目标。如果 fi 描述目录，则会在名称后附加斜杠。

由于 fs.FileInfo 的 Name 方法只返回其描述文件的基本名称，因此可能需要修改 Header.Name，以提供文件的完整路径名。

如果 fi 实现了 FileInfoNames，则 Header.Gname 和 Header.Uname 由该接口的方法提供。

func (*Reader) Next 

func (tr *Reader) Next() (*Header, error)

Next 前进到 tar 归档中的下一个条目。Header.Size 决定可以为下一个文件读取多少字节。当前文件中剩余的所有数据都会自动丢弃。到达归档末尾时，Next 返回错误 io.EOF。

如果 Next 遇到非本地文件名（按 filepath.IsLocal 的定义），且 GODEBUG 环境变量包含 `tarinsecurepath=0`，则 Next 会在返回头部的同时返回 ErrInsecurePath 错误。只验证文件名，不验证链接目标。未来的 Go 版本可能默认启用此行为。希望接受非本地名称的程序可以忽略 ErrInsecurePath 错误并使用返回的头部。

func (*Reader) Read 

func (tr *Reader) Read(b []byte) (int, error)

Read 从 tar 归档中的当前文件读取。到达该文件末尾时，它返回 (0, io.EOF)，直到调用 [Next] 前进到下一个文件。

如果当前文件是稀疏文件，则标记为空洞的区域会读出为 NUL 字节。

对 TypeLink、TypeSymlink、TypeChar、TypeBlock、TypeDir 和 TypeFifo 等特殊类型调用 Read，无论 Header.Size 声明的大小是多少，均返回 (0, io.EOF)。

func (*Writer) AddFS 1.22 

func (tw *Writer) AddFS(fsys fs.FS) error

AddFS 将 fs.FS 中的文件添加到归档。它从文件系统根目录开始遍历目录树，在保留目录结构的同时将每个文件添加到 tar 归档。

func (*Writer) Close 

func (tw *Writer) Close() error

Close 刷新填充数据并写入尾部，从而关闭 tar 归档。如果当前文件（由先前的 Writer.WriteHeader 调用开始）尚未写完，则返回错误。

func (*Writer) Flush 

func (tw *Writer) Flush() error

Flush 完成当前文件的块填充写入。调用 Flush 之前必须已完整写入当前文件。

通常无须调用此方法，因为下一次调用 Writer.WriteHeader 或 Writer.Close 会隐式刷新文件的填充数据。

func (*Writer) Write 

func (tw *Writer) Write(b []byte) (int, error)

Write 向 tar 归档中的当前文件写入。如果在 Writer.WriteHeader 之后写入的字节数超过 Header.Size，Write 返回 ErrWriteTooLong 错误。

对 TypeLink、TypeSymlink、TypeChar、TypeBlock、TypeDir 和 TypeFifo 等特殊类型调用 Write，无论 Header.Size 声明的大小是多少，均返回 (0, ErrWriteTooLong)。

func (*Writer) WriteHeader 

func (tw *Writer) WriteHeader(hdr *Header) error

WriteHeader 写入 hdr，并准备接收文件内容。Header.Size 决定可以为下一个文件写入多少字节。如果当前文件尚未写完，则返回错误。此方法会在写入头部之前隐式刷新所需的所有填充数据。
