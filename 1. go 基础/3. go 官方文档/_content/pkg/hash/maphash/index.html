maphash 包提供作用于字节序列和可比较值的哈希函数。它还定义了 Hasher，作为哈希函数与哈希表之间的接口。

这些哈希函数用于实现哈希表、布隆过滤器，以及其他需要将任意字符串或字节序列映射为均匀分布的无符号 64 位整数的数据结构。

哈希表或数据结构的每个不同实例都应使用自己的 Seed。

这些哈希函数不具备密码学安全性。（密码学用途请参见 crypto/sha256 和 crypto/sha512。）

type Hash
				
				1.14
			

			
Hash 计算字节序列的带种子哈希值。
Hash 的零值是可直接使用的有效 Hash。零值 Hash 会在首次调用 Reset、Write、Seed、Clone 或 Sum64 方法期间为自己选择随机种子。要控制种子，请使用 SetSeed。
计算出的哈希值仅取决于初始种子和提供给 Hash 对象的字节序列，而不取决于提供这些字节的方式。例如，以下三个操作序列：
h.Write([]byte{'f','o','o'})
h.WriteByte('f'); h.WriteByte('o'); h.WriteByte('o')
h.WriteString("foo")



效果完全相同。
这些哈希的设计目标是抗碰撞，即使对手能够控制被哈希的字节序列也是如此。
Hash 不能由多个 goroutine 安全地并发使用，但 Seed 可以。如果多个 goroutine 必须计算相同种子的哈希，每个 goroutine 都可以声明自己的 Hash，并以共同的 Seed 调用 SetSeed。

type Hasher
				
				
			

			
Hasher 定义基于哈希的容器与其元素之间的接口。它为 T 类型的值提供哈希函数和等价关系，使这些值能够插入哈希表及类似数据结构中。
当然，可比较类型本来就可以作为 Go 内建 map 类型的键，而 Hasher 也允许不可比较类型用作适当哈希表的键。即使对于可比较类型，Hasher 也可能有用，因为它可以定义不同于通常比较（==）的等价关系，例如对结构体指针按字段比较，或者像以下示例一样对字符串进行忽略大小写的比较：
// CaseInsensitive 是一个 Hasher[string]，
// 其等价关系忽略字母大小写。
type CaseInsensitive struct{}

func (CaseInsensitive) Hash(h *Hash, s string) {
	h.WriteString(strings.ToLower(s))
}

func (CaseInsensitive) Equal(x, y string) bool {
	// （这里避免使用 strings.EqualFold，因为它并非
	// 对所有值都与 ToLower 保持一致。）
	return strings.ToLower(x) == strings.ToLower(y)
}



Hasher 还允许将值用于布隆过滤器等其他基于哈希的数据结构。ComparableHasher 类型使可比较类型能够方便地按通常的（==）等价关系用于这些数据结构。
哈希不变量


如果两个值按 Equal(x, y) 的定义相等，则按照 Hash(h, x) 对 h 的影响所定义的哈希值也必须相同。
Hasher 在逻辑上必须无状态：Hash 和 Equal 方法的行为只能依赖实参。
编写良好的函数


为数据类型定义哈希函数和等价关系时，可以先将该类型值的规范编码定义为一串元素，每个元素是数值、字符串、布尔值或指针。如果逻辑上相等的两个值即使表示方式不同，也具有相同的编码，那么该编码就是规范编码。例如，字符串的一种忽略大小写的规范编码是 strings.ToLower。
定义编码后，Hasher 的 Hash 方法应通过一系列调用将值编码进 Hash：字节切片使用 Hash.Write，字符串使用 Hash.WriteString，字节使用 Hash.WriteByte，其他类型的元素使用 WriteComparable。Hasher 的 Equal 方法应计算两个值的编码，然后比较对应元素，在发现第一处不匹配时返回 false。
Hash 方法可以丢弃信息，只要仍与前述定义下的 Equal 方法保持一致。例如，CaseInsensitive.Hash 的有效实现可以只检查字符串的第一个字母，甚至使用一个常量值。不过，哈希函数丢失的信息越多，哈希碰撞就越频繁，哈希表也越慢。
某些数据类型（例如集合）本质上无序：集合 {a, b, c} 等于集合 {c, b, a}。某些情况下，可以通过将元素按某种顺序排序，为集合定义规范编码。其他情况下，这可能因为需要分配内存而低效，或者因为不存在方便的顺序而不可行。对无序集合进行哈希的另一种方式是分别计算每个元素的哈希值，再使用 + 或 ^ 这类满足交换律（与顺序无关）的运算符组合所有元素的哈希值。
下面为一个假想 Set 类型定义的 Hash 方法展示了此做法：
type Set[T comparable] struct{ ... }

type setHasher[T comparable] struct{}

func (setHasher[T]) Hash(hash *maphash.Hash, set *Set[T]) {
	var accum uint64
	for elem := range set.Elements() {
		// 为元素初始化哈希器，
		// 使用与外层哈希相同的种子。
		var sub maphash.Hash
		sub.SetSeed(hash.Seed())

		// 计算元素的哈希。
		maphash.WriteComparable(&sub, elem)

		// 将元素的哈希混入集合的哈希。
		accum ^= sub.Sum64()
	}
	maphash.WriteComparable(hash, accum)
}



在许多语言中，数据类型的哈希操作只是返回一个整数值。但这会让对手能够系统性地构造大量哈希值相同的值，降低哈希表的渐近性能，形成一种称为“哈希洪泛”的拒绝服务攻击。相比之下，将一系列值写入 Hash 来计算哈希，并为不同哈希表使用各不相同、不可预测的 Seed，可以缓解这种攻击。
实际上，Seed 从 2⁶⁴ 个不同的哈希函数中选出一个。上面的代码示例对元素的子 Hasher 调用 SetSeed，使其使用与 Set 自身相同的哈希函数，而不是随机的另一个。
type Hasher[T any] interface {
    Hash(*Hash, T)
    Equal(x, y T) bool
}


			

			

			

			

			
		
			
			
type Seed
				
				1.14
			

			
Seed 是一个随机值，用于选择 Hash 计算的具体哈希函数。如果两个 Hash 使用相同的 Seed，则对任意给定输入都会计算出相同的哈希值。如果两个 Hash 使用不同的 Seed，则对任意给定输入很可能计算出不同的哈希值。
Seed 必须通过调用 MakeSeed 初始化。零值种子尚未初始化，不能用于 Hash 的 SetSeed 方法。
每个 Seed 值仅限于单个进程，不能序列化，也不能以其他方式在另一个进程中重新创建。

    // 包含已过滤或未导出的字段
