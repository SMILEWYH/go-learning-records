pprof 包按 pprof 可视化工具所需的格式写出运行时性能剖析数据。

对 Go 程序进行性能剖析

对 Go 程序进行性能剖析的第一步是启用剖析。go test 内置了对使用标准 testing 包编写的基准测试进行性能剖析的支持。例如，以下命令运行当前目录中的基准测试，并将 CPU 和内存剖析数据分别写入 cpu.prof 和 mem.prof：

go test -cpuprofile cpu.prof -memprofile mem.prof -bench .

要为独立程序添加同等的性能剖析支持，请在 main 函数中添加如下代码：

var cpuprofile = flag.String("cpuprofile", "", "write cpu profile to `file`")
var memprofile = flag.String("memprofile", "", "write memory profile to `file`")

func main() {
    flag.Parse()
    if *cpuprofile != "" {
        f, err := os.Create(*cpuprofile)
        if err != nil {
            log.Fatal("could not create CPU profile: ", err)
        }
        defer f.Close() // 示例中省略错误处理
        if err := pprof.StartCPUProfile(f); err != nil {
            log.Fatal("could not start CPU profile: ", err)
        }
        defer pprof.StopCPUProfile()
    }

    // ……程序的其余部分……

    if *memprofile != "" {
        f, err := os.Create(*memprofile)
        if err != nil {
            log.Fatal("could not create memory profile: ", err)
        }
        defer f.Close() // 示例中省略错误处理
        runtime.GC() // 获取最新统计信息
        // Lookup("allocs") 创建与 go test -memprofile 类似的剖析数据。
        // 也可以使用 Lookup("heap")，获取
        // 以 inuse_space 为默认索引的剖析数据。
        if err := pprof.Lookup("allocs").WriteTo(f, 0); err != nil {
            log.Fatal("could not write memory profile: ", err)
        }
    }
}

性能剖析数据也有标准 HTTP 接口。添加以下导入会在 /debug/pprof/ URL 下注册处理器，用于下载实时剖析数据：

import _ "net/http/pprof"

详情请参阅 net/http/pprof 包。

随后可以使用 pprof 工具将剖析数据可视化：

go tool pprof cpu.prof

pprof 命令行提供了许多命令。常用命令包括 "top"，用于输出程序主要热点的摘要；以及 "web"，用于打开热点及其调用关系的交互式图表。使用 "help" 可查看所有 pprof 命令的信息。

有关 pprof 的更多信息，请参阅 https://github.com/google/pprof/blob/main/doc/README.md。

func Do 1.9 

func Do(ctx context.Context, labels LabelSet, f func(context.Context))

Do 复制父上下文，并将给定标签添加到父上下文的标签映射中，然后使用该上下文调用 f。在执行 f 期间创建的 goroutine 会继承扩充后的标签集。labels 中的每个键值对按给定顺序插入标签映射，覆盖相同键的已有值。扩充后的标签映射会在调用 f 期间生效，并在 f 返回后恢复。

func ForLabels 1.9 

func ForLabels(ctx context.Context, f func(key, value string) bool)

ForLabels 对上下文中设置的每个标签调用 f。函数 f 应返回 true 以继续迭代，或返回 false 以提前终止迭代。

func Label 1.9 

func Label(ctx context.Context, key string) (string, bool)

Label 返回 ctx 中给定键对应的标签值，以及表示该标签是否存在的布尔值。

func SetGoroutineLabels 1.9 

func SetGoroutineLabels(ctx context.Context)

SetGoroutineLabels 将当前 goroutine 的标签设置为与 ctx 一致。新 goroutine 会继承创建它的 goroutine 的标签。这是比 Do 更底层的 API，应尽可能使用后者。

func StartCPUProfile 

func StartCPUProfile(w io.Writer) error

StartCPUProfile 为当前进程启用 CPU 性能剖析。在剖析期间，剖析数据会先缓冲再写入 w。如果已启用剖析，StartCPUProfile 返回错误。

在类 Unix 系统上，对于使用 -buildmode=c-archive 或 -buildmode=c-shared 构建的 Go 代码，StartCPUProfile 默认无法正常工作。StartCPUProfile 依赖 SIGPROF 信号，但该信号会交给主程序的 SIGPROF 信号处理器（如果有），而不是 Go 使用的处理器。要使其生效，请针对 syscall.SIGPROF 调用 os/signal.Notify，但注意，这可能破坏主程序正在进行的性能剖析。

func StopCPUProfile 

func StopCPUProfile()

StopCPUProfile 停止当前的 CPU 性能剖析（如果有）。只有在剖析数据全部写入完成后，StopCPUProfile 才会返回。

type Profile

Profile 是栈轨迹的集合，展示导致某类事件（例如分配）发生的调用序列。包可以创建并维护自己的剖析数据；最常见的用途是跟踪必须显式关闭的资源，例如文件或网络连接。

Profile 的方法可以由多个 goroutine 同时调用。

每个 Profile 都有唯一的名称。以下是几个预定义的剖析类型：

goroutine      - 当前所有 goroutine 的栈轨迹
goroutineleak  - 所有泄漏的 goroutine 的栈轨迹
allocs         - 所有历史内存分配的采样
heap           - 存活对象内存分配的采样
threadcreate   - 导致创建新操作系统线程的栈轨迹
block          - 导致在同步原语上阻塞的栈轨迹
mutex          - 存在争用的互斥锁持有者的栈轨迹

这些预定义的剖析数据会自行维护，显式调用 Profile.Add 或 Profile.Remove 方法会引发 panic。

CPU 剖析不以 Profile 的形式提供。它有专用 API，即 StartCPUProfile 和 StopCPUProfile 函数，因为它在剖析期间会将输出以流的形式写入写入器。

堆剖析

堆剖析报告截至最近一次已完成垃圾回收时的统计信息；它省略更近的分配，以避免剖析结果偏离存活数据而偏向垃圾数据。如果尚未进行过垃圾回收，堆剖析会报告所有已知分配。这一例外主要有助于在未启用垃圾回收的情况下运行的程序，通常用于调试。

堆剖析既跟踪应用内存中所有存活对象的分配位置，也跟踪程序启动以来分配过的所有对象的分配位置。pprof 的 -inuse_space、-inuse_objects、-alloc_space 和 -alloc_objects 标志用于选择显示哪一类信息，默认为 -inuse_space（存活对象，按大小计量）。

分配剖析

allocs 剖析与堆剖析相同，但将 pprof 的默认显示方式改为 -alloc_space，即程序启动以来累计分配的字节数（包括已被垃圾回收的字节）。

阻塞剖析

阻塞剖析跟踪在同步原语上阻塞所花费的时间，例如 sync.Mutex、sync.RWMutex、sync.WaitGroup、sync.Cond，以及通道发送、接收和 select。

栈轨迹对应发生阻塞的位置（例如 sync.Mutex.Lock）。

样本值对应在该栈轨迹处累计阻塞的时间，并受 runtime.SetBlockProfileRate 所指定的基于时间的采样控制。

互斥锁剖析

互斥锁剖析跟踪互斥锁上的争用，例如 sync.Mutex、sync.RWMutex 和运行时内部锁。

栈轨迹对应导致争用的临界区结束的位置。例如，某个锁被长时间持有，其他 goroutine 一直等待获取该锁，那么最终解锁时（即在 sync.Mutex.Unlock 处）就会报告争用。

样本值对应其他 goroutine 等待获取该锁而阻塞的大致累计时间，并受 runtime.SetMutexProfileFraction 所指定的基于事件的采样控制。例如，如果调用方持锁 1 秒，同时另外 5 个 goroutine 在整整这 1 秒内都在等待获取该锁，那么其解锁调用栈将报告 5 秒的争用时间。

func Lookup 

func Lookup(name string) *Profile

Lookup 返回给定名称的剖析数据；如果不存在，则返回 nil。

func NewProfile 

func NewProfile(name string) *Profile

NewProfile 创建具有给定名称的新剖析数据。如果已存在同名剖析数据，NewProfile 会引发 panic。惯例是使用 'import/path.' 前缀，为每个包创建独立的命名空间。为了兼容读取 pprof 数据的各种工具，剖析名称不应包含空格。

func Profiles 

func Profiles() []*Profile

Profiles 返回所有已知剖析数据的切片，按名称排序。

func (*Profile) Add 

func (p *Profile) Add(value any, skip int)

Add 将当前执行栈添加到剖析数据中，并与 value 关联。Add 将 value 存储在内部映射中，因此 value 必须适合作为映射键，且在调用相应的 Profile.Remove 之前不会被垃圾回收。如果剖析数据中已经包含与 value 关联的栈，Add 会引发 panic。

skip 参数与 runtime.Caller 的 skip 含义相同，用于控制栈轨迹的起始位置。传入 skip=0 时，栈轨迹从调用 Add 的函数开始。例如，给定以下执行栈：

Add
由 rpc.NewClient 调用
由 mypkg.Run 调用
由 main.main 调用

传入 skip=0 时，栈轨迹从 rpc.NewClient 内对 Add 的调用开始。传入 skip=1 时，栈轨迹从 mypkg.Run 内对 NewClient 的调用开始。

func (*Profile) Count 

func (p *Profile) Count() int

Count 返回剖析数据当前包含的执行栈数量。

func (*Profile) Name 

func (p *Profile) Name() string

Name 返回此剖析数据的名称；可以将该名称传给 Lookup，再次取得此剖析数据。

func (*Profile) Remove 

func (p *Profile) Remove(value any)

Remove 从剖析数据中移除与 value 关联的执行栈。如果剖析数据中不存在该值，则不进行任何操作。

func (*Profile) WriteTo 

func (p *Profile) WriteTo(w io.Writer, debug int) error

WriteTo 将 pprof 格式的剖析数据快照写入 w。如果向 w 写入时返回错误，WriteTo 就返回该错误；否则返回 nil。

debug 参数用于启用额外输出。传入 debug=0 时，会写出 gzip 压缩的 Protocol Buffers 数据，格式见 https://github.com/google/pprof/tree/main/proto#overview。传入 debug=1 时，会写出旧版文本格式，并附带将地址转换为函数名和行号的注释，以便开发者不借助工具即可阅读剖析数据。

预定义的剖析类型可能为其他 debug 值赋予特定含义。例如，输出 "goroutine" 剖析时，debug=2 表示以 Go 程序因未恢复的 panic 而终止时所用的形式输出 goroutine 栈。
