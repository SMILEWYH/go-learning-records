http 包提供 HTTP 客户端和服务器实现。

Get、Head、Post 和 PostForm 可发起 HTTP（或 HTTPS）请求： 

resp, err := http.Get("http://example.com/")
...
resp, err := http.Post("http://example.com/upload", "image/jpeg", &buf)
...
resp, err := http.PostForm("http://example.com/form",
	url.Values{"key": {"Value"}, "id": {"123"}})

调用者使用完响应体后必须将其关闭： 

resp, err := http.Get("http://example.com/")
if err != nil {
	// 处理错误
}
defer resp.Body.Close()
body, err := io.ReadAll(resp.Body)
// ...

客户端与传输层

要控制 HTTP 客户端请求头、重定向策略和其他设置，请创建 Client： 

client := &http.Client{
	CheckRedirect: redirectPolicyFunc,
}

resp, err := client.Get("http://example.com")
// ...

req, err := http.NewRequest("GET", "http://example.com", nil)
// ...
req.Header.Add("If-None-Match", `W/"wyzzy"`)
resp, err := client.Do(req)
// ...

要控制代理、TLS 配置、连接保持、压缩和其他设置，请创建 Transport： 

tr := &http.Transport{
	MaxIdleConns:       10,
	IdleConnTimeout:    30 * time.Second,
	DisableCompression: true,
}
client := &http.Client{Transport: tr}
resp, err := client.Get("https://example.com")

Client 和 Transport 都可以由多个 goroutine 并发安全地使用。为提高效率，应只创建一次并重复使用。

服务器

ListenAndServe 使用给定地址和处理器启动 HTTP 服务器。handler 通常为 nil，表示使用 DefaultServeMux。Handle 和 HandleFunc 可向 DefaultServeMux 注册处理器： 

http.Handle("/foo", fooHandler)

http.HandleFunc("/bar", func(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "Hello, %q", html.EscapeString(r.URL.Path))
})

log.Fatal(http.ListenAndServe(":8080", nil))

创建自定义 Server 可以进一步控制服务器行为： 

s := &http.Server{
	Addr:           ":8080",
	Handler:        myHandler,
	ReadTimeout:    10 * time.Second,
	WriteTimeout:   10 * time.Second,
	MaxHeaderBytes: 1 << 20,
}
log.Fatal(s.ListenAndServe())

HTTP/2

http 包透明地支持 HTTP/2 协议。

使用 HTTPS 时，Server 和 DefaultTransport 会自动启用 HTTP/2。Transport 默认不启用 HTTP/2。

要启用或禁用 HTTP/1、HTTP/2 或未加密的 HTTP/2，请参阅 Server.Protocols 和 Transport.Protocols 配置字段。

要配置 HTTP/2 的高级功能，请参阅 Server.HTTP2 和 Transport.HTTP2 配置字段。

也可以使用目前支持的以下 GODEBUG 设置： 

GODEBUG=http2client=0  # disable HTTP/2 client support
GODEBUG=http2server=0  # disable HTTP/2 server support
GODEBUG=http2debug=1   # enable verbose HTTP/2 debug logs
GODEBUG=http2debug=2   # ... even more verbose, with frame dumps

可以使用 "omithttp2" 构建标签禁用 http 包内置的 HTTP/2 实现。

func CanonicalHeaderKey 

func CanonicalHeaderKey(s string) string

CanonicalHeaderKey 返回首部字段名 s 的规范形式：首字母及连字符后的字母转为大写，其余字母转为小写。例如，"accept-encoding" 的规范形式为 "Accept-Encoding"。如果 s 包含空格或首部字段名中不合法的字节，则原样返回。

func DetectContentType 

func DetectContentType(data []byte) string

DetectContentType 实现 https://mimesniff.spec.whatwg.org/ 描述的算法，用于判断给定数据的 Content-Type。它最多检查 data 的前 512 个字节，总会返回有效的 MIME 类型；无法判断更具体类型时，返回 "application/octet-stream"。

func ServeContent
				
				
			

			
func ServeContent(w ResponseWriter, req *Request, name string, modtime time.Time, content io.ReadSeeker)

			

ServeContent 使用给定 ReadSeeker 中的内容回复请求。相较于 io.Copy，主要优势是能正确处理 Range 请求、设置 MIME 类型，并处理 If-Match、If-Unmodified-Since、If-None-Match、If-Modified-Since 和 If-Range 请求。


如果响应尚未设置 Content-Type 首部，ServeContent 先尝试根据 name 的文件扩展名推断类型；失败后则读取内容的首个数据块，传给 DetectContentType。name 没有其他用途，可以为空，而且不会在响应中发送。

content 的 Seek 方法必须能正常工作：ServeContent 通过定位到内容末尾来确定大小。注意，*os.File 实现了 io.ReadSeeker 接口。


如果调用者为 w 设置了符合 RFC 7232 第 2.3 节格式的 ETag 首部，ServeContent 会使用它处理带有 If-Match、If-None-Match 或 If-Range 的请求。


处理请求时如果出错，例如遇到无效的范围请求，ServeContent 会回复错误消息。默认情况下，会从错误响应中删除 Cache-Control、Content-Encoding、ETag 和 Last-Modified 首部。设置 GODEBUG=httpservecontentkeepheaders=1 会让 ServeContent 保留这些首部。

type Client
				
				
			

			

Client 是 HTTP 客户端。其零值（DefaultClient）即可使用，并采用 DefaultTransport。


Client.Transport 通常包含缓存 TCP 连接等内部状态，因此应复用 Client，而非每次需要时重新创建。Client 可供多个 goroutine 并发安全地使用。


Client 比 RoundTripper（例如 Transport）更高层，还负责处理 cookie、重定向等 HTTP 细节。


跟随重定向时，Client 会转发初始 Request 上设置的所有首部，以下情况除外：

    

  • 
向不可信目标转发 "Authorization"、"WWW-Authenticate" 和 "Cookie" 等敏感首部时。如果重定向目标域名既不与初始域名完全相同，也不是其子域，就会忽略这些首部。例如，从 "foo.com" 重定向到 "foo.com" 或 "sub.foo.com" 会转发敏感首部，但重定向到 "bar.com" 不会。

  • 
在 cookie Jar 非 nil 时转发 "Cookie" 首部。每次重定向都可能修改 cookie jar 的状态，因此也可能改变初始请求中设置的 cookie。转发 "Cookie" 首部时会省略被修改的 cookie，预期由 Jar 在来源匹配时插入其更新后的值。如果 Jar 为 nil，初始 cookie 会原样转发。



			
type Client struct {
    // Transport 指定发送单个 HTTP 请求所使用的机制。
    // 若为 nil，则使用 DefaultTransport。
    Transport RoundTripper

    // CheckRedirect 指定处理重定向的策略。
    // 如果 CheckRedirect 非 nil，客户端会在跟随 HTTP 重定向前调用它。
    // 参数 req 是即将发送的请求；via 是已经发送的请求，按从早到晚排列。
    // 如果 CheckRedirect 返回错误，Client 的 Get 方法会同时返回前一个
    // Response（其 Body 已关闭）和 CheckRedirect 的错误
    //（包装在 url.Error 中），而不发送请求 req。
    // 特殊情况：如果 CheckRedirect 返回 ErrUseLastResponse，
    // 则返回最近一次响应，保留其响应体不关闭，且错误为 nil。
    //
    // 如果 CheckRedirect 为 nil，Client 使用默认策略：
    // 连续发出 10 个请求后停止。
    CheckRedirect func(req *Request, via []*Request) error

    // Jar 指定 cookie 存储器。
    //
    // Jar 为每个发出的 Request 插入相关 cookie，
    // 并使用每个收到的 Response 中的 cookie 值更新自身。
    // Client 每次跟随重定向时都会查询 Jar。
    //
    // 如果 Jar 为 nil，则只有在 Request 中显式设置了 cookie 时才发送它们。
    Jar CookieJar

    // Timeout 指定此 Client 发出请求的时间限制。
    // 超时时间包括建立连接、所有重定向和读取响应体的时间。
    // 在 Get、Head、Post 或 Do 返回后，计时器仍会继续运行，
    // 并能中断对 Response.Body 的读取。
    //
    // Timeout 为零表示没有超时限制。
    //
    // Client 向底层 Transport 取消请求的方式，
    // 与 Request 的 Context 结束时相同。
    //
    // 为兼容旧代码，如果 Transport 提供了已弃用的 CancelRequest 方法，
    // Client 也会使用它。新的 RoundTripper 实现应使用 Request 的 Context
    // 处理取消，而不应实现 CancelRequest。
    Timeout time.Duration // Go 1.3
}

func (*Client) Do
					
					
				

				
func (c *Client) Do(req *Request) (*Response, error)

				

Do 发送 HTTP 请求并返回 HTTP 响应，遵循客户端配置的重定向、cookie、身份验证等策略。


如果客户端策略（如 CheckRedirect）导致失败，或无法完成 HTTP 通信（例如网络连接问题），会返回错误。非 2xx 状态码本身不会导致错误。


返回错误为 nil 时，Response 包含非 nil 的 Body，调用者应负责关闭。如果 Body 没有读到 EOF 并关闭，Client 底层的 RoundTripper（通常是 Transport）可能无法在后续 keep-alive 请求中复用到服务器的持久 TCP 连接。不过，Body 关闭时，Transport 会在一个保守的读取上限内，自动尝试异步将 Response 的 Body 读到 EOF。


如果请求 Body 非 nil，底层 Transport 会将其关闭，即使出错也一样。关闭可能在 Do 返回之后异步进行。


发生错误时，可以忽略返回的 Response。只有 CheckRedirect 失败时，才会同时返回非 nil 的 Response 和非 nil 错误；即使如此，返回的 Response.Body 也已关闭。


通常会使用 Get、Post 或 PostForm，而不是直接使用 Do。


如果服务器返回重定向，Client 先调用 CheckRedirect 判断是否跟随。获准后，301、302 或 303 重定向会使后续请求使用 GET 方法（若原请求为 HEAD，则仍用 HEAD），并且不带请求体。307 或 308 重定向会保留原 HTTP 方法和请求体，前提是定义了 Request.GetBody。对于常见标准库请求体类型，NewRequest 会自动设置 GetBody。


注意，Client 的重定向行为不遵循 WHATWG Fetch 标准，因为实现时尚无成熟标准。因此按现代标准来看，Client 的行为相当宽松。例如，重定向到子域，或在同一主机上切换协议方案时，会保留敏感首部。


返回的错误均为 *url.Error 类型。如果请求超时，该 url.Error 值的 Timeout 方法返回 true。

type Handler
				
				
			

			

Handler 响应 HTTP 请求。


Handler.ServeHTTP 应将响应头和数据写入 ResponseWriter，然后返回。返回表示请求处理完毕；在 ServeHTTP 调用结束之后，或与其结束过程并发地使用 ResponseWriter 或读取 Request.Body，都是无效的。

如果 ServeHTTP 触发 panic，服务器（ServeHTTP 的调用方）会假定 panic 的影响仅限于当前请求。它会恢复 panic，将调用栈记录到服务器错误日志，并根据 HTTP 协议版本关闭网络连接或发送 HTTP/2 RST_STREAM。要中止处理器，让客户端看到中断的响应但服务器不记录错误，可以用 ErrAbortHandler 作为 panic 值。

type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

type Pusher
				
				1.8
			

			

Pusher 由支持 HTTP/2 服务器推送的 ResponseWriter 实现。背景介绍见 https://tools.ietf.org/html/rfc7540#section-8.2。

type Pusher interface {
    // Push 发起 HTTP/2 服务器推送。它使用给定目标和选项构造一个合成请求，
    // 将其序列化为 PUSH_PROMISE 帧，然后交由服务器的请求处理器处理。
    // opts 为 nil 时使用默认选项。
    //
    // target 必须是绝对路径（如 "/path"），或包含有效主机且与父请求
    // 使用相同方案的绝对 URL。若 target 是路径，则继承父请求的方案和主机。
    //
    // HTTP/2 规范禁止递归推送和跨 authority（目标主机与端口）的推送。
    // Push 不一定能检测出这些无效推送，但遵循规范的客户端
    // 会检测并取消它们。
    //
    // 若处理器希望推送 URL X，应在发送任何可能触发对 X 的请求的数据前
    // 调用 Push。这样可避免客户端在收到 X 的 PUSH_PROMISE 前就请求 X
    // 所导致的竞态。
    //
    // Push 会在单独的 goroutine 中运行，因此到达顺序不确定。
    // 所需同步必须由调用者实现。
    //
    // 如果客户端禁用了推送，或底层连接不支持推送，
    // Push 返回 ErrNotSupported。
    Push(target string, opts *PushOptions) error
}


			

			

			

			

			
		
			
			
type Request
				
				
			

			

Request 表示服务器收到的 HTTP 请求，或客户端即将发送的 HTTP 请求。


字段在客户端和服务器端的语义略有差异。除了下方字段说明，还请参阅 Request.Write 和 RoundTripper 的文档。

type Request struct {
    // Method 指定 HTTP 方法（GET、POST、PUT 等）。
    // 对客户端请求，空字符串表示 GET。
    Method string

    // URL 指定被请求的 URI（服务器收到的请求），
    // 或要访问的 URL（客户端发出的请求）。
    //
    // 对服务器请求，URL 从请求行提供的 URI 解析而来，
    // 原始 URI 保存在 RequestURI 中。对于大多数请求，
    // 除 Path 和 RawQuery 外的字段均为空。（参见 RFC 7230 第 5.3 节。）
    //
    // 对客户端请求，URL.Host 指定要连接的服务器；
    // Request.Host 则可选地指定 HTTP 请求中要发送的 Host 首部值。
    URL *url.URL

    // 服务器收到的请求的协议版本。
    //
    // 对客户端请求，这些字段会被忽略。HTTP 客户端代码始终使用
    // HTTP/1.1 或 HTTP/2。详情参见 Transport 的文档。
    Proto      string // "HTTP/1.0"
    ProtoMajor int    // 1
    ProtoMinor int    // 0

    // Header 包含服务器收到或客户端将要发送的请求首部字段。
    //
    // 如果服务器收到的请求带有以下首部行：
    //
    //	Host: example.com
    //	accept-encoding: gzip, deflate
    //	Accept-Language: en-us
    //	fOO: Bar
    //	foo: two
    //
    // 则得到：
    //
    //	Header = map[string][]string{
    //		"Accept-Encoding": {"gzip, deflate"},
    //		"Accept-Language": {"en-us"},
    //		"Foo": {"Bar", "two"},
    //	}
    //
    // 对于收到的请求，Host 首部被提升到 Request.Host 字段，
    // 并从 Header 映射中移除。
    //
    // HTTP 规定首部名称不区分大小写。请求解析器使用 CanonicalHeaderKey
    // 实现这一点：首字符及连字符后的字符转为大写，其余字符转为小写。
    //
    // 对客户端请求，Content-Length、Connection 等某些首部会在需要时
    // 自动写入，Header 中的相应值可能被忽略。
    // 参见 Request.Write 方法的文档。
    Header Header

    // Body 是请求体。
    //
    // 对客户端请求，Body 为 nil 表示没有请求体，例如 GET 请求。
    // HTTP Client 的 Transport 负责调用 Close 方法。
    //
    // 对服务器请求，Request.Body 始终非 nil；没有请求体时，读取会
    // 立即返回 EOF。Server 会关闭请求体，ServeHTTP 处理器无需关闭它。
    //
    // Body 必须允许并发调用 Read 和 Close。
    // 尤其是，调用 Close 应解除正在等待输入的 Read 的阻塞。
    Body io.ReadCloser

    // GetBody 是可选函数，用于返回 Body 的一个新副本。
    // 它用于客户端请求：当重定向要求多次读取请求体时使用。
    // 即使使用 GetBody，也仍然需要设置 Body。
    //
    // 对服务器请求，此字段不使用。
    GetBody func() (io.ReadCloser, error) // Go 1.8

    // ContentLength 记录关联内容的长度。
    // -1 表示长度未知。值 >= 0 表示可从 Body 读取对应数量的字节。
    //
    // 对客户端请求，若 Body 非 nil，值为 0 也会被视为长度未知。
    ContentLength int64

    // TransferEncoding 按从最外层到最内层列出传输编码。
    // 空列表表示 "identity" 编码。通常可以忽略此字段；
    // 发送和接收请求时，会按需自动添加和移除分块编码。
    TransferEncoding []string

    // Close 表示是否在回复此请求后（服务器端），
    // 或在发送此请求并读完响应后（客户端）关闭连接。
    //
    // 对服务器请求，HTTP 服务器会自动处理，处理器无需使用此字段。
    //
    // 对客户端请求，设置此字段将禁止同一主机的不同请求复用 TCP 连接，
    // 效果与设置 Transport.DisableKeepAlives 相同。
    Close bool

    // 对服务器请求，Host 指定所请求 URL 所在的主机。
    // 对 HTTP/1（RFC 7230 第 5.4 节），它是 "Host" 首部值，
    // 或 URL 本身给出的主机名；对 HTTP/2，它是 ":authority" 伪首部值。
    // 它可以采用 "host:port" 形式。对于国际化域名，Host 可采用
    // Punycode 或 Unicode 形式；需要时可用 golang.org/x/net/idna 转换。
    // 为防止 DNS 重绑定攻击，服务器处理器应验证 Host 首部值是否属于
    // 自己负责处理的主机。内置 ServeMux 支持为特定主机名注册模式，
    // 因而能保护注册到它的处理器。
    //
    // 对客户端请求，Host 可选地覆盖要发送的 Host 首部。若为空，
    // Request.Write 使用 URL.Host 的值。Host 可以包含国际化域名。
    Host string

    // Form 包含解析后的表单数据，既包括 URL 字段中的查询参数，
    // 也包括 PATCH、POST 或 PUT 的表单数据。
    // 只有调用 ParseForm 后此字段才可用。HTTP 客户端忽略 Form，改用 Body。
    Form url.Values

    // PostForm 包含从 PATCH、POST 或 PUT 请求体参数中解析出的表单数据。
    //
    // 只有调用 ParseForm 后此字段才可用。
    // HTTP 客户端忽略 PostForm，改用 Body。
    PostForm url.Values // Go 1.1

    // MultipartForm 是解析后的多部分表单，包含上传的文件。
    // 只有调用 ParseMultipartForm 后此字段才可用。
    // HTTP 客户端忽略 MultipartForm，改用 Body。
    MultipartForm *multipart.Form

    // Trailer 指定在请求体之后发送的附加首部。
    //
    // 对服务器请求，Trailer 映射最初只包含尾部字段的键，值为 nil
    //（客户端会声明稍后将发送哪些尾部字段）。处理器从 Body 读取时，
    // 不得访问 Trailer。读取 Body 返回 EOF 后，可以再次读取 Trailer；
    // 如果客户端发送了相应值，此时就会包含非 nil 的值。
    //
    // 对客户端请求，Trailer 必须初始化为包含稍后要发送的尾部字段键的映射。
    // 值可以为 nil，也可以直接设为最终值。ContentLength 必须为 0 或 -1，
    // 以便发送分块请求。HTTP 请求发出后，在请求体被读取期间仍可更新映射值。
    // 一旦请求体返回 EOF，调用者就不得再修改 Trailer。
    //
    // 写入请求时，如果 Trailer 的键包含无效字节（例如 CR 或 LF），
    // 或在 Write 开始时存在包含这些字节的值，将返回错误。
    //
    // 支持 HTTP 尾部字段的客户端、服务器或代理很少。
    Trailer Header

    // RemoteAddr 让 HTTP 服务器和其他软件记录发出请求的网络地址，
    // 通常用于日志。ReadRequest 不会填充此字段，其格式也没有规定。
    // 本包的 HTTP 服务器在调用处理器前，会将它设为 "IP:port" 地址。
    // HTTP 客户端忽略此字段。
    RemoteAddr string

    // RequestURI 是客户端发送给服务器的请求行中，未经修改的请求目标
    //（RFC 7230 第 3.1.1 节）。通常应改用 URL 字段。
    // 在 HTTP 客户端请求中设置此字段会导致错误。
    RequestURI string

    // TLS 让 HTTP 服务器和其他软件记录接收该请求的 TLS 连接信息。
    // ReadRequest 不会填充此字段。本包的 HTTP 服务器对启用 TLS 的连接，
    // 会在调用处理器前设置此字段；否则保留为 nil。
    // HTTP 客户端忽略此字段。
    TLS *tls.ConnectionState

    // Cancel 是可选通道，关闭此通道表示应将客户端请求视为已取消。
    // 并非所有 RoundTripper 实现都支持 Cancel。
    //
    // 此字段不适用于服务器请求。
    //
    // 已弃用：请改用 NewRequestWithContext 设置请求的上下文。
    // 如果同时设置 Request.Cancel 和上下文，是否遵从 Cancel 未作规定。
    Cancel <-chan struct{} // Go 1.5

    // Response 是导致此请求被创建的重定向响应。
    // 仅在客户端重定向过程中填充此字段。
    Response *Response // Go 1.7

    // Pattern 是与请求匹配的 [ServeMux] 模式。
    // 如果请求没有匹配任何模式，则为空。
    Pattern string // Go 1.23
    // 包含已过滤或未导出的字段
}

type Response
				
				
			

			

Response 表示 HTTP 请求的响应。


Client 和 Transport 在收到响应首部后就会返回服务器的 Response。响应体则在读取 Body 字段时按需以流的形式读取。

type Response struct {
    Status     string // 例如 "200 OK"
    StatusCode int    // 例如 200
    Proto      string // 例如 "HTTP/1.0"
    ProtoMajor int    // 例如 1
    ProtoMinor int    // 例如 0

    // Header 将首部键映射到值。如果响应有多个同名首部，
    // 它们可能以逗号为分隔符拼接起来。（RFC 7230 第 3.2.2 节要求，
    // 多个同名首部在语义上等价于以逗号分隔的序列。）
    // 当 Header 中的值也由此结构体中的其他字段表示时（例如
    // ContentLength、TransferEncoding、Trailer），以这些字段的值为准。
    //
    // 映射中的键均已规范化（参见 CanonicalHeaderKey）。
    Header Header

    // Body 表示响应体。
    //
    // 读取 Body 字段时，响应体按需以流的方式传输。
    // 如果网络连接失败或服务器终止响应，Body.Read 会返回错误。
    //
    // http Client 和 Transport 保证 Body 始终非 nil，
    // 即使响应不含响应体或响应体长度为零也是如此。调用者负责关闭 Body。
    // 如果 Body 未被读完并关闭，默认 HTTP 客户端的 Transport 可能不会
    // 复用 HTTP/1.x 的 keep-alive TCP 连接；不过，大多数情况下无需手动
    // 读完响应体，因为关闭响应体也会触发异步读取剩余内容，
    // 读取量受一个保守的上限约束。
    //
    // 如果服务器以 "chunked" Transfer-Encoding 响应，
    // Body 会自动去除分块编码。
    //
    // 自 Go 1.12 起，对于成功的 "101 Switching Protocols" 响应，
    // Body 还会实现 io.Writer，例如 WebSocket 和 HTTP/2 的 "h2c" 模式。
    Body io.ReadCloser

    // ContentLength 记录关联内容的长度。-1 表示长度未知。
    // 除非 Request.Method 为 "HEAD"，值 >= 0 表示可从 Body
    // 读取对应数量的字节。
    ContentLength int64

    // 按从最外层到最内层的顺序包含传输编码。
    // 值为 nil 表示使用 "identity" 编码。
    TransferEncoding []string

    // Close 记录首部是否指示在读完 Body 后关闭连接。
    // 此值仅向客户端提供建议：ReadResponse 和 Response.Write 都不会关闭连接。
    Close bool

    // Uncompressed 表示响应发送时经过压缩，但已由 http 包解压。
    // 若为 true，从 Body 读取的是解压后的内容，而非服务器实际发送的
    // 压缩内容；ContentLength 会设为 -1，响应首部中的 "Content-Length"
    // 和 "Content-Encoding" 字段会被删除。若要获取服务器的原始响应，
    // 请将 Transport.DisableCompression 设为 true。
    Uncompressed bool // Go 1.7

    // Trailer 将尾部字段的键映射到值，格式与 Header 相同。
    //
    // Trailer 最初只有 nil 值，键对应于服务器 "Trailer" 首部
    // 声明的各个名称。这些值不会加入 Header。
    //
    // 不得在调用 Body.Read 的同时并发访问 Trailer。
    //
    // Body.Read 返回 io.EOF 后，Trailer 将包含服务器发送的全部尾部字段值。
    Trailer Header

    // Request 是为了取得此 Response 而发送的请求。
    // 其中 Body 为 nil（已被消费）。仅对 Client 请求填充此字段。
    Request *Request

    // TLS 包含接收该响应的 TLS 连接信息。
    // 对未加密的响应，它为 nil。此指针由多个响应共享，不应修改。
    TLS *tls.ConnectionState // Go 1.3
}

type ResponseWriter interface {
    // Header 返回将由 [ResponseWriter.WriteHeader] 发送的首部映射。
    // [Handler] 实现也通过此 [Header] 映射设置 HTTP 尾部字段。
    //
    // 调用 [ResponseWriter.WriteHeader]（或 [ResponseWriter.Write]）后
    // 修改首部映射通常无效，除非 HTTP 状态码属于 1xx，
    // 或者修改的是尾部字段。
    //
    // 设置尾部字段有两种方式。推荐通过 "Trailer" 首部预先声明
    // 稍后将发送的尾部字段名称。此时，Header 映射中的相应键
    // 就会被当作尾部字段，参见示例。第二种方式用于 [Handler]
    // 直到首次调用 [ResponseWriter.Write] 后才知道名称的尾部字段：
    // 在 [Header] 映射的键前添加 [TrailerPrefix] 常量作为前缀。
    //
    // 若要禁止自动添加某个响应首部（例如 "Date"），将其值设为 nil。
    Header() Header

    // Write 将数据作为 HTTP 响应的一部分写入连接。
    //
    // 如果尚未调用 [ResponseWriter.WriteHeader]，Write 会在写入数据前
    // 调用 WriteHeader(http.StatusOK)。如果 Header 没有 Content-Type，
    // Write 会将写入数据的前 512 字节传给 [DetectContentType]，
    // 用其结果添加 Content-Type。此外，若总写入数据量少于几 KB，
    // 且没有调用 Flush，还会自动添加 Content-Length 首部。
    //
    // 根据 HTTP 协议版本和客户端的不同，调用 Write 或 WriteHeader 后
    // 可能无法继续读取 Request.Body。对于 HTTP/1.x 请求，处理器应在
    // 写入响应前读完所需的请求体数据。一旦首部被刷新发送
    //（显式调用 Flusher.Flush，或写入足够多的数据而触发刷新），
    // 请求体可能就无法再读取。对于 HTTP/2 请求，Go HTTP 服务器允许
    // 处理器在写入响应的同时继续读取请求体。不过，并非所有 HTTP/2
    // 客户端都支持这种行为。为获得最大兼容性，处理器应尽量先读后写。
    Write([]byte) (int, error)

    // WriteHeader 使用给定状态码发送 HTTP 响应首部。
    //
    // 若未显式调用 WriteHeader，首次调用 Write 会隐式触发
    // WriteHeader(http.StatusOK)。因此，显式调用 WriteHeader
    // 主要用于发送错误码或 1xx 信息性响应。
    //
    // code 必须是有效的 HTTP 1xx 至 5xx 状态码。
    // 可以写入任意数量的 1xx 首部，然后最多写入一次 2xx 至 5xx 首部。
    // 1xx 首部会立即发送，而 2xx 至 5xx 首部可能被缓冲。
    // 使用 Flusher 接口可发送缓冲的数据。发送 2xx 至 5xx 首部时会清空
    // 首部映射，发送 1xx 首部时则不会。
    //
    // 如果请求带有 "Expect: 100-continue" 首部，
    // 服务器会在首次读取请求体时自动发送 100（Continue）首部。
    WriteHeader(statusCode int)
}

type RoundTripper
				
				
			

			

RoundTripper 接口表示执行单次 HTTP 事务的能力，即为给定的 Request 获取对应的 Response。


RoundTripper 必须能安全地由多个 goroutine 并发使用。

type RoundTripper interface {
    // RoundTrip 执行一次 HTTP 事务，为给定 Request 返回 Response。
    //
    // RoundTrip 不应尝试解释响应。特别是，只要获得了响应，
    // 无论 HTTP 状态码是什么，都必须返回 err == nil。
    // 只有无法获得响应时才应返回非 nil 错误。同样，RoundTrip 不应尝试
    // 处理重定向、身份验证、cookie 等更高层的协议细节。
    //
    // 除消费并关闭 Request.Body 外，RoundTrip 不应修改请求。
    // RoundTrip 可能在单独的 goroutine 中读取请求字段。
    // 调用者在 Response.Body 关闭之前，不应修改或复用请求。
    //
    // RoundTrip 必须始终关闭请求体，包括发生错误时；但具体实现可能
    // 在单独的 goroutine 中执行关闭，甚至在 RoundTrip 返回之后才关闭。
    // 因此，如果调用者希望在后续请求中复用请求体，
    // 必须先安排等待 Close 调用完成。
    //
    // Request 的 URL 和 Header 字段必须已初始化。
    RoundTrip(*Request) (*Response, error)
}

type ServeMux
				
				
			

			

ServeMux 是 HTTP 请求多路复用器。它将每个传入请求的 URL 与已注册的模式列表匹配，并调用与该 URL 最精确匹配的模式所对应的处理器。


模式




模式可以匹配请求的方法、主机和路径。例如：

    

  • 
"/index.html" 匹配任意主机和方法下路径为 "/index.html" 的请求。

  • 
"GET /static/" 匹配路径以 "/static/" 开头的 GET 请求。

  • 
"example.com/" 匹配发往主机 "example.com" 的任意请求。

  • 
"example.com/{$}" 匹配主机为 "example.com" 且路径为 "/" 的请求。

  • 
"/b/{bucket}/o/{objectname...}" 匹配第一段为 "b"、第三段为 "o" 的路径。名称 "bucket" 表示第二段，"objectname" 表示路径的剩余部分。




通常，模式的形式如下：

[METHOD ][HOST]/[PATH]




这三个部分都可省略；"/" 是有效模式。如果存在 METHOD，其后必须至少有一个空格或制表符。


模式中的字面量部分（即非通配符部分）会区分大小写地匹配请求的相应部分。


未指定方法的模式匹配所有方法。指定 GET 方法的模式同时匹配 GET 和 HEAD 请求。其他情况下，方法必须完全匹配。


未指定主机的模式匹配所有主机。指定主机的模式只匹配该主机上的 URL。


路径可以包含 {NAME} 或 {NAME...} 形式的通配符路径段，例如 "/b/{bucket}/o/{objectname...}"。通配符名称必须是有效的 Go 标识符。通配符必须占据完整的路径段：前面必须是斜杠，后面必须是斜杠或字符串末尾。例如，"/b_{bucket}" 不是有效模式。


通常，通配符只匹配一个路径段，到请求 URL 中下一个字面斜杠（不是 %2F）为止。但如果包含 "..."，通配符就会匹配 URL 路径的所有剩余部分，包括斜杠。（因此，"..." 通配符只能出现在模式末尾，否则无效。）将通配符名称传给 Request.PathValue，即可获取匹配的值。路径末尾的斜杠相当于匿名的 "..." 通配符。


特殊通配符 {$} 只匹配 URL 末尾。例如，模式 "/{$}" 只匹配路径 "/"，而模式 "/" 会匹配所有路径。


匹配时，模式路径和传入请求的路径都会逐段进行反转义。例如，路径 "/a%2Fb/100%25" 被视为两个路径段："a/b" 和 "100%"。模式 "/a%2fb/" 能匹配它，但模式 "/a/b/" 不能。


优先级




如果两个或更多模式匹配同一个请求，则最具体的模式优先。如果 P1 匹配的请求集合是 P2 的真子集，P1 就比 P2 更具体；也就是说，P2 能匹配 P1 的所有请求，还能匹配更多请求。如果两者都不比对方更具体，则这两个模式冲突。为向后兼容，这条规则有一个例外：如果两个原本会冲突的模式中，一个指定了主机，另一个没有，那么指定了主机的模式优先。如果传给 ServeMux.Handle 或 ServeMux.HandleFunc 的模式与已注册的另一个模式冲突，这些函数会引发 panic。


例如，按一般规则，"/images/thumbnails/" 比 "/images/" 更具体，因此两者可以同时注册。前者匹配以 "/images/thumbnails/" 开头的路径，后者则匹配 "/images/" 子树下的其他路径。


再以模式 "GET /" 和 "/index.html" 为例：两者都匹配针对 "/index.html" 的 GET 请求，但前者还匹配所有其他 GET 和 HEAD 请求，后者则匹配使用其他方法请求 "/index.html" 的请求。因此，这两个模式冲突。


末尾斜杠重定向




假设 ServeMux 使用末尾斜杠或 "..." 通配符，为某个子树注册了处理器。如果 ServeMux 收到针对子树根路径的请求，且路径没有末尾斜杠，它会通过补上末尾斜杠进行重定向。单独注册不带末尾斜杠或 "..." 通配符的路径，可以覆盖此行为。例如，注册 "/images/" 后，ServeMux 会将对 "/images" 的请求重定向到 "/images/"，除非另外注册了 "/images"。


请求规范化




ServeMux 也会规范化请求 URL 的路径和 Host 首部：去除端口号，并将包含 . 或 .. 路径段、或者重复斜杠的请求重定向到等价但更规范的 URL。经过转义的路径元素（如表示 "." 的 "%2e" 和表示 "/" 的 "%2f"）会予以保留，在请求路由中不会被视为分隔符。


兼容性




Go 1.22 对 ServeMux 的模式语法和匹配行为做了较大修改。要恢复旧行为，可将 GODEBUG 环境变量设为 "httpmuxgo121=1"。该设置仅在程序启动时读取一次，运行期间的修改会被忽略。


不向后兼容的修改包括：

    

  • 
在 Go 1.21 中，通配符只是普通的字面路径段。例如，模式 "/{x}" 在 Go 1.21 中只匹配该路径，而在 Go 1.22 中会匹配任意仅含一个路径段的路径。

  • 
在 Go 1.21 中，除非模式为空或与已有模式冲突，否则都会被接受。在 Go 1.22 中，语法无效的模式会使 ServeMux.Handle 和 ServeMux.HandleFunc 引发 panic。例如，在 Go 1.21 中，模式 "/{" 和 "/a{x}" 会匹配它们自身；在 Go 1.22 中，它们则是无效模式，注册时会引发 panic。

  • 
在 Go 1.22 中，模式的每个路径段都会进行反转义；Go 1.21 不会这样做。例如，在 Go 1.22 中，模式 "/%61" 匹配路径 "/a"（"%61" 是 "a" 的 URL 转义序列）；但在 Go 1.21 中，它只会匹配路径 "/%2561"（其中 "%25" 是百分号的转义序列）。

  • 
将模式与路径匹配时，Go 1.22 会逐段对路径进行反转义，而 Go 1.21 会对整个路径进行反转义。此修改主要影响斜杠旁出现 %2F 转义序列时的路径处理方式。详情请参阅 https://go.dev/issue/21955。

Server 定义运行 HTTP 服务器所需的参数。Server 的零值是有效配置。

type Server struct {
    // Addr 可选地指定服务器监听的 TCP 地址，形式为 "host:port"。
    // 若为空，则使用 ":http"（端口 80）。服务名称由 RFC 6335 定义并由 IANA 分配。
    // 地址格式详情参见 net.Dial。
    Addr string

    Handler Handler // 要调用的处理器；若为 nil，则使用 http.DefaultServeMux

    // DisableGeneralOptionsHandler 若为 true，将 "OPTIONS *" 请求交给 Handler；
    // 否则回复 200 OK 和 Content-Length: 0。
    DisableGeneralOptionsHandler bool // Go 1.20

    // TLSConfig 可选地提供 ServeTLS 和 ListenAndServeTLS 使用的 TLS 配置。
    // 注意，这两个方法会克隆此值，因此不能通过 tls.Config.SetSessionTicketKeys
    // 等方法修改实际使用的配置。若要使用 SetSessionTicketKeys，
    // 请改为将 TLS Listener 传给 Server.Serve。
    TLSConfig *tls.Config

    // ReadTimeout 是读取整个请求（包括请求体）允许的最长时间。
    // 零值或负值表示没有超时限制。
    //
    // ReadTimeout 不允许处理器针对每个请求，分别决定请求体可接受的
    // 截止时间或上传速率，因此大多数使用者更倾向于使用
    // ReadHeaderTimeout。二者可以同时使用。
    ReadTimeout time.Duration

    // ReadHeaderTimeout 是读取请求首部允许的时间。
    // 读完首部后会重设连接的读取截止时间，处理器可自行决定
    // 请求体读取多慢才算超时。若为零，则使用 ReadTimeout 的值。
    // 若为负，或为零且 ReadTimeout 为零或负值，则没有超时限制。
    ReadHeaderTimeout time.Duration // Go 1.8

    // WriteTimeout 是写入响应的最长超时时间。
    // 每当读取一个新请求的首部时，都会重置此超时。与 ReadTimeout 一样，
    // 它不允许处理器按请求分别作出决定。零值或负值表示没有超时限制。
    WriteTimeout time.Duration

    // IdleTimeout 是启用保持连接时等待下一个请求的最长时间。
    // 若为零，则使用 ReadTimeout 的值。若为负，
    // 或为零且 ReadTimeout 为零或负值，则没有超时限制。
    IdleTimeout time.Duration // Go 1.8

    // MaxHeaderBytes 控制服务器解析请求首部键和值时
    // 最多读取的字节数，包括请求行。它不限制请求体大小。
    // 若为零，则使用 DefaultMaxHeaderBytes。
    MaxHeaderBytes int

    // MaxHeaderValueCount 控制服务器愿意从一个请求中解析的
    // 首部值的最大数量。若为零，则使用 DefaultMaxHeaderValueCount。
    // 注意，单个首部行内用逗号分隔的值只计一次；
    // 分别放在多个首部行中发送的值则会计多次。
    MaxHeaderValueCount int // Go 1.27

    // TLSNextProto 可选地指定发生 ALPN 协议升级后，
    // 接管给定 TLS 连接的函数。映射的键是协商后的协议名。
    // 应使用 Handler 参数处理 HTTP 请求；如果 Request.TLS 和
    // Request.RemoteAddr 尚未设置，它会初始化这些字段。
    // 函数返回时会自动关闭连接。TLSNextProto 非 nil 时，
    // 不会自动启用 HTTP/2 支持。
    //
    // 过去常用 TLSNextProto 禁用 HTTP/2。
    // 现在 Server.Protocols 提供了更简单的方式。
    TLSNextProto map[string]func(*Server, *tls.Conn, Handler) // Go 1.1

    // ConnState 指定可选回调，在客户端连接改变状态时调用。
    // 详情参见 ConnState 类型及相关常量。
    ConnState func(net.Conn, ConnState) // Go 1.3

    // ErrorLog 指定可选日志记录器，用于记录接受连接时的错误、
    // 处理器的意外行为和底层 FileSystem 错误。
    // 若为 nil，则使用 log 包的标准日志记录器。
    ErrorLog *log.Logger // Go 1.3

    // BaseContext 可选地指定一个函数，返回此服务器收到请求时
    // 使用的基础上下文。传入的 Listener 是即将开始接受请求的具体监听器。
    // BaseContext 为 nil 时，默认使用 context.Background()。
    // 若非 nil，则它必须返回非 nil 的上下文。
    BaseContext func(net.Listener) context.Context // Go 1.13

    // ConnContext 可选地指定一个函数，修改新连接 c 使用的上下文。
    // 传入的 ctx 派生自基础上下文，且包含 ServerContextKey 对应的值。
    ConnContext func(ctx context.Context, c net.Conn) context.Context // Go 1.13

    // HTTP2 配置 HTTP/2 连接。
    HTTP2 *HTTP2Config // Go 1.24

    // Protocols 是服务器接受的协议集合。
    //
    // 若包含 UnencryptedHTTP2，服务器就接受未加密的 HTTP/2 连接。
    // 服务器可在同一地址和端口同时提供 HTTP/1 与未加密的 HTTP/2 服务。
    //
    // Protocols 为 nil 时，默认通常是 HTTP/1 和 HTTP/2。
    // 如果 TLSNextProto 非 nil 且不包含 "h2" 条目，则默认仅支持 HTTP/1。
    Protocols *Protocols // Go 1.24

    // DisableClientPriority 指定是否遵从客户端按 RFC 9218 设置的优先级。
    //
    // 仅在使用 HTTP/2 且没有为 HTTP/2 服务器定义自定义写入调度器时，
    // 此字段才有效；否则不起作用。
    //
    // 若为 true，将以轮询方式处理请求，不按优先级调度。
    DisableClientPriority bool // Go 1.27
    // 包含已过滤或未导出的字段
}

type Transport
				
				
			

			

Transport 是 RoundTripper 的一种实现，支持 HTTP、HTTPS 和 HTTP 代理（用于 HTTP，或通过 CONNECT 用于 HTTPS）。


默认情况下，Transport 会缓存连接，以供后续复用。当访问多个主机时，这可能会留下大量打开的连接。可以使用 Transport.CloseIdleConnections 方法以及 Transport.MaxIdleConnsPerHost 和 Transport.DisableKeepAlives 字段来管理此行为。


应复用 Transport，而不是每次需要时都创建一个。Transport 可以安全地由多个 goroutine 并发使用。


Transport 是发送 HTTP 和 HTTPS 请求的底层基础组件。Cookie 和重定向等高级功能请参阅 Client。


对于 HTTP URL，Transport 使用 HTTP/1.1；对于 HTTPS URL，则根据服务器是否支持 HTTP/2 以及 Transport 的配置，使用 HTTP/1.1 或 HTTP/2。DefaultTransport 支持 HTTP/2。要为某个 Transport 显式启用 HTTP/2，请设置 Transport.Protocols。


状态码在 1xx 范围内的响应会被自动处理（100 expect-continue）或忽略。唯一的例外是 HTTP 状态码 101（切换协议），它被视为最终状态，由 Transport.RoundTrip 返回。要观察被忽略的 1xx 响应，请使用 httptrace 跟踪包的 ClientTrace.Got1xxResponse。


Transport 仅在遇到网络错误且满足以下条件时重试请求：该连接曾被成功使用；请求是幂等的；并且请求没有请求体，或者已定义 Request.GetBody。HTTP 方法为 GET、HEAD、OPTIONS 或 TRACE 的请求被视为幂等请求；Header 映射中包含 "Idempotency-Key" 或 "X-Idempotency-Key" 条目的请求也被视为幂等请求。如果幂等键的值是长度为零的切片，请求仍会被视为幂等，但该首部不会在网络上传输。

type Transport struct {

    // Proxy 指定一个函数，返回给定 Request 所使用的代理。
    // 如果函数返回非 nil 错误，请求就会中止并返回该错误。
    //
    // 代理类型由 URL 的方案决定。支持 "http"、"https"、"socks5"
    // 和 "socks5h"；方案为空时按 "http" 处理。
    // "socks5" 与 "socks5h" 的处理方式相同。
    //
    // 如果代理 URL 包含 userinfo 部分，代理请求会通过
    // Proxy-Authorization 首部传递用户名和密码。
    //
    // 若 Proxy 为 nil，或返回的 *URL 为 nil，则不使用代理。
    Proxy func(*Request) (*url.URL, error)

    // 当 Transport 收到代理对 CONNECT 请求的 HTTP 响应时，
    // 会在检查响应是否为 200 OK 之前调用 OnProxyConnectResponse。
    // 若它返回错误，请求就会以该错误失败。
    OnProxyConnectResponse func(ctx context.Context, proxyURL *url.URL, connectReq *Request, connectRes *Response) error // Go 1.20

    // DialContext 指定用于建立未加密 TCP 连接的拨号函数。
    // 如果 DialContext 为 nil（且下面已弃用的 Dial 也为 nil），
    // Transport 将使用 net 包建立连接。
    //
    // DialContext 与 RoundTrip 调用并发执行。
    // 发起拨号的 RoundTrip 调用最终可能使用先前建立的连接：
    // 只要先前的连接在此次 DialContext 完成前已变为空闲即可。
    DialContext func(ctx context.Context, network, addr string) (net.Conn, error) // Go 1.7

    // Dial 指定用于建立未加密 TCP 连接的拨号函数。
    //
    // Dial 与 RoundTrip 调用并发执行。
    // 发起拨号的 RoundTrip 调用最终可能使用先前建立的连接：
    // 只要先前的连接在此次 Dial 完成前已变为空闲即可。
    //
    // 已弃用：请改用 DialContext，以便 Transport 在不再需要连接时
    // 立即取消拨号。若两者都已设置，DialContext 优先。
    Dial func(network, addr string) (net.Conn, error)

    // DialTLSContext 可选地指定拨号函数，
    // 为不经过代理的 HTTPS 请求建立 TLS 连接。
    //
    // 若 DialTLSContext 为 nil（且下面已弃用的 DialTLS 也为 nil），
    // 则使用 DialContext 和 TLSClientConfig。
    //
    // 设置 DialTLSContext 后，HTTPS 请求不再使用 Dial 和 DialContext
    // 钩子，并忽略 TLSClientConfig 和 TLSHandshakeTimeout。
    // 返回的 net.Conn 被假定为已完成 TLS 握手。
    //
    // 要支持 ALPN 协议协商，返回的 net.Conn 应为 *tls.Conn，
    // 或实现与 *tls.Conn 相同的 ConnectionState 方法。
    DialTLSContext func(ctx context.Context, network, addr string) (net.Conn, error) // Go 1.14

    // DialTLS 可选地指定拨号函数，
    // 为不经过代理的 HTTPS 请求建立 TLS 连接。
    //
    // 已弃用：请改用 DialTLSContext，以便 Transport 在不再需要连接时
    // 立即取消拨号。若两者都已设置，DialTLSContext 优先。
    DialTLS func(network, addr string) (net.Conn, error) // Go 1.4

    // TLSClientConfig 指定 tls.Client 使用的 TLS 配置。
    // 若为 nil，使用默认配置。
    // 若非 nil，可能不会默认启用 HTTP/2 支持。
    TLSClientConfig *tls.Config

    // TLSHandshakeTimeout 指定等待 TLS 握手的最长时间。
    // 零值表示没有超时限制。
    TLSHandshakeTimeout time.Duration // Go 1.3

    // DisableKeepAlives 若为 true，会禁用 HTTP 连接复用，
    // 每条到服务器的连接只用于一个 HTTP 请求。
    //
    // 这与名称相似的 TCP keep-alive 机制无关。
    DisableKeepAlives bool

    // DisableCompression 若为 true，则在 Request 没有现成的
    // Accept-Encoding 值时，禁止 Transport 通过添加
    // "Accept-Encoding: gzip" 请求首部来请求压缩。
    // 如果 Transport 自行请求 gzip 并收到 gzip 响应，
    // 则会在 Response.Body 中透明解压。
    // 但如果用户显式请求 gzip，则不会自动解压。
    DisableCompression bool

    // MaxIdleConns 控制所有主机的空闲（保持连接）连接总数上限。
    // 零值表示不限制。
    MaxIdleConns int // Go 1.7

    // MaxIdleConnsPerHost 非零时，控制为每个主机保留的
    // 最大空闲（保持连接）连接数。若为零，则使用 DefaultMaxIdleConnsPerHost。
    MaxIdleConnsPerHost int

    // MaxConnsPerHost 可选地限制每个主机的连接总数，
    // 包括正在拨号、活动和空闲的连接。达到限制后，拨号会阻塞。
    //
    // 零值表示不限制。
    MaxConnsPerHost int // Go 1.11

    // IdleConnTimeout 是空闲（保持连接）连接在自行关闭前
    // 最多可保持空闲的时间。零值表示不限制。
    IdleConnTimeout time.Duration // Go 1.7

    // ResponseHeaderTimeout 非零时，指定完整写入请求
    //（包括请求体，如果存在）后，等待服务器响应首部的时间。
    // 此时间不包括读取响应体的时间。
    ResponseHeaderTimeout time.Duration // Go 1.1

    // 如果请求带有 "Expect: 100-continue" 首部，
    // ExpectContinueTimeout 非零时指定完整写入请求首部后，
    // 等待服务器首次响应首部的时间。零值表示不等待，
    // 会立即发送请求体，无需等服务器许可。
    // 此时间不包括发送请求首部的时间。
    ExpectContinueTimeout time.Duration // Go 1.6

    // TLSNextProto 指定 Transport 在 TLS ALPN 协议协商后
    // 如何切换到其他协议（例如 HTTP/2）。如果 Transport 建立的 TLS 连接
    // 协商了非空协议名，且 TLSNextProto 映射中存在该键（例如 "h2"），
    // 就会以请求的 authority（主机及可选端口，例如 "example.com" 或 "example.com:1234"）
    // 和 TLS 连接为参数调用对应函数。函数必须返回一个 RoundTripper，
    // 由它继续处理请求。TLSNextProto 非 nil 时，不会自动启用 HTTP/2。
    //
    // 过去常用 TLSNextProto 禁用 HTTP/2。
    // 现在 Transport.Protocols 提供了更简单的方式。
    TLSNextProto map[string]func(authority string, c *tls.Conn) RoundTripper // Go 1.6

    // ProxyConnectHeader 可选地指定发送 CONNECT 请求时
    // 传给代理的首部。动态设置首部请参见 GetProxyConnectHeader。
    ProxyConnectHeader Header // Go 1.8

    // GetProxyConnectHeader 可选地指定一个函数，返回为连接 ip:port 目标
    // 而向 proxyURL 发送 CONNECT 请求时使用的首部。
    // 如果返回错误，Transport.RoundTrip 就会以该错误失败。
    // 可返回 (nil, nil) 表示不添加首部。
    // GetProxyConnectHeader 非 nil 时，ProxyConnectHeader 会被忽略。
    GetProxyConnectHeader func(ctx context.Context, proxyURL *url.URL, target string) (Header, error) // Go 1.16

    // MaxResponseHeaderBytes 指定服务器响应首部
    // 所允许的最大字节数。
    //
    // 零值表示使用默认限制。
    MaxResponseHeaderBytes int64 // Go 1.7

    // WriteBufferSize 指定向 Transport 写入数据时使用的写缓冲区大小。
    // 若为零，则使用默认值（当前为 4KB）。
    WriteBufferSize int // Go 1.13

    // ReadBufferSize 指定从 Transport 读取数据时使用的读缓冲区大小。
    // 若为零，则使用默认值（当前为 4KB）。
    ReadBufferSize int // Go 1.13

    // ForceAttemptHTTP2 控制在提供了非零的 Dial、DialTLS、
    // DialContext 函数或 TLSClientConfig 时，是否启用 HTTP/2。
    // 默认情况下，使用任一这些字段都会出于保守考虑禁用 HTTP/2。
    // 若要使用自定义拨号函数或 TLS 配置，同时仍尝试升级到 HTTP/2，
    // 请将此字段设为 true。
    ForceAttemptHTTP2 bool // Go 1.13

    // HTTP2 配置 HTTP/2 连接。
    HTTP2 *HTTP2Config // Go 1.24

    // Protocols 是 Transport 支持的协议集合。
    //
    // 若包含 UnencryptedHTTP2 但不包含 HTTP1，
    // 则对 http:// URL 的请求使用未加密的 HTTP/2。
    //
    // Protocols 为 nil 时，默认通常仅使用 HTTP/1。
    // 如果 ForceAttemptHTTP2 为 true，或 TLSNextProto 包含 "h2" 条目，
    // 则默认支持 HTTP/1 和 HTTP/2。
    Protocols *Protocols // Go 1.24
    // 包含已过滤或未导出的字段
}

func (*Transport) NewClientConn
					
					1.26
				

				
func (t *Transport) NewClientConn(ctx context.Context, scheme, address string) (*ClientConn, error)

				

NewClientConn 为给定地址创建一个新的客户端连接。


如果 scheme 为 "http"，连接不加密。如果 scheme 为 "https"，连接使用 TLS。


新连接使用的协议由 scheme、Transport.Protocols 配置字段以及服务器支持的协议共同决定。详情请参阅 Transport.Protocols。


如果设置了 Transport.Proxy，并且它表示发送到给定地址的请求应使用代理，新连接就会使用该代理。


NewClientConn 始终创建新连接，即使 Transport 已经缓存了到给定主机的连接。


新连接不会加入 Transport 的连接缓存，也不会被 Transport.RoundTrip 使用。它不计入 MaxIdleConns 和 MaxConnsPerHost 的限制。


调用者负责关闭新连接。

func (*Transport) RegisterProtocol
					
					
				

				
func (t *Transport) RegisterProtocol(scheme string, rt RoundTripper)

				

RegisterProtocol 为 scheme 注册新协议。Transport 会将使用给定协议方案的请求交给 rt。rt 负责模拟 HTTP 请求语义。


其他包可以使用 RegisterProtocol 提供 "ftp" 或 "file" 等协议方案的实现。


如果 rt.RoundTrip 返回 ErrSkipAltProtocol，Transport 会自行处理该次请求的 Transport.RoundTrip，就像从未注册过该协议一样。
