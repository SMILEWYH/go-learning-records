func DumpRequest 

func DumpRequest(req *http.Request, body bool) ([]byte, error)

DumpRequest 返回给定请求的 HTTP/1.x 传输表示。它仅应由服务器用于调试客户端请求。返回的表示只是近似值；原始请求解析为 http.Request 时会丢失一些细节。尤其是，头部字段名的顺序和大小写会丢失。多值头部中值的顺序会完整保留。HTTP/2 请求会转储为 HTTP/1.x 形式，而非其原始二进制表示。

如果 body 为 true，DumpRequest 还会返回请求体。为此，它会读取完 req.Body，再用一个产生相同字节的新 io.ReadCloser 替换它。如果 DumpRequest 返回错误，req 的状态未定义。

转储中包含 req 的哪些字段，详见 http.Request.Write 文档。

func NewChunkedReader 

func NewChunkedReader(r io.Reader) io.Reader

NewChunkedReader 返回一个新的 chunkedReader，将从 r 读取的数据从 HTTP“chunked”格式解码后返回。读到最后一个长度为 0 的分块时，chunkedReader 返回 io.EOF。

普通应用不需要 NewChunkedReader。http 包在读取响应体时会自动解码分块传输。

func NewChunkedWriter 

func NewChunkedWriter(w io.Writer) io.WriteCloser

NewChunkedWriter 返回一个新的 chunkedWriter，将写入的数据转换为 HTTP“chunked”格式后再写入 w。关闭返回的 chunkedWriter 会发送标记流结束的最后一个长度为 0 的分块，但不会发送尾部字段之后的最终 CRLF；尾部字段和最终 CRLF 必须单独写入。

普通应用不需要 NewChunkedWriter。如果处理器没有设置 Content-Length 头部，http 包会自动添加分块编码。在处理器中使用 NewChunkedWriter 会导致重复分块编码，或在具有 Content-Length 的情况下使用分块编码，这两种情况都是错误的。

func (*ClientConn) Read 

func (cc *ClientConn) Read(req *http.Request) (resp *http.Response, err error)

Read 从连接读取下一个响应。它可能同时返回有效响应和 ErrPersistEOF，这表示远端要求将此次请求作为最后一个处理的请求。Read 可以与 ClientConn.Write 并发调用，但不能与另一次 Read 并发调用。

func (*ClientConn) Write 

func (cc *ClientConn) Write(req *http.Request) error

Write 写入请求。如果连接在 HTTP keep-alive 语义上已关闭，则返回 ErrPersistEOF 错误。如果 req.Close 为 true，持久连接会在此请求后逻辑关闭，并通知对端服务器。ErrUnexpectedEOF 表示远端关闭了底层 TCP 连接，通常视为正常关闭。

type ProxyRequest 1.20

ProxyRequest 包含一个将由 ReverseProxy 重写的请求。 

type ProxyRequest struct {
    // In 是代理接收到的请求。
    // Rewrite 函数不得修改 In。
    In *http.Request

    // Out 是代理将要发送的请求。
    // Rewrite 函数可以修改或替换此请求。
    // 调用 Rewrite 之前，
    // 会从此请求中移除逐跳头部。
    Out *http.Request
}

func (*ProxyRequest) SetURL 1.20 

func (r *ProxyRequest) SetURL(target *url.URL)

SetURL 将发出的请求路由到 target 指定的协议、主机和基础路径。如果 target 的路径为“/base”，传入请求的路径为“/dir”，则目标请求的路径为“/base/dir”。若要在路由请求时不拼接传入路径，请直接设置 r.Out.URL。

SetURL 重写发出请求的 Host 头部，使其与目标主机一致。若要保留传入请求的 Host 头部（即 NewSingleHostReverseProxy 的默认行为）： 

rewriteFunc := func(r *httputil.ProxyRequest) {
	r.SetURL(url)
	r.Out.Host = r.In.Host
}

func (*ProxyRequest) SetXForwarded 1.20 

func (r *ProxyRequest) SetXForwarded()

SetXForwarded 设置发出请求的 X-Forwarded-For、X-Forwarded-Host 和 X-Forwarded-Proto 头部。

  • X-Forwarded-For 头部设为客户端 IP 地址。
  • X-Forwarded-Host 头部设为客户端请求的主机名。
  • X-Forwarded-Proto 头部根据传入请求是否使用启用 TLS 的连接，设为“http”或“https”。

如果发出请求中已有 X-Forwarded-For 头部，SetXForwarded 会向其追加客户端 IP 地址。若要追加到传入请求的 X-Forwarded-For 头部（即使用 Director 函数时 ReverseProxy 的默认行为），请在调用 SetXForwarded 之前，从传入请求复制该头部： 

rewriteFunc := func(r *httputil.ProxyRequest) {
	r.Out.Header["X-Forwarded-For"] = r.In.Header["X-Forwarded-For"]
	r.SetXForwarded()
}

type ReverseProxy

ReverseProxy 是一个 HTTP 处理器，接收传入请求并将其发送到另一台服务器，再将响应代理回客户端。

如果底层传输实现支持 ClientTrace.Got1xxResponse，则 1xx 响应会被转发给客户端。

逐跳头部（见 RFC 9110 第 7.6.1 节）会从客户端请求和后端响应中移除，包括 Connection、Proxy-Connection、Keep-Alive、Proxy-Authenticate、Proxy-Authorization、TE、Trailer、Transfer-Encoding 和 Upgrade。可以使用 Rewrite 函数向请求添加逐跳头部，也可以使用 ModifyResponse 函数从响应移除它们。 

type ReverseProxy struct {
    // Rewrite 必须是一个修改请求的函数，
    // 将其转换为通过 Transport 发送的
    // 新请求。得到的响应会原样复制
    // 回最初的客户端。
    // Rewrite 返回后，不得访问所提供的 ProxyRequest
    // 或其内容。
    //
    // 调用 Rewrite 之前，Forwarded、X-Forwarded、
    // X-Forwarded-Host 和 X-Forwarded-Proto 头部会从
    // 发出的请求中移除。另见
    // ProxyRequest.SetXForwarded 方法。
    //
    // 调用 Rewrite 之前，无法解析的查询参数会
    // 从发出的请求中移除。
    // Rewrite 函数可以将传入 URL 的 RawQuery
    // 复制到发出的 URL，以保留原始
    // 参数字符串。注意，如果代理对查询参数
    // 的解释与下游服务器不同，
    // 这可能导致安全问题。
    //
    // Rewrite 和 Director 最多只能设置一个。
    Rewrite func(*ProxyRequest) // Go 1.20

    // 用于执行代理请求的传输实现。
    // 如果为 nil，则使用 http.DefaultTransport。
    Transport http.RoundTripper

    // FlushInterval 指定复制响应体时，
    // 向客户端刷新数据的
    // 时间间隔。
    // 如果为零，则不进行定期刷新。
    // 负值表示每次向客户端写入后
    // 立即刷新。
    // 当 ReverseProxy 识别出响应为流式响应，
    // 或其 ContentLength 为 -1 时，
    // 会忽略 FlushInterval；对于这些响应，
    // 每次写入后都会立即向客户端刷新。
    FlushInterval time.Duration

    // ErrorLog 指定一个可选的日志记录器，用于记录
    // 尝试代理请求时发生的错误。
    // 如果为 nil，则使用 log 包的标准日志记录器。
    ErrorLog *log.Logger // Go 1.4

    // BufferPool 可选，用于指定缓冲池，
    // 在复制 HTTP 响应体时，从中获取
    // io.CopyBuffer 所使用的字节切片。
    BufferPool BufferPool // Go 1.6

    // ModifyResponse 是可选函数，用于修改
    // 后端返回的 Response。只要后端返回响应，
    // 无论 HTTP 状态码为何，都会调用它。
    // 如果无法连接后端，则调用可选的 ErrorHandler，
    // 而不会调用 ModifyResponse。
    //
    // 调用 ModifyResponse 前，会从响应中移除
    // 逐跳头部。ModifyResponse 可能还需要移除
    // 其他头部（如 Alt-Svc），以适应实际部署方式。
    //
    // 如果 ModifyResponse 返回错误，会将该错误值
    // 传给 ErrorHandler。如果 ErrorHandler 为 nil，
    // 则使用其默认实现。
    ModifyResponse func(*http.Response) error // Go 1.8

    // ErrorHandler 是可选函数，用于处理连接后端时
    // 发生的错误，或 ModifyResponse 返回的错误。
    //
    // 如果为 nil，默认行为是记录给定错误，并返回
    // 状态码为 502 Bad Gateway 的响应。
    ErrorHandler func(http.ResponseWriter, *http.Request, error) // Go 1.11

    // Director 已弃用。请改用 Rewrite。
    //
    // 此函数不安全：
    //
    //   - Director 返回后会从请求中移除逐跳头部，
    //     这可能移除 Director 添加的头部。
    //     客户端可以在 Connection 头部中列出某些头部，
    //     将它们指定为逐跳头部，因此恶意客户端可以
    //     移除 Director 可能添加的任何头部。
    //
    //   - 默认会保留传入请求中的 X-Forwarded-For、
    //     X-Forwarded-Host 和 X-Forwarded-Proto 头部；
    //     如果 Director 函数没有谨慎地移除这些头部，
    //     就可能允许 IP 欺骗。
    //
    // Rewrite 解决了这些问题。
    //
    // 下面演示如何将 Director 函数转换为 Rewrite：
    //
    //	// 使用 Director 函数的 ReverseProxy。
    //	proxy := &httputil.ReverseProxy{
    //		Director: func(req *http.Request) {
    //			req.URL.Scheme = "https"
    //			req.URL.Host = proxyHost
    //
    //			// 恶意客户端可以移除此头部。
    //			req.Header.Set("Some-Header", "some-header-value")
    //
    //			// 客户端发送的 X-Forwarded-* 头部会保留，
    //			// 因为 Director 没有移除它们。
    //		},
    //	}
    //
    //	// 使用 Rewrite 函数的 ReverseProxy。
    //	proxy := &httputil.ReverseProxy{
    //		Rewrite: func(preq *httputil.ProxyRequest) {
    //			// 另见 ProxyRequest.SetURL。
    //			preq.Out.URL.Scheme = "https"
    //			preq.Out.URL.Host = proxyHost
    //
    //			// 恶意客户端无法影响此头部。
    //			preq.Out.Header.Set("Some-Header", "some-header-value")
    //
    //			// 客户端发送的 X-Forwarded- 头部已
    //			// 从 preq.Out 中移除。
    //			// 可以调用 ProxyRequest.SetXForwarded 添加新的头部。
    //			preq.SetXForwarded()
    //		},
    //	}
    //
    // Director 是一个修改请求的函数，
    // 将其转换为通过 Transport 发送的
    // 新请求。得到的响应会原样复制
    // 回最初的客户端。
    // Director 返回后，不得访问所提供的 Request。
    //
    //
    // 默认情况下，X-Forwarded-For 头部设为
    // 客户端 IP 地址。如果已存在 X-Forwarded-For
    // 头部，则将客户端 IP 追加到
    // 现有值后面。有一种特殊情况：如果该头部
    // 存在于 Request.Header 映射中，但值为 nil
    // （例如由 Director 函数设置），则不会修改
    // X-Forwarded-For 头部。
    //
    // 为防止 IP 欺骗，务必删除来自客户端
    // 或不可信代理的任何已有
    // X-Forwarded-For 头部。
    //
    // Director 返回后会从请求中移除
    // 逐跳头部，这可能移除 Director
    // 添加的头部。请改用 Rewrite 函数，
    // 以确保对请求的修改得到保留。
    //
    // 如果 Director 返回后 Request.Form 已设置，
    // 则会从发出请求中移除无法解析的查询参数。
    //
    // Rewrite 和 Director 最多只能设置一个。
    //
    // 已弃用：请改用 Rewrite。
    Director func(*http.Request)
}

func NewSingleHostReverseProxy 

func NewSingleHostReverseProxy(target *url.URL) *ReverseProxy

NewSingleHostReverseProxy 返回一个新的 ReverseProxy，将 URL 路由到 target 指定的协议、主机和基础路径。如果 target 的路径为“/base”，传入请求的路径为“/dir”，则目标请求的路径为 /base/dir。

NewSingleHostReverseProxy 不会重写 Host 头部。

出于向后兼容的原因，NewSingleHostReverseProxy 返回的 ReverseProxy 使用已弃用的 Director 函数。该代理会保留客户端发送的 X-Forwarded-* 头部。

若要在 NewSingleHostReverseProxy 提供的行为之外进一步定制 ReverseProxy，请直接使用带 Rewrite 函数的 ReverseProxy。可以使用 ProxyRequest 的 SetURL 方法路由发出的请求。（注意，与 NewSingleHostReverseProxy 不同，SetURL 默认会重写发出请求的 Host 头部。） 

proxy := &ReverseProxy{
	Rewrite: func(r *ProxyRequest) {
		r.SetURL(target)
		r.Out.Host = r.In.Host // 如果需要
	},
}
