net 包为网络 I/O 提供可移植的接口，包括 TCP/IP、UDP、域名解析和 Unix 域套接字。

虽然本包提供了底层网络原语，但多数使用者只需要 Dial、Listen 和 Accept 函数，以及相关的 Conn 和 Listener 接口所提供的基本功能。crypto/tls 包采用相同接口，并提供类似的 Dial 和 Listen 函数。

Dial 函数连接到服务器： 

conn, err := net.Dial("tcp", "golang.org:80")
if err != nil {
	// 处理错误
}
fmt.Fprintf(conn, "GET / HTTP/1.0\r\n\r\n")
status, err := bufio.NewReader(conn).ReadString('\n')
// ...

Listen 函数创建服务器： 

ln, err := net.Listen("tcp", ":8080")
if err != nil {
	// 处理错误
}
for {
	conn, err := ln.Accept()
	if err != nil {
		// 处理错误
	}
	go handleConnection(conn)
}

名称解析

域名解析方法因操作系统而异，无论是通过 Dial 等函数间接解析，还是通过 LookupHost 和 LookupAddr 等函数直接解析，都如此。

在 Unix 系统上，名称解析器有两种解析方式。它可以使用纯 Go 解析器，直接向 /etc/resolv.conf 中列出的服务器发送 DNS 请求；也可以使用基于 cgo 的解析器，调用 getaddrinfo、getnameinfo 等 C 库函数。

在 Unix 上，优先使用纯 Go 解析器，因为阻塞的 DNS 请求只消耗一个 goroutine（轻量级协程），而阻塞的 C 调用会占用一个操作系统线程。当 cgo 可用时，以下情况会改用基于 cgo 的解析器：系统不允许程序直接发送 DNS 请求（OS X）；存在 LOCALDOMAIN 环境变量（即使值为空）；RES_OPTIONS 或 HOSTALIASES 环境变量非空；ASR_CONFIG 环境变量非空（仅 OpenBSD）；/etc/resolv.conf 或 /etc/nsswitch.conf 指定了 Go 解析器尚未实现的功能。

在除 Plan 9 之外的所有系统上，使用 cgo 解析器时，本包会限制并发 cgo 查询数量，以防耗尽系统线程。目前上限为 500 个并发查询。

可以将 GODEBUG 环境变量（见 runtime 包）的 netdns 值设为 go 或 cgo，覆盖解析器选择，例如： 

export GODEBUG=netdns=go    # 强制使用纯 Go 解析器
export GODEBUG=netdns=cgo   # 强制使用原生解析器（cgo、win32）

构建 Go 源码树时，也可以设置 netgo 或 netcgo 构建标签，强制选择解析器。netgo 标签完全禁用原生（CGO）解析器，因此只能使用 Go 解析器。netcgo 标签会将原生和纯 Go 解析器都编译进二进制文件，但优先使用原生（CGO）解析器。使用 netcgo 时，仍可在运行时通过 GODEBUG=netdns=go 强制使用 Go 解析器。

将 netdns 设为数值，例如 GODEBUG=netdns=1，会使解析器打印有关其选择的调试信息。要在强制使用特定解析器的同时打印调试信息，可用加号连接这两项设置，例如 GODEBUG=netdns=go+1。

Go 解析器会随 DNS 请求发送 EDNS0 附加头部，表明愿意接收更大的 DNS 数据包。据报告，这可能导致某些调制解调器和路由器运行的 DNS 服务器偶发失败。设置 GODEBUG=netedns0=0 可禁止发送该附加头部。

在 macOS 上，如果使用 net 包的 Go 代码以 -buildmode=c-archive 构建，将生成的归档链接到 C 程序时，需要在链接 C 代码时传入 -lresolv。

在 Plan 9 上，解析器始终访问 /net/cs 和 /net/dns。

在 Windows 上，Go 1.18.x 及更早版本的解析器始终使用 GetAddrInfo 和 DnsQuery 等 C 库函数。

func JoinHostPort 

func JoinHostPort(host, port string) string

JoinHostPort 将 host 和 port 合并为“host:port”形式的网络地址。如果 host 包含冒号（例如 IPv6 地址字面量），JoinHostPort 返回“[host]:port”。

host 和 port 参数的说明见 Dial 函数。

func LookupAddr 

func LookupAddr(addr string) (names []string, err error)

LookupAddr 对给定地址执行反向查询，返回映射到该地址的名称列表。

返回的名称会经过验证，确保它们是格式正确的呈现格式域名。如果响应包含无效名称，这些记录会被过滤，同时返回错误和其余结果（如果有）。

type Conn

Conn 是通用的面向流的网络连接。

多个 goroutine 可以同时调用 Conn 的方法。 

type Conn interface {
    // Read 从连接读取数据。
    // 可将 Read 设置为在固定时限后超时并返回错误；
    // 参见 SetDeadline 和 SetReadDeadline。
    Read(b []byte) (n int, err error)

    // Write 向连接写入数据。
    // 可将 Write 设置为在固定时限后超时并返回错误；
    // 参见 SetDeadline 和 SetWriteDeadline。
    Write(b []byte) (n int, err error)

    // Close 关闭连接。
    // 所有阻塞的 Read 或 Write 操作都会解除阻塞并返回错误。
    // Close 是否阻塞直到缓冲数据全部发送，取决于具体情况；
    // 对于 TCP 连接，参见 [*TCPConn.SetLinger]。
    Close() error

    // LocalAddr 返回本地网络地址（如果已知）。
    LocalAddr() Addr

    // RemoteAddr 返回远端网络地址（如果已知）。
    RemoteAddr() Addr

    // SetDeadline 设置连接的读取和写入
    // 截止时间。它等价于同时调用
    // SetReadDeadline 和 SetWriteDeadline。
    //
    // 截止时间是一个绝对时间点，超过该时间后，I/O 操作
    // 会失败，而不是继续阻塞。截止时间适用于所有未来
    // 和正在等待的 I/O，而不仅是紧接着的那次
    // Read 或 Write 调用。超过截止时间后，
    // 可通过设置未来的截止时间恢复连接的使用。
    //
    // 如果超过截止时间，Read、Write 或其他
    // I/O 方法会返回一个包装 os.ErrDeadlineExceeded 的错误。
    // 可使用 errors.Is(err, os.ErrDeadlineExceeded) 判断。
    // 该错误的 Timeout 方法返回 true，但应注意，
    // 即使没有超过截止时间，其他一些错误的 Timeout 方法
    // 也可能返回 true。
    //
    // 可以在每次 Read 或 Write 成功后延长截止时间，
    // 以此实现空闲超时。
    //
    // t 的零值表示 I/O 操作不会超时。
    SetDeadline(t time.Time) error

    // SetReadDeadline 设置未来 Read 调用
    // 以及当前已阻塞的 Read 调用的截止时间。
    // t 的零值表示 Read 不会超时。
    SetReadDeadline(t time.Time) error

    // SetWriteDeadline 设置未来 Write 调用
    // 以及当前已阻塞的 Write 调用的截止时间。
    // 即使写入超时，也可能返回 n > 0，
    // 表示部分数据已成功写入。
    // t 的零值表示 Write 不会超时。
    SetWriteDeadline(t time.Time) error
}

func Dial 

func Dial(network, address string) (Conn, error)

Dial 连接到指定网络上的地址。

已知的网络有“tcp”、“tcp4”（仅 IPv4）、“tcp6”（仅 IPv6）、“udp”、“udp4”（仅 IPv4）、“udp6”（仅 IPv6）、“ip”、“ip4”（仅 IPv4）、“ip6”（仅 IPv6）、“unix”、“unixgram”和“unixpacket”。

对于 TCP 和 UDP 网络，地址形式为“host:port”。host 必须是 IP 地址字面量，或可以解析为 IP 地址的主机名。port 必须是端口号字面量或服务名。如果 host 是 IPv6 地址字面量，必须用方括号包裹，例如“[2001:db8::1]:80”或“[fe80::1%zone]:80”。zone 指定 IPv6 地址字面量的作用域，定义见 RFC 4007。JoinHostPort 和 SplitHostPort 函数用于处理这种形式的主机和端口对。使用 TCP 时，如果主机解析为多个 IP 地址，Dial 会依次尝试，直到其中一个连接成功。

示例： 

Dial("tcp", "golang.org:http")
Dial("tcp", "192.0.2.1:http")
Dial("tcp", "198.51.100.1:80")
Dial("udp", "[2001:db8::1]:domain")
Dial("udp", "[fe80::1%lo0]:53")
Dial("tcp", ":80")

对于 IP 网络，network 必须为“ip”、“ip4”或“ip6”，后接冒号和协议编号字面量或协议名称；地址形式为“host”。host 必须是 IP 地址字面量，或带区域标识的 IPv6 地址字面量。对于“0”或“255”等非通用协议编号，具体行为取决于操作系统。

示例： 

Dial("ip4:1", "192.0.2.1")
Dial("ip6:ipv6-icmp", "2001:db8::1")
Dial("ip6:58", "fe80::1%lo0")

对于 TCP、UDP 和 IP 网络，如果主机为空或为未指定 IP 地址字面量，则默认指本机。例如，TCP 和 UDP 中的“:80”、“0.0.0.0:80”或“[::]:80”，以及 IP 中的空字符串、“0.0.0.0”或“::”。

对于 Unix 网络，地址必须是文件系统路径。

type Dialer 1.1

Dialer 包含连接到地址时使用的选项。

各字段的零值等价于拨号时不使用该选项。因此，使用 Dialer 的零值拨号等价于直接调用 Dial 函数。

可以安全地并发调用 Dialer 的方法。 

type Dialer struct {
    // Timeout 是拨号等待连接
    // 完成的最长时间。如果同时设置了 Deadline，
    // 则可能更早失败。
    //
    // 默认不设置超时。
    //
    // 使用 TCP 拨号到具有多个 IP 地址的主机名时，
    // 超时时长可能会在这些地址之间分配。
    //
    // 无论是否设置超时，操作系统都可能施加
    // 更早的超时。例如，TCP 超时时长
    // 通常约为 3 分钟。
    Timeout time.Duration

    // Deadline 是一个绝对时间点，超过它之后拨号
    // 会失败。如果设置了 Timeout，则可能更早失败。
    // 零值表示没有截止时间，或与 Timeout 选项一样
    // 取决于操作系统。
    Deadline time.Time

    // LocalAddr 是拨号到某地址时使用的
    // 本地地址。该地址的类型必须
    // 与所拨号的网络兼容。
    // 如果为 nil，则自动选择本地地址。
    LocalAddr Addr

    // DualStack 以前用于启用 RFC 6555 快速回退
    // 支持，也称为 "Happy Eyeballs"：如果 IPv6 看起来
    // 配置错误且连接挂起，就会很快
    // 尝试 IPv4。
    //
    // 已弃用：快速回退默认启用。要禁用它，
    // 请将 FallbackDelay 设为负值。
    DualStack bool // Go 1.2

    // FallbackDelay 指定启动 RFC 6555
    // 快速回退连接之前的等待时长。
    //
    // 拨号到 "tcp" 且 IPv6 和 IPv4 地址都
    // 可用时，将第一个解析地址所属的地址族
    // 作为首选。经过 FallbackDelay 后，如果首选
    // 连接尚未成功，则开始尝试
    // 另一个地址族的连接。
    //
    // 如果为零，使用默认延迟 300 毫秒。
    // 负值禁用快速回退支持。
    FallbackDelay time.Duration // Go 1.5

    // KeepAlive 指定活动网络连接上
    // 保活探测之间的间隔。
    //
    // 如果 KeepAliveConfig.Enable 为 true，则忽略 KeepAlive。
    //
    // 如果为零，且协议和操作系统支持，
    // 则按默认值（当前为 15 秒）
    // 发送保活探测。不支持保活的网络协议
    // 或操作系统会忽略此字段。
    // 如果为负值，则禁用保活探测。
    KeepAlive time.Duration // Go 1.3

    // 在协议和操作系统支持时，KeepAliveConfig
    // 指定活动网络连接的
    // 保活探测配置。
    //
    // 如果 KeepAliveConfig.Enable 为 true，则启用保活探测。
    // 如果 KeepAliveConfig.Enable 为 false 且 KeepAlive 为负值，
    // 则禁用保活探测。
    KeepAliveConfig KeepAliveConfig // Go 1.23

    // Resolver 可选，用于指定另一个解析器。
    Resolver *Resolver // Go 1.8

    // Cancel 是可选通道，关闭该通道表示
    // 应取消拨号。并非所有拨号类型都支持
    // 取消。
    //
    // 已弃用：请改用 DialContext。
    Cancel <-chan struct{} // Go 1.6

    // 如果 Control 非 nil，会在创建网络连接之后、
    // 实际拨号之前调用它。
    //
    // 传给 Control 函数的 network 和 address 参数不一定
    // 与传给 Dial 的相同。对 TCP 网络调用 Dial 时，
    // 会向 Control 传入 "tcp4" 或 "tcp6"；
    // UDP 网络变为 "udp4" 或 "udp6"，IP 网络变为 "ip4" 或 "ip6"，
    // 其他已知网络则原样传入。
    //
    // 如果 ControlContext 非 nil，则忽略 Control。
    Control func(network, address string, c syscall.RawConn) error // Go 1.11

    // 如果 ControlContext 非 nil，会在创建网络连接之后、
    // 实际拨号之前调用它。
    //
    // 传给 ControlContext 函数的 network 和 address 参数不一定
    // 与传给 Dial 的相同。对 TCP 网络调用 Dial 时，

    //

    // 包含已过滤或未导出的字段
}

type KeepAliveConfig
				
				1.23
			

			
KeepAliveConfig 包含 TCP 保活选项。

type PacketConn
				
				
			

			
PacketConn 是通用的面向数据包的网络连接。

多个 goroutine 可以同时调用 PacketConn 的方法。

			
type PacketConn interface {
    // ReadFrom 从连接读取一个数据包，
    // 将负载复制到 p。它返回复制到 p 的
    // 字节数，以及数据包上携带的
    // 回传地址。
    // 它返回读取的字节数（0 <= n <= len(p)）
    // 和遇到的错误。调用者应始终先处理
    // 返回的 n > 0 字节，再考虑错误 err。
    // 可将 ReadFrom 设置为在固定时限后超时并返回错误；
    // 参见 SetDeadline 和 SetReadDeadline。
    ReadFrom(p []byte) (n int, addr Addr, err error)

    // WriteTo 向 addr 写入负载为 p 的数据包。
    // 可将 WriteTo 设置为在固定时限后超时并返回 Error；
    // 参见 SetDeadline 和 SetWriteDeadline。
    // 面向数据包的连接很少发生写入超时。
    WriteTo(p []byte, addr Addr) (n int, err error)

    // Close 关闭连接。
    // 所有阻塞的 ReadFrom 或 WriteTo 操作都会解除阻塞并返回错误。
    Close() error

    // LocalAddr 返回本地网络地址（如果已知）。
    LocalAddr() Addr

    // SetDeadline 设置连接的读取和写入
    // 截止时间。它等价于同时调用
    // SetReadDeadline 和 SetWriteDeadline。
    //
    // 截止时间是一个绝对时间点，超过该时间后，I/O 操作
    // 会失败，而不是继续阻塞。截止时间适用于所有未来
    // 和正在等待的 I/O，而不仅是紧接着的那次
    // Read 或 Write 调用。超过截止时间后，
    // 可通过设置未来的截止时间恢复连接的使用。
    //
    // 如果超过截止时间，Read、Write 或其他
    // I/O 方法会返回一个包装 os.ErrDeadlineExceeded 的错误。
    // 可使用 errors.Is(err, os.ErrDeadlineExceeded) 判断。
    // 该错误的 Timeout 方法返回 true，但应注意，
    // 即使没有超过截止时间，其他一些错误的 Timeout 方法
    // 也可能返回 true。
    //
    // 可以在每次 ReadFrom 或 WriteTo 成功后延长截止时间，
    // 以此实现空闲超时。
    //
    // t 的零值表示 I/O 操作不会超时。
    SetDeadline(t time.Time) error

    // SetReadDeadline 设置未来 ReadFrom 调用
    // 以及当前已阻塞的 ReadFrom 调用的截止时间。
    // t 的零值表示 ReadFrom 不会超时。
    SetReadDeadline(t time.Time) error

    // SetWriteDeadline 设置未来 WriteTo 调用
    // 以及当前已阻塞的 WriteTo 调用的截止时间。
    // 即使写入超时，也可能返回 n > 0，
    // 表示部分数据已成功写入。
    // t 的零值表示 WriteTo 不会超时。
    SetWriteDeadline(t time.Time) error
}

返回的 cname 是第一条 SRV 应答记录的所有者名称，通常为构造出的 DNS 名称（_service._proto.name）；如果 CNAME 记录将查询重定向到其他名称，则可能不同。

返回的服务名称会经过验证，确保它们是格式正确的呈现格式域名。如果响应包含无效名称，这些记录会被过滤，同时返回错误和其余结果（如果有）。
