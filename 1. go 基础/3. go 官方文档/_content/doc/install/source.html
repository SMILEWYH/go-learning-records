本文介绍如何从源代码构建并运行 Go。若使用安装程序，请参阅下载与安装。

简介

Go 是一个开源项目，采用 BSD 风格许可证发布。本文介绍如何获取源代码，在本机上构建并运行。

大多数用户不需要自行构建，而是按照下载与安装中的说明安装预编译二进制包，过程更简单。如果你希望参与这些预编译包所包含内容的开发，请继续阅读。

Go 官方提供两套编译器工具链。本文主要介绍 gc Go 编译器及其工具。gccgo 是使用 GCC 后端的较传统编译器，有关它的开发说明，请参阅配置和使用 gccgo。

Go 编译器支持以下指令集：

amd64, 386
x86 指令集，支持 64 位和 32 位。
arm64, arm
ARM 指令集，支持 64 位（AArch64）和 32 位。
loong64
64 位 LoongArch 指令集。
mips64, mips64le, mips, mipsle
MIPS 指令集，支持大端、小端以及 64 位和 32 位。
ppc64, ppc64le
64 位 PowerPC 指令集，支持大端和小端。
riscv64
64 位 RISC-V 指令集。
s390x
IBM z/Architecture 架构。
wasm
WebAssembly.

这些编译器可面向 AIX、Android、DragonFly BSD、FreeBSD、Illumos、Linux、macOS/iOS（Darwin）、NetBSD、OpenBSD、Plan 9、Solaris 和 Windows 操作系统生成代码，但并非每个操作系统都支持所有架构。

被列为“一等支持”的平台移植列表见 Wiki 中的一等支持平台页面。

所有支持的组合都列在下文的环境变量一节中。

完整的系统要求请参阅 Go Wiki 的 MinimumRequirements 页面。

安装用于引导的 Go 编译器二进制文件

Go 工具链本身由 Go 编写，因此构建它之前需要先安装 Go 编译器。首次构建工具的脚本会在 $PATH 中查找“go”命令；只要系统已经安装 Go，并配置好了 $PATH，就可以从源代码构建 Go。你也可以将 $GOROOT_BOOTSTRAP 设置为某个 Go 安装的根目录，用它来构建新的 Go 工具链；此时将使用 $GOROOT_BOOTSTRAP/bin/go 这个 go 命令。

所需的最低 Go 版本取决于要构建的目标 Go 版本：

  • Go <= 1.4：C 工具链。
  • 1.5 <= Go <= 1.19：Go 1.4 编译器。
  • 1.20 <= Go <= 1.21：Go 1.17 编译器。
  • 1.22 <= Go <= 1.23：Go 1.20 编译器。
  • 此后，Go 1.N 需要 Go 1.M 编译器，其中 M 是将 N-2 向下取整到偶数所得的值。例如，Go 1.24 和 1.25 需要 Go 1.22。

有四种方法可以获得引导工具链：

  • 下载较新的 Go 二进制发行版。
  • 在已安装可用 Go 的系统上交叉编译工具链。
  • 使用 gccgo。
  • 从 Go 1.4 编译工具链，这是最后一个使用 C 编写编译器的 Go 发行版本。

下面分别介绍这些方法。

使用二进制发行版作为引导工具链

要使用二进制发行版作为引导工具链，请访问下载页面，或使用其他满足最低版本要求的 Go 安装包。

交叉编译源代码获得引导工具链

对于 Go 1.4 未支持的系统（例如 linux/ppc64le），需要从源代码交叉编译引导工具链。先在另一台系统上安装 Go，然后运行 bootstrap.bash。

例如，执行： 

$ GOOS=linux GOARCH=ppc64 ./bootstrap.bash

bootstrap.bash 会针对指定的 GOOS/GOARCH 组合交叉编译工具链，并将生成的目录树保存在 ../../go-${GOOS}-${GOARCH}-bootstrap。将该目录树复制到相应目标平台的机器上，再将其作为 GOROOT_BOOTSTRAP，即可引导本地构建。

使用 gccgo 引导工具链

使用 gccgo 作为引导工具链时，需要确保 $GOROOT_BOOTSTRAP/bin/go 指向 gccgo 5 附带的 go 工具。例如，在 Ubuntu Vivid 上： 

$ sudo apt-get install gccgo-5
$ sudo update-alternatives --set go /usr/bin/go-5
$ GOROOT_BOOTSTRAP=/usr ./make.bash

从 C 源代码构建引导工具链

要从 C 源代码构建引导工具链，请使用 Git 分支 release-branch.go1.4 或 go1.4-bootstrap-20171003.tar.gz。它包含 Go 1.4 源代码，以及为了让工具在较新操作系统上运行而积累的修复。（Go 1.4 是最后一个以 C 编写工具链的发行版本。）解压 Go 1.4 源代码后，使用 cd 进入 src 子目录，在环境中设置 CGO_ENABLED=0，然后运行 make.bash（Windows 上运行 make.bat）。

将 Go 1.4 源代码解压到 GOROOT_BOOTSTRAP 目录后，必须让这个 Git 克隆始终保持在 release-branch.go1.4 分支。尤其不要在后文“获取代码仓库”的步骤中复用这个克隆。Go 1.4 引导工具链假定仓库根目录下存在 Go 1.4 源代码，并且必须能够正确遍历这些源文件。

注意，Go 1.4 无法在后续 Go 版本所支持的所有系统上运行，尤其不支持当前版本的 macOS。在这些系统上，必须通过其他方法获得引导工具链。

按需安装 Git

下一步需要安装 Git。继续之前，请确认 git 命令可用。

如果尚未安装可用的 Git，请按照 Git 下载页面中的说明安装。

（可选）安装 C 编译器

要构建支持 cgo 的 Go 安装，使 Go 程序能够导入 C 库，需要先安装 gcc 或 clang 等 C 编译器。请使用系统常规的安装方式完成安装。

要在不支持 cgo 的情况下构建，请在运行 all.bash 或 make.bash 之前设置环境变量 CGO_ENABLED=0。

获取代码仓库

进入准备安装 Go 的目录，并确保其中不存在 goroot 目录。然后克隆仓库，检出最新发行版标签或发布分支（例如 go1.22.0 或 release-branch.go1.22）： 

$ git clone https://go.googlesource.com/go goroot
$ cd goroot
$ git checkout <tag>

其中，<tag> 是发行版的版本字符串。

Go 会安装到源代码的检出目录中。例如，若检出到 $HOME/goroot，可执行文件会安装到 $HOME/goroot/bin。该目录可以使用任意名称，但如果检出到 $HOME/go，就会与 $GOPATH 的默认位置冲突。请参阅下文的 GOPATH。

提醒：如果你在前文选择从源代码编译引导工具链，此处仍然需要再次执行 git clone，以检出最新的 <tag>。必须单独保留 Go 1.4 仓库。

（可选）切换到 master 分支

如果你准备修改 Go 源代码并向项目贡献修改，请将仓库从发行版标签切换到 master（开发）分支；否则跳过此步骤。 

$ git checkout master

安装 Go

运行以下命令构建 Go 发行版： 

$ cd src
$ ./make.bash

（在 Windows 上构建时使用 make.bat。）

如果一切顺利，完成时会输出类似以下内容： 

---
Installed Go for linux/amd64 in /home/you/go.
Installed commands in /home/you/go/bin.
*** You need to add /home/you/go/bin to your $PATH. ***

最后几行的具体内容取决于安装时使用的操作系统、架构和根目录。

有关控制构建过程的更多信息，请参阅下文的环境变量一节。也可以运行 all.bash（或 all.bat）来执行 Go 的重要测试，这比仅构建 Go 花费的时间更长。

验证安装

构建一个简单程序，检查 Go 是否安装正确。

创建名为 hello.go 的文件，并写入以下程序： 

package main

import "fmt"

func main() {
	fmt.Printf("hello, world\n")
}

然后使用 go 工具运行： 

$ go run hello.go
hello, world

如果看到“hello, world”消息，说明 Go 已正确安装。

安装其他工具

一些 Go 工具（包括 gopls）的源代码保存在 golang.org/x/tools 仓库中。要安装其中一个工具（以 gopls 为例）： 

$ go install golang.org/x/tools/gopls@latest

社区资源

帮助页面列出了常用的社区资源，其中活跃的开发者可以帮助你解决安装和开发过程中的问题。若希望跟进最新变化，还可以订阅 golang-checkins 邮件列表，它会为 Go 仓库中的每次提交发送摘要。

可以通过 Go 问题跟踪系统报告缺陷。

跟进版本发布

新版本会在 golang-announce 邮件列表中发布公告。每份公告都会提到最新版本标签，例如 go1.9。

要将现有目录树更新到最新版本，可以运行： 

$ cd go/src
$ git fetch
$ git checkout <tag>
$ ./all.bash

其中，<tag> 是发行版的版本字符串。

可选环境变量

可以通过环境变量自定义 Go 工具。构建过程不要求设置任何这些变量，但你可以通过设置它们覆盖默认值。运行 make.bash 时设置这些环境变量，会为新构建的工具指定默认值。使用工具时，也可以针对某次构建覆盖这些默认值，具体见 go 命令文档。

  • $GOROOT

    Go 目录树的根目录，通常为 $HOME/go1.X。它的值会在编译时写入构建结果，默认是运行 all.bash 的目录的上一级目录。除非需要在本地多个仓库副本之间切换，否则无需设置。

  • $GOOS 和 $GOARCH

    目标操作系统和编译架构的名称。$GOOS 默认为引导工具链中的 runtime.GOOS 值。$GOARCH 默认为下文介绍的 $GOHOSTARCH 值。

    $GOOS 可取 android、darwin、dragonfly、freebsd、illumos、ios、js、linux、netbsd、openbsd、plan9、solaris、wasip1 和 windows。

    $GOARCH 可取 amd64（64 位 x86，最成熟的移植）、386（32 位 x86）、arm（32 位 ARM）、arm64（64 位 ARM）、ppc64le（64 位 PowerPC，小端）、ppc64（64 位 PowerPC，大端）、mips64le（64 位 MIPS，小端）、mips64（64 位 MIPS，大端）、mipsle（32 位 MIPS，小端）、mips（32 位 MIPS，大端）、s390x（64 位 IBM System z，大端）和 wasm（32 位 WebAssembly）。

  • $GOHOSTARCH

    宿主机编译架构的名称，默认为本机系统架构。

    可用取值与上面列出的 $GOARCH 相同，但所指定的值必须与本机系统兼容。例如，在 x86 系统上不应将 $GOHOSTARCH 设置为 arm。

  • $GO386 （仅适用于 386，默认值为 sse2）

    此变量控制 gc 实现浮点运算的方式。

    • GO386=softfloat：使用软件浮点运算，应该支持所有 x86 芯片（Pentium MMX 及更新型号）。
    • GO386=sse2：使用 SSE2 执行浮点运算，性能更好，但仅适用于 Pentium 4、Opteron、Athlon 64 及更新型号。
  • $GOARM （仅适用于 arm；在目标处理器上构建时自动检测默认值，否则默认为 7）

    指定运行时所面向的 ARM 浮点协处理器架构版本。如果在目标系统上编译，会自动检测此值。

    • GOARM=5：使用软件浮点运算，适用于没有 VFP 协处理器的 CPU
    • GOARM=6：仅使用 VFPv1；原文将其列为交叉编译时的默认值，通常适用于 ARM11 及更新内核（也支持 VFPv2 及更新版本）
    • GOARM=7：使用 VFPv3，通常适用于 Cortex-A 内核

    如果不确定，可以先不设置此变量，首次运行 Go 可执行文件时再根据需要调整。Go 社区 Wiki 中的 GoARM 页面提供了 Go 对 ARM 支持的更多信息。

  • $GOARM64 （仅适用于 arm64，默认值为 v8.0）

    指定编译所面向的 ARM64 架构版本。允许的取值见 Go Wiki 的 MinimumRequirements 页面。

  • $GOAMD64 （仅适用于 amd64，默认值为 v1）

    指定编译所面向的微架构级别。有效值为 v1（默认值）、v2、v3 和 v4。详情请参阅 Go Wiki 的 MinimumRequirements 页面。

  • $GOMIPS （仅适用于 mips 和 mipsle）
    $GOMIPS64 （仅适用于 mips64 和 mips64le）

    这些变量指定是否使用浮点指令。设置为 hardfloat 时使用浮点指令，这也是默认值；设置为 softfloat 时使用软件浮点运算。

  • $GOPPC64 （仅适用于 ppc64 和 ppc64le）

    此变量指定编译器面向的处理器级别，即指令集架构版本。默认值为 power8。

    • GOPPC64=power8：生成 ISA v2.07 指令
    • GOPPC64=power9：生成 ISA v3.00 指令
  • $GORISCV64 （仅适用于 riscv64）

    此变量指定编译所面向的 RISC-V 用户态应用配置规范，默认值为 rva20u64。

    • GORISCV64=rva20u64：仅使用 RVA20U64 配置规范强制要求的 RISC-V 扩展
    • GORISCV64=rva22u64：仅使用 RVA22U64 配置规范强制要求的 RISC-V 扩展
    • GORISCV64=rva23u64：仅使用 RVA23U64 配置规范强制要求的 RISC-V 扩展
  • $GOWASM （仅适用于 wasm）

    此变量是以逗号分隔的实验性 WebAssembly 特性列表，指定编译后的 WebAssembly 二进制文件允许使用的特性。默认不使用任何实验性特性。

    • GOWASM=satconv：生成 饱和式（不触发陷阱的）浮点数到整数转换
    • GOWASM=signext：生成 符号扩展运算符

注意，$GOARCH 和 $GOOS 标识的是目标环境，而不是运行构建工具的环境。从这个意义上说，你始终在进行交叉编译。这里的架构指目标环境能够运行的二进制文件类型：如果 x86-64 机器运行的是仅支持 32 位的操作系统，就必须将 GOARCH 设为 386，而非 amd64。

再次强调，构建、安装和开发 Go 目录树时，不要求设置上述任何变量。
