简介

下面介绍为 GCC 的 gccgo 前端贡献代码时需要了解的事项。关于 gccgo 之外的 Go 项目贡献，请参阅为 Go 项目作贡献；自行构建 gccgo 的说明见安装和使用 gccgo。gccgo 前端开发流程的更多细节，请参阅 gofrontend 仓库中的 HACKING 文件。

法律方面的前提条件

对 gccgo 前端和相关 libgo 库的所有修改，都必须遵守 Go 版权规则。对于属于 GCC 而非 gccgo 的代码，必须遵守通用的 GCC 贡献规则。

代码

gccgo 前端的主源码位于 https://go.googlesource.com/gofrontend，镜像位于 https://github.com/golang/gofrontend。主源码无法单独构建，必须与 GCC 一起构建（将来可能支持其他编译器）。对 gccgo 前端的修改也会同步到托管在 gcc.gnu.org 上的 GCC 源码仓库。gofrontend 仓库中的 go 目录镜像到 GCC 仓库的 gcc/go/gofrontend 目录；gofrontend 的 libgo 目录镜像到 GCC 的 libgo 目录。此外，Go 主仓库中的 test 目录镜像到 GCC 仓库的 gcc/testsuite/go.test/test 目录。

这些目录的修改始终从主源码流向 GCC 仓库。不要直接修改 GCC 仓库中的这些文件；应先修改主源码，再同步镜像。

gccgo 前端使用 C++ 编写，遵循 GNU 和 GCC 的 C++ 编码规范。编写前端代码时，应沿用周围代码的格式。几乎所有 GCC 专有代码都不在前端本身，而是在 GCC 源码的 gcc/go 目录中。

gccgo 的运行时库与 Go 主仓库中的库大体相同。通过 shell 脚本 libgo/merge.sh，Go 仓库中的库代码会定期合并到 gofrontend 的 libgo/go 目录，然后再合并到 GCC 仓库。因此，大多数库代码修改都应在 Go 主仓库中进行。libgo/go 之外的文件是 gccgo 专有的；不过，libgo/runtime 中的部分文件源自 Go 主仓库的 src/runtime。

测试

所有补丁都必须经过测试。引入新的测试失败的补丁不能被接受。

要运行 gccgo 测试套件，请在构建目录中执行 make check-go。这会运行 gcc/testsuite/go.* 下的各种测试，以及 libgo 测试套件。其中，从 Go 主仓库复制的测试通过 gcc/testsuite/go.test/go-test.exp 中的 DejaGNU 脚本运行。

大多数新增测试应提交到 Go 主仓库，随后再同步到 GCC 仓库。如果需要 gccgo 专用测试，应将其放入 GCC 仓库的 gcc/testsuite/go.go-torture 或 gcc/testsuite/go.dg 目录。

提交修改

Go 前端的修改应遵循与 Go 主仓库相同的流程，不过使用的是 gofrontend 项目和 gofrontend-dev@googlegroups.com 邮件列表，而不是 go 项目和 golang-dev@googlegroups.com 邮件列表。这些修改随后会合并到 GCC 源码中。
