# Go 实战项目导览

已根据桌面 `go-demo` 的全部学习内容，生成三个可独立运行的业务项目。建议按下表顺序阅读：先在线交易，再时间排期，最后并发文件处理。

## 三个项目

| 项目 | 业务类型 | 完整流程 | 开始阅读 |
| --- | --- | --- | --- |
| go-shop-orders | 电商交易与库存 | 查询商品 → 下单扣库存 → 发货或取消 → 文件保存与重启恢复 | [中文 README](/Users/vvyh/Desktop/go-shop-orders/README.md) |
| go-room-booking | 企业资源排期 | 查询会议室 → 校验容量和冲突 → 创建预约 → 取消释放时间段 | [中文 README](/Users/vvyh/Desktop/go-room-booking/README.md) |
| go-log-report | 运维离线分析 | 枚举日志 → 有界并发读取 → 聚合错误率和耗时 → 生成报告 | [中文 README](/Users/vvyh/Desktop/go-log-report/README.md) |

每个项目都是独立 Go 模块，可单独复制、编译和运行。所有依赖来自标准库。两个服务默认端口分别为 8091、8092，可同时启动；日志工具不监听端口。

## 五分钟体验

以下每段独立执行，不要求同时开启服务：

```sh
cd ~/Desktop/go-shop-orders
go run ./cmd/demo
```

```sh
cd ~/Desktop/go-room-booking
go run ./cmd/demo
```

```sh
cd ~/Desktop/go-log-report
go run .
```

前两个命令使用临时目录和空闲端口演示完整业务，结束后自动清理。第三个读取项目内的模拟日志，只向终端打印报告。所有项目都提供本机构建产物 `bin/项目英文名`，也可以自己重新 build。

## 能力边界

- 持久化采用小规模 JSON 文件；一个文件只允许一个进程写入，不包含数据库、事务框架、Redis 或消息队列。
- 订单不接真实支付和物流，会议预约不接企业账号或外部日历，日志分析不访问生产主机。
- 没有 JWT、OAuth、gRPC、容器编排或 CI/CD。默认本机运行，以现有 Go 知识完成真实业务规则和失败路径。
- 文件保存时持有业务锁，是保证这个小型实现顺序一致的取舍；性能优化、数据库并发控制和多实例部署留给后续学习。
- 三个项目互相独立，少量公共 HTTP/文件辅助代码分别保留在各自模块内，复制一个目录即可继续学习。

## 建议的学习方式

1. 先运行 demo，预测下一步库存、状态或统计值。
2. 读 model，再读 service，最后读 HTTP 与启动代码。
3. 跟随 README 中的原章节对照回到 go-demo 复习。
4. 修改一个边界输入，运行对应测试观察拒绝原因。
5. 完成 README 末尾的可选练习；当前主业务都已实现，练习不影响项目直接运行。

原 `go-demo` 的源码、练习和已有修改均保留；新项目放在桌面的三个独立目录中。
