# 运行与部署

以下命令先进入项目目录：

```sh
cd ~/Desktop/go-room-booking
go version
go test -race ./...
go vet ./...
go run ./cmd/demo
```

沿用原项目的 `go 1.27.0`，本机使用 Go 1.27.1。所有依赖都来自标准库，因此无需安装数据库、Node.js 或第三方框架。项目是一个独立模块，不需要原学习项目的 go.work。

## 启动和配置

```sh
go run .
# 另一个终端：
curl -i http://127.0.0.1:8092/healthz
```

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `-addr` | 未设置 | 指定 host:port，优先于 PORT |
| `PORT` 环境变量 | 8092 | 未提供 -addr 时使用，端口必须为 1..65535 |
| `-data` | ./data/state.json | 状态文件路径，相对于启动程序时的工作目录 |
| `-version` | false | 输出构建版本后退出 |

```sh
PORT=9091 go run .
go run . -addr 127.0.0.1:9092 -data ./data/another-state.json
go run . -h
```

第一次启动没有数据文件时加载初始状态；第一次成功修改才保存文件。后续重启读回旧数据。文件损坏会报错退出，不会悄悄清空。不要让两个进程同时使用同一个数据文件；Mutex 仅保护一个进程。停止服务后，可以手动复制状态文件备份，或选择新的 `-data` 路径开始一套独立数据。

数据存储使用同目录临时文件、Sync、Close、Rename。当前方案针对本机 macOS/Linux 的小型练习，文件大小上限 16 MiB；不提供数据库事务、多进程协调或掉电持久性保证。保存整个快照时会占有业务锁，适合少量数据，不适合高吞吐业务。

## 构建本机程序

```sh
mkdir -p bin
go build -trimpath -ldflags '-X main.version=v1.0.0' -o ./bin/go-room-booking .
./bin/go-room-booking -version
./bin/go-room-booking -data ./data/state.json
```

`go build .` 编译整个 main 包；不要只构建某个 Go 文件。按 Ctrl+C 或发送 SIGTERM 后，程序停止接收连接，并给正在执行的 HTTP 请求最多 5 秒收尾。超时会强制关闭网络连接并报告错误；操作系统磁盘故障导致的阻塞不属于 Go context 能强行取消的范围。

## 练习交叉编译

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o ./bin/go-room-booking-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o ./bin/go-room-booking-linux-arm64 .
```

产物适配的 CPU 由部署目标决定；Linux 产物不能直接在 macOS 执行。这些是本地构建命令，没有上传或发布动作。当前服务没有用户认证，默认监听本机；学习范围内以本地运行和测试为验收。

## 常见问题

- **address already in use**：改用 `-addr 127.0.0.1:9091`，不要结束其他不相关程序。
- **重启后看不到数据**：确认 `-data` 和启动工作目录是否一致。
- **invalid JSON / 数据内容不合法**：保留旧文件，检查意外手动编辑或选择新的数据文件路径。
- **400 / 409**：查看响应中的 `error`；分别表示输入问题或业务冲突。
- **为什么没有数据库**：原第 25 章只讲反射生成 SQL，明确将 database/sql、事务和真正 ORM 留到后续。
